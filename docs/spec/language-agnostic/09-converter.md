# 09. 変換器(TOML と YAML の相互変換)

この文書は、`conductor convert <ファイル> --to <yaml|toml>` の中身である変換器の振る舞いを、実装言語に依存しない形で定める。この文書だけで、任意の言語・任意のライブラリ(または自前の構文解析)により、同じ受理・拒否・出力・エラーを返す変換器を実装できることを目標とする。

- 変換器は、定義ファイルの**検証をしない**。変換した結果が `conductor` の定義([03. 定義ファイルの書式と検証](03-definition-format.md))として正しいかは見ない(任意の TOML / YAML のマップを変換する)。
- (v0.9.0 以降)変換器は、定義のキーを列挙しない。したがって、v0.9.0 で加わったキー(`[pipeline.env]`、`[job.env]`(値は文字列のテーブル)、`env_file`(文字列、または文字列の配列))も、ほかのキーと同じ規則で往復する。v0.9.0 のために、変換の規則は変わっていない。
- 副作用はない: ファイルへの書き込み、環境変数、プロセス、ネットワークに触れない(読むのは入力ファイル 1 つだけ)。
- 入力の値を、エラーの文に含めない(キー名だけを、エスケープと切り詰めをして、場所として示すことがある)。
- 確認できなかった点は「未確認」と書く。
- 「必須」の挙動は、利用者から見える結果(受理/拒否、変換結果の文字列、エラーの種類・文言・行・場所)で、同じにしなければならない。「任意」「実装に任せてよい」と書いた点は、利用者から見える結果の意味(変換結果を読み戻した木)が変わらない範囲で、実装が選んでよい。
- コマンドの引数・終了コードの全体は [04. CLI](04-cli.md) と [10. エラーと終了コード](10-errors-and-exit-codes.md)、メッセージの言語の選び方は [08. 出力と多言語対応](08-output-and-i18n.md) に従う。

## 1. 入口と入出力

| 入口 | 引数 | 戻り値 |
|------|------|--------|
| `convert(request)` | 入力ファイルのパス、変換後の形式 | 成功: 変換結果の文字列、失敗: 変換の誤り(第 10 節) |
| `convert_text(text, target, file_label)` | 文字列、変換後の形式、表示用のファイル名 | 同上(ファイルに触れない) |

- 変換後の形式は `yaml` または `toml`。
- **入力の形式は、変換後の形式の反対**とみなす(`--to yaml` なら入力は TOML、`--to toml` なら入力は YAML)。拡張子は見ない。`.toml` の名前のファイルでも、`--to toml` なら YAML として読む。同じファイルを `--to yaml` にすれば、TOML として読もうとして、文法の誤りになる。
- 変換結果は、全部作ってから 1 つの文字列として返す。失敗のときは、出力は無い。
- `conductor convert` は、成功したら結果を標準出力に 1 回で書く。失敗したら標準出力は空で、標準エラーに原因を出し、終了コード 67 で終わる([04](04-cli.md)・[10](10-errors-and-exit-codes.md))。

## 2. 処理の流れと失敗の順序

```
Intake → 読み取り(Read) → [YAML 入力のみ] 文書の確認(RootCheck) → 展開と写し取り(Resolve) → 書き出し(Write)
```

失敗は、次の順で最初に見つかったものを 1 件だけ返す(以降は実行しない)。

| 順 | 段階 | 失敗 |
|----|------|------|
| 1〜2 | Intake: 開く(存在しない → `fileMissing`、権限など → `unreadable`) | 第 3 節 |
| 3 | Intake: 通常のファイルでない → `unreadable`、大きさが 1 MiB を超える → `tooLarge` | 第 3 節 |
| 4 | Intake: 上限 + 1 バイトまでの読み取りと UTF-8 の確認 → `unreadable` | 第 3 節 |
| 5 | 読み取り: 文法の誤り、キーの重複(リテラル)、再帰するアンカー、定義されていないアンカー、読み取り時の深さ超過 → `syntax`(YAML は最後の文書まで読んで確かめる) | 第 4・5 節 |
| 6 | 複数の文書(YAML)→ `unrepresentable` | 第 5.3 節 |
| 7 | 最上位がマップでない(YAML)→ `rootNotMap` | 第 5.3 節 |
| 8 | 展開: 要素数の上限(`tooLarge`)、文字の大きさの上限(`tooLarge`)、展開後の深さの上限(`syntax`)、マージキーの値がマップでない(`unrepresentable`)、展開でだけ生じるキーの重複(`syntax`) | 第 6 節 |
| 9 | 展開で記録した、表せない値のうち、入力に現れる順で最初のもの → `unrepresentable` | 第 7 節 |

- 順 8 の上限超過は、順 9 より優先する(先に `null` があっても、上限超過が返る)。
- 同じ段階で複数あるときは、入力に現れる順で最初のものを返す。
- 順 5(文法)は、順 6(複数の文書)より先。たとえば `a: 1\n---\nb: [1\n` は、2 つ目の文書の文法の誤りを `syntax` として返す。
- 順 3 は順 4 より先: 1 MiB を超え、かつ UTF-8 でない入力は `tooLarge`。順 3 は順 5 より先: 1 MiB を超える入力は、中身が壊れていても `tooLarge`。

## 3. 取り込み(Intake)

| 順 | 条件 | `kind` | 理由(日本語の原文) |
|----|------|--------|----------------------|
| 1 | ファイルを開こうとして「存在しない」 | `fileMissing` | `指定の場所にファイルがありません` |
| 2 | ファイルを開けない。権限がない | `unreadable` | `読み取りの権限がありません` |
| 2' | 同、メタデータで通常のファイルでないと分かるとき(ディレクトリを開く操作自体は成功する OS など) | `unreadable` | `通常のファイルではありません` |
| 2'' | 同、その他の失敗 | `unreadable` | `読み取りに失敗しました` |
| 3 | 開いたファイルの情報(種別・大きさ)が取れない | `unreadable` | 権限なら `読み取りの権限がありません`、他は `読み取りに失敗しました` |
| 3' | 通常のファイルでない(ディレクトリなど) | `unreadable` | `通常のファイルではありません` |
| 4 | 大きさが 1 MiB(1,048,576 バイト)を超える | `tooLarge` | `入力が上限(1 MiB)を超えています` |
| 5 | 読み取り結果が上限を超える(順 4 のあとに大きくなった場合) | `tooLarge` | 同上 |
| 6 | 読み取りの途中の失敗 | `unreadable` | 権限なら `読み取りの権限がありません`、他は `読み取りに失敗しました` |
| 7 | UTF-8 として読めない | `unreadable` | `UTF-8 として読めません` |

- 先にファイルを開き、**開いたもの**の情報で通常のファイルかと大きさを調べる(開いてから調べるので、調べたあとにファイルが差し替わっても、読み取りの結果と食い違わない)。
- **ちょうど 1 MiB は受理**し、1 バイトでも超えれば `tooLarge`。読み取りは「上限 + 1 バイト」まで。
- 権限のない(mode 000 の)ファイルは、大きさにかかわらず `unreadable`(開く操作が先に失敗するので、1 MiB を超える mode 000 のファイルも `unreadable`)。
- 行番号は付かない。
- 空のファイル(0 バイト)は、空の入力として次へ進む(YAML は `rootNotMap`、TOML は空のマップ)。
- OS による権限・種別の判定の細部は、実装に任せてよい。必須なのは、上の表の条件の順序と、各理由の文言である。
- 定義ファイルの取り込み([03 第 3 節](03-definition-format.md))とは、上限超過と UTF-8 の理由の文言が違う(ここは `入力が上限(1 MiB)を超えています`、`UTF-8 として読めません`)。

## 4. TOML の読み取り(`--to yaml` のとき)

受理する文法は、[03. 定義ファイルの書式と検証](03-definition-format.md)の第 4 節(4.1〜4.8)と**同じ**である。定義ファイルの読み取りとの違いは次のとおり(すべて必須)。

| 項目 | 定義ファイル(03) | 変換器 |
|------|-------------------|--------|
| 64 ビット符号つき整数の範囲外の整数リテラル | 読み取りでは受理し、値を使う箇所で拒否 | **`syntax`**(行つき)。例: `n = 9223372036854775808` は 1 行目 |
| 範囲外の浮動小数(`1e400`、`-1e400`) | 受理(検査しない) | **`syntax`**(行つき) |
| 日時(オフセットつき日時・ローカル日時・日付・時刻) | 受理(型は日時) | 受理するが、「日時」の印をつけた値になり、第 7 節で `unrepresentable` |
| 文法の誤りの理由 | `TOML の文法に誤りがあります` | `TOML として読めません`(v0.9.6 までは `文法の誤りです`) |
| 深さの数え方・理由 | 根を数えない。32 段まで。理由 `入れ子が深すぎます(上限は 32 段)`、行つき | **根を 1 段と数える。合計 32 段まで**。理由 `入れ子が深すぎます(上限 32)`、**行なし** |

- 受理しなければならない TOML の構文と、拒否しなければならない構文は、03 の 4.6、4.7。受理してよい任意の拡張(インラインテーブルの中の改行と末尾のカンマ、エスケープ `\e` と `\xHH`、秒を省略した時刻)は、03 の 4.8 のとおり任意。
- 空の入力、コメントだけの入力は、空のマップ。UTF-8 の BOM は受理される。LF・CRLF の両方を受理する。
- 文法の誤りは、`syntax`、理由 `TOML として読めません`(v0.9.6 までは、種類の文と同じ `文法の誤りです`)。行番号は、03 の 4.9 の規則(位置の決め方、行の数え方)に従う。例: `a = 1\nb = = 2\n` は 2 行目、`a = 1\na = 2\n` は 2 行目、`n = 9223372036854775808` は 1 行目。位置が決まらないときは行なし。
- 値の写し取り: 文字列、整数、浮動小数(`inf`、`-inf`、`nan`、`+nan`、`-nan`、`-0.0` を含む。NaN の符号は区別しない)、真偽値、配列、テーブルを、そのまま内部表現(第 6 節)にする。日時は、印だけをつけた値にする。
- 浮動小数の書式の例(受理): `+inf`、`-nan`、`1_0.5_0`(値 10.5)、`6.02e+2`(値 602.0)、`1E3`(値 1000.0)、`0e0`(値 0.0)、`1e1_0`(値 1e10)。拒否: `1.e3`、`00`、`.5`。整数: `-0` は 0、`+5` は 5。
- 深さの制限: **根のテーブルを 1 段として、テーブルと配列の入れ子が合計 32 段まで受理**、33 段目(根の下に 32 段目のコンテナを開くとき)を拒否する。**根の下で数えると 31 段まで受理で、32 段目を拒否する**ので、定義ファイルの深さ(根を数えず 32 段まで)より 1 段浅い。テーブルの配列(`[[a]]`)は、配列と要素のテーブルで 2 段と数える(定義ファイルと同じ)。数え方の例:
  - 配列: `a = [[[...]]]` は、`[` が 31 個までは受理、32 個で拒否(根が 1 段、配列が 31 段で 32 段)。
  - ドットキー: `a.a.....a = 1` は、キーが 32 個まで受理(根 + テーブル 31 段)、33 個で拒否。
  - インラインテーブル: `a = {a={a=1}}` は、`{` が 31 個まで受理、32 個で拒否。
- 数千〜数十万段の入力は、異常終了せず失敗(`syntax`)で返らなければならない(必須)。理由の文が `入れ子が深すぎます(上限 32)` か `TOML として読めません` かは、実装に任せてよい(未確認)。
- 読み取った木は、第 5 節以降の「展開と写し取り」(第 6 節)に渡す。TOML の木には、アンカー・エイリアス・マージキーがないので、第 6 節の検査(要素数・大きさ・深さ・表せない値の検出)だけが働く。

## 5. YAML の読み取り(`--to toml` のとき)

YAML 1.2 のコアスキーマ(5.2)で読む。この節は、受理しなければならない文法(5.0)、拒否しなければならない書き方、受理してもしなくてもよい点を定める。YAML の読み取りライブラリを使ってよいが、ライブラリが 5.0〜5.3 と違う結果を返すときは、この文書の規定が優先する。

読み取りの結果は、アンカーとエイリアスの参照をそのまま持つ「素の木」にする(展開は第 6 節)。入れ子の深い入力でも異常終了しないよう、再帰を使わず、明示のスタックで読むこと(実装に任せてよい点。必須なのは、深い入力でも `syntax` の 1 件で返ること)。

### 5.0 受理する YAML の部分集合

文法の細部は、外部の規格 YAML 1.2(改訂 1.2.2)に従う。必須で受理する構文は次のとおり。

| 区分 | 受理する構文(必須) |
|------|----------------------|
| ストリーム | 先頭の BOM(U+FEFF)(無視)。コメントだけ・空の入力(文書 0 個)。`%YAML 1.2` ディレクティブ。`---`(文書の開始)、`...`(文書の終了)。1 つのストリームに複数の文書(`---` で区切る。受理したうえで、第 5.3 節で拒否) |
| 改行・空白 | LF、CRLF(混在可)。インデントは**半角スペースだけ**(タブをインデントに使うことは拒否) |
| コメント | 行頭の `#`、および空白の後ろの `#`。`foo#bar`(`#` の前に空白がない)は、コメントではなく、スカラーの一部 |
| ブロックのマップ | `key: value`。値が次の行からのブロック(`key:` + 改行 + 深いインデント)。値が同じ行のスカラー・フロー形式。キーは 1 行に収まる(単純キー)。明示のキー(`? key` + `: value`。キーはスカラーでもコレクションでもよい) |
| ブロックのシーケンス | `- item`。親のマップのキーと同じインデントの `- `(インデントなしのシーケンス)。`- - x`(入れ子)、`- key: v`(要素がマップ) |
| フロー形式 | `[a, b]`、`{a: 1, b: [c]}`。入れ子、複数行、末尾のカンマ(`[1, 2, ]`)、フローのシーケンスの中の単一の組(`[x: y]` は `[{x: y}]` と同じ)、フローのマップの空(`{}`)・空のシーケンス(`[]`) |
| スカラー(引用符なし) | 1 行および複数行(行の折りたたみ: 改行は空白 1 個に、空行は改行に)。先頭が `@` か `` ` ``(予約の記号)のものは拒否 |
| スカラー(引用符つき) | `'...'`(`''` で `'`。複数行は折りたたむ)、`"..."`(エスケープ: `\0 \a \b \t \n \v \f \r \e \<空白> \" \/ \\ \N \_ \L \P \xXX \uXXXX \UXXXXXXXX`、行末の `\` による行の継続、複数行の折りたたみ)。未知のエスケープ(`\q`)は拒否 |
| ブロックスカラー | `\|`(リテラル)、`>`(折りたたみ)。インデントの指示子(`\|2`)、チョンプの指示子(`-` 削る、`+` 保つ、なし = 末尾の改行 1 個) |
| アンカーとエイリアス | `&name` をノードの前に、`*name` で参照。`name` は、空白と `,[]{}` を含まない 1 文字以上。同じ名前のアンカーの再定義は可(参照は、それより前の最後の定義を指す)。エイリアスはキーにもできる(`*k : 1`) |
| タグ | `!!str`、`!!int` などの標準のタグ、独自のタグ(`!foo`)の**書式**は受理し、5.2 の規則で扱う(多くは第 7 節で失敗) |
| マージキー | `<<`(5.2・第 6.2 節) |

必須で**拒否**する(`syntax`、理由 `YAML として読めません`。v0.9.6 までは `文法の誤りです`)もの:

- 閉じていないフロー(`a: [1, 2`)、閉じていない引用符、不正なインデント(`a: 1\n  b: 2`)、タブのインデント(`a:\n\t- 1`)。
- 1 行に複数のブロックのマップの値(`a: b: c`、`a: x: y`)。
- 引用符なしのスカラーの先頭が `@` または `` ` ``(`a: @x`、``a: `x``)。
- 値の位置にある `-` だけ(`a: -`)。
- 未知のエスケープ(`"\q"`)。
- 定義されていないアンカーの参照(`a: *x`)。ただし、理由は `YAML として読めません`(5.1 の注)。

受理しても拒否してもよい(任意。テストはこれらを使わない): 引用符なしのスカラーの中の、タブ以外の制御文字(元の実装は、U+0001 を含む `a: \x01` を受理して値に取り込む)、`%TAG` ディレクティブ、単純キーが 1024 文字を超える場合の扱い(YAML 規格は 1024 文字までと定める。元の実装の YAML 読み取りは、1024 文字を超える単純キーを拒否して `syntax` にする)。

### 5.1 読み取り時に見つける誤り(すべて `syntax`、行つき)

| 条件 | 理由(日本語の原文) | 行 |
|------|----------------------|----|
| YAML の文法の誤り(5.0 の拒否の一覧) | `YAML として読めません` | 誤りを検出した位置の行(1 始まり。下の注) |
| 同じマップに、同じキーが 2 回(リテラルで)ある | `キーが重複しています` | 2 つ目のキーの行 |
| 再帰するアンカー(自分自身を含む。`a: &r [*r]`) | `アンカーが自分自身を含んでいます` | エイリアスの行 |
| 定義されていないアンカーの参照(`a: *x`) | `YAML として読めません` | 参照の行(下の注) |
| 読み取り時の入れ子の深さが 32 を超える | `入れ子が深すぎます(上限 32)` | 33 段目を開く行 |

- 定義されていないアンカーの参照は、`YAML として読めません` の `syntax`(元の実装では、パーサーが先に拒否する)。v0.9.6 までは、YAML の文法の誤りの理由は、種類の文と同じ `文法の誤りです` だった。専用の理由 `定義されていないアンカーを参照しています` の文は、実装内に存在するが、通常の入力では使われない(`syntax` の理由の一覧に載せるが、出さなくてよい)。
- **文法の誤りの行は、検出した位置の行**である。YAML の文法の誤りは、どこで検出されるかがパーサーの作りで変わる(誤りの原因の行より後ろ、またはタブのように前になることがある)。必須なのは、種類(`syntax`)と理由(`YAML として読めません`)で、行は次の観測した例に合わせることが望ましいが、これ以外の入力の行は、実装に任せてよい(未確認)。行番号の例(実行で確認): `a: 1\nb: [1, 2\nc: 3\n` は 3 行目、`a: 1\nb: 2\na: 3\n`(重複)は 3 行目、`a: 1\n\tb: 2\n` は 1 行目、`a: &x 1\nb: *y\n` は 2 行目、`a: [\n` は 2 行目、`a: 1\n  b: 2\n` は 2 行目、`a:\n\t- 1\n` は 2 行目。
- キーの重複の判定は、**解決したあとの同一性**で行う。同じ文字列なら、引用符の有無が違っても重複(`a: 1` と `"a": 2`)。値が同じ整数になるキーも重複(`1` と `01`、`1` と `0x1`)。型が違うキー(整数 `1` と文字列 `"1"`)は重複ではない。入れ子のマップごとに別。エイリアスをキーにした場合は、参照先で判定する。マージキー `<<` は、同じマップに 2 回書くと重複になる(`<<: {x: 1}` を 2 回で、2 つ目の行)。
- キーの重複の検出は、第 6 節の「文字列でないキーは表せません」(順 9)より先(順 5)。`1: a` と `"1": b` は、重複ではなく、「文字列でないキー」の失敗になる。
- 閉じたアンカーへの参照は、再帰ではない(`a: &r [1]\nb: *r` は受理)。
- 読み取り時の深さ: 開いているコレクション(マップ・シーケンス。フロー・ブロックとも)の数が 32 を超える(33 段目を開く)と拒否。最上位のマップが 1 段目。`a: ` に続けて `[` が 31 個までは受理、32 個で拒否。ブロックシーケンス(`- - - ...x`)は `- ` が 32 個まで受理、33 個で拒否。数千〜数十万段(フロー・ブロック・インデントの入れ子)でも、異常終了せず `syntax`(必須)。
- 展開前の深さの制限は、アンカーとエイリアスの参照を展開する前の構造に対するもの。エイリアスの入れ子による展開後の深さは、第 6 節。
- 複数の文書(`---` で区切る)は、文書の数を数える。最初の文書の木だけを残し、2 つ目以降も文法・重複・深さの誤りは検査する。末尾の `---`(その後が空)は、空の文書がもう 1 つあるものとして数える(`a: 1\n---\n` は 2 文書)。

### 5.2 スカラーの解決(YAML 1.2 コアスキーマ)

引用符なしのスカラー(`plain`。引用符も `|`・`>` もない書き方)は、次の順に判定する。判定は、スカラーの文字列全体に対して行う。

| 順 | 条件 | 結果 |
|----|------|------|
| 1 | `` (空)、`~`、`null`、`Null`、`NULL` | null(表せない値) |
| 2 | `true`、`True`、`TRUE` / `false`、`False`、`FALSE` | 真偽値 |
| 3 | `.inf`、`.Inf`、`.INF`、`+.inf`、`+.Inf`、`+.INF` / `-.inf`、`-.Inf`、`-.INF` / `.nan`、`.NaN`、`.NAN` | 浮動小数(+∞、-∞、NaN) |
| 4 | `0x` + 1 桁以上の 16 進数字 | 整数(16 進) |
| 5 | `0o` + 1 桁以上の 8 進数字(0〜7) | 整数(8 進) |
| 6 | `[+-]?[0-9]+`(`007` は 7、`-0` は 0、`+7` は 7) | 整数(10 進) |
| 7 | 浮動小数の書式(下記) | 浮動小数 |
| 8 | 上のどれでもない | 文字列 |

- 整数は 64 ビット符号つき整数の範囲(-9,223,372,036,854,775,808〜9,223,372,036,854,775,807)。範囲を超える整数の書式(`9223372036854775808`、`0xFFFFFFFFFFFFFFFFFF`)は「数値が表せる範囲を超えている」(表せない値。第 7 節)。
- 浮動小数の書式: `[-+]? ( \.[0-9]+ | [0-9]+ (\.[0-9]*)? ) ([eE] [-+]? [0-9]+)?`(整数だけの書式は先に整数として扱う)。例: `1.5`、`-0.0`、`.5`、`1.`、`1e3`、`1.5E-2`。有限の倍精度浮動小数に収まらないもの(`1e999`)は「数値が表せる範囲を超えている」。`.`、`e3`、`1e`、`1.2.3`、`-`、`+`、`.e1`、`inf`、`nan`、`NaN` は文字列。
- **`yes`・`no`・`on`・`off`・`y`・`n`(大文字小文字を問わず)は文字列**(YAML 1.1 の真偽値ではない)。`0b11`、`1_000`、`0x`(桁なし)、`0o8`、`+0x1` は文字列。
- 日付・時刻らしい書式(`2001-01-01`、`12:30:00`)は、**文字列**(コアスキーマに日付の型がない)。
- 引用符つき(`'...'`、`"..."`)のスカラーと、`|`・`>` のブロックスカラーは、常に文字列(`'1'` は文字列 `1`、`"null"` は文字列 `null`)。
- キーは、値と同じ規則で解決する。解決した結果が文字列のときだけ、文字列のキーになる(第 7 節)。

タグ:

| タグ | 扱い |
|------|------|
| なし | 上の規則 |
| `!!str` | 書き方によらず文字列(`!!str 1` は文字列 `1`、`!!str`(中身なし)は空文字列) |
| `!!int` | 解決した結果が整数(範囲外を含む)のときだけ、タグなしと同じ。引用符つき(`!!int '5'`)でも、中身を plain として解決する。合わなければ「タグつきの値は表せない」 |
| `!!float` | 解決した結果が浮動小数(範囲外を含む)または整数のときだけ受理。整数は浮動小数にする(`!!float 1` は 1.0)。合わなければ表せない |
| `!!bool` | 解決した結果が真偽値のときだけ受理(`!!bool true` は真偽値。`!!bool yes` は文字列に解決されるので表せない) |
| `!!null` | 解決した結果が null のときだけ受理(null なので、結局、表せない値) |
| スカラーへの `!!map`、`!!seq`、`!!binary`、`!!set` など、そのほかの標準のタグ | 表せない |
| 独自のタグ(`!foo`) | 表せない |
| コレクションへのタグ | マップには `!!map`、シーケンスには `!!seq` だけ許す(タグを無視して、そのまま通常のコレクションとして扱う)。それ以外(`!!set {x}`、`!!seq {x: 1}`、独自のタグ)は表せない |
| アンカーとタグの両方(`&a !!str 5`) | 両方を受理し、タグの規則で解決する(アンカーは、解決後の値を指す) |

- 「表せない」とは、第 7 節の「タグつきの値は表せません」として記録することを指す(順 9)。
- キーに付けたタグ: `!!str <<: 5` のように、タグつきの `<<` は、マージキーではなく、通常のキー `<<`(文字列)として扱う。

### 5.3 文書の確認(RootCheck)

- 文書が 2 つ以上: `unrepresentable`、理由 `複数の文書は表せません`、行なし、場所なし。
- 文書が無い(空の入力、コメントだけ): `rootNotMap`、理由 `文書が空です`、行なし。
- 最初の文書の最上位が、マップでない(シーケンス、スカラー、`---` だけの文書など): `rootNotMap`、理由 `最上位がマップではありません`、行は最上位のノードの行(`- 1\n- 2\n` は 1 行目、`--- a\n` は 1 行目、`---\n` だけの入力は 2 行目(空のスカラーの位置)。最後の `---` の厳密な規則は未確認)。
- 空のフローのマップ(`{}`)は受理され、`{}` と `` (空)のあいだで変換できる(第 9 節)。最上位のフローのマップ(`{a: 1}`)も受理する。

## 6. 展開と写し取り(Resolve)

素の木を、明示のスタックで(再帰を使わず)深さ優先・入力に現れる順に走査し、アンカー・エイリアス・マージキーを展開して、内部表現にする。TOML の木も、同じ処理を通る(アンカーなどは無いので、要素数・大きさ・深さの検査と、表せない値の検出になる)。

内部表現:

| 種類 | 内容 |
|------|------|
| 文字列 | 文字列 |
| 整数 | 64 ビット符号つき整数 |
| 浮動小数 | 64 ビット浮動小数(IEEE 754 binary64) |
| 真偽値 | 真偽値 |
| 配列 | 内部表現の並び |
| マップ | (文字列のキー, 内部表現)の並び。**キーは重複しない** |

内部表現の等価(往復の確認に使う): 型が違えば不等(`"1"` と 1、1 と 1.0、`true` と `"true"`)。浮動小数は、ビット表現が同じなら等しい(NaN どうしは等しい。`0.0` と `-0.0` は**異なる**)。マップは、キーの順序を無視して比べる。配列は順序を含めて比べる。

### 6.1 エイリアスの展開

- エイリアスは、参照先のノードの内容に置き換える(コレクションは複製して展開する)。エイリアスをキーにもできる(`k: &k name\n*k : 1` は `{"k": "name", "name": 1}`)。
- 展開でだけ生じるキーの重複(エイリアスのキーなど)は、`syntax`、理由 `キーが重複しています`、行は重複したキーの行。

### 6.2 マージキー(`<<`)

- マージキーとして扱うのは、**引用符なし・タグなし**のキー `<<` だけ。`"<<"`(引用符つき)や `!!str <<` は通常のキー。
- 値は、マップ、またはマップだけのシーケンス(`<<: [*a, *b]`)。それ以外(整数、文字列、null(`<<: ~` を含む)、マップでない要素を含むシーケンス)は、`unrepresentable`、理由 `マージキーの値がマップではありません`、場所は `<マップまでの経路>.<<`(例: `a.<<`)、行はマージキーの行。順 8 に属し、先にある null より先に返る。
- 優先順位: マップ自身のキーが、マージの内容より優先する(位置に関係なく。自身のキーが `<<` の前にあっても後にあっても同じ)。マージの値がシーケンスのときは、**先頭のマップが優先**。マージされるマップ自身が `<<` を含むとき(入れ子のマージ)は、そのマージも同じ規則で先に展開された結果を使う。
- マージ後の重複するキーは、エラーにならず、優先されなかった側が捨てられる。
- マージで加わるキーの並び順は、最終の出力では意味を持たない(第 8.1 節: 出力のキーは辞書順)。

### 6.3 展開の上限

| 上限 | 値 | 超過したときの失敗 |
|------|----|--------------------|
| 展開後の要素数 | 100,000 | `tooLarge`、理由 `展開後の要素数が上限(100000)を超えています` |
| 展開後の文字の大きさ | 16 MiB(16,777,216 バイト) | `tooLarge`、理由 `展開後の文字の大きさが上限(16 MiB)を超えています` |
| 展開後の入れ子の深さ | 32 | `syntax`、理由 `展開後の入れ子が深すぎます(上限 32)` |

- 要素数の数え方: 展開で訪れたノードを 1 つずつ数える。**キーのスカラーも数える**。コレクションも 1。エイリアスは、エイリアス自身ではなく、**展開した参照先のノードを数える**(同じアンカーを n 回参照すれば、n 回数える)。マージキー `<<` のキー自身も数える(1)。捨てられるマージの項目も数える。上限は 100,000 ちょうどまで受理、100,001 個目で失敗する。例: `a: [0,0,...]`(0 を n 個)は、根のマップ 1 + キー 1 + 配列 1 + 要素 n で、n = 99,997 まで受理、99,998 で失敗。TOML 入力にも同じ上限がある(`a = [0,0,...]` で同じ境界)。
- 文字の大きさの数え方: 訪れたスカラーの文字のバイト数(UTF-8)を足す。キーと値の両方。YAML のスカラーは、数値や真偽値の書式の文字も、書かれた文字のバイト数で数える(`123` は 3。`0x1F` は 4。引用符は数えない)。エイリアスの参照のたびに、参照先のスカラーの大きさを足す。マージキー `<<` は 2 バイト。TOML 入力では、文字列(キーと値)だけを数える(整数・浮動小数・真偽値・日時は 0)。**16 MiB ちょうどは受理**し、1 バイト超えると失敗。複製・確保の**前**に確認すること(予算を超えて確保する量は、高々スカラー 1 つ分。実装に任せてよい点だが、巨大な展開でメモリを使い果たさないために必要)。例: 「長さ n の文字列を 1 回アンカーにして 2 回参照する」入力で、`3n + 7`(キー 4 バイト + 数値 `123` の 3 バイト)が 16 MiB ちょうどなら受理、`123` を `1234` にして 1 バイト超えると `tooLarge`。
- 展開後の深さ: 根のマップが 1 段目で、開いているコレクションが 32 を超えると拒否(33 段目を開くとき)。アンカーの入れ子(`l0: &l0 [x]`、`l1: &l1 [*l0]`、...)で、読み取り時の深さは 2 でも、展開後は深くなる。`l30` までで 32 段(受理)、`l31` で 33 段(拒否)。失敗には、場所(キーの経路)がつく。
- 上限超過の失敗には、行(YAML の場合、そのノードの行)と場所(キーの経路)がつく。TOML 入力では行はない。
- 展開による爆発(アンカーの入れ子による指数的な増加、大きなスカラーの繰り返しの参照、マージキーを使った増幅)は、上の上限で止まらなければならない(必須。実装は、30 秒以内に `tooLarge` で終わることを確認している)。

## 7. 表せない値(`unrepresentable`)

展開の途中で見つけた「相手の形式で表せない値」のうち、**入力に現れる順で最初の 1 つ**だけを記録し、走査の終了後に返す(上限超過・マージキーの誤りなど順 8 の失敗は、これより優先する)。失敗の `reason` と、場所(キーの経路、行なし)は次のとおり。

| 値 | 理由(日本語の原文) | 入力の例 |
|----|----------------------|----------|
| null(`~`、`null`、`Null`、`NULL`、空の値) | `null は表せません` | `a: ~`、`a: null`、`a:`、`a: &x`(アンカーだけで中身がない) |
| タグつきの値 | `タグつきの値は表せません` | `a: !!binary aGk=`、`a: !mytag 1`、`a: !!set {x}`、`a: !!seq {x: 1}`、`a: !!bool yes` |
| 範囲外の数値 | `数値が表せる範囲を超えています` | `a: 9223372036854775808`、`a: 1e999`、`a: [1, 99999999999999999999]` |
| 日時(TOML の日時・日付・時刻) | `日時の値は表せません` | `d = 1979-05-27T07:32:00Z`、`d = 1979-05-27`、`t = 07:32:00` |
| 文字列でないキー | `文字列でないキーは表せません` | `1: x`、`true: x`、`? [1, 2]\n: x`、`? ~\n: x`、`[a]: 1` |

- 文字列でないキーの判定: キーのスカラーを解決した結果が文字列でないとき(整数、浮動小数、真偽値、null、タグつき、範囲外の数値)、およびキーがマップ・シーケンスのとき。キーの中の表せない値は、種類によらず `文字列でないキーは表せません` として記録する。
- YAML の日付(`a: 2001-01-01`)は、日時ではなく**文字列**(コアスキーマに日付の型がない)。
- 失敗の表示: `kind` は `unrepresentable`、行なし。**場所(`key_path`)**がつく(ただし、複数の文書の失敗は場所なし)。
- **場所の書式**: キーを `.` でつなぐ。配列の要素は `[添字]`(0 始まり。直前のキーに続けて、`.` なしで書く)。文字列でないキーは `(非文字列キー)`。キー名は、制御文字・書式文字をエスケープし(`\n`、`\r`、`\t`、その他は `\u{16進小文字}`。対象の文字と切り詰めは [03 第 9.2 節](03-definition-format.md)と同じ)、64 文字(エスケープ後の文字数)を超えると、64 文字で切って `…` を付ける。例: `job[1].note`、`a.b`、`a.(非文字列キー)`、`a.<<`、`(非文字列キー)`(最上位のキー)。
- 入力に現れる順の例: `a: 1\njob:\n  - id: x\n  - id: y\n    note: ~\n  - z: ~\nlater: ~\n` は、最初の null の `job[1].note` を返す。`a: ~\nb: !!binary x\n` は `a`、`b: !!binary x\na: ~\n` は `b`。

## 8. 書き出し(Write)

### 8.1 共通(必須)

- 書き出しの前に、最上位は(必ず)マップになっている(YAML 入力は RootCheck、TOML 入力は根のテーブル)。
- **各マップのキーは、文字列の UTF-8 バイト列の昇順(辞書順)に並べて出力する**。YAML・TOML のどちらへの出力も同じ。入力の記述順は保たれない。配列の順序は保たれる。コメントは捨てられる。(バイト列の昇順は、Unicode のコードポイントの昇順と同じ。例: `B` < `Z` < `_` < `a` < `é`。)
- 変換結果の最後は改行(LF)で終わる(ただし、最上位が空のマップで TOML のときは空文字列)。改行は LF だけ。

### 8.2 TOML の書き出し(`--to toml`)

**必須**(利用者から見える結果):

1. 出力は、第 4 節の文法(TOML v1.0.0 の範囲)に合う文書で、読み戻した木が、元の木と等しい(第 6 節の等価。第 9 節)。
2. 各テーブルのキーは、8.1 のとおり辞書順。その際、各テーブルでは、**サブテーブル(およびテーブルの配列)でない値を先に**、続けてサブテーブル(テーブルの配列)を、それぞれ辞書順に書く。
3. 要素がすべてマップである、空でない配列は、**テーブルの配列**(`[[job]]`、`[[job.transitions]]`)で書く。マップの値は、`[a.b]` の見出しのテーブルで書く(空のマップは、見出しだけ `[b]`)。要素に、マップ以外(数、文字列、配列)が混ざる配列、空の配列(`d = []`)、配列の配列は、1 行の配列で書く(マップの要素は、`e = [1, { x = 1 }]` のように、インラインテーブルで書く)。
4. 整数は 10 進(64 ビット符号つき整数のまま)。浮動小数は、浮動小数と分かる形で書く: `1.0`、`-0.0`、`nan`、`inf`、`-inf`。有限の値は、往復で同じ値になる桁数の 10 進で、必ず `.` を含める(`1000000000000000000000.0`、`0.00000015`。元の実装は指数を使わない。指数形(`1.5e-7`)で書いてもよい(任意))。
5. キーが、ベアキーの文字(`A-Za-z0-9_-`)だけでなければ、引用符で囲む(`"a.b" = 1`、`"" = 2`、`"é" = 3`、`"a b" = 8`)。
6. 見出しの前には空行を 1 行入れる(文書の先頭を除く)。見出しの直後の行は、そのテーブルの最初のキー、または次の見出し(中身が空のとき。見出しの間に空行が入る)。
7. 日時は内部表現にない(第 7 節で失敗する)。
8. 失敗: 内部表現を TOML に書き出せなかったとき、`unrepresentable`、理由 `変換後の形式として書き出せません`(通常は起こらない)。

**実装に任せてよい点**(読み戻した木が同じなら、どれでもよい。元の実装の観測を示す):

- 文字列の引用符の選び方: 元の実装は、基本文字列(`"..."`)を原則とし、`"` または `\` を含み `'` と改行を含まないときはリテラル文字列(`'q"x'`、`'back\slash'`)、改行を含むときは複数行の基本文字列(開く `"""` の直後に改行を入れ、`"""` で閉じる)、`"` と `'` の両方を含むなどのときは複数行の文字列(`h = """it's "both""""`、`i = '''back\slash 'q''''`)を選ぶ。制御文字は `\u0001` のようにエスケープする(`\u007F` は、16 進を大文字で書く)。
- 空白の入れ方(`key = value`、配列の `[1, 2]`、インラインテーブルの `{ x = 1 }`)。
- 暗黙のテーブルの見出しの省略(`a: {b: {c: 1}}` を `[a.b]` + `c = 1` だけで書く。元の実装がそうする)。

TOML の出力例(`a: 1.5e-7` などの値の例は、第 8.2 節の規則 4 のとおり)。次は、第 11 節の例に出てくる出力の例である(行ごとの完全な一致は要求しない)。

```toml
format_version = 1

[defaults]
success_exit_codes = [0, 2]
```

### 8.3 YAML の書き出し(`--to yaml`)

自前の書き出し(ブロック形式の YAML)。**すべて必須**(出力の文字列が一致する)。

**レイアウト**

- 最上位のマップが空: `{}` + 改行。空でなければ、各エントリを書く。
- マップのエントリ: `<キー>: <値>`。値がスカラー、空の配列(`[]`)、空のマップ(`{}`)なら同じ行に書く。値がコレクションなら、`<キー>:` のあと改行し、子を**2 スペース深く**書く。
- シーケンスの要素: `- <値>`。要素がスカラー・`[]`・`{}` なら同じ行。要素がマップなら、最初のエントリを `- ` と同じ行に書き、残りのエントリを、`- ` の内容の位置(ダッシュの桁 + 2)に揃える。要素がシーケンスなら、`- - 1`(最初の要素を同じ行)の形で、残りの要素も、内容の位置に揃える。
- シーケンスは、親のキーより 2 スペース深く書く(`job:` の次の行に `  - id: a`)。
- インデントは 2 スペース。タブは使わない。行末に空白を残さない。

例(TOML `format_version = 1`、`[[job]]` と `[pipeline]` を含む定義を `--to yaml` で変換した出力。キーは辞書順):

```yaml
format_version: 1
job:
  - command: extract --all --since yesterday
    id: extract
  - command: "transform \"in dir\" $HOME"
    id: transform
    success_exit_codes:
      - 0
      - 2
    transitions:
      - next: notify
        "on": warning
    warning_exit_codes:
      - 3
      - 4
  - command: load
    id: load
    transitions:
      - next: "@end"
        "on": success
  - command: notify --channel ops
    id: notify
pipeline:
  description: "夜間バッチ(抽出、変換、読み込み、通知)"
  name: nightly
```

入れ子の配列とマップの例(入力 TOML `a = [[1,2],[3,[4]]]` と `b = [{x=1,y=[{z=2}]}]`):

```yaml
a:
  - - 1
    - 2
  - - 3
    - - 4
b:
  - x: 1
    "y":
      - z: 2
```

空の TOML の入力は `{}` + 改行になる。`x = {}`、`y = []`、`[z]` を含む TOML の入力は次になる。

```yaml
x: {}
"y": []
z: {}
```

**スカラー**

- 整数: 10 進。真偽値: `true` / `false`。
- 浮動小数: NaN は `.nan`、+∞ は `.inf`、-∞ は `-.inf`。それ以外は、往復で同じ値になる最短の桁数の 10 進で書く。次の規則とする(必須)。
  - 絶対値が 1e16 以上、または 1e-4 未満(0 を除く)のときは指数形: 仮数(最短の桁。2 桁以上なら `d.ddd`、1 桁なら `d`)に `e` と指数(符号は負のときだけ `-`、先頭の 0 なし)を続ける。例: `1e16`、`1e21`、`1e-5`、`1.5e-7`、`1.2345678901234568e17`、`5e-324`、`1.7976931348623157e308`。
  - それ以外は、10 進の小数表記で、整数値でも必ず小数部を付ける(`1.0`、`100.0`)。`-0.0` も保つ。`1e15` は `1000000000000000.0`、`0.0001` は `0.0001`、`0.1` は `0.1`。
- 文字列(値もキーも同じ規則): 次の条件を**すべて**満たすときだけ、引用符なし(plain)で書く。1 つでも外れたら、二重引用符で囲む。
  1. 空でない。
  2. 先頭が、ASCII の英字(`A-Za-z`)、`_`、`/` のどれか(数字・`-`・`.` などで始まるものは、数値や記号に読まれうるので引用符)。
  3. 末尾が空白でない。
  4. すべての文字が、ASCII の英数字、`_`、`-`、`.`、`/`、半角スペース のどれか。
  5. 半角スペースが 2 つ連続しない。
  6. YAML 1.1 の語(`y`、`Y`、`yes`、`Yes`、`YES`、`n`、`N`、`no`、`No`、`NO`、`on`、`On`、`ON`、`off`、`Off`、`OFF`)でない。
  7. 第 5.2 節の規則で解決して文字列になる(`true`、`false`、`null`、`Null`、`NULL`、`True` などは引用符)。
  - plain になる例: `hello`、`echo hello world`、`/bin/run.sh`、`a-b_c.d`、`prog build --release`、`inf`、`_x`、`a b`。引用符になる例: `yes`、`no`、`on`(キー `on` は `"on": warning`)、`off`、`y`(キー `y` は `"y": []`)、`true`、`null`、`~`、`1`、`-1`、`1.5`、`0x1F`、`` (空)、` lead`、`trail `、`<<`、`a: b`、`a #b`、`.nan`、`1e3`、`Yes`、`Y`、`@end`、`-a`、`x  y`、`a `、非 ASCII を含む文字列(`"夜間バッチ"`、`"é key"`)。
- 二重引用符の中のエスケープ: `"` → `\"`、`\` → `\\`、改行 → `\n`、復帰 → `\r`、タブ → `\t`。そのほかの制御文字(U+0000〜U+001F、U+007F〜U+009F)と U+2028、U+2029、U+FEFF、U+FFFE、U+FFFF は `\uXXXX`(16 進の**大文字** 4 桁。例: `\u001B`、`\u007F`)。その他の文字(非 ASCII、絵文字を含む)は、そのまま書く。例: `"a\u2028b \u007F é 😀"`。
- キー `<<` は、必ず引用符で囲む(マージキーとして読み戻されないように。上の plain の規則で、`<` で始まるので引用符になる)。
- 非 ASCII を含む文字列は、常に二重引用符で囲む(値もキーも)。
- **長いキーの制限**: 1024 文字を超える plain のキー(`aaaa…`)を、元の実装は plain のまま書く。その出力は、YAML 1.2 の単純キーの上限(1024 文字)を超えるので、元の実装の YAML 読み取りでは読み戻せない(`syntax`)。互換の実装は、同じ出力(plain)にしてよいし、1024 文字を超えるキーを二重引用符で囲んでもよい(任意)。この場合、第 9 節の往復の保証は、前者では成り立たない。

## 9. 往復の保証

- 保証するのは、**木の等価**である。入力を読んだ内部表現と、変換結果を(変換後の形式として)読み戻した内部表現が、等しい(第 6 節の等価。マップのキーの順序は無視、配列の順序は有意)。さらに、変換結果を元の形式へ戻した結果の木も、元の木と等しい。ただし、第 8.3 節の長いキーの場合を除く。
- 保証されないもの: コメント、マップのキーの記述順(出力は辞書順)、アンカー・エイリアス・マージキー(展開される。出力に `<<`・`*`・`&` は残らない)、引用符・文字列の書き方(plain と引用符の別、ブロックスカラーの形)、数値の書式(`0x1F` → `31`、`007` → `7`、`1e3` → `1000.0`)、YAML の `1_000` のような文字列の再解釈。
- 往復で保たれることが、確認されている値: 文字列(`yes`、`no`、`on`、`off`、`1`、`1.5`、`null`、`~`、`true`、`false`、`<<`、空文字列、前後に空白がある文字列、`a: b`、改行・タブ・引用符・バックスラッシュ・制御文字・日本語・絵文字を含む文字列、長い文字列)、整数(64 ビット符号つき整数の最小値・最大値、0)、浮動小数(`1.0`、`-0.0`、NaN、±∞、`1.5e-7`、`1e21`、`0.1`)、真偽値、空の配列・空のマップ、入れ子の配列(`[1, [2, [3, []]]]`)、配列の中のマップ、型が混在する配列、`on` キー、文字列の `command` と配列の `command`(空白・引用符・`$`・空の要素を含む配列)。
- 空のマップ: YAML `{}` → TOML は空文字列、TOML の空の入力 → YAML は `{}` + 改行。
- 複数行の文字列: TOML の複数行の基本文字列の中の CRLF は、値として CRLF のまま保持される([03 第 4.4.3 節](03-definition-format.md))。YAML へ変換すると `"x\r\n"` のように書かれる。

## 10. エラーの構造と表示

| フィールド | 内容 |
|------------|------|
| `file` | 入力ファイルの表示用の名前 |
| `line` | 行番号(1 始まり)。位置が分かるときだけ |
| `key_path` | 表せない値などの場所(キーの経路)。値そのものは含まない |
| `kind` | 種類 |
| `reason` | 固定の文(入力の値・ライブラリのエラー文は含まない) |

種類(6 種):

| 識別子 | 日本語 | 英語(英語のメッセージのとき) |
|--------|--------|----------------------------|
| `fileMissing` | 入力ファイルが存在しません | input file does not exist |
| `unreadable` | 入力ファイルを読めません | cannot read input file |
| `tooLarge` | 入力が大きすぎます | input is too large |
| `syntax` | 文法の誤りです | syntax error |
| `unrepresentable` | 相手の形式で表せない値があります | value cannot be represented in the target format |
| `rootNotMap` | 最上位がキーと値の集まり(マップ)ではありません | top level is not a map |

ライブラリの表示:

```
<file>:<line>: <種類の文>: <reason>(場所: <key_path>)    行も場所もあるとき
<file>: <種類の文>: <reason>                              どちらも無いとき
```

行だけ・場所だけのときは、それぞれ `<file>:<line>: <種類の文>: <reason>`、`<file>: <種類の文>: <reason>(場所: <key_path>)` となる。`(場所: …)` は、`key_path` があるときだけ、末尾に付く(直前に区切りの空白はない)。`<file>` は、制御文字・書式文字をエスケープし、エスケープ後の文字数で 256 文字までに切る(超えるときは末尾に `…`。エスケープの規則は [03 第 9.2 節](03-definition-format.md))。

`conductor convert` の失敗の表示(標準エラーの 1 行、終了コード 67):

```
conductor: error: <file>[:<line>]: <種類の文(言語による)>: <reason> (<at|場所>: <key_path>)
```

`<reason>` は日本語のまま。`(at: …)` は英語のメッセージ、`(場所: …)` は日本語のメッセージ(言語の選び方は [08](08-output-and-i18n.md))。`(…)` の前に半角スペース 1 個。`key_path` がないときは `(…)` を付けない。`<file>`・`<reason>`・`<key_path>` は、制御文字・書式文字をエスケープして出す(ここでは文字数で切らない。`key_path` の中のキー名は、第 7 節の規則で 64 文字に切られている)。実行例:

```
conductor: error: n.yaml: value cannot be represented in the target format: null は表せません (at: a)
conductor: error: x.yaml:3: syntax error: YAML として読めません
conductor: error: x.yaml: top level is not a map: 文書が空です
conductor: error: m.yaml: value cannot be represented in the target format: 複数の文書は表せません
```

### 理由の一覧(日本語の原文。英語版はない)

| 理由 | 使われる種類 |
|------|--------------|
| `指定の場所にファイルがありません` | `fileMissing` |
| `読み取りの権限がありません` / `読み取りに失敗しました` / `通常のファイルではありません` / `UTF-8 として読めません` | `unreadable` |
| `入力が上限(1 MiB)を超えています` / `展開後の要素数が上限(100000)を超えています` / `展開後の文字の大きさが上限(16 MiB)を超えています` | `tooLarge` |
| `TOML として読めません` / `YAML として読めません` / `キーが重複しています` / `アンカーが自分自身を含んでいます` / `定義されていないアンカーを参照しています`(通常は使われない) / `入れ子が深すぎます(上限 32)` / `展開後の入れ子が深すぎます(上限 32)` / `入力の構造を解釈できません`(形式に依らない内部の守り。通常は使われない) | `syntax` |

- v0.9.6 までは、TOML・YAML の文法の誤りの理由は、どちらも種類の文と同じ `文法の誤りです` だった(日本語の表示が「文法の誤りです: 文法の誤りです」と重なった)。v0.9.7 以降は、形式ごとの文にする。種類の文(`文法の誤りです` / `syntax error`)は変わらない。
| `複数の文書は表せません` / `null は表せません` / `文字列でないキーは表せません` / `タグつきの値は表せません` / `日時の値は表せません` / `数値が表せる範囲を超えています` / `マージキーの値がマップではありません` / `変換後の形式として書き出せません` | `unrepresentable` |
| `最上位がマップではありません` / `文書が空です` | `rootNotMap` |

## 11. 例

YAML(アンカー、エイリアス、マージキー、`on` キー、`on: error` を含む)→ TOML:

```yaml
format_version: 1
pipeline:
  name: nightly
defaults: &defaults
  success_exit_codes: [0, 2]
  warning_exit_codes: [3, 4]
job:
  - id: extract
    command: extract --all --since yesterday
    <<: *defaults
  - id: transform
    command: 'transform "in dir" $HOME'
    <<: *defaults
    success_exit_codes: [0]
    transitions:
      - on: warning
        next: notify
      - on: error
        next: "@end"
```

出力(`defaults` はそのまま残り、`<<` は展開され、キーは辞書順):

```toml
format_version = 1

[defaults]
success_exit_codes = [0, 2]
warning_exit_codes = [3, 4]

[[job]]
command = "extract --all --since yesterday"
id = "extract"
success_exit_codes = [0, 2]
warning_exit_codes = [3, 4]

[[job]]
command = 'transform "in dir" $HOME'
id = "transform"
success_exit_codes = [0]
warning_exit_codes = [3, 4]

[[job.transitions]]
next = "notify"
on = "warning"

[[job.transitions]]
next = "@end"
on = "error"

[pipeline]
name = "nightly"
```

(`on: error` のような遷移は、変換器は検査しない。定義として読み込むときに `errorTransition` になる([03 第 7.4 節](03-definition-format.md)))。

失敗の例:

| 入力(`--to toml`、YAML) | 結果 |
|------|------|
| `a: 1\nb: 2\na: 3\n` | `syntax` 3 行目、`キーが重複しています` |
| `- 1\n- 2\n` | `rootNotMap` 1 行目、`最上位がマップではありません` |
| `` (空) | `rootNotMap`、行なし、`文書が空です` |
| `a: 1\n---\nb: 2\n` | `unrepresentable`、`複数の文書は表せません` |
| `a:\n  <<: 5\n` | `unrepresentable`、`マージキーの値がマップではありません`、場所 `a.<<` |
| `a:\n  <<: ~\n` | 同上(場所 `a.<<`、2 行目) |
| `a: &r [*r]\n` | `syntax`、`アンカーが自分自身を含んでいます` |
| `a: ~\n` | `unrepresentable`、`null は表せません`、場所 `a` |
| `1: x\n` | `unrepresentable`、`文字列でないキーは表せません`、場所 `(非文字列キー)` |
| `a:\n  <<: {x: 1}\n  <<: {y: 2}\n` | `syntax` 3 行目、`キーが重複しています` |
| `a: 1\n---\n` | `unrepresentable`、`複数の文書は表せません` |

成功の例(`--to toml`、YAML):

| 入力 | 出力 |
|------|------|
| `a: \|\n  x\n  y\nb: >\n  p\n  q\n\n  r\nc: \|-\n  k\n` | `a = """\nx\ny\n"""`、`b = """\np q\nr\n"""`、`c = "k"`(文字列の引用符の選び方は任意。値は `"x\ny\n"`、`"p q\nr\n"`、`"k"`) |
| `a: foo\n  bar\n  baz\n` | 値 `"foo bar baz"` |
| `a: 0o17\nb: 0x1F\nc: 1e3\nd: .5\ne: 1.\nf: +.inf\n` | 値 15、31、1000.0、0.5、1.0、+∞ |
| `a: 2001-01-01\nb: 12:30:00\n` | 値 `"2001-01-01"`、`"12:30:00"`(文字列) |
| `b: &b {x: 1}\na:\n  <<: [*b, {x: 2, y: 3}]\n  y: 9\n` | `a` は `{x: 1, y: 9}`(自身のキーが優先、シーケンスは先頭が優先) |
| `a: &x 1\nb: &x 2\nc: *x\n` | `c` は 2(最後のアンカーの定義を指す) |
| `a: !!int "0x10"` | 値 16 |
| `a: !!float 1\nb: !!str 1` | 値 1.0、`"1"` |

## 12. 未確認事項

- YAML の受理する文法の、5.0 の表に載せていない細部(`%TAG` ディレクティブ、制御文字の扱い、1024 文字を超える単純キー、タブの扱いの細部など)。5.0 の表の構文は、実行して確認した範囲(必須として挙げたもの)。
- YAML の文法の誤りの行番号: 5.1 の例に載せていない入力での、検出位置の厳密な規則。
- 定義されていないアンカーの参照が、`syntax` の専用の理由(`定義されていないアンカーを参照しています`)になる経路の有無(通常の入力では、`YAML として読めません` になった。v0.9.6 までは `文法の誤りです`)。
- 深さが 33 を大きく超える TOML の入力で、理由が `入れ子が深すぎます(上限 32)` か `TOML として読めません`(v0.9.6 までは `文法の誤りです`)のどちらになるか。
- YAML の `---` だけの文書などの、`rootNotMap` の行番号の厳密な規則(観測: `---\n` は 2 行目)。
- TOML の書き出しの整形規則の完全な記述(元の実装は、ライブラリの標準の整形に従う。出力の特徴は、8.2 に挙げた観測の範囲。必須としたのは 8.2 の 1〜8 のみ)。
- TOML の浮動小数の、極小の値(`1e-400` など)の読み取り(0 になるのか、拒否されるのかは、確認していない)。
- 非 ASCII のキー・値の YAML 出力は、常に二重引用符で囲む(実行で確認した)。plain で書ける範囲を広げる変更は、この仕様の変更になる。
