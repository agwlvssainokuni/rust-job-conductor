# 09. 変換器(YAML と JSON の相互変換)

この文書は、`conductor convert <ファイル> --to <yaml|json>` の中身である変換器の振る舞いを定める。この文書だけで、TypeScript(Node.js)でゼロから、同じ受理・拒否・出力・エラーを返す変換器を実装できることを目標とする。

- 変換器は、定義ファイルの**検証をしない**。変換した結果が `conductor` の定義([03. 定義ファイルの書式と検証](03-definition-format.md))として正しいかは見ない(任意の YAML / JSON のマップを変換する)。
- 副作用はない: ファイルへの書き込み、環境変数、プロセス、ネットワークに触れない(読むのは入力ファイル 1 つだけ)。変換結果は、文字列として返す(標準出力への書き出しは、[04. CLI](04-cli.md) の側の仕事)。
- 入力の値を、エラーの文に含めない(キー名だけを、エスケープと切り詰めをして、場所として示すことがある)。
- 確認できなかった点は「未確認」と書く。この文書の作成時に実際に動かして確かめた点は「確認」と書く(環境: Node.js v26.13.0、YAML ライブラリ `yaml` 2.9.1)。
- 「必須」の挙動は、利用者から見える結果(受理/拒否、変換結果の文字列、エラーの種類・文言・行・場所)で、同じにしなければならない。「任意」「実装に任せてよい」と書いた点は、変換結果を読み戻した木が変わらない範囲で、実装が選んでよい。
- コマンドの引数・終了コードの全体は [04. CLI](04-cli.md) と [10. エラーと終了コード](10-errors-and-exit-codes.md)、メッセージの言語の選び方は [08. 出力と多言語対応](08-output-and-i18n.md) に従う。
- YAML と JSON の**読み取り**(文法、スカラーの型、アンカー、マージキー、重複キー、上限、木の型)は、[03](03-definition-format.md)の第 4〜7 節と**同じ**で、実装も共有する(`src/definition/` の木の読み取りを、`src/convert/` が呼ぶ)。この文書は、読み取りの上の差分(取り込み、最上位、拒否する数)と、書き出しを定める。
- JavaScript の `number` は倍精度の浮動小数で、2^53(9,007,199,254,740,992)を超える整数を正確に表せない。この変換器は、整数を **`bigint`** で扱い、`number` に落とさない(第 6.3 節)。`JSON.parse`、`JSON.stringify`、`Number.parseInt`、`Number.parseFloat` を、変換の本体では使わない。

## 1. 入口と入出力

型と関数の骨格(例):

```ts
export type Format = 'yaml' | 'json'; // 変換後の形式

export type ConvertResult =
  | { readonly ok: true; readonly text: string }
  | { readonly ok: false; readonly error: ConvertError };

/** パスのファイルを読み、to の形式に変換した文字列を返す(非同期)。 */
export function convertFile(path: string, to: Format): Promise<ConvertResult>;

/** ファイルに触れない(同期)。fileLabel はエラーの表示に使う名前。 */
export function convertText(text: string, to: Format, fileLabel: string): ConvertResult;
```

| 入口 | 引数 | 戻り値 |
|------|------|--------|
| `convertFile` | 入力ファイルのパス、変換後の形式 | 成功: 変換結果の文字列、失敗: 変換の誤り(第 10 節) |
| `convertText` | 文字列(復号済み)、変換後の形式、表示用のファイル名 | 同上(ファイルに触れない) |

- 変換後の形式は `yaml` または `json`。
- **入力の形式は、変換後の形式の反対**とみなす(`--to yaml` なら入力は JSON、`--to json` なら入力は YAML)。**拡張子は見ない**。`.yaml` の名前のファイルでも、`--to yaml` なら JSON として読む(YAML を JSON として読めば、JSON の文法の誤りになる)。
- 変換結果は、全部作ってから 1 つの文字列として返す。失敗のときは、出力は無い。
- 誤りは、例外ではなく戻り値で返す。例外(`throw`)は、実装の不具合にだけ使う。
- `conductor convert` は、成功したら結果を標準出力に 1 回で書く。失敗したら標準出力は空で、標準エラーに原因を出し、終了コード 67 で終わる([04](04-cli.md)・[10](10-errors-and-exit-codes.md))。

## 2. 処理の流れと失敗の順序

```
Intake → 読み取り(Parse) → 展開と写し取り(Resolve) → 最上位の確認(RootCheck) → 書き出し(Write)
```

失敗は、次の順で最初に見つかったものを 1 件だけ返す(以降は実行しない)。

| 順 | 段階 | 失敗 |
|----|------|------|
| 1〜2 | Intake: 開く(存在しない → `fileMissing`、権限など → `unreadable`) | 第 3 節 |
| 3 | Intake: 通常のファイルでない → `unreadable`、大きさが 1 MiB を超える → `tooLarge` | 第 3 節 |
| 4 | Intake: 上限 + 1 バイトまでの読み取りと UTF-8 の確認 → `unreadable` | 第 3 節 |
| 5 | Parse: 文法の誤り → `syntax`。JSON は、先頭から読んで最初に見つかった文法の誤り・重複キー。YAML は、ライブラリで全文書を読み終えてからの文法の誤り | 第 4 節 |
| 6 | Resolve(入力に現れる順で、最初に見つかったもの): 複数の文書(YAML)・タグ・非文字列キー・重複キー・再帰するアンカー・マージキーの誤り(いずれも `syntax`)、要素数・文字の大きさの上限(`tooLarge`)、入れ子の深さの上限(`syntax`) | 第 4 節 |
| 7 | RootCheck: 最上位がマップでない → `rootNotMap` | 第 4.3 節 |
| 8 | Resolve で記録した、表せない値のうち、入力に現れる順で最初のもの → `unrepresentable` | 第 5 節 |

- 順 6 の失敗は、順 8 より優先する(先に表せない数があっても、上限超過が返る)。
- 順 7 は順 6 より後。最上位がマップでない入力に順 6 の失敗が含まれるときは、順 6 の失敗が先に返る(例: `- &a [*a]\n` は、`rootNotMap` ではなく、再帰の `syntax`)。実装は、順 6 の走査を終えてから最上位を確認する。
- 順 3 は順 4 より先: 1 MiB を超え、かつ UTF-8 でない入力は `tooLarge`。順 3 は順 5 より先: 1 MiB を超える入力は、中身が壊れていても `tooLarge`。
- 順 5(文法)は、順 6(複数の文書など)より先。たとえば `a: 1\n---\nb: [1\n` は、2 つ目の文書の文法の誤りを `syntax` として返す。

## 3. 取り込み(Intake)

| 順 | 条件 | `kind` | 理由(日本語の原文) |
|----|------|--------|----------------------|
| 1 | ファイルを開こうとして「存在しない」 | `fileMissing` | `指定の場所にファイルがありません` |
| 2 | ファイルを開けない。権限がない | `unreadable` | `読み取りの権限がありません` |
| 2' | 同、メタデータで通常のファイルでないと分かるとき(ディレクトリを開く操作自体は成功する OS など) | `unreadable` | `通常のファイルではありません` |
| 2'' | 同、その他の失敗 | `unreadable` | `読み取りに失敗しました` |
| 3 | 開いたファイルの情報(種別・大きさ)が取れない | `unreadable` | 権限なら `読み取りの権限がありません`、他は `読み取りに失敗しました` |
| 3' | 通常のファイルでない(ディレクトリなど) | `unreadable` | `通常のファイルではありません` |
| 4 | 大きさが 1 MiB(1,048,576 バイト)を超える | `tooLarge` | `入力が上限(1 MiB)を超えています` |
| 5 | 読み取り結果が上限を超える(順 4 のあとに大きくなった場合) | `tooLarge` | 同上 |
| 6 | 読み取りの途中の失敗 | `unreadable` | 権限なら `読み取りの権限がありません`、他は `読み取りに失敗しました` |
| 7 | UTF-8 として読めない | `unreadable` | `UTF-8 として読めません` |

実装(Node.js)の対応:

- 順 1〜2'': `fs.promises.open(path, 'r')`。失敗したときのエラーの `code` が `ENOENT` なら順 1、`EACCES`・`EPERM` なら順 2、`EISDIR` なら順 2'、それ以外(`ENOTDIR`、`ELOOP`、`EMFILE` など)は順 2''。
- 順 3・3'・4: 開いた `FileHandle` の `stat()`(開いたものの情報)。失敗は順 3(エラーの `code` の分類は、順 2 と同じ)。`isFile()` が偽なら順 3'(確認: POSIX の OS では、ディレクトリを `'r'` で開く操作は成功し、`stat()` が `isFile() === false` を返す)。`size` が 1,048,576 を超えれば順 4。
- 順 5・6: `FileHandle.read` で、**上限 + 1 バイトまで**をバッファに読む(`readFile` は使わない)。`FileHandle` は、`finally` で閉じる。
- 順 7: `new TextDecoder('utf-8', { fatal: true, ignoreBOM: true })`([03 第 3 節](03-definition-format.md)と同じ。`ignoreBOM: true` が必須)。

- 先にファイルを開き、**開いたもの**の情報で通常のファイルかと大きさを調べる。開いてから調べるので、調べたあとにファイルが差し替わっても、読み取りの結果と食い違わない。
- **ちょうど 1 MiB は受理**し、1 バイトでも超えれば `tooLarge`。
- 権限のない(mode 000 の)ファイルは、大きさにかかわらず `unreadable`(開く操作が先に失敗するので、1 MiB を超える mode 000 のファイルも `unreadable`)。ただし、権限の確認を迂回する利用者(root など)では、この結果にならない(その場合は、通常どおり読める)。
- 行番号は付かない。
- 空のファイル(0 バイト)は、空の入力として次へ進む(YAML は `rootNotMap`(`文書が空です`)、JSON は `syntax`)。
- OS による権限・種別の判定の細部(Windows でのエラーの `code` など)は、実装に任せてよい(Windows での `code` の値は未確認)。必須なのは、上の表の条件の順序と、各理由の文言である。
- 定義ファイルの取り込み([03 第 3 節](03-definition-format.md))とは、上限超過と UTF-8 の理由の文言が違う(ここは `入力が上限(1 MiB)を超えています`、`UTF-8 として読めません`)。また、定義ファイルと違い、**拡張子の確認はしない**。

## 4. 読み取り

### 4.1 受理する文法

- `--to yaml`(入力は JSON)のとき: JSON は、[03 第 5 節](03-definition-format.md)の形式(RFC 8259 の厳格な形式。コメント・末尾カンマ・重複キー・対にならないサロゲートの拒否を含む)で、[03 第 5.3 節](03-definition-format.md)の自前の字句・構文解析で読む。
- `--to json`(入力は YAML)のとき: YAML は、[03 第 4 節](03-definition-format.md)の部分集合を、[03 第 7 節](03-definition-format.md)のライブラリの設定と補完で読む。要点: YAML 1.2 のコアスキーマ、ブロックとフローのマップ・リスト、引用符なしと引用符つきとブロックのスカラー、コメント(捨てる)、アンカーとエイリアス(展開する)、マージキー `<<`(展開する)。**拒否**: タグ(標準のタグも)、複数の文書、非文字列のキー、重複したキー、タブのインデント。
- 読み取りの誤りの種類・理由・行は、[03 第 12.3 節](03-definition-format.md)の `syntax`/`tooLarge` の理由の表と同じ(`YAML の文法に誤りがあります`、`JSON の文法に誤りがあります`、`キーが重複しています`、`キーは文字列で書きます`、`タグは使えません`、`複数の文書は書けません(1 ファイルに書ける文書は 1 つです)`、`アンカーが自分自身を含んでいます`、`マージキーの値がマップではありません`、`入れ子が深すぎます(上限は 32 段)`、`要素数が上限(100000)を超えています`、`文字の大きさが上限(16 MiB)を超えています`)。行の出し方も、[03 第 13 節](03-definition-format.md)と同じ。
- 入力の先頭の BOM(U+FEFF)は受理される(無視する)。LF・CRLF の両方を受理する。
- YAML の対にならないサロゲートのエスケープ(`"\ud800"`)は、`syntax`(`YAML の文法に誤りがあります`。[03 第 7.4 節](03-definition-format.md) #12)。

### 4.2 上限(03 と同じ)

| 上限 | 値 | 超過したときの失敗 |
|------|----|--------------------|
| 入力の大きさ | 1 MiB | `tooLarge`(Intake) |
| 要素数 | 100,000 | `tooLarge` |
| 文字の大きさ | 16 MiB | `tooLarge` |
| 入れ子の深さ | **根のマップを数えず 32 段まで** | `syntax`(33 段目) |

数え方は [03 第 6.3 節](03-definition-format.md)の規定のとおり(要素数にはキーも数える、エイリアスは参照のたびに参照先を数える、文字の大きさは値のバイト数など)。ここでは、JSON の入力にも同じ上限があり、同じ境界になる(例: `{"a":[0,0,...]}` で、0 を n 個並べるとき、n = 99,997 まで受理、99,998 で失敗)。

数千〜数十万段の入れ子の入力、アンカーの入れ子による爆発的な展開、マージキーによる増幅は、いずれも、プロセスを落とさず、30 秒以内に、上の上限の失敗(または `syntax`)で終わること(必須)。ライブラリの重複キーの検査の無効化と、敵対的な入力の前処理は、[03 第 7.4 節](03-definition-format.md)のとおり。

### 4.3 最上位の確認(RootCheck)

| 入力 | 結果 |
|------|------|
| 最上位がマップ(YAML の `{a: 1}`、JSON の `{}` を含む) | 次へ |
| YAML で、文書が 0 個(空の入力、コメントと空行だけ) | `rootNotMap`、理由 ``文書が空です``、行なし |
| 最上位が、マップでない(YAML のリスト・スカラー・null(`---` だけの文書)、JSON の配列・数・文字列・`null`) | `rootNotMap`、理由 ``最上位がマップではありません``、行は最上位のノードの位置の行 |

- 定義ファイルと違い、**空の入力や null の文書を、空のマップとして扱わない**(変換器は、中身のない入力をマップにしない)。
- JSON で、空の入力(0 バイト、空白だけ)は、`rootNotMap` ではなく `syntax`(JSON は値が 1 つ必要)。
- 空のマップ(`{}`)は受理され、変換できる(第 8 節)。
- 実装の注意: 定義の読み込みでは、文書が 0 個、または最上位が null のとき、空のマップにして続ける([03 第 6.7 節](03-definition-format.md))。変換器は、同じ読み取りの関数を使い、その手前の結果(文書が 0 個、最上位が null)を見分けられる形で受け取る(読み取りの関数が、「空のマップとして扱った」という印、または最上位のノードそのものを返す)。

### 4.4 内部表現

読み取りと展開の結果は、[03 第 6.1 節](03-definition-format.md)の木にする。

| 種類(`kind`) | 内容 |
|--------------|------|
| `null` | 値なし |
| `bool` | `boolean` |
| `int` | `bigint`(64 ビット符号つき整数の範囲) |
| `hugeInt` | 範囲外の整数(値は持たない。第 5 節で拒否) |
| `float` | `number`(IEEE 754 binary64)と、`overflow` の印 |
| `string` | `string`(対にならないサロゲートを含まない) |
| `seq` | 木の並び |
| `map` | (文字列のキー, 木)の並び。**キーは重複しない。記述順を保つ** |

- 変換器は、`hugeInt` と、`overflow` の印のある浮動小数を、第 5 節のとおり記録して失敗させる。
- **内部表現の等価**(往復の確認に使う): 型が違えば不等(`"1"` と 1、1 と 1.0、`true` と `"true"`、null と `"null"`)。整数は、`bigint` の値が等しいこと(`===`)。浮動小数は、ビット表現が同じなら等しい(`Object.is(a, b)` で判定する。NaN どうしは等しい。`0.0` と `-0.0` は**異なる**)。マップは、**キーの順序を無視**して比べる。リストは順序を含めて比べる。

## 5. 表せない値(`unrepresentable`)

展開の途中で見つけた「相手の形式で表せない値」のうち、**入力に現れる順で最初の 1 つ**だけを記録し、走査の終了後に返す(上限超過・マージキーの誤りなど、第 2 節の順 6 の失敗は、これより優先する)。展開の走査は、捨てられるマージのエントリも訪れるので、そこにある表せない値も、記録の対象である。

| 値 | 理由(日本語の原文) | 対象の入力 | 例 |
|----|----------------------|------------|-----|
| 範囲外の整数(64 ビット符号つき整数に収まらない。種別 `hugeInt`) | `数値が表せる範囲を超えています` | JSON、YAML | `{"a": 9223372036854775808}`、`a: 0xFFFFFFFFFFFFFFFFFF` |
| 範囲を超える浮動小数(`overflow` の印) | `数値が表せる範囲を超えています` | JSON、YAML | `{"a": 1e400}`、`a: 1e999`、`a: -1e999` |
| NaN、無限大(YAML の `.nan`、`.inf`、`-.inf`、`+.inf` など。`overflow` の印がない、値が NaN・±`Infinity` の浮動小数) | `NaN と無限大は JSON で表せません` | YAML(`--to json` のときだけ) | `a: .nan`、`a: [1, .inf]` |
| 長すぎるキー(1,024 文字を超える。文字数で数える) | `キーが長すぎます(上限 1024 文字)` | JSON(`--to yaml` のときだけ。YAML の単純キーの上限のため) | 1,025 文字のキー |

- 失敗の表示: `kind` は `unrepresentable`、行なし。**場所(`keyPath`)**がつく。
- **場所の書式**: キーを `.` でつなぐ。リストの要素は `[添字]`(0 始まり。直前のキーに続けて、`.` なしで書く)。リストが最上位に来ることはない(最上位はマップ)。キー名は、制御文字・書式文字をエスケープし(`\n`、`\r`、`\t`、その他は `\u{16進小文字}`。対象の文字と切り詰めは [03 第 12.2 節](03-definition-format.md)と同じ)、64 文字(エスケープ後の文字数。コードポイントで数える)を超えると、64 文字で切って `…` を付ける。例: `job[1].note`、`a.b`、`a[2]`。マージで取り込まれる値の中の表せない値の場所は、`<<` のキーを経由した経路(`a.<<.x`)とする(この仕様の決定)。エイリアスの中の表せない値の場所は、エイリアスを書いた場所の経路とする。
  - 実装の指針: 経路は、走査の明示のスタックから、**最初の 1 件を記録するときだけ**文字列にする(すべてのノードで作らない)。
- **長すぎるキーの検査**: 内部表現のキー(エスケープを解いた後の文字列)の文字数(コードポイントの数。`.length` ではない)で判定する。1,024 文字ちょうどは受理。
- YAML の NaN・無限大は、`--to json` のときだけ拒否する。`--to yaml` の入力は JSON なので、NaN・無限大は文法として存在しない。
- 範囲外の数は、変換後の形式が YAML でも JSON でも拒否する(内部表現が 64 ビットのため)。
- 入力に現れる順の例: `a: 1\njob:\n  - id: x\n  - id: y\n    note: .nan\n  - z: .inf\nlater: .nan\n`(`--to json`)は、最初の `job[1].note` を返す。

読み取り(Resolve)の関数は、変換器のために、記録の機能を持つ(例):

```ts
export interface UnrepresentableValue {
  readonly reason: string;
  readonly keyPath: string;
}

export interface ResolveOptions {
  /** 変換器のとき、変換後の形式を渡す。定義の読み込みでは undefined(記録しない) */
  readonly convertTo: Format | undefined;
}

export type ResolveOutcome =
  | { readonly ok: true; readonly root: TreeNode | undefined; readonly firstUnrepresentable: UnrepresentableValue | undefined }
  | { readonly ok: false; readonly error: ReadError };
```

(`root` が `undefined` は、YAML で文書が 0 個のとき。型 `ReadError` は、[03](03-definition-format.md)の第 2・3 節の読み取りの誤り(種類、行、理由)。名前と形は任意。)

## 6. 書き出し(共通)

- 書き出しの前に、最上位は(必ず)マップになっている(第 4.3 節)。
- **各マップのキーは、入力の記述順のまま出力する**(キーをソートしない)。マージキーで取り込まれたエントリは、`<<` のエントリのあった位置に並ぶ([03 第 4.5 節](03-definition-format.md))。リストの順序も保たれる。コメントは捨てられる。
- 変換結果の最後は改行(LF)で終わる。改行は LF だけ。
- 木の深さは、読み取りの上限により 33 以下(根を含む)なので、書き出しの関数は、再帰で書いてよい(スタックあふれは起きない)。
- 出力は、断片の配列に溜めて、最後に `join('')` で 1 つの文字列にする(任意。性能のため)。

### 6.1 浮動小数の書き方(YAML と JSON で共通)

内部表現の浮動小数を、**必ず浮動小数と読み戻される形**で書く。

- NaN、+∞、-∞: YAML は `.nan`、`.inf`、`-.inf`。JSON は書けない(第 5 節で拒否済み)。
- それ以外は、往復で同じ値になる**最短の桁数**の 10 進で書く。JavaScript の `Number.prototype.toString`(`String(x)`)と `Number.prototype.toExponential()`(**引数なし**。必要な桁数だけを出す)が、いずれも最短の桁数を返す(確認)。次の規則で組み立てる。
  - `-0` は `-0.0`(`Object.is(x, -0)` で判定する。`String(-0)` は `"0"` を返すので、そのままでは使えない)。
  - 絶対値が 1e16 以上、または 1e-4 未満(0 を除く)のときは**指数形**: `x.toExponential()` の結果から、指数の `+` を取り除く(`1e+21` → `1e21`、`1.7976931348623157e+308` → `1.7976931348623157e308`。負の指数 `1.5e-7` は、そのまま)。仮数は、2 桁以上なら `d.ddd`、1 桁なら `d`。例: `1e16`、`1e21`、`1e-5`、`1.5e-7`、`1.2345678901234568e17`、`5e-324`、`1.7976931348623157e308`。
  - それ以外は、10 進の小数表記で、整数値でも必ず小数部を付ける。`String(x)` の結果に `.` が無ければ `.0` を付ける(`1` → `1.0`、`100` → `100.0`)。確認: 絶対値が 1e-4 以上 1e16 未満の範囲では、`String(x)` は指数形にならない(JavaScript の `String` が指数形に切り替えるのは、1e21 以上と 1e-7 未満なので、この範囲は常に小数表記)。`1e15` は `1000000000000000.0`、`0.0001` は `0.0001`、`0.1` は `0.1`。
- 指数形(`1e16`)は、JSON でも YAML でも、読み戻すと浮動小数になる(JSON は指数部を持つ数、YAML は [03 第 4.2 節](03-definition-format.md)の順 7)。
- 確認した例: `1` → `1.0`、`100` → `100.0`、`1e15` → `1000000000000000.0`、`1e16` → `1e16`、`1e21` → `1e21`、`1e-5` → `1e-5`、`0.0001` → `0.0001`、`0.00009999` → `9.999e-5`、`0.1` → `0.1`、`-0` → `-0.0`、`9999999999999998` → `9999999999999998.0`、`0.30000000000000004` → `0.30000000000000004`、`12345678901234567.0`(入力。値は 12345678901234568)→ `1.2345678901234568e16`。

### 6.2 整数・真偽値・null

- 整数: 10 進(64 ビット符号つき整数。`-9223372036854775808` を含む)。**`bigint` の `toString()` で書く**(`number` に変換しない)。
- 真偽値: `true` / `false`。
- null: `null`。

### 6.3 整数の精度と `bigint`(決定)

JavaScript の `number` は、-(2^53 − 1)〜2^53 − 1(±9,007,199,254,740,991)の範囲の整数だけを、正確に表せる。64 ビット符号つき整数の範囲(±9.22 × 10^18)の整数を、変換で保つために、次を**必須**とする。

| 場面 | 規定 |
|------|------|
| 入力の整数の字句(YAML の 10 進・`0x`・`0o`、JSON の整数) | 数字の列から `BigInt(...)` で値を得る([03 第 4.2・5.1 節](03-definition-format.md))。`Number`・`parseInt`・`JSON.parse` を経由しない。範囲を超えるものは、`BigInt` を呼ばずに(桁数で)`hugeInt` にする |
| 木 | 整数は `bigint`(`kind: 'int'`)。浮動小数は `number`(`kind: 'float'`)。**型が違えば別の値**(JSON の `1` と `1.0`、YAML の `1` と `1.0` は、変換でも区別する) |
| 出力 | 整数は `bigint.toString()`。浮動小数は第 6.1 節 |
| 浮動小数の書き方の整数値 | 値が整数でも、書き方に小数部か指数部があれば浮動小数。2^53 を超える値は、`number` の最も近い値になり、桁が変わりうる(`9007199254740993.0` → 値 9007199254740992 → 出力 `9007199254740992.0`。`12345678901234567.0` → `1.2345678901234568e16`)。これは浮動小数の性質であり、エラーにしない |
| 比較・検査 | 範囲の比較は `bigint` どうしで行う(`-9223372036854775808n` と `9223372036854775807n`)。`number` に変換してから比べない |

- 例: JSON `{"a": 9007199254740993}`(2^53 + 1)→ YAML `a: 9007199254740993`(値が保たれる。`number` を経由すると 9007199254740992 になって誤る)。YAML `a: 9223372036854775807` → JSON `"a": 9223372036854775807`。YAML `a: -9223372036854775808` → JSON でも同じ。`{"a": 9223372036854775808}` と `a: 9223372036854775808` は、`unrepresentable`(範囲外の整数)。
- 実装の前提: TypeScript の `target` は ES2020 以上(`bigint` の型と、`123n` の書き方、`BigInt` を使うため)。

## 7. JSON の書き出し(`--to json`)

**すべて必須**(出力の文字列が一致する)。

**レイアウト**(インデントは半角スペース 2 個。タブは使わない。行末に空白を残さない):

- 空のマップ: `{}`。空のリスト: `[]`。
- 空でないマップ: `{` + 改行、各エントリを `<インデント + 2>"<キー>": <値>` で、エントリの間を `,` + 改行で区切り、最後のエントリの後に改行、`<インデント>}`。キーと値の間は `": `(コロンの後に半角スペース 1 個)。
- 空でないリスト: `[` + 改行、各要素を `<インデント + 2><値>` で、`,` + 改行で区切り、最後の後に改行、`<インデント>]`。**要素は 1 行に 1 つ**(短い配列も 1 行にまとめない)。
- 最上位の値の後ろに LF を 1 個付ける。

**文字列(値もキーも同じ)**: `"` で囲み、次のとおりエスケープする。

| 文字 | 出力 |
|------|------|
| `"` | `\"` |
| `\` | `\\` |
| U+000A | `\n` |
| U+000D | `\r` |
| U+0009 | `\t` |
| U+0008 | `\b` |
| U+000C | `\f` |
| そのほかの U+0000〜U+001F、U+007F〜U+009F、U+2028、U+2029、U+FEFF、U+FFFE、U+FFFF | `\u` + 16 進の**小文字** 4 桁(例: `\u001b`、`\u007f`、`\u2028`) |
| それ以外(`/`、`<`、`>`、`&`、非 ASCII、絵文字を含む) | そのまま書く(エスケープしない) |

- **`JSON.stringify` は使えない**(確認: U+007F、U+2028 などをエスケープせずにそのまま出す。この規定と違う)。自前で書く(必須)。文字列は、UTF-16 のコード単位ごとに走査してよい(上の表の文字はすべて BMP の文字で、サロゲートの対はそのまま書く。木の文字列は、対にならないサロゲートを含まない)。
- 数・真偽値・null は、第 6 節のとおり。

JSON の出力例(YAML の入力 `a: 1.5e-7\nb: [1, [2, []], {}]\nc: "x\ty"\n`):

```json
{
  "a": 1.5e-7,
  "b": [
    1,
    [
      2,
      []
    ],
    {}
  ],
  "c": "x\ty"
}
```

## 8. YAML の書き出し(`--to yaml`)

自前の書き出し(ブロック形式の YAML)。ライブラリの書き出し(`stringify` など)は**使わない**(出力の文字列を、この規定に一致させるため)。**すべて必須**(出力の文字列が一致する)。

**レイアウト**

- 最上位のマップが空: `{}` + 改行。空でなければ、各エントリを書く。
- マップのエントリ: `<キー>: <値>`。値がスカラー、空のリスト(`[]`)、空のマップ(`{}`)なら同じ行に書く。値がコレクションなら、`<キー>:` のあと改行し、子を**2 スペース深く**書く。
- リストの要素: `- <値>`。要素がスカラー・`[]`・`{}` なら同じ行。要素がマップなら、最初のエントリを `- ` と同じ行に書き、残りのエントリを、`- ` の内容の位置(ダッシュの桁 + 2)に揃える。要素がリストなら、`- - 1`(最初の要素を同じ行)の形で、残りの要素も、内容の位置に揃える。
- リストは、親のキーより 2 スペース深く書く(`job:` の次の行に `  - id: a`)。
- インデントは 2 スペース。タブは使わない。行末に空白を残さない。

**スカラー**

- 整数・真偽値・null・浮動小数: 第 6 節のとおり。
- 文字列(値もキーも同じ規則): 次の条件を**すべて**満たすときだけ、引用符なし(plain)で書く。1 つでも外れたら、二重引用符で囲む。
  1. 空でない。
  2. 先頭が、ASCII の英字(`A-Za-z`)、`_`、`/` のどれか(数字・`-`・`.` などで始まるものは、数値や記号に読まれうるので引用符)。
  3. 末尾が空白でない。
  4. すべての文字が、ASCII の英数字、`_`、`-`、`.`、`/`、半角スペース のどれか。
  5. 半角スペースが 2 つ連続しない。
  6. YAML 1.1 の語(`y`、`Y`、`yes`、`Yes`、`YES`、`n`、`N`、`no`、`No`、`NO`、`on`、`On`、`ON`、`off`、`Off`、`OFF`)でない。
  7. [03 第 4.2 節](03-definition-format.md)の規則で解決して文字列になる(`true`、`false`、`null`、`Null`、`NULL`、`True` などは引用符)。この判定は、読み取りと**同じ関数**(引用符なしのスカラーの型の判定)を呼んで行う。
  - 条件 1〜5 は、正規表現 `/^[A-Za-z_/][A-Za-z0-9_./ -]*$/` に一致し、末尾が半角スペースでなく、`  `(半角スペース 2 つ)を含まない、と言い換えられる(**`$` の注意**: JavaScript の `$` は、`m` フラグが無ければ入力の末尾だけに一致する。`m` を付けない。末尾の改行を含む文字列は、条件 4 で外れる)。
  - plain になる例: `hello`、`echo hello world`、`/bin/run.sh`、`a-b_c.d`、`prog build --release`、`inf`、`_x`、`a b`。引用符になる例: `yes`、`no`、`on`(キー `on` は `"on": warning`)、`off`、`y`(キー `y` は `"y": []`)、`true`、`null`、`~`、`1`、`-1`、`1.5`、`0x1F`、`` (空)、` lead`、`trail `、`<<`、`a: b`、`a #b`、`.nan`、`1e3`、`Yes`、`Y`、`@end`、`-a`、`x  y`、`a `、非 ASCII を含む文字列(`"夜間バッチ"`、`"é key"`)。
- 二重引用符の中のエスケープ: `"` → `\"`、`\` → `\\`、改行 → `\n`、復帰 → `\r`、タブ → `\t`。そのほかの制御文字(U+0000〜U+001F、U+007F〜U+009F)と U+2028、U+2029、U+FEFF、U+FFFE、U+FFFF は `\uXXXX`(16 進の**大文字** 4 桁。例: `\u001B`、`\u007F`)。その他の文字(非 ASCII、絵文字を含む)は、そのまま書く。例: `"a\u2028b \u007F é 😀"`。(JSON の書き出しは小文字の 16 進。第 7 節。)
- キー `<<` は、必ず引用符で囲む(マージキーとして読み戻されないように。上の plain の規則で、`<` で始まるので引用符になる)。
- 非 ASCII を含む文字列は、常に二重引用符で囲む(値もキーも)。
- **長いキー**: 1,024 文字を超えるキーは書き出せない(第 5 節で `unrepresentable` として拒否済み。確認: ブロックのマップでは、1,025 文字の単純キーを YAML のライブラリが拒否するため)。

例(JSON の入力を `--to yaml` で変換した出力):

```yaml
format_version: 1
pipeline:
  name: nightly
job:
  - id: extract
    command: extract --all --since yesterday
    warning_exit_codes:
      - 3
      - 4
  - warning_exit_codes:
      - 3
      - 4
    id: transform
    command: "transform \"in dir\" $HOME"
    success_exit_codes:
      - 0
```

入れ子のリストとマップの例(入力 JSON `{"a": [[1,2],[3,[4]]], "b": [{"x":1,"y":[{"z":2}]}]}`):

```yaml
a:
  - - 1
    - 2
  - - 3
    - - 4
b:
  - x: 1
    "y":
      - z: 2
```

空のマップ、空のリスト、null、浮動小数を含む入力 JSON `{"x": {}, "y": [], "n": null, "f": 1.0, "e": 1e21}` は次になる。

```yaml
x: {}
"y": []
n: null
f: 1.0
e: 1e21
```

空の入力に近い最小の入力 `{}` は、`{}` + 改行になる。

## 9. 往復の保証

- 保証するのは、**木の等価**である(第 4.4 節。マップのキーの順序は無視、リストの順序は有意)。入力を読んだ内部表現と、変換結果を(変換後の形式として)読み戻した内部表現が、等しい。さらに、変換結果を元の形式へ戻した結果の木も、元の木と等しい。
- 保証されないもの: コメント、アンカー・エイリアス・マージキー(展開される。出力に `<<`・`*`・`&` は残らない)、引用符・文字列の書き方(plain と引用符の別、ブロックスカラーの形)、数値の書式(`0x1F` → `31`、`007` → `7`、`1e3` → `1000.0`、JSON の `-0` → `0`)、`1_000` のような YAML の文字列の、他の形式での再解釈(YAML の `1_000` は文字列なので、`"1_000"` になる)。
- 往復で保たれることが確認されている値(第 11 節の例の範囲): 文字列(`yes`、`no`、`on`、`off`、`1`、`1.5`、`null`、`~`、`true`、`false`、`<<`、空文字列、前後に空白がある文字列、`a: b`、改行・タブ・引用符・バックスラッシュ・制御文字・日本語・絵文字を含む文字列、長い文字列)、整数(64 ビット符号つき整数の最小値・最大値、0、2^53 + 1 などの 2^53 を超える整数)、浮動小数(`1.0`、`-0.0`、`1.5e-7`、`1e21`、`0.1`。NaN、±∞ は YAML 内だけ)、真偽値、null、空のリスト・空のマップ、入れ子のリスト、リストの中のマップ、型が混在するリスト、`on` キー。
- ただし、**NaN と無限大を含む YAML は、JSON に変換できない**(第 5 節)。また、**範囲外の数**は、どちらにも変換できない。

## 10. エラーの構造と表示

型の骨格(例。種類 `kind` を判別に使う判別共用体):

```ts
export type ConvertErrorKind =
  | 'fileMissing'
  | 'unreadable'
  | 'tooLarge'
  | 'syntax'
  | 'unrepresentable'
  | 'rootNotMap';

interface ConvertErrorFields {
  readonly file: string;
  /** 1 始まり。undefined は行なし */
  readonly line: number | undefined;
  /** 空は場所なし(undefined) */
  readonly keyPath: string | undefined;
  /** 固定の文(日本語)。入力の値・ライブラリのエラー文は含まない */
  readonly reason: string;
}

export type ConvertError = {
  [K in ConvertErrorKind]: ConvertErrorFields & { readonly kind: K };
}[ConvertErrorKind];
```

| フィールド | 内容 |
|------------|------|
| `file` | 入力ファイルの表示用の名前 |
| `line` | 行番号(1 始まり)。位置が分かるときだけ |
| `keyPath` | 表せない値の場所(キーの経路)。値そのものは含まない |
| `kind` | 種類 |
| `reason` | 固定の文(入力の値・ライブラリのエラー文は含まない) |

種類(6 種):

| 識別子 | 日本語 | 英語(英語のメッセージのとき) |
|--------|--------|----------------------------|
| `fileMissing` | 入力ファイルが存在しません | input file does not exist |
| `unreadable` | 入力ファイルを読めません | cannot read input file |
| `tooLarge` | 入力が大きすぎます | input is too large |
| `syntax` | 文法の誤りです | syntax error |
| `unrepresentable` | 相手の形式で表せない値があります | value cannot be represented in the target format |
| `rootNotMap` | 最上位がキーと値の集まり(マップ)ではありません | top level is not a map |

ライブラリ(呼び出し側)の表示:

```
<file>:<line>: <種類の文>: <reason>(場所: <keyPath>)    行も場所もあるとき
<file>: <種類の文>: <reason>                              どちらも無いとき
```

行だけ・場所だけのときは、それぞれ `<file>:<line>: <種類の文>: <reason>`、`<file>: <種類の文>: <reason>(場所: <keyPath>)` となる。`(場所: …)` は、`keyPath` があるときだけ、末尾に付く(直前に区切りの空白はない)。`<file>` は、制御文字・書式文字をエスケープし、エスケープ後の文字数で 256 文字までに切る(超えるときは末尾に `…`。エスケープの規則は [03 第 12.2 節](03-definition-format.md))。

`conductor convert` の失敗の表示(標準エラーの 1 行、終了コード 67):

```
conductor: error: <file>[:<line>]: <種類の文(言語による)>: <reason> (<at|場所>: <keyPath>)
```

`<reason>` は日本語のまま。`(at: …)` は英語のメッセージ、`(場所: …)` は日本語のメッセージ(言語の選び方は [08](08-output-and-i18n.md))。`(…)` の前に半角スペース 1 個。`keyPath` がないときは `(…)` を付けない。`<file>`・`<reason>`・`<keyPath>` は、制御文字・書式文字をエスケープして出す(ここでは文字数で切らない。`keyPath` の中のキー名は、第 5 節の規則で 64 文字に切られている)。実行例:

```
conductor: error: n.yaml: value cannot be represented in the target format: NaN と無限大は JSON で表せません (at: a)
conductor: error: x.json:3: syntax error: JSON の文法に誤りがあります
conductor: error: x.yaml: top level is not a map: 文書が空です
conductor: error: m.yaml: syntax error: 複数の文書は書けません(1 ファイルに書ける文書は 1 つです)
```

### 理由の一覧(日本語の原文。英語版はない)

| 理由 | 使われる種類 |
|------|--------------|
| `指定の場所にファイルがありません` | `fileMissing` |
| `読み取りの権限がありません` / `読み取りに失敗しました` / `通常のファイルではありません` / `UTF-8 として読めません` | `unreadable` |
| `入力が上限(1 MiB)を超えています` / `要素数が上限(100000)を超えています` / `文字の大きさが上限(16 MiB)を超えています` | `tooLarge` |
| `YAML の文法に誤りがあります` / `JSON の文法に誤りがあります` / `キーが重複しています` / `キーは文字列で書きます` / `タグは使えません` / `複数の文書は書けません(1 ファイルに書ける文書は 1 つです)` / `アンカーが自分自身を含んでいます` / `マージキーの値がマップではありません` / `入れ子が深すぎます(上限は 32 段)` | `syntax` |
| `数値が表せる範囲を超えています` / `NaN と無限大は JSON で表せません` / `キーが長すぎます(上限 1024 文字)` | `unrepresentable` |
| `最上位がマップではありません` / `文書が空です` | `rootNotMap` |

## 11. 例

### 11.1 YAML(アンカー、エイリアス、マージキー、`on` キー、`on: error` を含む)→ JSON(`--to json`)

```yaml
format_version: 1
pipeline:
  name: nightly
job:
  - &base
    id: extract
    command: extract --all --since yesterday
    warning_exit_codes: [3, 4]
  - <<: *base
    id: transform
    command: 'transform "in dir" $HOME'
    success_exit_codes: [0]
    transitions:
      - on: warning
        next: notify
      - on: error
        next: "@end"
```

出力(アンカーとマージは展開され、`<<` はそのマップの位置に取り込み元のキー `warning_exit_codes` が入り、`id`・`command` は自分のキーが優先する。キーの順は入力の記述順):

```json
{
  "format_version": 1,
  "pipeline": {
    "name": "nightly"
  },
  "job": [
    {
      "id": "extract",
      "command": "extract --all --since yesterday",
      "warning_exit_codes": [
        3,
        4
      ]
    },
    {
      "warning_exit_codes": [
        3,
        4
      ],
      "id": "transform",
      "command": "transform \"in dir\" $HOME",
      "success_exit_codes": [
        0
      ],
      "transitions": [
        {
          "on": "warning",
          "next": "notify"
        },
        {
          "on": "error",
          "next": "@end"
        }
      ]
    }
  ]
}
```

(`on: error` のような遷移は、変換器は検査しない。定義として読み込むときに `errorTransition` になる([03 第 9.4 節](03-definition-format.md))。)

この JSON を `--to yaml` で変換すると、第 8 節の例(`transitions` を含めたもの)の形になる。

### 11.2 失敗の例

| 入力(`--to json`、YAML) | 結果 |
|------|------|
| `a: 1\nb: 2\na: 3\n` | `syntax` 3 行目、`キーが重複しています` |
| `- 1\n- 2\n` | `rootNotMap` 1 行目、`最上位がマップではありません` |
| `` (空) | `rootNotMap`、行なし、`文書が空です` |
| `a: 1\n---\nb: 2\n` | `syntax`、`複数の文書は書けません(1 ファイルに書ける文書は 1 つです)` |
| `a:\n  <<: 5\n` | `syntax` 2 行目、`マージキーの値がマップではありません` |
| `a:\n  <<: ~\n` | 同上 |
| `a: &r [*r]\n` | `syntax` 1 行目、`アンカーが自分自身を含んでいます` |
| `a: *x\n` | `syntax` 1 行目、`YAML の文法に誤りがあります` |
| `a: .nan\n` | `unrepresentable`、`NaN と無限大は JSON で表せません`、場所 `a` |
| `a: [1, .inf]\n` | `unrepresentable`、場所 `a[1]` |
| `a: 9223372036854775808\n` | `unrepresentable`、`数値が表せる範囲を超えています`、場所 `a` |
| `1: x\n` | `syntax` 1 行目、`キーは文字列で書きます` |
| `a: !!str 1\n` | `syntax` 1 行目、`タグは使えません` |
| `a:\n  <<: {x: 1}\n  <<: {y: 2}\n` | `syntax` 3 行目、`キーが重複しています` |
| `a: 1\n---\n` | `syntax`、`複数の文書は書けません(1 ファイルに書ける文書は 1 つです)` |
| `a: "\ud800"\n` | `syntax` 1 行目、`YAML の文法に誤りがあります` |

| 入力(`--to yaml`、JSON) | 結果 |
|------|------|
| `{"a":1,}` | `syntax` 1 行目、`JSON の文法に誤りがあります` |

| `[1]` | `rootNotMap` 1 行目、`最上位がマップではありません` |
| `null` | `rootNotMap` 1 行目、`最上位がマップではありません` |
| `` (空) | `syntax`(JSON は値が 1 つ必要) |
| `{"a": 1e400}` | `unrepresentable`、`数値が表せる範囲を超えています`、場所 `a` |
| `{"a": 9223372036854775808}` | `unrepresentable`、同上 |
| `{"a": 9223372036854775807}` | 受理(`a: 9223372036854775807`) |
| キーが 1,025 文字のオブジェクト | `unrepresentable`、`キーが長すぎます(上限 1024 文字)`、場所は 64 文字で切った名前 |
| `// c\n{}` | `syntax` |

### 11.3 成功の例(`--to json`、YAML)

| 入力 | 出力(値) |
|------|------|
| `a: \|\n  x\n  y\nb: >\n  p\n  q\n\n  r\nc: \|-\n  k\n` | `a` は `"x\ny\n"`、`b` は `"p q\nr\n"`、`c` は `"k"`(出力は `{`、`  "a": "x\ny\n",`、`  "b": "p q\nr\n",`、`  "c": "k"`、`}`) |
| `a: foo\n  bar\n  baz\n` | 値 `"foo bar baz"` |
| `a: 0o17\nb: 0x1F\nc: 1e3\nd: .5\ne: 1.\nf: 007\ng: yes\nh: ~\n` | 値 15、31、1000.0、0.5、1.0、7、`"yes"`、`null` |
| `a: 2001-01-01\nb: 12:30:00\nc: 1_000\n` | 値 `"2001-01-01"`、`"12:30:00"`、`"1_000"`(すべて文字列) |
| `b: &b {x: 1}\na:\n  <<: [*b, {x: 2, y: 3}]\n  y: 9\n` | 出力のキーの順は `b`、`a`。`a` は `{"x": 1, "y": 9}`(自身のキーが優先、リストは先頭が優先。取り込まれた `x` は `<<` の位置に入る) |
| `a: &x 1\nb: &x 2\nc: *x\n` | `c` は 2(最後のアンカーの定義を指す。確認: ライブラリの `Alias.resolve` が最後の定義を返す。[03 第 4.3 節](03-definition-format.md)) |

| `a: 9007199254740993\nb: -9223372036854775808\nc: 9007199254740993.0\nd: 0\ne: -0\n` | 値は整数 9007199254740993(桁が保たれる)、整数 -9223372036854775808、浮動小数 `9007199254740992.0`(`number` の最も近い値)、整数 0、整数 0(`-0` は 0) |

## 12. 未確認事項

- YAML の受理する文法の細部(引用符なしのスカラー中の制御文字、CR だけの改行、他の版のライブラリの挙動)と、ライブラリの採否: [03 第 7・17 節](03-definition-format.md)と同じ。YAML ライブラリの採否は、そこに書いた受け入れ試験で決める。
- YAML の文法の誤りの行番号の厳密な規則(ライブラリの検出位置による。[03 第 13.4 節](03-definition-format.md)の表は、確認した例に限る)。
- 極小の浮動小数(`1e-400` など)の読み取りは、0 になり、エラーにしない(確認: `Number('1e-400')` は 0)。
- 非 ASCII のキー・値の YAML 出力は、常に二重引用符で囲む(この仕様で決めた)。plain で書ける範囲を広げる変更は、この仕様の変更になる。
- JSON の出力で、U+007F〜U+009F などを `\u` でエスケープする(この仕様で決めた。他の実装が、これらをそのまま書いても、木は同じだが、出力の文字列は一致しない)。
- 入力の YAML の `---` だけの文書の `rootNotMap` の行(最上位のノードの位置の行とした。ライブラリが空のノードに返す位置は、`---` の直後で、1 行目。確認: `---\n` の文書の内容の範囲は、`---` の直後)。
- マージで取り込まれる値の中の表せない値の場所(`a.<<.x`)は、この仕様の決定であり、他の規定による裏づけはない。
- Windows での `code`(エラーの種類の分類)、Node.js の LTS 系列での確認: [03 第 3・17 節](03-definition-format.md)と同じ。
