# 00. README(rust 版 conductor 仕様書の案内)

この仕様書は、Rust 製のコマンドラインツール `conductor` の **v0.10.2(v0.9.0 と v0.10.0 の機能、v0.10.1 の直しを含む)の現在の実装** を、忠実に書き起こしたものである。「この仕様書だけを渡された実装者(人または AI)が、ゼロから、同じ挙動のツールを実装できる」ことを目標とする。

## 1. 範囲と版

| 項目 | 内容 |

| 版 | v0.9.0 の機能(環境変数の注入と `.env`、`graph`、`--dry-run`、`init`)と、v0.10.0 の機能(`watch --follow`/`--interval`、`[pipeline] log_dir`、`unset_env`、`[pipeline.retry]` と `retry = false`、`env_file` の表 `{ path, required }`、`graph --format dot`、ステートの `[[job.attempt]]` と `watch` の所要時間の列)、v0.10.1 の直し(ログの名前の空白、読む前の「止める」印、計画の模擬の内部の入口)を含む。4 クレートの `Cargo.toml` の版は `0.10.2` である(`--version` の表示は `conductor 0.10.2`) |

## 4. 用語集

用語は 03〜11 で、次の意味で統一して使う。

| 用語 | 意味 |
|------|------|
| ジョブ(job) | 定義の `[[job]]` 1 つ。ID(`id`)、実行するコマンド(`command`)、結果の扱い(終了コードの集合、遷移、リトライ)を持つ。`conductor` が子プロセスとして起動する単位 |
| ジョブID | ジョブの識別子(`id`)。定義の中で一意。空でなく、`@` で始まらない文字列 |
| パイプライン(pipeline) | 1 つの定義ファイルが表すジョブの並び全体。名前(`[pipeline].name`)を持つ。1 ファイルに 1 パイプライン。`conductor pipeline <名前>` は、その全ジョブを記述順に処理する |
| 定義ファイル(definition file) | パイプラインを書く TOML ファイル(既定の名前は `conductor.toml`)。書式の版は `format_version = 1` |
| 記述順 | 定義ファイルの中での `[[job]]` の並び。ジョブの実行順と、遷移の方向(前から後ろ)を決める |
| `command` | ジョブが実行するコマンド。文字列(空白で分割し引用符を解く)または文字列の配列(分割しない)。シェルを介さず、直接起動する |
| 終了コード(exit code) | ジョブ(子プロセス)の終了コード。または `conductor` 自身の終了コード(文脈で区別する。後者は「`conductor` の終了コード」と書く) |
| 成功コード | ジョブを成功とみなす終了コードの集合。`success_exit_codes` があればその値、なければ `[0]` |
| 警告コード | ジョブを警告とみなす終了コードの集合(`warning_exit_codes`。0 を含まず、成功コードと重ならない) |
| 分類(classification) | ジョブの結果の区分。`success`(成功)、`warning`(警告)、`error`(エラー)、および「分類なし」(起動する前に中断された場合) |
| 警告(warning) | ジョブの分類の 1 つ。`conductor` の終了コードは 0 で、流れは成功と同様に進む(遷移は `on = "warning"` で別に書ける)。別に、`reset --all` の「警告(`conductor: warning:`)」の表示がある(終了コード 0)。文脈で区別する |
| 遷移(transition) | ジョブの結果(`success` または `warning`)ごとに書く、次の動き。行き先は、記述順で後ろのジョブのID、または `@end`。`error` には書けない |
| `@end` | 遷移先の特別な値。以降のジョブをスキップして終える |
| スキップ(skip) | ジョブを実行せずに済ませること。理由は `byTransition`(遷移で飛ばされた)、`byEnd`(`@end` より後ろ)、実行済み(`AlreadyExecuted`。ステートには記録しない) |
| 起動前の判断 | ジョブを起動する前に、ステートから決める「実行(Run)・スキップ(Skip)・拒否(Reject)」 |
| 拒否(reject) | 順序外の呼び出し(前のジョブが終わっていない)。ジョブを実行せず、ステートも変えず、終了コード 66 |
| ステート(state) | 実行の途中経過(各ジョブの状態、再開位置、`@end` に到達したか、完了したか)。メモリ上は `PipelineState` |
| ステートファイル | ステートを保存する TOML ファイル。定義ファイルと同じディレクトリの `<定義ファイル名>.state`(run ID があれば `<定義ファイル名>.<run-id>.state`) |
| ジョブの状態(`status`) | ステートの中の、ジョブごとの値。`pending`、`success`、`warning`、`error`、`skipped` |
| run ID | 同じ定義を、別々の実行単位で並行して使うときに、ステートファイルを分ける識別子。`A-Za-z0-9._-` の 1〜64 文字で、先頭は `.` でない。`--run-id` または環境変数で与える |
| 再開位置(`resume_job_id`) | 次に実行する、または再開するジョブのID。エラーで止まったとき、そのジョブになる |
| 再開(resume) | エラーなどで止まった実行を、同じコマンドをもう一度呼ぶことで、止まったジョブから続けること。成功・警告のジョブは実行済みとしてスキップされる |
| 完了(completed) | パイプラインのすべてのジョブが済んだ(最後のジョブの終了、`@end` への到達、スキップによる終了)状態。ステートの `completed = true` |
| リトライ(retry) | `[job.retry]` を書いたジョブ(v0.10.0 以降は、`retry` を書かずに `[pipeline.retry]` の既定を当てはめたジョブも)が、指定の終了コードで終わったとき、待ってから同じジョブを実行し直すこと。`retry = false` のジョブはリトライしない。ステートには回数を書かない。`conductor` が落ちたあとの再開は、最初の実行から数え直す |
| 試行(attempt) | ジョブの 1 回の起動(リトライと再開を含めて、起動のたびに 1 つ)。v0.10.0 以降、試行ごとの開始と終了の時刻を、ステートの `[[job.attempt]]` に書く(06 の 2.3a)。`watch` の所要時間の列は、これから求める |
| 中断(interrupt) | `conductor` がシグナル(UNIX 系: SIGHUP・SIGINT・SIGQUIT・SIGTERM、Windows: Ctrl+C)を受け取ること。「中断の合図」(`InterruptSignal`)が立つ。終了コードは `128 + 番号` |
| 一括実行 / 個別実行 | `pipeline`(全ジョブを記述順に処理)/ `run`(ジョブ 1 つ。スケジューラが 1 つずつ呼ぶ) |
| スケジューラ | `conductor` を呼び出す外部のもの(cron など)。`conductor` 自身はスケジュール機能を持たない |
| 変換(convert) | 定義ファイルを TOML と YAML のあいだで変換する `convert` コマンド。定義の検証はしない |
| 環境変数の層(`env`・`env_file`、v0.9.0 以降。`unset_env`、v0.10.0 以降) | ジョブに足す環境変数の出どころ。後ろが勝つ順に、`[pipeline].env_file`、`[pipeline.env]`、`[job].env_file`、`[job.env]`、自動の変数(`CONDUCTOR_*`)。引き継いだ環境(親から受け取ったもの)は、これらの手前の土台。v0.10.0 以降は、`[pipeline].unset_env` と `[job].unset_env` の名前を、足す前に土台から消す(書かなければ何も消さない。05 の 14.2) |
| `.env` | `env_file` で指す、`KEY=VALUE` の行からなるファイル。書式は 03 の 6.7。実行の前にすべて読む。誤りは終了コード 64。v0.10.0 以降、表 `{ path, required = false }` で書いたファイルは、無ければ読み飛ばす |
| ログのファイル(`log_dir`、v0.10.0 以降) | `[pipeline].log_dir` のディレクトリに、試行ごとに 1 つ作る、ジョブの標準出力と標準エラーの写し(`<安全な ID>.<詰めた時刻>.<試行の番号>.log`。07 の 4.5)。端末にも同じ内容が流れる |
| 予約名 | `CONDUCTOR_` で始まる環境変数の名前(ASCII の大文字小文字を区別しない)。利用者は、`env` にも `.env` にも(v0.10.0 以降は `unset_env` にも)書けない。自動の変数が使う |
| 自動の変数 | ジョブに常に足される `CONDUCTOR_PIPELINE`、`CONDUCTOR_JOB_ID`、`CONDUCTOR_RUN_ID`(run ID があるときだけ)、`CONDUCTOR_ATTEMPT`(1 から。リトライごとに増える) |
| 辺(edge)(`graph`、v0.9.0 以降) | 図の中の、ジョブから行き先(後ろのジョブまたは終点 `@end`)への矢印。成功と警告のそれぞれの行き先から作る。エラーに辺はない |
| 計画(plan)(`--dry-run`、v0.9.0 以降) | ジョブを実行せず、仮定した終了コード(既定は 0)で、実行と同じ判断を進めて得る「実行したら何が起こるか」の表示 |
| 仮定(assume) | `--assume <ジョブID>=<終了コード>` で与える、計画の中のジョブの終了コード(0〜255) |
| ひな形(`init`、v0.9.0 以降) | `conductor init` が作る、有効な定義の例(日本語と英語の 2 つの文面。パイプライン名だけが入れ替わる) |
| Intake / Parse / Depth / VersionCheck / Walk | 定義の読み込みの 5 段階(03 の 1 章)。Intake=場所の決定と読み取り、Parse=TOML の文法、Depth=入れ子の深さ、VersionCheck=`format_version`、Walk=構造・型・遷移などの検査 |
| 耐久性(`Durable` / `Fast`) | ステートの書き込みで、ファイルの内容の同期を行う(Durable)か省く(Fast)か。v0.10.0 以降、試行の開始の書き込みは `Fast`、結果の書き込みは `Durable`(06 の 3 章) |
| 時刻(`Timestamp`、v0.10.0 以降) | UTC の秒。ステートには `YYYY-MM-DDTHH:MM:SSZ`、ログのファイル名には `YYYYMMDDTHHMMSSZ` で書く(05 の 18.1) |
| at-least-once | ジョブの終了とステートへの記録のあいだで `conductor` が落ちると、ジョブが再実行されうる、という保証の範囲 |
| NFR | 非機能要件(性能、堅牢性、セキュリティ、保守性)。テストのコメントで使う識別子 |
| MSRV | 対応する最小の Rust の版(1.100) |

## 5. 表記の規約

- 本文は日本語。識別子、コード、エラーの文は原文のまま(`コード` 書式)で書く。
- 終了コード、キー名、既定値、メッセージの文言は、実装の値をそのまま書く。メッセージには、英語と日本語の両方がある場合に、両方を示す(08 章が全件)。
- 「`crates/…`」は、このリポジトリのファイルの場所である(根拠の所在)。仕様の本体は、場所ではなく、挙動である。
- 「章」「節」は、同じ文書の見出しの番号を指す(`§` や `5.2` の形でも書く)。他の文書への参照は、文書の番号を付ける(例: 「06 の 5 章」)。
- 型は Rust の名前で示す(`Option<T>`、`Vec<T>`、`i32` など)。擬似コードは `text` のコードブロックで示す。
- 「未確認」は、確認できなかった点を指す。断定しない。
- 表の「行」は 1 始まりの行番号。「位置」はファイル先頭からのバイト位置。
- 数値の範囲は、閉区間で「1〜255」のように書く(両端を含む)。
- 他の仕様書や他の言語の実装への言及は書かない。
