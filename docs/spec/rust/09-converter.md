# 09. 変換器(TOML と YAML の相互変換。rust 版 conductor v0.9.4)

この文書は、`conductor convert <ファイル> --to <yaml|toml>` の中身である変換器(`crates/converter`、クレート `conductor-converter`)の振る舞いを定める。根拠は実装(`crates/converter/src/*`)とテスト(`crates/converter/tests/*`、fixtures を含む)、および実際に実行して確かめた出力である。確認できなかった点は「未確認」と書く。

- 変換器は、定義ファイルの**検証をしない**。変換した結果が `conductor` の定義として正しいかは見ない(任意の TOML / YAML のマップを変換する)。
- (v0.9.0 以降)変換器は、定義のキーを列挙しない。したがって、v0.9.0 で加わったキー(`[pipeline.env]`、`[job.env]`(値は文字列のテーブル)、`env_file`(文字列、または文字列の配列))も、ほかのキーと同じ規則で往復する。v0.9.0 のために、変換器のコードは変わっていない。
- 副作用はない: ファイルへの書き込み、環境変数、プロセス、ネットワークに触れない(読むのは入力ファイル 1 つだけ)。
- 入力の値を、エラーの文に含めない(キー名だけを、エスケープと切り詰めをして、場所として示すことがある)。

## 1. 入口と入出力

| 入口 | 引数 | 戻り値 |
|------|------|--------|
| `convert(request)` | `ConversionRequest { input_path, target_format }` | 成功: `ConvertedText { text }`、失敗: `ConversionError` |
| `convert_text(text, target, file_label)` | 文字列、変換後の形式、表示用のファイル名 | 同上(ファイルに触れない) |

- `target_format` / `target` は `Yaml` または `Toml`(変換**後**の形式)。
- **入力の形式は、変換後の形式の反対**とみなす(`--to yaml` なら入力は TOML、`--to toml` なら入力は YAML)。拡張子は見ない。`.toml` の名前のファイルでも、`--to toml` なら YAML として読む。同じファイルを `--to yaml` にすれば、TOML として読もうとして、文法の誤りになる。
- 変換結果は、全部作ってから 1 つの文字列として返す。失敗のときは、出力は無い。
- CLI の `convert` は、成功したら結果を標準出力に 1 回で書く。失敗したら標準出力は空で、標準エラーに原因を出し、終了コード 67 で終わる(CLI の仕様は別文書)。

## 2. 処理の流れと失敗の順序

```
Intake → 読み取り(Read) → [YAML 入力のみ] 文書の確認(RootCheck) → 展開と写し取り(Resolve) → 書き出し(Write)
```

失敗は、次の順で最初に見つかったものを 1 件だけ返す(以降は実行しない)。

| 順 | 段階 | 失敗 |
|----|------|------|
| 1〜2 | Intake: 開く(存在しない → `fileMissing`、権限など → `unreadable`) | 第 3 節 |
| 3 | Intake: 大きさが 1 MiB を超える → `tooLarge` | 第 3 節 |
| 4 | Intake: 上限 + 1 バイトまでの読み取りと UTF-8 の確認 → `unreadable` | 第 3 節 |
| 5 | 読み取り: 文法の誤り、キーの重複(リテラル)、再帰するアンカー、定義されていないアンカー、読み取り時の深さ超過 → `syntax`(YAML は最後の文書まで読んで確かめる) | 第 4・5 節 |
| 6 | 複数の文書(YAML)→ `unrepresentable` | 第 5.3 節 |
| 7 | 最上位がマップでない(YAML)→ `rootNotMap` | 第 5.3 節 |
| 8 | 展開: 要素数の上限(`tooLarge`)、文字の大きさの上限(`tooLarge`)、展開後の深さの上限(`syntax`)、マージキーの値がマップでない(`unrepresentable`)、展開でだけ生じるキーの重複(`syntax`) | 第 6 節 |
| 9 | 展開で記録した、表せない値のうち、入力に現れる順で最初のもの → `unrepresentable` | 第 7 節 |

- 順 8 の上限超過は、順 9 より優先する(先に `null` があっても、上限超過が返る)。
- 同じ段階で複数あるときは、入力に現れる順で最初のものを返す。
- 順 5(文法)は、順 6(複数の文書)より先。たとえば `a: 1\n---\nb: [1\n` は、2 つ目の文書の文法の誤りを `syntax` として返す。
- 順 3 は順 4 より先: 1 MiB を超え、かつ UTF-8 でない入力は `tooLarge`。順 3 は順 5 より先: 1 MiB を超える入力は、中身が壊れていても `tooLarge`。

## 3. 取り込み(Intake)

| 順 | 条件 | `kind` | 理由(日本語の原文) |
|----|------|--------|----------------------|
| 1 | ファイルを開こうとして「存在しない」 | `fileMissing` | `指定の場所にファイルがありません` |
| 2 | ファイルを開けない(その他)。メタデータで通常のファイルでないと分かるとき(Windows でディレクトリを開いたときなど) | `unreadable` | `通常のファイルではありません` |
| 2' | 同、権限がない | `unreadable` | `読み取りの権限がありません` |
| 2'' | 同、その他の失敗 | `unreadable` | `読み取りに失敗しました` |
| 3 | 開いたハンドルのメタデータが取れない | `unreadable` | 権限なら `読み取りの権限がありません`、他は `読み取りに失敗しました` |
| 3' | 通常のファイルでない(ディレクトリなど) | `unreadable` | `通常のファイルではありません` |
| 4 | 大きさが 1 MiB(1,048,576 バイト)を超える | `tooLarge` | `入力が上限(1 MiB)を超えています` |
| 5 | 読み取り結果が上限を超える(確認のあとに大きくなった場合) | `tooLarge` | 同上 |
| 6 | 読み取りの途中の失敗 | `unreadable` | 権限なら `読み取りの権限がありません`、他は `読み取りに失敗しました` |
| 7 | UTF-8 として読めない | `unreadable` | `UTF-8 として読めません` |

- **ちょうど 1 MiB は受理**し、1 バイトでも超えれば `tooLarge`。読み取りは「上限 + 1 バイト」まで。
- 権限のない(mode 000 の)ファイルは、大きさにかかわらず `unreadable`(権限の確認が大きさの確認より先。1 MiB を超える mode 000 のファイルも `unreadable`)。
- 行番号は付かない。
- 空のファイル(0 バイト)は、空の入力として次へ進む(YAML は `rootNotMap`、TOML は空のマップ)。

## 4. TOML の読み取り(`--to yaml` のとき)

読み取りは、外部クレート `toml`(1.2.1、機能 `parse`・`std`・`display`・`serde`)の `str::parse::<toml::Table>()` による。自前の構文解析はない。したがって、受理する文法は、そのクレートが受理する TOML である(TOML 1.0 の全構文。TOML 1.1 の構文として、インラインテーブル内の改行と末尾カンマ、エスケープ `\e`・`\xHH`、秒を省略した時刻を受理することを実行で確認した)。

- 空の入力、コメントだけの入力は、空のマップ。
- UTF-8 の BOM は受理される。LF・CRLF の両方を受理する。
- 文法の誤り(キーの重複、見出しの重複、整数の `i64` の範囲外、閉じていない括弧など)は、`syntax`、理由 `文法の誤りです`。行番号は、読み取り器が返した誤りの位置(バイト位置)の行(1 始まり。LF の数で数える)。位置が無いときは行なし。例: `a = 1\nb = = 2\n` は 2 行目、`a = 1\na = 2\n` は 2 行目、`n = 9223372036854775808` は 1 行目。
- 値の写し取り: 文字列、整数(`i64`)、浮動小数(`f64`。`inf`、`-inf`、`nan`、`-0.0` を含む)、真偽値、配列、テーブルを、そのまま内部表現にする。**日時(オフセットつき日時、ローカル日時、日付、時刻)は、内部では印だけ付ける**(第 7 節で「表せない値」になる)。
- 深さの制限: 根のテーブルを 1 段として、テーブルと配列の入れ子が**合計 32 段まで受理**、33 段目を拒否する。拒否は `syntax`、理由 `入れ子が深すぎます(上限 32)`、行番号なし。数え方の例:
  - 配列: `a = [[[...]]]` は、`[` が 31 個までは受理、32 個で拒否(根が 1 段、配列が 31 段で 32 段)。
  - ドットキー: `a.a.....a = 1` は、キーが 32 個まで受理(根 + 31)、33 個で拒否。
  - インラインテーブル: `a = {a={a=1}}` は、`{` が 31 個まで受理、32 個で拒否。
  - 数千〜数十万段の入力は、異常終了せず失敗(`syntax`)で返る(配列・インラインテーブル・ドットキー・見出しの 1000 段、100,000 段で確認。理由の文が `入れ子が深すぎます(上限 32)` か `文法の誤りです` かは、読み取り器の再帰制限によるため未確認。種類は `syntax`)。

## 5. YAML の読み取り(`--to toml` のとき)

読み取りは、外部クレート `saphyr-parser`(0.3.4)のイベント列を、**再帰を使わず、明示のスタックで**読んで、展開しない素の木(アンカーとエイリアスの参照をそのまま持つ)にする。YAML 1.2 のコアスキーマで解釈する(第 5.2 節)。受理する文法の全範囲は、このクレートの仕様に従う。確認できた範囲では、次のものを受理する: ブロック形式とフロー形式のマップ・シーケンス、`|` と `>` のブロックスカラー、シングル・ダブルクォートの文字列(`\uXXXX`、`\xXX` のエスケープ)、複雑なキー(`? key`)、アンカー(`&`)・エイリアス(`*`)・マージキー(`<<`)、タグ、コメント、`%YAML` ディレクティブと `---` / `...`、UTF-8 の BOM、CRLF 改行。

### 5.1 読み取り時に見つける誤り(すべて `syntax`、行つき)

| 条件 | 理由(日本語の原文) | 行 |
|------|----------------------|----|
| YAML の文法の誤り(閉じていない `[`、不正なインデント、タブのインデント、`a: b: c` など) | `文法の誤りです` | パーサーの示す位置の行(1 始まり) |
| 同じマップに、同じキーが 2 回(リテラルで)ある | `キーが重複しています` | 2 つ目のキーの行 |
| 再帰するアンカー(自分自身を含む。`a: &r [*r]`) | `アンカーが自分自身を含んでいます` | エイリアスの行 |
| 定義されていないアンカーの参照(`a: *x`) | 下記の注 | パーサーの示す行 |
| 読み取り時の入れ子の深さが 32 を超える | `入れ子が深すぎます(上限 32)` | 33 段目を開く行 |

- 定義されていないアンカーの参照は、実行したところ `文法の誤りです` の `syntax`(パーサーが先に拒否する)になった。実装には、専用の理由 `定義されていないアンカーを参照しています` もあるが、通常の入力では到達しないと考えられる(未確認)。
- 行番号の例(実行で確認): `a: 1\nb: [1, 2\nc: 3\n` は 3 行目、`a: 1\nb: 2\na: 3\n`(重複)は 3 行目、`a: 1\n\tb: 2\n` は 1 行目、`a: &x 1\nb: *y\n` は 2 行目。
- キーの重複の判定は、**解決したあとの同一性**で行う。同じ文字列なら、引用符の有無が違っても重複(`a: 1` と `"a": 2`)。型が違うキー(整数 `1` と文字列 `"1"`)は重複ではない。入れ子のマップごとに別。エイリアスをキーにした場合は、参照先で判定する。
- 閉じたアンカーへの参照は、再帰ではない(`a: &r [1]\nb: *r` は受理)。
- 読み取り時の深さ: 開いているコレクションの数が 32 を超える(33 段目を開く)と拒否。最上位のマップが 1 段目。`a: ` に続けて `[` が 31 個までは受理、32 個で拒否。ブロックシーケンス(`- - - ...x`)は `- ` が 32 個まで受理、33 個で拒否。数千〜数十万段(フロー・ブロック・インデントの入れ子)でも、異常終了せず `syntax`。
- 展開前の深さの制限は、アンカーとエイリアスの参照を展開する前の構造に対するもの。エイリアスの入れ子による展開後の深さは、第 6 節。
- 複数の文書(`---` で区切る)は、文書の数を数える。最初の文書の木だけを残し、2 つ目以降も文法・重複・深さの誤りは検査する。

### 5.2 スカラーの解決(YAML 1.2 コアスキーマ)

引用符なしのスカラー(`plain`。引用符も `|`・`>` もない書き方)は、次の順に判定する。判定は、スカラーの文字列全体に対して行う。

| 順 | 条件 | 結果 |
|----|------|------|
| 1 | `` (空)、`~`、`null`、`Null`、`NULL` | null(表せない値) |
| 2 | `true`、`True`、`TRUE` / `false`、`False`、`FALSE` | 真偽値 |
| 3 | `.inf`、`.Inf`、`.INF`、`+.inf`、`+.Inf`、`+.INF` / `-.inf`、`-.Inf`、`-.INF` / `.nan`、`.NaN`、`.NAN` | 浮動小数(+∞、-∞、NaN) |
| 4 | `0x` + 1 桁以上の 16 進数字 | 整数(16 進) |
| 5 | `0o` + 1 桁以上の 8 進数字(0〜7) | 整数(8 進) |
| 6 | `[+-]?[0-9]+`(`007` は 7、`-0` は 0、`+7` は 7) | 整数(10 進) |
| 7 | 浮動小数の書式(下記) | 浮動小数 |
| 8 | 上のどれでもない | 文字列 |

- 整数は `i64` の範囲(-9,223,372,036,854,775,808〜9,223,372,036,854,775,807)。範囲を超える整数の書式(`9223372036854775808`、`0xFFFFFFFFFFFFFFFFFF`)は「数値が表せる範囲を超えている」(表せない値)。
- 浮動小数の書式: `[-+]? ( \.[0-9]+ | [0-9]+ (\.[0-9]*)? ) ([eE] [-+]? [0-9]+)?`(整数だけの書式は先に整数として扱う)。例: `1.5`、`-0.0`、`.5`、`1.`、`1e3`、`1.5E-2`。有限の `f64` に収まらないもの(`1e999`)は「数値が表せる範囲を超えている」。`.`、`e3`、`1e`、`1.2.3`、`-`、`+`、`.e1`、`inf`、`nan`、`NaN` は文字列。
- **`yes`・`no`・`on`・`off`・`y`・`n`(大文字小文字を問わず)は文字列**(YAML 1.1 の真偽値ではない)。`0b11`、`1_000`、`0x`(桁なし)、`0o8` は文字列。
- 引用符つき(`'...'`、`"..."`)のスカラーと、`|`・`>` のブロックスカラーは、常に文字列(`'1'` は文字列 `1`、`"null"` は文字列 `null`)。
- キーは、値と同じ規則で解決する。解決した結果が文字列のときだけ、文字列のキーになる(第 7 節)。

タグ:

| タグ | 扱い |
|------|------|
| なし | 上の規則 |
| `!!str` | 書き方によらず文字列(`!!str 1` は文字列 `1`、`!!str`(中身なし)は空文字列) |
| `!!int` | 解決した結果が整数(範囲外を含む)のときだけ、タグなしと同じ。引用符つき(`!!int '5'`)でも、中身を plain として解決する。合わなければ「タグつきの値は表せない」 |
| `!!float` | 解決した結果が浮動小数(範囲外を含む)または整数のときだけ受理。整数は浮動小数にする(`!!float 1` は 1.0)。合わなければ表せない |
| `!!bool` | 解決した結果が真偽値のときだけ受理 |
| `!!null` | 解決した結果が null のときだけ受理(null なので、結局、表せない値) |
| スカラーへの `!!map`、`!!seq`、`!!binary`、`!!set` など、そのほかの標準のタグ | 表せない |
| 独自のタグ(`!foo`) | 表せない |
| コレクションへのタグ | マップには `!!map`、シーケンスには `!!seq` だけ許す。それ以外(`!!set {x}`、`!!seq {x: 1}`、独自のタグ)は表せない |

### 5.3 文書の確認(RootCheck)

- 文書が 2 つ以上: `unrepresentable`、理由 `複数の文書は表せません`、行なし、場所なし。
- 文書が無い(空の入力、コメントだけ): `rootNotMap`、理由 `文書が空です`、行なし。
- 最初の文書の最上位が、マップでない(シーケンス、スカラー、`---` だけの文書など): `rootNotMap`、理由 `最上位がマップではありません`、行は最上位のノードの行(`---\n` だけの入力は 2 行目、`- 1\n- 2\n` は 1 行目)。
- 空のマップ(`{}`)は受理され、`{}` と `` (空)のあいだで変換できる(第 9 節)。

## 6. 展開と写し取り(Resolve)

素の木を、明示のスタックで(再帰を使わず)深さ優先・入力に現れる順に走査し、アンカー・エイリアス・マージキーを展開して、内部表現 `Value` にする。TOML の木も、同じ処理を通る(アンカーなどは無いので、要素数・大きさ・深さの検査と、表せない値の検出になる)。

内部表現 `Value`:

| 種類 | 内容 |
|------|------|
| `Str` | 文字列 |
| `Int` | `i64` |
| `Float` | `f64` |
| `Bool` | 真偽値 |
| `Array` | `Value` の並び |
| `Map` | (文字列のキー, `Value`) の並び |

内部表現の等価(往復の確認に使う): 型が違えば不等(`"1"` と 1、1 と 1.0、`true` と `"true"`)。浮動小数は、ビット表現が同じなら等しい(NaN どうしは等しい。`0.0` と `-0.0` は**異なる**)。マップは、キーの順序を無視して比べる。配列は順序を含めて比べる。

### 6.1 エイリアスの展開

- エイリアスは、参照先のノードの内容に置き換える(コレクションは複製して展開する)。エイリアスをキーにもできる(`k: &k name\n*k : 1` は `{"k": "name", "name": 1}`)。
- 展開でだけ生じるキーの重複(エイリアスのキーなど)は、`syntax`、理由 `キーが重複しています`、行は重複したキーの行。

### 6.2 マージキー(`<<`)

- マージキーとして扱うのは、**引用符なし・タグなし**のキー `<<` だけ。`"<<"`(引用符つき)は通常のキー。
- 値は、マップ、またはマップだけのシーケンス(`<<: [*a, *b]`)。それ以外(整数、文字列、null、マップでない要素を含むシーケンス)は、`unrepresentable`、理由 `マージキーの値がマップではありません`、場所は `<マップまでの経路>.<<`(例: `a.<<`)、行はマージキーの行。順 8 に属し、先にある null より先に返る。
- 優先順位: マップ自身のキーが、マージの内容より優先する(位置に関係なく。自身のキーが `<<` の前にあっても後にあっても同じ)。マージの値がシーケンスのときは、**先頭のマップが優先**。マージで加わるキーは、自身のキーのあと、マージの並びの順に追加される(結果のキー順は、最終の出力では意味を持たない。第 9 節)。
- マージ後の重複するキーは、エラーにならず、優先されなかった側が捨てられる。

### 6.3 展開の上限

| 上限 | 値 | 超過したときの失敗 |
|------|----|--------------------|
| 展開後の要素数 | 100,000 | `tooLarge`、理由 `展開後の要素数が上限(100000)を超えています` |
| 展開後の文字の大きさ | 16 MiB(16,777,216 バイト) | `tooLarge`、理由 `展開後の文字の大きさが上限(16 MiB)を超えています` |
| 展開後の入れ子の深さ | 32 | `syntax`、理由 `展開後の入れ子が深すぎます(上限 32)` |

- 要素数の数え方: 展開で訪れたノードを 1 つずつ数える。**キーのスカラーも数える**。コレクションも 1。エイリアスは、エイリアス自身ではなく、**展開した参照先のノードを数える**(同じアンカーを n 回参照すれば、n 回数える)。マージキー `<<` のキー自身も数える(1)。捨てられるマージの項目も数える。上限は 100,000 ちょうどまで受理、100,001 個目で失敗する。例: `a: [0,0,...]`(0 を n 個)は、根のマップ 1 + キー 1 + 配列 1 + 要素 n で、n = 99,997 まで受理、99,998 で失敗。TOML 入力にも同じ上限がある(`a = [0,0,...]` で同じ境界)。
- 文字の大きさの数え方: 訪れたスカラーの文字のバイト数(UTF-8)を足す。キーと値の両方。YAML のスカラーは、数値や真偽値の書式の文字も、書かれた文字のバイト数で数える(`123` は 3)。エイリアスの参照のたびに、参照先のスカラーの大きさを足す。マージキー `<<` は 2 バイト。TOML 入力では、文字列だけを数える(整数・浮動小数・真偽値・日時は 0)。**16 MiB ちょうどは受理**し、1 バイト超えると失敗。複製・確保の**前**に確認するので、予算を超えて確保する量は、高々スカラー 1 つ分。例: 「長さ n の文字列を 1 回アンカーにして 2 回参照する」入力で、`3n + 7`(キー 4 バイト + 数値 `123` の 3 バイト)が 16 MiB ちょうどなら受理、`123` を `1234` にして 1 バイト超えると `tooLarge`。
- 展開後の深さ: 根のマップが 1 段目で、開いているコレクションが 32 を超えると拒否(33 段目を開くとき)。アンカーの入れ子(`l0: &l0 [x]`、`l1: &l1 [*l0]`、...)で、読み取り時の深さは 2 でも、展開後は深くなる。`l30` までで 32 段(受理)、`l31` で 33 段(拒否)。失敗には、場所(キーの経路)がつく。
- 上限超過の失敗には、行(YAML の場合、そのノードの行)と場所(キーの経路)がつく。TOML 入力では行はない。
- 展開による爆発(アンカーの入れ子による指数的な増加、大きなスカラーの繰り返しの参照、マージキーを使った増幅)は、上の上限で止まる(30 秒以内に `tooLarge` で終わることを確認)。

## 7. 表せない値(`unrepresentable`)

展開の途中で見つけた「相手の形式で表せない値」のうち、**入力に現れる順で最初の 1 つ**だけを記録し、走査の終了後に返す(上限超過・マージキーの誤りなど順 8 の失敗は、これより優先する)。失敗の `reason` と、場所(キーの経路、行なし)は次のとおり。

| 値 | 理由(日本語の原文) | 入力の例 |
|----|----------------------|----------|
| null(`~`、`null`、`Null`、`NULL`、空の値) | `null は表せません` | `a: ~`、`a: null`、`a:` |
| タグつきの値 | `タグつきの値は表せません` | `a: !!binary aGk=`、`a: !mytag 1`、`a: !!set {x}`、`a: !!seq {x: 1}` |
| 範囲外の数値 | `数値が表せる範囲を超えています` | `a: 9223372036854775808`、`a: 1e999`、`a: [1, 99999999999999999999]` |
| 日時(TOML の日時・日付・時刻) | `日時の値は表せません` | `d = 1979-05-27T07:32:00Z`、`d = 1979-05-27`、`t = 07:32:00` |
| 文字列でないキー | `文字列でないキーは表せません` | `1: x`、`true: x`、`? [1, 2]\n: x`、`? ~\n: x` |

- 文字列でないキーの判定: キーのスカラーを解決した結果が文字列でないとき(整数、浮動小数、真偽値、null、タグつき、範囲外の数値)、およびキーがマップ・シーケンスのとき。キーの中の表せない値は、種類によらず `文字列でないキーは表せません` として記録する。
- YAML の日付(`a: 2001-01-01`)は、日時ではなく**文字列**(コアスキーマに日付の型がない)。
- 失敗の表示: `kind` は `unrepresentable`、行なし。**場所(`key_path`)**がつく。
- **場所の書式**: キーを `.` でつなぐ。配列の要素は `[添字]`(0 始まり。直前のキーに続けて、`.` なしで書く)。文字列でないキーは `(非文字列キー)`。キー名は、制御文字・書式文字をエスケープし(`\n`、`\r`、`\t`、その他は `\u{16進小文字}`)、64 文字(エスケープ後の文字数)を超えると、64 文字で切って `…` を付ける。例: `job[1].note`、`a.b`、`a.(非文字列キー)`、`a.<<`、`(非文字列キー)`(最上位のキー)。
- 入力に現れる順の例: `a: 1\njob:\n  - id: x\n  - id: y\n    note: ~\n  - z: ~\nlater: ~\n` は、最初の null の `job[1].note` を返す。`a: ~\nb: !!binary x\n` は `a`、`b: !!binary x\na: ~\n` は `b`。

## 8. 書き出し(Write)

### 8.1 共通

- 書き出しの前に、最上位は(必ず)マップになっている(YAML 入力は RootCheck、TOML 入力は根のテーブル)。
- **マップのキーの順序は、入力の順序を保たない**。TOML への書き出しは `toml` クレートの標準の `Table`(キーの辞書順に整列する)を経由し、TOML の読み取りも同じ型に写すため、**YAML・TOML のどちらへの出力も、各マップのキーが辞書順(文字列のバイト列の昇順)に並ぶ**。配列の順序は保たれる。コメントは捨てられる。
- 変換結果の最後は改行で終わる(最上位が空のマップで TOML のときは空文字列)。

### 8.2 TOML の書き出し(`--to toml`)

内部表現を `toml` クレートの値に写し、そのクレートの標準の書き出し(`toml::to_string`)で文字列にする。引用符の選び方、浮動小数の形、表と表の配列の分け方は、そのクレートに任せる。確認できた出力の特徴は次のとおり(実行して観測した。クレートの標準の整形のため、完全な再現には同じクレートの使用が必要)。

- 各テーブルでは、スカラーと、インラインにできる配列・値を先に、サブテーブルを後に書く。
- マップの配列(要素がすべてテーブル)は、`[[job]]` の表の配列で書く。空のマップは `[b]` の見出しだけ。要素に型が混ざる配列は、`e = [1, { x = 1 }]` のようにインラインで書く。
- 文字列は、基本文字列(`"..."`)、リテラル文字列(`'...'`、`"` を含み `\` を含まないとき。例: `command = 'transform "in dir" $HOME'`)、複数行文字列(`"""` ... `"""`、改行を含むとき)から、クレートが選ぶ。
- 整数は `i64` のまま。浮動小数は、`1.0`、`-0.0`、`nan`、`inf`、`-inf`、`0.1`、`1000000000000000000000.0`(`1e21` は指数にならない)のように、浮動小数と分かる形で書く。
- キーが、ベアキーに使えない文字(空文字列、`.`、非 ASCII など)を含むときは、引用符で囲む(`"a.b" = 1`、`"" = 2`、`"é" = 3`)。
- 日時は内部表現にない(第 7 節で失敗する)。
- 失敗: 内部表現を TOML に書き出せなかったとき、`unrepresentable`、理由 `変換後の形式として書き出せません`(通常は起こらない)。

### 8.3 YAML の書き出し(`--to yaml`)

自前の書き出し(ブロック形式の YAML)。

**レイアウト**

- 最上位のマップが空: `{}` + 改行。空でなければ、各エントリを書く。
- マップのエントリ: `<キー>: <値>`。値がスカラー、空の配列(`[]`)、空のマップ(`{}`)なら同じ行に書く。値がコレクションなら、`<キー>:` のあと改行し、子を**2 スペース深く**書く。
- シーケンスの要素: `- <値>`。要素がスカラー・`[]`・`{}` なら同じ行。要素がマップなら、最初のエントリを `- ` と同じ行に書き、残りのエントリを 2 スペース深く揃える。要素がシーケンスなら、`- - 1`(最初の要素を同じ行)の形。
- シーケンスは、親のキーより 2 スペース深く書く(`job:` の次の行に `  - id: a`)。
- インデントは 2 スペース。タブは使わない。

例(`tests/fixtures/pipeline.toml` を `--to yaml` で変換した実際の出力。キーは辞書順):

```yaml
format_version: 1
job:
  - command: extract --all --since yesterday
    id: extract
  - command: "transform \"in dir\" $HOME"
    id: transform
    success_exit_codes:
      - 0
      - 2
    transitions:
      - next: notify
        "on": warning
    warning_exit_codes:
      - 3
      - 4
  - command: load
    id: load
    transitions:
      - next: "@end"
        "on": success
  - command: notify --channel ops
    id: notify
pipeline:
  description: "夜間バッチ(抽出、変換、読み込み、通知)"
  name: nightly
```

**スカラー**

- 整数: 10 進。真偽値: `true` / `false`。
- 浮動小数: NaN は `.nan`、+∞ は `.inf`、-∞ は `-.inf`。それ以外は、Rust の `f64` の `Debug` 書式(往復で同じ値になる最短の表現。整数値でも `1.0` の形になり、整数と区別できる。`-0.0` も保つ)。絶対値が 1e16 以上、または 1e-4 未満(0 を除く)のときは指数形(`1e16`、`1e21`、`1e-5`、`1.5e-7`、`1.2345678901234568e17`、`5e-324`、`1.7976931348623157e308`)。`1e15` は `1000000000000000.0`、`0.0001` は `0.0001`。
- 文字列(値もキーも同じ規則): 次の条件を**すべて**満たすときだけ、引用符なし(plain)で書く。1 つでも外れたら、二重引用符で囲む。
  1. 空でない。
  2. 先頭が、ASCII の英字(`A-Za-z`)、`_`、`/` のどれか(数字・`-`・`.` などで始まるものは、数値や記号に読まれうるので引用符)。
  3. 末尾が空白でない。
  4. すべての文字が、ASCII の英数字、`_`、`-`、`.`、`/`、半角スペース のどれか。
  5. 半角スペースが 2 つ連続しない。
  6. YAML 1.1 の語(`y`、`Y`、`yes`、`Yes`、`YES`、`n`、`N`、`no`、`No`、`NO`、`on`、`On`、`ON`、`off`、`Off`、`OFF`)でない。
  7. コアスキーマで解決して文字列になる(`true`、`false`、`null`、`Null` 系などは引用符)。
  - plain になる例: `hello`、`echo hello world`、`/bin/run.sh`、`a-b_c.d`、`cargo build --release`、`inf`、`_x`、`a b`。引用符になる例: `yes`、`no`、`on`(キー `on` は `"on": warning`)、`off`、`true`、`null`、`~`、`1`、`-1`、`1.5`、`0x1F`、`` (空)、` lead`、`trail `、`<<`、`a: b`、`a #b`、`.nan`、`1e3`、`Yes`、`Y`、`@end`、`-a`、`x  y`、`a `、非 ASCII を含む文字列(`"夜間バッチ"`、`"é key"`)。
- 二重引用符の中のエスケープ: `"` → `\"`、`\` → `\\`、改行 → `\n`、復帰 → `\r`、タブ → `\t`。そのほかの制御文字(`char::is_control` が真: `U+0000`〜`U+001F`、`U+007F`〜`U+009F`)と `U+2028`、`U+2029`、`U+FEFF`、`U+FFFE`、`U+FFFF` は `\uXXXX`(16 進の大文字 4 桁)。その他の文字(非 ASCII、絵文字を含む)は、そのまま書く。例: `"a\u2028b \u007F é 😀"`。
- キー `<<` は、必ず引用符で囲む(マージキーとして読み戻されないように)。

## 9. 往復の保証

- 保証するのは、**木の等価**である。入力を読んだ内部表現と、変換結果を(変換後の形式として)読み戻した内部表現が、等しい(第 6 節の等価。マップのキーの順序は無視、配列の順序は有意)。さらに、変換結果を元の形式へ戻した結果の木も、元の木と等しい。
- 保証されないもの: コメント、マップのキーの記述順(出力は辞書順)、アンカー・エイリアス・マージキー(展開される。出力に `<<`・`*`・`&` は残らない)、引用符・文字列の書き方(plain と引用符の別、ブロックスカラーの形)、数値の書式(`0x1F` → `31`、`007` → `7`、`1e3` → `1000.0`)、YAML の `1_000` のような文字列の再解釈。
- 往復で保たれることが、テストで確認されている値: 文字列(`yes`、`no`、`on`、`off`、`1`、`1.5`、`null`、`~`、`true`、`false`、`<<`、空文字列、前後に空白がある文字列、`a: b`、改行・タブ・引用符・バックスラッシュ・制御文字・日本語・絵文字を含む文字列、長い文字列)、整数(`i64` の最小値・最大値、0)、浮動小数(`1.0`、`-0.0`、NaN、±∞、`1.5e-7`、`1e21`、`0.1`)、真偽値、空の配列・空のマップ、入れ子の配列(`[1, [2, [3, []]]]`)、配列の中のマップ、型が混在する配列、`on` キー、文字列の `command` と配列の `command`(空白・引用符・`$`・空の要素を含む配列)。
- 空のマップ: YAML `{}` → TOML は空文字列、TOML の空の入力 → YAML は `{}` + 改行。

## 10. エラーの構造と表示

| フィールド | 内容 |
|------------|------|
| `file` | 入力ファイルの表示用の名前。ライブラリ側の `Display` では、制御文字をエスケープし、256 文字までに切る。CLI の表示は、エスケープだけで切らない(08 章 9 章) |
| `line` | 行番号(1 始まり)。位置が分かるときだけ |
| `key_path` | 表せない値などの場所(キーの経路)。値そのものは含まない |
| `kind` | 種類 |
| `reason` | 固定の文(入力の値・ライブラリのエラー文は含まない) |

種類(6 種):

| 識別子 | 日本語(ライブラリの表示) | 英語(CLI の英語ロケール) |
|--------|----------------------------|----------------------------|
| `fileMissing` | 入力ファイルが存在しません | input file does not exist |
| `unreadable` | 入力ファイルを読めません | cannot read input file |
| `tooLarge` | 入力が大きすぎます | input is too large |
| `syntax` | 文法の誤りです | syntax error |
| `unrepresentable` | 相手の形式で表せない値があります | value cannot be represented in the target format |
| `rootNotMap` | 最上位がキーと値の集まり(マップ)ではありません | top level is not a map |

ライブラリの表示(`Display`):

```
<file>:<line>: <種類の文>: <reason>(場所: <key_path>)    行も場所もあるとき
<file>: <種類の文>: <reason>                              どちらも無いとき
```

`(場所: …)` は、`key_path` があるときだけ、末尾に付く(直前に区切りの空白はない)。

CLI の表示(`conductor convert` の失敗。標準エラーの 1 行、終了コード 67):

```
conductor: error: <file>[:<line>]: <種類の文(言語による)>: <reason> (<at|場所>: <key_path>)
```

`<reason>` は日本語のまま。`(at: …)` は英語ロケール、`(場所: …)` は日本語ロケール。`<file>`・`<reason>`・`<key_path>` は、制御文字・書式文字をエスケープして出す。実行例:

```
conductor: error: n.yaml: value cannot be represented in the target format: null は表せません (at: a)
conductor: error: x.yaml:3: syntax error: 文法の誤りです
conductor: error: x.yaml: top level is not a map: 文書が空です
conductor: error: m.yaml: value cannot be represented in the target format: 複数の文書は表せません
```

### 理由の一覧(日本語の原文。英語版はない)

| 理由 | 使われる種類 |
|------|--------------|
| `指定の場所にファイルがありません` | `fileMissing` |
| `読み取りの権限がありません` / `読み取りに失敗しました` / `通常のファイルではありません` / `UTF-8 として読めません` | `unreadable` |
| `入力が上限(1 MiB)を超えています` / `展開後の要素数が上限(100000)を超えています` / `展開後の文字の大きさが上限(16 MiB)を超えています` | `tooLarge` |
| `文法の誤りです` / `キーが重複しています` / `アンカーが自分自身を含んでいます` / `定義されていないアンカーを参照しています` / `入れ子が深すぎます(上限 32)` / `展開後の入れ子が深すぎます(上限 32)` | `syntax` |
| `複数の文書は表せません` / `null は表せません` / `文字列でないキーは表せません` / `タグつきの値は表せません` / `日時の値は表せません` / `数値が表せる範囲を超えています` / `マージキーの値がマップではありません` / `変換後の形式として書き出せません` | `unrepresentable` |
| `最上位がマップではありません` / `文書が空です` | `rootNotMap` |

## 12. 実装と README の差

README(`convert の使い方`)の記述と、実装の観測した振る舞いは、矛盾しない。実装の細部で、README にない点:

- README は「コメントと、マップのキーの記述順は、保持されません」と述べる。実装では、**出力のキーは、辞書順に整列される**(記述順の「保持されない」ではなく、整列)。
- README は「`null`・日時などの、相手の形式で表せない値は、失敗になります」と述べる。実装は、さらに、タグつきの値、`i64`・`f64` の範囲外の数値、文字列でないキー、複数の文書、マージキーの値がマップでないとき、も失敗にする。最上位がマップでない YAML は、`rootNotMap`(終了コード 67)。
- README は、展開の上限(要素数 100,000、展開後の文字の大きさ 16 MiB、深さ 32)に触れていない。実装は課す。入力は 1 MiB まで、という README の記述は、実装と一致する。
- README は、入力の形式を「`--to` の反対」と述べる。実装は、それに加えて、**TOML 1.1 の構文の一部を受理**する(読み取りクレートの仕様による)。
