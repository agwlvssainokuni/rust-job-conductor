# 03. 定義ファイルの書式と検証

この文書は、`conductor` の定義ファイルの書式と、読み込み時の検証を定める。この文書だけで、Python でゼロから、同じ受理・拒否・エラー(種類、文言、行番号)を返す読み込み処理を実装できることを目標とする。

- 定義ファイルの書式は **YAML(主)** と **JSON** の 2 つ。書式は**拡張子**で決める(第 2 節)。既定のファイル名は `conductor.yaml`。
- 検証は、見つけた誤りを**まとめて**返す。ただし、早い段階の誤り(取り込み、文法、展開と上限、版)は 1 件だけで打ち切る(第 2 節)。
- 定義の内容は、読み込みでは実行も評価もしない。`command` の文字列は、そのまま保持する。
- 確認できなかった点は「未確認」と書く。この文書の作成時に実際に動かして確かめた点は「確認」と書く。確かめた環境は第 7.6 節(CPython 3.10.7、3.14.10、3.15.2、PyYAML 6.0.3。いずれも macOS)。実装時には、実際に採用する版で、第 7.5 節の試験を再度行う。
- 「必須」と書いた挙動は、利用者から見える結果(受理/拒否、エラーの種類・文言・行番号、取り込み後の値)であり、同じにしなければならない。「任意」「実装に任せてよい」と書いた点は、利用者から見える結果が変わらない範囲で、実装が選んでよい。
- このツールの終了コード、エラー行の標準エラーへの出し方は [10. エラーと終了コード](10-errors-and-exit-codes.md)、メッセージの言語の選び方と標準出力・標準エラーの文字コードは [08. 出力と多言語対応](08-output-and-i18n.md) に従う。この文書は、エラーの内容(種類・位置・理由)までを定める。
- YAML と JSON の読み取り(第 4〜7 節)は、[09. 変換器](09-converter.md)と共有する。実装は、`src/conductor/definition/` の中に「木の読み取り」の部分(`tree.py`、`read_yaml.py`、`read_json.py`、`limits.py` など。ファイル名は任意)を置き、`src/conductor/convert/` はその公開関数を使う([02. アーキテクチャ](02-architecture.md))。
- 実装は、型ヒントを全面に付け、`mypy --strict` を通す。読み込み処理は、利用者の入力の誤りを**例外ではなく戻り値**(結果の型)で返す。例外は、実装の不具合(想定外の内部失敗)にだけ使う。ただし、ライブラリが投げる例外は、第 7.4 節のとおり、読み込み処理の内側で捕まえて `syntax` の戻り値にする。

## 1. 記法と用語

| 語 | 意味 |
|----|------|
| 文字 | Unicode のコードポイント(U+0000〜U+10FFFF)。Python の `str` の 1 要素。「N 文字」は、この単位で数える(`len(s)`。UTF-8 のバイト数でも、書記素でもない)。**入力から得た `str` は、対にならないサロゲート(U+D800〜U+DFFF)を含まない**(UTF-8 の復号が拒否し、エスケープで書かれたものも拒否する。第 3、5、7.4 節)。文字列のバイト数は `len(s.encode("utf-8"))` で数える(対にならないサロゲートがないので、`encode` は失敗しない)。 |
| 空白を取り除く(trim) | 文字列の先頭と末尾から、Unicode の White_Space 属性を持つ文字(U+0009〜U+000D、U+0020、U+0085、U+00A0、U+1680、U+2000〜U+200A、U+2028、U+2029、U+202F、U+205F、U+3000)を取り除く。「空白だけ」は、取り除いた結果が空文字列になること。**`str.strip()`・`str.isspace()` は使えない**(確認: どちらも、この列挙に無い U+001C〜U+001F を空白として扱う。全コードポイントで比べた結果、違いはこの 4 文字だけ)。この列挙を `frozenset[int]` で持ち、先頭と末尾から 1 文字ずつ調べる。実装時に、全コードポイントを使う単体テストで、この列挙と一致することを確かめる。 |
| 位置 | 値や構文要素の、入力中の場所。行(1 始まり)と列(1 始まり)の組。取り方は第 13 節。 |
| 行 | 行番号。1 始まり。**LF(U+000A)の数**で数える(CRLF でも同じ)。ライブラリが報告する行(U+0085、U+2028、U+2029、CR だけの改行も改行として数える)は**使わない**(第 13.1 節)。 |
| 値の型 | 木の値は、null、真偽値(bool)、整数(int)、範囲外の整数(hugeInt)、浮動小数(float)、文字列(string)、リスト(seq)、マップ(map。キーと値の対応)の 8 種のいずれか(第 6 節)。 |
| 範囲外の整数 | 64 ビット符号つき整数の範囲(-9,223,372,036,854,775,808〜9,223,372,036,854,775,807)に収まらない整数の書き方。木では種別 `hugeInt` で表し、値は持たない。エラーにはしない(使う側の検査が拒否する)。 |
| マップのリスト | 要素がすべてマップであるリスト(`job` や `transitions`)。 |
| 誤り | エラーの 1 件。種類(`kind`)、行(なしもある)、理由(`reason`)をもつ(第 12 節)。 |
| 受理 | その値や書き方を誤りなく読み込むこと。拒否はその逆。 |

**Python の `bool` と `int`**: Python の `bool` は `int` の部分クラスで、`isinstance(True, int)` は真(確認)。この文書の木は、真偽値(`BoolNode`)と整数(`IntNode`)を別の型で持つので、検査は「ノードの種別」で行い、`isinstance(value, int)` で整数かを判定しない。木を作る前の素の値(たとえば標準ライブラリの `json` が返す値)を検査する実装は、この規定を満たせない(第 5 節)。

## 2. 書式の決定と処理の段階

### 2.1 書式の決定(拡張子)

- 定義ファイルのパスの指定(`--config`)があれば、それを使う。なければ、カレントディレクトリの `conductor.yaml`。
- 書式は、パスの**拡張子**で決める。拡張子は、パスの最後の要素(最後のパス区切りより後ろ。区切りは `/`、`sys.platform` が `"win32"` のときは `\` も)の、最後の `.` から末尾まで。ASCII の大文字小文字を区別しない(`.YAML` は `.yaml`)。大文字小文字の畳み込みは、拡張子が `str.isascii()` を満たすときだけ `str.lower()` で行う(確認: `"K".lower()` は ASCII の `"k"` になる。非 ASCII を含む拡張子に `lower()` を使うと、別の文字が ASCII に化ける)。
- **`os.path.splitext` は使わない**(確認: `os.path.splitext(".yaml")` は `(".yaml", "")` を返し、拡張子なしと扱う。この仕様では、`.yaml` という名前のファイルの拡張子は `.yaml` であり、YAML として読む)。上の規則を自前で実装する。

| 拡張子 | 書式 |
|--------|------|
| `.yaml`、`.yml` | YAML |
| `.json` | JSON |
| それ以外(拡張子なしを含む。`.txt`、`.xml`、末尾が `.` のものなど) | 拒否: `unsupportedFormat`、行なし、理由 ``拡張子は .yaml、.yml、.json のいずれかで書きます`` |

- この判定は、ファイルに触れる前に行う(ファイルが存在しなくても、拡張子が合わなければ `unsupportedFormat` になる)。
- 表示用のファイル名は、パスを文字列にしたもの(`os.fspath` の結果。与えられた表記のまま。正規化しない)である。

### 2.2 処理の段階と打ち切り

`load(path, expected_pipeline_name)` は次の順に処理する。前の段階で失敗したら、そこで打ち切り、**その 1 件だけ**を返す(後ろの段階は実行しない)。最後の Walk だけが、複数の誤りを返す。

| 段階 | 内容 | 失敗の種類(`kind`) | 返る誤りの数 |
|------|------|----------------------|--------------|
| 1. Intake | 書式の決定、ファイルの読み取り | `unsupportedFormat` / `fileMissing` / `unreadable` / `tooLarge` | 1 |
| 2. Parse | 文法の検査(YAML はライブラリ、JSON は自前の読み取り)と、木の組み立て | `syntax` | 1 |
| 3. Resolve | 文書の数、タグ、キー、アンカーとエイリアスの展開、マージキー、重複キー、上限(要素数・文字の大きさ・入れ子の深さ) | `syntax` / `tooLarge` / `typeMismatch`(最上位がマップでない) | 1 |
| 4. VersionCheck | `format_version` | `versionMissing` / `versionUnsupported` | 1 |
| 5. Walk | 構造、型、遷移、終了コード、名前 | 第 12.3 節の種類のうち該当するもの | 1 件以上(位置の順) |

`parse(text, fmt, file_label, expected_pipeline_name)` は、段階 2〜5 を文字列に対して行う(ファイルに触れない)。`file_label` は、エラーの表示に使うファイル名である。

- `expected_pipeline_name`(`pipeline` コマンドで渡されたパイプライン名)が無い(`None`)ときは、名前の照合をしない。
- 検証に成功したときだけ、定義(第 14 節)を返す。誤りが 1 件でもあれば、定義は返さない。
- 版の確認(段階 4)に通らないと、構造の検査(段階 5)は一切行わない。たとえば `format_version` が無い定義に、未知のキーや型の誤りがあっても、返るのは `versionMissing` の 1 件だけである。
- 文法の誤り(段階 2)は版の確認より先である。
- **JSON の段階 2 は、入力を 1 回、先頭から読み、最初に見つかった問題(文法の誤り、重複キー)で打ち切る。** 入れ子の深さ・要素数・文字の大きさの上限は、段階 2 では確認しない(段階 3 で確認する。第 5.3 節)。
- **YAML の段階 2 は、入力の全体(全文書)を、文法の誤りが無いか最後まで読み終えてから、段階 3 の結果を返す。** したがって、YAML では、入力の後ろにある文法の誤りが、前にある段階 3 の誤り(タグ、重複キー、上限)より先に返る。実装は、読み取り(段階 2)と展開(段階 3)を 1 回の走査で行ってよい。そのとき、段階 3 の最初の誤りを覚えておき、以降は展開を止めて、文法の誤りの検出だけのために最後まで読み進め、読み取りの途中で文法の誤りが出たらそれを返し、出なければ覚えておいた誤りを返す(第 7.4 節 #5)。確認: `a: &x 1` + `---` + `b: [1` は、2 つ目の文書の文法の誤りが返る(4 行目)。
- 段階 3 は、木を、深さ優先・入力に現れる順に走査し、最初に見つかった問題で打ち切る。

## 3. 取り込み(Intake)

書式の決定(第 2.1 節)のあと、次の順に調べる。最初に当てはまったもので失敗する。

| 順 | 条件 | `kind` | 理由(日本語の原文) |
|----|------|--------|----------------------|
| 1 | ファイルの情報(種別・大きさ)の取得で「存在しない」 | `fileMissing` | `指定の場所にファイルがありません` |
| 2 | 同、権限がない | `unreadable` | `読み取りの権限がありません` |
| 3 | 同、その他の失敗 | `unreadable` | `読み取りに失敗しました` |
| 4 | 通常のファイルでない(ディレクトリなど) | `unreadable` | `通常のファイルではありません` |
| 5 | 取得した大きさが 1 MiB(1,048,576 バイト)を超える | `tooLarge` | `ファイルの大きさが上限(1 MiB)を超えています` |
| 6 | ファイルを開けない(権限) | `unreadable` | `読み取りの権限がありません` |
| 6' | ファイルを開けない(その他) | `unreadable` | `読み取りに失敗しました` |
| 7 | 読み取りの途中の失敗 | `unreadable` | 権限の問題なら `読み取りの権限がありません`、他は `読み取りに失敗しました` |
| 8 | 読み取った結果が上限を超える(順 5 のあとに大きくなった場合) | `tooLarge` | 順 5 と同じ |
| 9 | UTF-8 として解釈できない | `unreadable` | `文字コードが UTF-8 ではありません` |

実装(Python)の対応:

- 順 1〜5: `os.stat(path)`(シンボリックリンクはリンク先の情報で判定する。リンクを辿る)。失敗したとき、`FileNotFoundError` なら順 1、`PermissionError` なら順 2、それ以外(`NotADirectoryError`、リンクの循環、名前が長すぎる場合などの `OSError`。パスに NUL を含むときの `ValueError` を含む)は順 3。成功したら、`stat.S_ISREG(st.st_mode)` が偽なら順 4、`st.st_size` が 1,048,576 を超えれば順 5。確認(macOS): 存在しないパス、リンク先のないリンクは `FileNotFoundError`(errno 2)。権限のないディレクトリの下のファイルは `PermissionError`(13)。ファイルを「ディレクトリ」として辿るパスは `NotADirectoryError`(20)。自分自身を指すリンクは `OSError`(62)、長すぎる名前は `OSError`(63)。パスに NUL を含む `os.stat("a\0b")` は `ValueError`(`embedded null character in path`)。ディレクトリ、名前つきパイプは `S_ISREG` が偽。
- 順 6・7: `open(path, "rb")` で開き(失敗のときの分類は順 1〜3 と同じ。`FileNotFoundError` はここでは順 6' になる)、**上限 + 1 バイトまで**を読む(`read` が空を返すか、上限 + 1 バイトに達するまで繰り返す)。読み取りの失敗が `PermissionError` なら権限、他は失敗。`with` で必ず閉じる。**ファイル全体を一度に読む `read()` や `Path.read_bytes()` は使わない**(上限を超える巨大なファイルを、メモリに読み込まないため)。確認: モード 000 のファイルは、`os.stat` は成功し、`open` が `PermissionError`(13)になる(順 6)。
- 順 8: 読み取ったバイト数が 1,048,576 を超えていれば。
- 順 9: `data.decode("utf-8")`(厳格。`errors` の既定の `"strict"`)で復号し、`UnicodeDecodeError` なら順 9。**`"utf-8-sig"` は使わない**(先頭の BOM が黙って消え、位置と BOM の扱いが変わる)。**テキストモードで開く、`encoding=` を付けて読む、は使わない**(改行の変換で、CR だけの改行が LF になり、第 4.1 節の CR の規定が働かなくなる)。確認: `"utf-8"` で復号すると、先頭の BOM は U+FEFF の文字として残る。過長な符号化(`C0 80`)、サロゲートの符号化(`ED A0 80`)、範囲外(`F4 90 80 80`)、単独の `FF` は、いずれも `UnicodeDecodeError` になる。

- 上限は **1 MiB = 1,048,576 バイトちょうどまで受理**し、1 バイトでも超えると `tooLarge`。
- 空のファイル(0 バイト)は、空の文字列として読めて、次の段階へ進む。YAML では文書が 0 個の入力として扱われ、`versionMissing` になる(第 6.7 節)。JSON では文法の誤り(`syntax`)になる(第 5 節)。
- 順 5 の大きさの確認は UTF-8 の確認(順 9)より先なので、1 MiB を超えて UTF-8 でないファイルは `tooLarge` である。
- 先頭の BOM(バイト列 EF BB BF)は不正ではない(順 9 を通る)。この後の段階が、BOM を取り除く(第 4.1・5 節)。
- いずれも、行番号は付かない。
- OS による権限・種別の判定の細部(Windows での `OSError` の `errno` や `winerror` の値など)は、実装に任せてよい(Windows での値は未確認)。必須なのは、上の表の条件の順序と、各理由の文言である。

## 4. YAML の受理する部分集合

YAML は、YAML 1.2(改訂 1.2.2)の文法を基本として読み、スカラーの型は **コアスキーマ**(第 4.2 節)で決める。YAML 1.1 の型(`yes`/`no`/`on`/`off` の真偽値、`0777` の 8 進、日付、`<<` 以外の拡張など)は扱わない。

文法の細部(エスケープ、折りたたみ、インデントの規則など)は YAML 1.2.2 の規格に従い、読み取りライブラリがそれを実装する。ただし、採用するライブラリ(PyYAML。第 7 節)は、YAML 1.1 の流れをくむ読み取りで、**1.2 の文法と違う点がある**。**この文書が規格と別に決めること**は、次の 4.1 の表の「扱い」の列と、第 4.2〜4.6 節である。ライブラリがこれと違う結果を返すときは、この文書の規定が優先し、実装が補う(第 7 節)。この文書の規定が、ライブラリの制約のために規格より狭い点(タブ、アンカー名など)は、4.1 の表に「狭い」と明記する。

### 4.1 受理する部分集合と拒否するもの(一覧)

「確認」の列は、PyYAML 6.0.3(第 7 節の設定)で、ライブラリがその入力をどう扱ったかである。

| 項目 | 扱い | 備考(確認) |
|------|------|------|
| 入力の先頭の BOM(U+FEFF) | 受理(無視) | 実装が、ライブラリに渡す前に取り除く(位置にも数えない。第 13.1 節)。入力の途中の U+FEFF は、ライブラリが受理し、文字として残る(確認) |
| 改行 | LF、CRLF(混在可)を受理 | CRLF の行番号が LF の数と一致することを確認。**CR だけの改行は拒否**(`syntax`、行はその CR がある行)。確認: ライブラリは CR だけを改行として受理する。そのため、**実装が、ライブラリに渡す前に、CR の直後が LF でない CR を検出して拒否する** |
| U+0085(NEL)、U+2028、U+2029 | **拒否**(`syntax`、行はその文字がある行)。**狭い** | 確認: ライブラリはこれらを(YAML 1.1 のとおり)改行として扱う。`a: x` + U+0085 + `y` は文法の誤りに、引用符つきの値の中の U+2028 は受理されるが行の数え方が変わる。この文書は、これらを改行として扱わない(1.2 の規定)ので、実装が、ライブラリに渡す前に検出して拒否する。引用符つきの値の中に、これらの文字を入れたいときは、エスケープ(`" "`)で書く |
| 制御文字、非文字 | **拒否**(`syntax`、行はその文字がある行)。コメントの中も同じ | 確認: ライブラリは、U+0009、U+000A、U+000D、U+0020〜U+007E、U+0085、U+00A0〜U+D7FF、U+E000〜U+FFFD、U+10000〜U+10FFFF 以外の文字(U+0000〜U+0008、U+000B、U+000C、U+000E〜U+001F、U+007F〜U+0084、U+0086〜U+009F、U+FFFE、U+FFFF)を、読み取りの前に一括で拒否する(`ReaderError`)。文字としては、エスケープ(`"\x07"`)で書ける |
| インデント | 半角スペースだけ。タブをインデントに使うことは拒否(`syntax`) | 確認: ライブラリが拒否する。**狭い**: ライブラリは、タブを「区切り」に使う書き方も拒否する。拒否される例: `a:` + タブ + `1`、`-` + タブ + `b`、`a: 1` + タブ(値のあと、コメントの前も含む)、`[1,` + タブ + `2]`、`{b:` + タブ + `1}`、引用符なしのスカラーの途中のタブ(`a: x` + タブ + `y`)、タブだけの行、`---` の後ろのタブ。受理される例: 引用符つきのスカラーの中のタブ(行の継続のタブを含む)、`\|`・`>` のブロックスカラーの中身の中のタブ(インデントの後ろ)、コメントの中のタブ。この文書は、タブを含む入力を、テストに使わない。**拒否の確認だけ**を、実装の受け入れ試験に含める(第 7.5 節) |
| コメント(`#`) | 受理し、**捨てる**(値に影響しない)。`foo#bar` の `#` は、スカラーの一部 | 確認 |
| ブロックのマップ(`key: value`)、ブロックのリスト(`- item`) | 受理 | 親のキーと同じ桁の `- `(インデントなしのリスト)も受理(確認) |

| 引用符なしのスカラー(1 行、複数行) | 受理。型は第 4.2 節で決める | 先頭が `@` または `` ` `` のものは拒否(`syntax`)。確認: ライブラリが拒否する(`found character '@' that cannot start any token`) |

| 明示のキー(`? key` + `: value`) | キーがスカラーで、第 4.2 節の解決の結果が**文字列**なら受理。それ以外は拒否(第 4.4 節) | 確認(ライブラリはリストのキー `? [a]` も構文としては受理する。拒否は実装の仕事) |
| アンカー(`&name`)とエイリアス(`*name`) | **受理**。展開して扱う(第 4.3 節) | **狭い**: ライブラリは、名前を ASCII の英数字、`-`、`_` だけで読む。確認: `&名前` は文法の誤りになり、`&x:y` は、アンカー `x` と、内容 `:y` に分かれる。この文書は、名前を `[0-9A-Za-z_-]+` に限る(これ以外の名前は、ライブラリの結果のとおり `syntax` か、別の読み方になる。テストに使わない) |
| マージキー(`<<`) | **受理**(第 4.5 節) | |

| ディレクティブ | `%YAML 1.2`、`%YAML 1.1`、`%TAG`、未知の `%FOO` を、いずれも**ライブラリが受理する**(確認)。実装は、ディレクティブに独自の検査を足さない。`%YAML 2.0`(主版が 1 でないもの)は、ライブラリが拒否する(確認。`syntax`) | `%TAG` で定義した名前のタグは、タグとして拒否される |

### 4.2 スカラーの解決(コアスキーマ)

**引用符なしのスカラー**(引用符も `|`・`>` もない書き方)の型は、スカラーの文字列**全体**に対して、次の順に判定する。ライブラリの型の解決は使わない(構文要素の読み取り(`yaml.parse` に `yaml.BaseLoader` を渡す)は、スカラーに型を付けず、書かれた文字を文字列のまま返す。第 7.3 節)。実装が自前で判定する。

| 順 | 条件 | 結果の型 |
|----|------|----------|
| 1 | 空文字列、`~`、`null`、`Null`、`NULL` | null |
| 2 | `true`、`True`、`TRUE` / `false`、`False`、`FALSE` | 真偽値 |
| 3 | `.inf`、`.Inf`、`.INF`、`+.inf`、`+.Inf`、`+.INF` / `-.inf`、`-.Inf`、`-.INF` / `.nan`、`.NaN`、`.NAN` | 浮動小数(+∞、-∞、NaN) |
| 4 | `0x` + 1 桁以上の 16 進数字(`0-9a-fA-F`) | 整数(16 進。符号なし) |
| 5 | `0o` + 1 桁以上の 8 進数字(0〜7) | 整数(8 進。符号なし) |
| 6 | `[-+]?[0-9]+`(`007` は 7、`-0` は 0、`+7` は 7) | 整数(10 進) |
| 7 | `[-+]? ( \.[0-9]+ \| [0-9]+ (\.[0-9]*)? ) ([eE] [-+]? [0-9]+)?`(整数の書式は順 6 が先) | 浮動小数 |
| 8 | 上のどれでもない | 文字列 |

- **判定は、`re.fullmatch` で行う**。正規表現は、数字を `[0-9]` と書く(**`\d` は使わない**。確認: `str` に対する `\d` は全角数字 `"１"` にも一致する。`re.ASCII` を付ければ ASCII だけになる)。**`re.match` や `re.search` に `$` を付ける書き方は使わない**(確認: `$` は文字列の末尾の改行の直前にも一致し、`re.match(r"^[A-Za-z_]+$", "A\n")` は一致する。`re.fullmatch` は一致しない)。
- **整数は Python の `int` で値にする**(任意精度なので、桁あふれしない)。数字の列から、16 進は `int(数字, 16)`、8 進は `int(数字, 8)`、10 進は符号を除いた数字から `int(数字, 10)` で得る(符号は別に扱う)。**正規表現で形を確かめた文字列だけ**を `int()` に渡す(確認: `int()` は `"１２"`(全角)、`"1_0"`、`" 7 "` も受け付け、それぞれ 12、10、7 になる)。
  - 値が 64 ビット符号つき整数の範囲(-9,223,372,036,854,775,808〜9,223,372,036,854,775,807)に収まれば、種別 `int`。範囲を超える整数の書式(`9223372036854775808`、`0xFFFFFFFFFFFFFFFFFF`、`-9223372036854775809`)は、種別 `hugeInt`(値は持たない)にする(エラーにはしない。第 6 節)。使う側の検査(第 9 節)が、範囲外として拒否する(例: `format_version: 99999999999999999999` は `versionUnsupported`)。
  - **巨大な数字の列で、時間を使わず、`int()` の桁数の上限に当たらないために**(確認: CPython は、10 進の整数と文字列の変換を、既定で 4,300 桁までに制限する(`sys.get_int_max_str_digits()`)。超えると `ValueError`。3.10.7、3.14.10 で確認)、先頭の 0 を除いた数字の桁数が 24 を超えるものは、`int()` を呼ばずに `hugeInt` とする(10 進 19 桁、16 進 16 桁、8 進 22 桁を超えれば、必ず範囲外なので、結果は同じ)。24 桁以下なら `int()` で値を得て、範囲を比べる。`sys.set_int_max_str_digits` で上限を変えることはしない。
  - `-0` は整数 0。
- 浮動小数は、スカラーの文字列を **`float(文字列)`** で値にする(確認: `float("1.")`=1.0、`float(".5")`=0.5、`float("+.5")`=0.5、`float("1.e3")`=1000.0、`float("1e400")`=`inf`、`float("1e-400")`=0.0。例外は投げない)。**順 7 の書式に一致した文字列だけを渡すこと**(確認: `float()` は `"1_0"`(=10.0)、`" 1 "`、`"infinity"`、`"nan"`、全角数字も受け付ける)。結果が `inf` / `-inf` になる(`1e999`)ときは、値は ±∞ のまま、「範囲を超えた」という印(`overflow=True`)を付ける(エラーにはしない。変換器だけが、これを拒否する)。極小の値(`1e-400`)は、0.0 の浮動小数として受理する(エラーにしない)。
- 浮動小数の例: `1.5`、`-0.0`、`.5`、`1.`、`1e3`、`1.5E-2`。文字列になるもの: `.`、`e3`、`1e`、`1.2.3`、`-`、`+`、`.e1`、`inf`、`nan`、`NaN`、`0b11`、`1_000`、`0x`(桁なし)、`0o8`、`+0x1`、`0X1F`。
- **`yes`・`no`・`on`・`off`・`y`・`n`(大文字小文字を問わず)は文字列**。日付・時刻らしい書式(`2001-01-01`、`12:30:00`)も**文字列**。
- 引用符つき(`'...'`、`"..."`)のスカラーと、`|`・`>` のブロックスカラーは、常に文字列(`'1'` は文字列 `1`、`"null"` は文字列 `null`)。
- 空の値(`key:` の後ろに何もない、`- ` の後ろに何もない)は、引用符なしの空文字列と同じ扱いで、**null**(確認: ライブラリは、値が空文字列の、スタイルなしのスカラーとして返す。引用符つきの空文字列 `''` は、スタイルが引用符なので見分けられる)。アンカーだけで中身がない(`a: &x`)も null。フローのマップでキーだけを書いた `{a, b: 1}` と、明示のキーだけの `? a` の「値」も、ライブラリが空のスカラーを返す(確認)ので、**YAML の null として扱い、位置はそのキーの位置とする**。
- 定義ファイルの検査で、null は「どの型でもない値」である。`description:`(値なし)は `description` の型の誤り、`retry:`(値なし)は `retryNotTable`、`job:`(値なし)は `job` の型の誤り、未知のキーの値が null なら `unknownKey` になる(第 9 節)。

#### 書き方による型の違い(YAML で起きやすい誤り)

| 書き方 | 型 | 定義での結果の例 |
|--------|----|------------------|
| `format_version: 1` | 整数 | 受理 |
| `format_version: "1"` | 文字列 | `versionUnsupported`(整数でない) |
| `format_version: 1.0` | 浮動小数 | `versionUnsupported`(整数でない) |
| `format_version: 0x1`、`0o1`、`01`、`+1` | 整数(値 1) | 受理 |
| `format_version: 1_0` | 文字列 | `versionUnsupported`(整数でない) |
| `id: 1` | 整数 | `typeMismatch`(文字列で書く) |
| `id: yes`、`id: on` | 文字列 | 受理(YAML 1.1 の真偽値ではない) |
| `id: true` | 真偽値 | `typeMismatch` |
| `id: null`、`id: ~`、`id:` | null | `typeMismatch` |
| `interval: 30` | 整数 | `retryDurationInvalid`(文字列で書く) |
| `interval: 30s`、`interval: "30s"` | 文字列 | 受理 |
| `max: "3"`、`max: 3.0` | 文字列、浮動小数 | `retryMaxInvalid` |
| `remove_on_complete: yes` | 文字列 | `typeMismatch`(真偽値で書く) |

### 4.3 アンカーとエイリアス

- `&name` で付けたアンカーを、`*name` で参照できる。`name` は、`[0-9A-Za-z_-]` の 1 文字以上(ライブラリの規則。第 4.1 節)。
- エイリアスは、参照先のノードの内容に置き換わる(コレクションは複製して展開する)。展開後の木には、アンカーもエイリアスも残らない。
- 同じ名前のアンカーを再定義してよい。エイリアスは、それより前の**最後の**定義を指す(確認: `a: &x 1`、`b: &x 2`、`c: *x` で、`c` は 2)。**ライブラリの文書の組み立て(`yaml.compose` や、`yaml.load` 系)は、アンカーの再定義を拒否する**(`found duplicate anchor`)ので使わない。構文要素(イベント)の読み取りは、再定義を受理する(確認)。
- アンカーより前にあるエイリアス(`a: *x` + `b: &x 1`)、定義のないエイリアスは、拒否: `syntax`、理由 ``YAML の文法に誤りがあります``、行はそのエイリアスの行(確認: 構文要素は、参照先の有無を調べない。実装の名前の表に無い)。
- 閉じたアンカーへの参照は再帰ではない(`a: &r [1]` + `b: *r` は受理)。**自分自身を含むエイリアス**(`a: &r [*r]`)は拒否: `syntax`、理由 ``アンカーが自分自身を含んでいます``、行はそのエイリアスの行。判定は、**まだ閉じていない(終了の要素に達していない)アンカーつきコレクションの集合**を持ち、エイリアスの参照先がその集合に含まれるかで行う。実装の指針: アンカーの名前の表に、スカラーと閉じたコレクションは完成した木を、閉じていないコレクションは「開いている」印を登録する。展開した木は、アンカーもエイリアスも含まないので、閉じたものを辿るだけでは再帰しない。
- エイリアスをキーにしてよい(`*k : 1`)。参照先が、文字列に解決されるスカラーのときに限る(第 4.4 節)。
- **展開の上限**: 第 6.3 節(要素数 100,000、文字の大きさ 16 MiB、深さ 32)。アンカーの入れ子による爆発的な増加(`l0: &l0 [x, x]`、`l1: &l1 [*l0, *l0]`、…)は、この上限で止まらなければならない(必須)。上限を超えたら、複製・確保の**前**に打ち切る(展開は、参照先の木を、上限を数えながら辿り、数え終わってから複製する)。ライブラリの、値を Python のオブジェクトに組み立てる機能(`yaml.load`、`yaml.safe_load`、構成機能のオブジェクトの生成)は、**使わない**(展開を自前で数えるため)。
- 定義の中でアンカーを置ける場所は、定義に存在するノードの中だけである(根のキーは 3 つだけなので、例えば根に `defaults:` を足すと `unknownKey` になる)。典型的な使い方は、ジョブの中のキーの値(`success_exit_codes: &ok [0, 2]` を別のジョブで `*ok`)や、ジョブのマップ全体(`- &base` を、別のジョブが `<<: *base` で取り込む)である(第 16 節の例)。

### 4.4 キー

- マップのキーは、**文字列に解決されるスカラー**でなければならない。次は `syntax`、理由 ``キーは文字列で書きます``、行はそのキーの位置: 整数・真偽値・浮動小数・null に解決されるスカラー(`1: x`、`true: x`、`1.5: x`、`~: x`)、範囲外の整数、リストやマップのキー(`? [1, 2]`、`[a]: 1`、`{a: 1}: x`)。引用符つきは常に文字列なので受理(`"1": x`)。キーが空の `: x` は、ライブラリが拒否する(確認。`syntax`、理由は ``YAML の文法に誤りがあります``)。
- **重複したキー**は拒否: `syntax`、理由 ``キーが重複しています``、行は 2 つ目のキーの位置。判定は、解決した後の文字列の同一性(`str` の `==`。コードポイントの完全一致)で行う。**Unicode の正規化はしない**(`"é"` の合成済みの 1 文字と、`e` + 結合アクセントは別のキー)。引用符の有無が違っても重複(`a: 1` と `"a": 2`)。入れ子のマップごとに別。エイリアスをキーにしたときは、参照先の文字列で判定する。マージキー `<<`(第 4.5 節)を同じマップに 2 回書くことも重複。引用符つきの `"<<"`(通常のキー)と、引用符なしの `<<`(マージキー)は、**互いに重複としない**(この文書の決定。別の集合で数える)。
  - 重複の判定は、マップごとに `set[str]` を持って行う。ライブラリには重複キーの検査が無い(構文要素の読み取りは、キーを調べない)ので、**時間の問題は起きない**(確認: 10 万個のキーの入力で、読み取りと展開が約 2 秒)。
- キーの空文字列(`"": x`)は受理する。キーの大文字小文字・前後の空白は区別する。
- この検査は、入力に現れる順(深さ優先)に、段階 3 で行う。重複と非文字列のキーが同じ位置にあれば、どちらでも同じ `syntax` だが、理由は非文字列が先(キーの解決が先)。

### 4.5 マージキー(`<<`)

- マージキーとして扱うのは、**引用符なし・タグなし**のキー `<<` だけ(構文要素のスカラーの `style` が `None`(引用符なし)で、値が `<<`。タグは元々拒否される)。`"<<"`(引用符つき)は、文字列のキー `<<` として、通常のキーと同じに扱う。エイリアスを通して得たキー `<<` も、通常の文字列のキーとして扱う(この仕様の決定)。
- 値は、マップ、またはマップだけのリスト(`<<: [*a, *b]`)。それ以外(整数・文字列・null(`<<: ~` を含む)、マップでない要素を含むリスト)は拒否: `syntax`、理由 ``マージキーの値がマップではありません``、行はマージキーの位置。
- 優先順位: マップ自身の(`<<` でない)キーが、マージの内容より優先する(自身のキーが `<<` の前にあっても後にあっても同じ)。値がリストのときは、**先頭のマップが優先**。マージされるマップが `<<` を含むとき(入れ子のマージ)は、そのマージも同じ規則で先に展開した結果を使う。優先されずに捨てられたキーは、エラーにしない。
- **キーの順**: マージで加わるエントリは、そのマップの `<<` のエントリがあった位置に、取り込み元の順(リストなら先頭のマップから)で並ぶ。捨てられたものは並ばない。その後ろに、`<<` の後ろにある自身のエントリが続く。
- **位置**: マージで取り込まれたエントリ(キーと値と、その中のすべての子)の位置は、そのマージキー `<<` 自身の位置に置き換える(元の位置は使わない)。これは、エラーの行を決めるための規則である(第 13 節)。
- 実装の指針(任意): マップの走査では、`<<` のエントリは「場所取り」として並びに入れ、取り込み元の内容(値のノード)を覚えておく。そのマップの全エントリの走査が終わってから(自身のキーの集合が決まってから)、場所取りを、捨てられないエントリで置き換える。確認: `b: &b {x: 1}` + `a:` の下に `<<: [*b, {x: 2, y: 3}]` と `y: 9` で、`a` は `{x: 1, y: 9}`(`x` は `b` の値、`<<` の位置に並ぶ)。

### 4.6 複数の文書と最上位

- 文書の数を数える(`---` で区切る。構文要素の `DocumentStartEvent` の数。末尾の `---` の後ろが空でも、空の文書が 1 つあるものとして数える。`a: 1\n---\n` は 2 文書。確認)。文書が 2 つ以上ある入力は、読み取り全体(段階 2)が成功し、かつ最初の文書の走査(段階 3)で他の失敗が無かったときに限り、拒否: `syntax`、理由 ``複数の文書は書けません(1 ファイルに書ける文書は 1 つです)``、行は 2 つ目の文書の内容(根のノード)の位置の行(第 13.2 節。確認: `a: 1\n---\n\n\nb: 2\n` で 5 行目、`a: 1\n---\n` で 3 行目)。
  - 最初の文書の失敗(タグなど)は、2 つ目の文書の拒否より先に返る(入力に現れる順)。2 つ目以降の文書は、走査しない(要素数・大きさの加算に含めない)。ただし、文法の誤りの検出のために、最後まで読み進める(第 2.2 節)。
- 文書が 0 個(空の入力、コメントと空行だけ)は、**空のマップ**として扱う(結果は `versionMissing`。確認: 文書の開始の要素が 1 つも出ない)。
- 最初の文書の最上位が **null**(`---` だけの文書など、中身が空)も、空のマップとして扱う(確認: `---\n` の文書は、空のスカラーを内容として持つ)。
- 最上位が、マップでもなく null でもない(リスト、文字列、数など)なら、拒否: `typeMismatch`、理由 ``最上位はマップで書きます``、行は最上位のノードの位置。

## 5. JSON の受理する形式

JSON は、RFC 8259 の厳格な形式で読む。読み取りは**自前の小さな字句・構文解析**で行う(第 5.3 節)。**標準ライブラリの `json`(`json.loads`、`json.load`)は使わない**。理由(確認: CPython 3.14.10。差のあるものは 3.10.7 を併記):

| `json` の挙動 | 結果 | この仕様との関係 |
|----|------|------|
| 重複キー | 黙って後勝ち(`{"a":1,"a":2}` は `{"a": 2}`)。`object_pairs_hook` に、キーの組を受け取る関数を渡せば、重複を検出できる(確認: 例外を投げて中断できる) | この仕様は拒否する。**位置は、`object_pairs_hook` が受け取れない**(重複したキーの位置を返せない) |
| 位置 | 文法の誤り(`JSONDecodeError`)にだけ `lineno`・`colno`・`pos`(コードポイント単位)がある。構文の誤りの位置の規則は、この仕様(第 5.2 節)と一致するとは限らない(確認: 欠けたカンマの位置は、直前の空白を飛ばす前の位置になる)。値の位置は、どこからも得られない | 値・キーの位置が必要(第 13 節) |
| `NaN`、`Infinity`、`-Infinity` | 受理して `float` にする(`parse_constant` に例外を投げる関数を渡せば拒否できる) | 拒否が規定 |
| 数 | 整数は `int`、小数部・指数部があれば `float`(`parse_int`、`parse_float` で字句の文字列を受け取れる)。`1e400` は `inf` になる。整数は 4,300 桁を超えると `ValueError`(確認: 3.14.10 と 3.10.7 でメッセージの文が違う) | 範囲外の整数と、浮動小数の溢れを区別する(第 5.1 節) |
| `bool` と `int` | `true` は Python の `True`。`isinstance(True, int)` は真 | 第 1 節 |
| 対にならないサロゲート | `"\ud800"` を受理して、単独のサロゲートを含む `str` を返す | 拒否が規定(出力が正しい UTF-8 にならないため) |
| 深い入れ子 | `[` を 10 万個並べると、3.14.10 は `JSONDecodeError`、3.10.7 は `RecursionError` | 深さの上限の前に、再帰で落ちない(第 6.4 節) |
| BOM | 文字列の先頭の U+FEFF は `JSONDecodeError`(`Unexpected UTF-8 BOM`) | BOM は無視が規定 |
| `__proto__` などのキー | 通常の文字列のキー(`{"__proto__": 1}`)。問題なし | 同じ |
| 空白 | `" \t\n\r"` だけ(垂直タブは `JSONDecodeError`) | 同じ |

したがって、`json` を `object_pairs_hook`、`parse_int`、`parse_float`、`parse_constant` で飾っても、位置が得られない。**自前で読む**(第 5.3 節)。

| 項目 | 規定 |
|------|------|
| 入力 | UTF-8 で復号済みの文字列(第 3 節)。先頭の BOM(U+FEFF)は無視する(位置には数えない。第 13.1 節)。 |
| 空白 | 半角スペース、タブ、LF、CR だけ。それ以外(垂直タブ、全角スペースなど)を、トークンの間に置くことは拒否。 |
| コメント(`//`、`/* */`、`#`) | **拒否**(`syntax`)。 |
| 末尾のカンマ(`[1,]`、`{"a":1,}`)、連続したカンマ、先頭のカンマ | **拒否**(`syntax`)。 |
| リテラル | `true`、`false`、`null`(小文字だけ)。`True`、`NaN`、`Infinity`、`undefined` は拒否。 |
| 文字列 | `"..."` だけ(単一引用符は拒否)。中にタブを含め、U+0000〜U+001F を直接書くことは拒否(`\t` などで書く)。U+007F 以上は直接書いてよい。エスケープは `\"`、`\\`、`\/`、`\b`、`\f`、`\n`、`\r`、`\t`、`\uXXXX`(16 進 4 桁。大文字小文字どちらでも)。それ以外のエスケープは拒否。`\u` でサロゲートの前半(U+D800〜U+DBFF)に、後半(U+DC00〜U+DFFF)の `\u` が続く対は 1 つの文字(`chr(0x10000 + ((前 - 0xD800) << 10) + (後 - 0xDC00))`)にする。**対にならないサロゲート**(単独の前半、単独の後半)は拒否(`syntax`)。 |
| 数 | `-?(0\|[1-9][0-9]*)(\.[0-9]+)?([eE][+-]?[0-9]+)?` だけ。`+1`、`01`、`.5`、`5.`、`1e`、`0x10`、`1_000` は拒否。 |
| キー | 文字列だけ。 |
| 重複したキー | **拒否**(`syntax`、理由 ``キーが重複しています``、行は 2 つ目のキーの位置)。判定は、エスケープを解いた後の文字列の完全一致(`"a"` と `"a"` は重複)。 |
| 最上位 | 任意の JSON の値を、文法としては受理する。最上位がオブジェクト(マップ)でなければ、第 6.7 節のとおり `typeMismatch`。JSON の `null` も(YAML と違い)マップではないので `typeMismatch`。 |
| 空の入力、空白だけの入力 | 拒否(`syntax`)。 |
| 最上位の値の後ろ | 空白以外が続くことは拒否(`syntax`。複数の値、`{}{}`、後ろのゴミ)。 |

### 5.1 数の型

- 整数: `-?(0|[1-9][0-9]*)` だけ(小数部も指数部もない書き方)。`-0` は整数 0。値は**数字の列から `int()` で**得る。64 ビット符号つき整数の範囲を超えるものは `hugeInt`(YAML と同じ。エラーにはしない)。桁数が 19 を超える(符号と先頭の 0 を除く。JSON は先頭の 0 を持たないので、`0` 以外の先頭は 1〜9)ものは、`int()` を呼ばずに `hugeInt`、19 桁以下は `int()` で得て範囲を比べる(4,300 桁の制限に当たらないため。第 4.2 節)。
- 浮動小数: 小数部または指数部を持つもの(`1.0`、`1e3`、`1E3`、`1e0`、`-0.0`)。値は `float(字句)` で得る。結果が ±`inf`(`1e400`)のものは、`overflow=True` の印を付ける(エラーにはしない)。極小(`1e-400`)は 0.0(エラーにしない)。
- **整数だけの項目**(`format_version`、`max`、`multiplier`、各種の終了コード)に、浮動小数が来たら、型の誤りとして拒否する。**`1.0`、`1e0`、`10e-1` のように値が整数になる書き方でも拒否**(YAML の `1.0` も同じ)。実装は、ノードの種別(`IntNode` か `FloatNode` か)で判定する。`float.is_integer()` や `value == int(value)` で整数と見なさない。
- JSON の数のうち、値を使う検査の対象外の場所にある浮動小数や範囲外の整数は、エラーにならない(そのキーが `unknownKey` になるだけ)。

### 5.2 JSON の誤りの位置

文法の誤りの位置は、**入力の先頭から読んでいって、読み進められなくなった最初の文字**(その前までが、有効な JSON の先頭部分になっているもの)の位置。入力が途中で終わったとき(閉じていない配列・文字列など)は、入力の末尾の位置(末尾が改行なら、その次の空の行を 1 行と数える)。例(確認: 自前の読み取りの試作で):

| 入力(`\n` は改行) | 誤りの位置 |
|------|------------|
| `{"a": 1,}` | `}` の位置(1 行目) |
| `{"a" 1}` | `1` の位置 |
| `{\n  "a": 1\n  "b": 2\n}` | `"b"` の位置(3 行目) |
| `[1, 2` + 末尾の改行 | 末尾(2 行目) |
| `{"a": "x` + 改行 + `"}` | 改行の位置(1 行目。文字列の中に改行を直接書いたため) |
| `{"a":1}{"b":2}` | 2 つ目の `{` の位置 |
| `{"a":1,"a":2}`(重複) | 2 つ目の `"a"` の位置(1 行目) |

文字列の中の誤り(不正なエスケープ、対にならないサロゲート、直接書いた制御文字)の行は、その文字列の行(文字列は改行を含められないので、どの文字でも同じ行)。

### 5.3 JSON の読み取りの規定(自前の字句・構文解析)

読み取りの関数: `read_json`(第 14.2 節。成功なら木、失敗なら 1 件の誤り)。ステートの読み込みも、同じ関数を `defer_duplicate_key=True` で呼ぶ(重複を見つけても止めず、後ろの文法の誤りを優先する。[06. ステートファイル](06-state-file.md))。実装の詳細は任せるが、次は**必須**である。

1. **入力を、先頭から 1 回だけ読む**。文字(`str` の添字、つまりコードポイント)の添字を進め、位置(行、列)を、改行(LF)の数と、行の先頭の添字から求める(第 13.1 節)。
2. **入れ子は、明示のスタック(`list`)で読む**(関数の再帰で読まない)。この段階では、入れ子の深さの上限を**適用しない**(段階 3 が適用する)。これは、深い入れ子の後ろに文法の誤りがあるとき、文法の誤りが先に返る(段階 2 が先)ことを守るためである。スタックの大きさは、入力の大きさ(1 MiB)で抑えられる。確認: `[` を 1,048,576 個並べた入力が、約 1.7 秒で、末尾の位置の文法の誤りとして返る(試作)。
3. **整数の字句**: 第 5 節の「数」の文法に従って、字句を先頭から読む(`re.compile(...).match(text, 位置)` で、`[0-9]` だけを使う正規表現で読んでよい)。読んだ字句に、小数部・指数部が無ければ整数、有れば浮動小数とする(第 5.1 節)。字句の直後の文字が、区切り(空白、`,`、`]`、`}`、入力の末尾)でなければ、その文字の位置で文法の誤り(`01` は 2 文字目の `1`、`1.` は `.` の次、`1e` は `e` の次、`+1` は `+`、`.5` は `.`、`0x10` は `x`)。
4. **リテラル**: `true`、`false`、`null` は、文字ごとに照合し、最初に合わない文字(または入力の末尾)の位置で文法の誤り。リテラルの直後が区切りでなければ、その文字の位置で文法の誤り。
5. **文字列**: 開きの `"` から読む。U+0000〜U+001F の文字、改行、入力の末尾は、その位置で文法の誤り。エスケープは第 5 節の表のとおり。`\u` の 4 桁が 16 進でなければ文法の誤り(`str.isalnum` などでなく、`[0-9a-fA-F]{4}` の正規表現で確かめる)。サロゲートの前半の `\uD800`〜`\uDBFF` の直後が、`\uDC00`〜`\uDFFF` の `\u` でなければ、文法の誤り(位置はそのエスケープの `\` の位置)。後半が単独で現れたときも同じ。読んだ文字列は、エスケープを解いた `str`(対のサロゲートは 1 つのコードポイント)として得る。
6. **オブジェクト**: `{` の後ろは、空白を飛ばして `}`(空のオブジェクト)か文字列(キー)。キーの文字列を読み終えた**時点で**、重複を調べる(そのオブジェクトの `set[str]` に、エスケープを解いたキーが既にあれば、**そのキーの開きの `"` の位置で**重複のエラー。`:` 以降は読まない。この仕様の決定)。次に `:`、値、そして `,`(次のキー)か `}`。
7. **配列**: `[` の後ろは、空白を飛ばして `]`(空の配列)か値。値の後ろは `,`(次の値)か `]`。`,` の直後に `]` が来ること(末尾のカンマ)は、`]` の位置で文法の誤り。
8. **最上位**: 空白を飛ばして値を 1 つ読み、空白を飛ばして入力の末尾に達しなければ、その位置で文法の誤り。入力が空(空白だけを含む)なら、入力の末尾の位置で文法の誤り。
9. 木のノードの位置は、第 13.2 節(オブジェクトは `{`、配列は `[`、スカラーは字句の先頭、キーの位置は開きの `"`)。
10. 木は、`tuple[MapEntry, ...]`(第 6.1 節の `entries`。キーを `str` で持つ並び)として作る。`dict` に入れて重複を落とすことをしない(重複は拒否するので、結果は同じだが、キーの順序と、重複の検出の時点を、この規定のとおりにするため)。

文法の誤りの理由は `JSON の文法に誤りがあります`、重複は `キーが重複しています`(いずれも `syntax`)。

## 6. 木への展開(Resolve)と上限

### 6.1 木の型

段階 3 の結果と、段階 4・5 の入力は、YAML と JSON に共通の木である。型の骨格(例。名前は実装が決めてよい。判別共用体で、種別 `kind` を判別に使う。`dataclass(frozen=True, slots=True)` と `Literal`)。この節、第 12.1 節、第 14.1 節、第 14.2 節、第 14.2 節の検査の関数、および [09. 変換器](09-converter.md)の型のコードブロックを、1 つのファイルに連ね(本体の無い関数には `raise NotImplementedError` を補い、「実装が決める」と書いた型(`PipelineParts` など)は `Any` に置いて)、`mypy --strict`(mypy 2.4.1)で検査し、エラーが無いこと、`typing.get_args(ErrorKind)` で種類が 31 個得られること、CPython 3.10.7、3.14.10、3.15.2 で読み込めることを確認した。木の種別について、`match` 文が全種別を尽くして型が通ることも、別に確認した。

```python
from __future__ import annotations

from dataclasses import dataclass
from typing import Literal, TypeAlias


@dataclass(frozen=True, slots=True)
class Pos:
    """入力中の位置(1 始まり)。順序づけと行の表示に使う。"""
    line: int
    column: int


@dataclass(frozen=True, slots=True)
class NullNode:
    pos: Pos
    kind: Literal["null"] = "null"


@dataclass(frozen=True, slots=True)
class BoolNode:
    pos: Pos
    value: bool
    kind: Literal["bool"] = "bool"


@dataclass(frozen=True, slots=True)
class IntNode:
    """64 ビット符号つき整数に収まる整数。値は Python の int。"""
    pos: Pos
    value: int
    kind: Literal["int"] = "int"


@dataclass(frozen=True, slots=True)
class HugeIntNode:
    """64 ビット符号つき整数の範囲を超える整数。値は持たない。"""
    pos: Pos
    kind: Literal["hugeInt"] = "hugeInt"


@dataclass(frozen=True, slots=True)
class FloatNode:
    pos: Pos
    value: float  # nan、±inf を含みうる
    overflow: bool = False  # 範囲を超えた書き方(1e999 など)のとき True
    kind: Literal["float"] = "float"


@dataclass(frozen=True, slots=True)
class StringNode:
    pos: Pos
    value: str
    kind: Literal["string"] = "string"


@dataclass(frozen=True, slots=True)
class SeqNode:
    pos: Pos
    items: tuple[TreeNode, ...]
    kind: Literal["seq"] = "seq"


@dataclass(frozen=True, slots=True)
class MapEntry:
    key: str
    key_pos: Pos
    value: TreeNode


@dataclass(frozen=True, slots=True)
class MapNode:
    pos: Pos
    entries: tuple[MapEntry, ...]  # 順序つき。キーは重複しない
    kind: Literal["map"] = "map"


TreeNode: TypeAlias = (
    NullNode | BoolNode | IntNode | HugeIntNode | FloatNode | StringNode | SeqNode | MapNode
)
```

- 木は、エイリアスもアンカーもマージキーも含まない(展開済み)。マップのキーは `str` で重複せず、**記述順**を保つ(第 4.5 節のマージの順を含む)。
- マップを `dict` で持たない(位置つきのエントリを順序どおりに持つため)。`entries` の `tuple` で持つ。キーの検索が要る検査では、`dict[str, MapEntry]` を一時的に作る(Python の `dict` は挿入順を保つ。確認)。「許されたキーか」の判定には、`frozenset[str]` を使う。
- **`IntNode.value` は `int`、`BoolNode.value` は `bool`** で、検査は種別で行う(第 1 節)。`FloatNode` の `value` の等価の判定は、`nan` が自分自身と等しくない(`float("nan") != float("nan")`)ことと、`0.0 == -0.0` が真であることに注意する(第 9 節の変換器の木の等価は、ビット表現で比べる)。
- 木を走査する処理(段階 3 の走査、深さの数え、検査 Walk、変換器の書き出し)は、**関数の再帰を使わず、明示のスタック**で行うことが望ましい。必須なのは、深い入力でも、`RecursionError`(`sys.getrecursionlimit()` の既定は 1,000。確認)などで異常終了せず、定められた誤りで返ること(第 6.4 節)。`sys.setrecursionlimit` を上げて対処しない。

### 6.2 YAML の展開の手順(段階 3)

ライブラリが返した、最初の文書の構文要素(イベント)の列を、入力に現れる順に走査し、上の木に写す(明示のスタックで、木を組み立てる)。各ノードについて、次を行う(ここで「ノードの位置」は、第 13.2 節の位置)。

1. エイリアスなら、参照先を(第 4.3 節の、定義の有無と再帰の確認のうえで)展開する。展開したノードとその子の位置は、**エイリアスのトークン `*name` の位置**に置き換える(第 13 節)。
2. 明示のタグがあれば、`syntax`(タグ)で打ち切る。
3. スカラーなら、第 4.2 節で型を決める(キーの位置のスカラーは、文字列でなければ `syntax`(第 4.4 節))。
4. マップなら、第 4.4・4.5 節のとおり、キーの確認、重複の確認、マージの展開を行う。
5. 第 6.3 節の上限を、ノードを訪れるごとに加算して確認する。確認の順は、深さ、要素数、文字の大きさ(同じノードで複数が超えるとき、先のものを返す。この仕様の決定)。

複数の文書のときは、最初の文書だけを走査し、走査で失敗が無かったとき、第 4.6 節の失敗を返す。

### 6.3 上限

| 上限 | 値 | 超過したときの失敗 |
|------|----|--------------------|
| 要素数 | 100,000 | `tooLarge`、理由 ``要素数が上限(100000)を超えています`` |
| 文字の大きさ | 16 MiB(16,777,216 バイト) | `tooLarge`、理由 ``文字の大きさが上限(16 MiB)を超えています`` |
| 入れ子の深さ | 32 | `syntax`、理由 ``入れ子が深すぎます(上限は 32 段)`` |

- **要素数の数え方**: 展開で訪れたノードを 1 つずつ数える。**キーのスカラーも数える**。マップ・リストも 1。根のマップも 1。エイリアスは、エイリアス自身ではなく、**展開した参照先のノード(コレクションなら、その全部)を数える**(同じアンカーを n 回参照すれば、n 回数える)。マージキー `<<` のキー自身も 1 と数え、マージで取り込まれるマップの中身も、捨てられるものを含めて数える(マージキーの値として、通常の値と同じに走査されるため)。**100,000 ちょうどまで受理**し、100,001 個目で失敗する。JSON にも同じ上限がある(展開はないが、数え方は同じ)。例: `a: [0, 0, ...]`(0 を n 個)は、根のマップ 1 + キー 1 + リスト 1 + 要素 n で、n = 99,997 まで受理、99,998 で失敗(JSON の `{"a":[0,0,...]}` も同じ境界)。確認(試作): YAML、JSON とも、n = 99,997 は受理、99,998 は `tooLarge`。
- **文字の大きさの数え方**: 訪れたスカラーの文字のバイト数(UTF-8)を足す。キーと値の両方。文字列(引用符つき、ブロックスカラーを含む)は、**値(エスケープを解いたもの)のバイト数**(`len(値.encode("utf-8"))`)。引用符なしのスカラー(数、真偽値、null を含む)と、JSON の数・真偽値・null は、**書かれた文字のバイト数**(`123` は 3、`0x1F` は 4、`null` は 4、`true` は 4。値が空の null は 0)。YAML の引用符なしのスカラーの書かれた文字は、入力の文字列の、スカラーの開始(アンカーを前置していれば、その後ろ。第 13.2 節)から、構文要素の `end_mark.index` までの部分文字列である。複数行にまたがるときは、途中の改行とインデントを含む。この点の境界は、実用上差が出る入力が 16 MiB 付近の複数行スカラーに限られる。エイリアスの参照のたびに、参照先のスカラーの大きさを足す。マージキー `<<` は 2 バイト。**16 MiB ちょうどは受理**し、1 バイト超えると失敗する。複製・確保の**前**に確認すること(巨大な展開でメモリを使い果たさないために必要)。なお、ファイルの大きさの上限(1 MiB)により、展開のない入力が 16 MiB に達することはない。この上限が働くのは、アンカーとエイリアスで展開が増える場合だけである。確認(試作): 10,000 バイトの文字列を 1,700 回参照する入力は、`tooLarge`(文字の大きさ)。
- **入れ子の深さの数え方**: テーブルに当たるもの、つまりマップとリストは、それぞれ**1 段**と数える。スカラーは数えない。**根のマップそのものは数えない**。根の直下のコレクションの深さを 1 とし、その子のコレクションは 2、…と数える。**32 段まで受理**し、**33 段目を拒否する**。数えるのは、**展開後の木**(アンカーの入れ子による深さを含む)に対して。失敗の行は、33 段目になったコレクションの位置(第 13 節)。YAML のフロー形式でもブロック形式でも同じに数える。
  - 例: `a: [[[...]]]`(`[` が n 個)は n 段。32 個は受理、33 個は拒否。JSON の `{"a": [[[...]]]}` も同じ。`a: {b: {b: ... 1}}` も、`{` の数が 32 まで受理、33 で拒否。
  - 例: ブロックのリスト `- - - ... x`(`- ` が n 個)は、根がリストでなくマップの値として置くなら n 段(`a:` の次の行から置く)。
  - 例: アンカーの入れ子 `l0: &l0 [x]`、`l1: &l1 [*l0]`、… の `l(k)` は、展開後に k + 1 段になる。`l31` まで(32 段)は受理、`l32`(33 段)は拒否(これらのキーが、`unknownKey` でない場所に置かれているときの話。深さの検査は Walk より先に行うので、根のキーの種類は関係ない)。確認(試作): 上の例は、いずれも書いたとおり。
- 上限超過の失敗は、いずれも段階 3 の 1 件の打ち切り(`tooLarge`/`syntax`)で、複数は返さない。同じ入力に複数の上限の超過があれば、入力に現れる順で最初のもの。
- どの上限にも、**30 秒以内に**(巨大な展開でも)到達して終わること(必須)。第 7.4 節の対策を含めて、実装時に、第 7.5 節の敵対的な入力で測る。確認(試作。CPython 3.14.10、PyYAML 6.0.3、macOS): 第 7.5 節の敵対的な入力は、いずれも約 5 秒以内に終わった(一覧は第 7.5 節)。

### 6.4 深い入力と異常終了の禁止

- 数千〜数十万段の入れ子の入力(フロー形式の `[[[[...`、ブロックのリストの `- - - ...`、深いインデントの入れ子)でも、プロセスが異常終了せず、`syntax` の 1 件で返らなければならない(必須)。理由が ``入れ子が深すぎます(上限は 32 段)`` か ``YAML の文法に誤りがあります`` かは、実装に任せてよい。
- JSON は自前の読み取りなので、明示のスタックで読む(第 5.3 節)。
- YAML は、構文要素の読み取り(`yaml.parse`)が、関数の再帰を使わない(確認: 1 MiB の `- ` の連続(524,288 個の入れ子)が、`RecursionError` なしで読めた)。しかし、**フロー形式の入れ子が深いと、字句の読み取りが、入れ子の深さに応じて極端に遅くなる**(確認: `[` を n 個並べた入力は、n = 1,000 で 0.06 秒、2,000 で約 1.0 秒、4,000 で約 3 秒、8,000 で約 6.7 秒、16,000 で約 14.5 秒。1 MiB(1,048,576 個)の入力は、120 秒待っても終わらなかったので、30 秒の上限を守れない)。そこで、**読み取りの途中の入れ子の深さ(開いているコレクションの数。構文要素の開始で +1、終了で -1)が 1,000 を超えた時点で、読み取りを打ち切り、`syntax`(理由 ``入れ子が深すぎます(上限は 32 段)``、行は 1,001 段目のコレクションの位置の行)にする**(この文書の決定)。ただし、それ以前に段階 3 の深さの失敗(33 段目)が記録されていれば、それを返す(第 2.2 節の、最初の誤りを覚えておく手順)。この打ち切りは、33〜1,000 段の入力には影響しない(それらは、最後まで読み、後ろの文法の誤りを優先する)。1,001 段以上の入力は、後ろに文法の誤りがあっても、深さの失敗を返す(この点が、JSON の規定(深さが後。第 5.3 節)と違う)。確認(試作): `[` を 1,048,576 個並べた入力は約 1.1 秒で、`- ` を並べた入力と `{a: ` を並べた入力は約 0.05 秒で、深さの失敗になった。
  - 1,000 段までの入れ子の上で、トークンを大量に並べた最悪の入力(`[` を 999 個、その後ろに `a,` を 52 万個)は、約 5 秒かかった(確認)。
- ライブラリの呼び出しは、`yaml.YAMLError`、`ValueError`(範囲外のエスケープ)、`RecursionError`、`MemoryError` を、すべて捕まえて、`syntax`(`YAML の文法に誤りがあります`)にする(防御。`RecursionError` と `MemoryError` は、確認では発生しなかった)。

### 6.5 変換器との違い

[09. 変換器](09-converter.md)は、この節の上限と数え方をそのまま使う。変換器だけが、範囲外の数(`hugeInt`、`overflow` の浮動小数)と NaN・∞ を、拒否する。定義の読み込みは、拒否しない。

### 6.6 JSON の段階 3

JSON には、タグ、アンカー、マージキーがないので、段階 3 は、第 6.3 節の上限の確認(木を深さ優先・入力に現れる順に走査して、第 6.2 節の 5 と同じ順で確認する)と、最上位の確認(次の 6.7)だけである。重複キーと文法の誤りは段階 2 で済んでいる。

### 6.7 最上位の確認

| 入力 | 結果 |
|------|------|
| 最上位がマップ | 次へ |
| YAML で、文書が 0 個、または最上位が null | 空のマップとして次へ(段階 4 で `versionMissing`) |
| それ以外(リスト、スカラー。JSON の `null` を含む) | `typeMismatch`、理由 ``最上位はマップで書きます``、行は最上位のノードの位置 |

## 7. YAML ライブラリの選定と、追加で実装すること

### 7.1 方針

YAML は Python の標準ライブラリにないので、外部ライブラリを使う(実行時の依存は、この YAML ライブラリ 1 つだけ。JSON は第 5.3 節の自前の読み取りで、標準ライブラリだけで済む)。**選定の基準**は次のとおり。

| 基準 | 内容 |
|------|------|
| 位置 | エラーの行と、各ノードの位置を取れる(構文要素に、入力中の位置が付く) |
| 構文要素の API | ノードの種別、スタイル(引用符・ブロック・フロー)、アンカー、エイリアス、明示のタグの有無を、型に落とさずに取れる(重複キー、非文字列キー、タグ、複数文書を、自前で拒否するため)。値を Python のオブジェクトに組み立てる前の段階(構文要素の列)を取り出せる |
| 複数の文書 | 入力に文書がいくつあるかを、数えられる |
| 重複キー・非文字列キー | ライブラリが拒否しなくてよい(自前で検出できる)。ライブラリの検査を、使わずに済む |
| アンカーの展開 | 展開をライブラリに任せず、自前で上限を数えながら展開できる(アンカーとエイリアスを参照のまま取れる。アンカーの再定義を、ライブラリが拒否しない) |
| 型の解決 | ライブラリの型の解決を使わずに、自前で YAML 1.2 のコアスキーマに沿った判定ができる(スカラーを、書かれた文字列のまま取れる) |
| 保守 | 保守が続いている(実装時に、直近の更新と、報告された不具合の状況を確認する) |
| 依存 | 依存が少ない(実行時に、ほかのパッケージを要しない) |
| 配布 | ビルド済みの配布物(wheel)が、3 つの OS でそろう。または、純粋な Python のみで動く |

### 7.2 候補と採用案

| 候補 | 評価(**この文書の作成時に確認できた範囲**) | 判断 |
|------|---------------------------------------------|------|
| `PyYAML`(MIT ライセンス) | 版 6.0.3(PyPI の最新の安定版。公開は 2025-09-25。`requires-python` は `>=3.8`。実行時の依存なし。確認)。純粋な Python の実装(`yaml.BaseLoader`)と、C の拡張(`yaml.CBaseLoader`。環境によっては無い。確認: 3.14.10 では `yaml.__with_libyaml__` が真、3.15.2 では偽)を持つ。**`yaml.parse(text, Loader=yaml.BaseLoader)` が、構文要素(`ScalarEvent`、`AliasEvent`、`SequenceStartEvent`、`MappingStartEvent`、`DocumentStartEvent` など)の列を返し、各要素が `start_mark`・`end_mark`(`index`・`line`・`column`)、`anchor`、`tag`(明示のタグの文字列。無ければ `None`)、スカラーの `style`(`None`=引用符なし、`'`、`"`、`\|`、`>`)、`value` を持つ**ことを、実際に動かして確認した。`BaseLoader` は、スカラーに型を付けない(書かれた文字を `str` のまま返す)。アンカーの再定義、未定義のエイリアス、重複キー、非文字列キー、複数の文書は、構文要素の段階では拒否しない(確認)。ただし、第 4.1 節の「狭い」点(タブ、アンカー名、U+0085・U+2028・U+2029・CR だけの改行の扱い)と、第 6.4 節の深いフロー形式の遅さがある | **採用案**。版は、実装時に最新の安定版を確認し、`pyproject.toml` の `dependencies` に、確認した版を下限、次の主版を上限とする範囲(例: `PyYAML>=6.0.3,<7`)で書く。受け入れ試験(第 7.5 節)は、CI で、下限の版と最新の版の両方で行う。C の拡張(`CBaseLoader`)は使わない(下の注) |
| `ruamel.yaml`(MIT ライセンス) | 版 0.19.1(公開は 2026-01-02。`requires-python` は `>=3.9`。実行時の必須の依存なし。C の拡張は、追加の指定(`extras`)でだけ入る。確認)。構文要素の列を `YAML(typ="safe", pure=True).parse(text)` で取れ、要素に `start_mark.index` がある(確認)。確認した範囲で、PyYAML と同じ種類の制約がある(タブを区切りに使う書き方、U+0085 を改行として扱う、CR だけの改行の受理、深いフロー形式の遅さ。`[` を 4,000 個並べた入力で約 3.8 秒)。**PyYAML と違う点**: 名前に非 ASCII を含むアンカー(`&名前`)を受理した(確認) | 採用しない(PyYAML で足りる。依存の大きさと保守の実績から、PyYAML を先にした)。PyYAML の版を替えても第 7.5 節の試験に通らないときの、代替の候補とする。その場合、第 7.4 節の追加の実装は、構文要素の API が同じ形なので、ほぼそのまま使える(未確認: 全項目を ruamel.yaml で試してはいない) |
| 構文木・別の実装(`strictyaml`、C などの別の言語で書かれた実装への束縛など) | 保守の状況、位置の API、依存を確認していない(未確認) | 検討しない |
| 自前の YAML 解析 | 文法が大きく、規格への適合の確認が重い | 採用しない |

- 注: **`yaml.CBaseLoader`(C の拡張)を使わない理由**: (1) 環境によって有無が違う(3.15.2 の環境には無かった)ので、使うと、環境ごとに挙動が分かれる。(2) 確認した範囲で、挙動が違う(`a: x` + タブ + `y` を受理する、`"x\ud800"` の単独のサロゲートのエスケープを拒否する、`"\U00110000"` で `ValueError` でなく文法の誤りを返す。位置の数(`index`)は、非 ASCII を含む入力でも同じだった)。(3) 速度の利点(確認: 60 万個の構文要素で、純粋な実装 4.1 秒、C の拡張 0.3 秒)は、この仕様の入力(1 MiB 以下)では不要。したがって、**常に純粋な Python の実装(`yaml.BaseLoader`)を使う**。
- この文書は、採用案のライブラリの構文要素(種別、スタイル、アンカー、エイリアス、タグ、`start_mark.index`、`end_mark.index`)だけに依存して、規定を満たせるように書いてある。同じ情報を返す別のライブラリでも、実装できる。
- 実装時に確認する(未確認): 採用する版の確認、ライセンスの確認、`pip-audit` の結果。
- `import yaml` は、YAML を読むときだけ行う(確認: 3.14.10 で約 12 ミリ秒。JSON だけの実行や、`--help`、`--version` では読み込まない。起動時間の計測は [11. 品質とビルド](11-quality-and-build.md))。

### 7.3 ライブラリの呼び出しと設定

読み取りは、BOM を取り除き、第 4.1 節の事前の確認(CR だけの改行、U+0085・U+2028・U+2029)を済ませた文字列に対して、次のように呼ぶ。

| 項目 | 値 | 理由 |
|------|----|------|
| 関数 | `yaml.parse(text, Loader=yaml.BaseLoader)` | 構文要素の列を、生成器(`Iterator[yaml.Event]`)として返す。値を Python のオブジェクトに組み立てない。**入力の文字列を渡す**(バイト列やファイルを渡さない。バイト列だと、符号化の判定がライブラリに移る)。生成器は、1 つずつ取り出しながら、明示のスタックで木を組み立てる。ライブラリは、取り出すまで読み進めない(遅延評価) |
| スカラーの型 | 付けない | 引用符なしのスカラーを、すべて書かれた文字の `str` として受け取る。型は、実装が第 4.2 節で決める(確認: `a: yes`、`0777`、`0o17`、`~`、空の値のいずれも、値は元の文字のまま、空の値は空文字列で、`style` は `None`) |
| 位置 | `event.start_mark.index`、`event.end_mark.index` | 入力の文字列の**添字(コードポイント)**。確認: `"é: 😀\nb: 2\n"` で、`b` の添字は 5(コードポイントの数。UTF-16 でも UTF-8 でもない)。**`mark.line`・`mark.column` は使わない**(U+0085・U+2028・U+2029・CR だけの改行も改行として数えるため。第 13.1 節)。実装が、LF の位置の表(`list[int]`)を作り、添字から行・列を `bisect` で求める |
| ライブラリの `yaml.load`、`yaml.safe_load`、`yaml.compose` | 使わない | 値の組み立て、アンカーの再定義の拒否(確認: `yaml.compose` は `found duplicate anchor 'x'` で拒否する)、制御の外の上限 |
| 警告 | 出ない | ライブラリは、警告を出さない(確認) |

- 構文要素の読み取りで、文書の中身の誤りは、例外(`yaml.YAMLError` の子の `ScannerError`、`ParserError`、`ReaderError`、`ComposerError`)として投げられる(確認: `ReaderError` は、読み取りの開始直後、最初の要素を取り出すときに、入力の全体の文字を確かめて投げる)。実装は、これらと、`ValueError` と `RecursionError` と `MemoryError` を、読み取りの呼び出しの外側(`try`)で捕まえる(第 7.4 節 #11)。
- 例外から行を得る: `YAMLError` が `problem_mark` を持てば、その `index`(無ければ `context_mark` の `index`)を、LF の表で行にする。`ReaderError` は `position`(添字)を持つ。`ValueError`(範囲外のエスケープ)は位置を持たず、**行なし**とする(確認)。
- 位置の確認は、第 13 節。例外の文(英語)は、利用者に見せない(第 7.4 節 #10)。

### 7.4 ライブラリだけでは足りないので、追加で実装すること

次は、いずれも**必須**である(利用者から見える結果が、この文書の規定と一致するために必要)。

| # | 追加で実装すること | 理由・確認 |
|---|--------------------|--------------------|
| 1 | 入力のすべての文書を読み、文書の数を数える(第 4.6 節) | 構文要素の `DocumentStartEvent` を数える。文書が 0 個の入力(空、コメントだけ)は、その要素が出ない(確認) |
| 2 | **スカラーの型の判定を自前で行う**(第 4.2 節) | ライブラリの型の解決は使わない。YAML 1.1 の型の混入を避けるため(`BaseLoader` は、そもそも型を付けない) |
| 3 | **明示のタグの検出**(第 4.1 節) | 確認: スカラー(`a: !!str 1`)、フローのマップ・リスト(`a: !!set {x}`)、ブロックのマップ・リスト(`!!map` + 改行、`!!seq` + 改行)、キーのスカラー(`? !!str a`)、文書の根(`--- !!str` + 改行 + `foo`)、空の値(`a: !!str`)、`!`(非特定のタグ。`tag` は `"!"`)、`!<tag:yaml.org,2002:str>`、`%TAG` で定義した名前(`!e!foo`)のいずれでも、構文要素の `tag` に文字列が入る。タグが無い要素の `tag` は `None`(引用符つき、ブロックスカラー、アンカーつき、エイリアスを含む)。**検出は、各要素の `tag is not None` で行う** |

## 8. 書式の版(VersionCheck)

根の `format_version` を確認する。

| 状況 | `kind` | 行 | 理由 |
|------|--------|----|------|
| キーが無い | `versionMissing` | なし | `` `format_version` が必要です(対応する版は 1 です) `` |

## 9. 定義の構造(Walk)

以降の「マップ」「リスト」は、木の型(第 6.1 節)である。**キーの型**は、すべて `str`(第 4.4 節で保証)。位置の取り方は第 13 節。

根のマップは、次のキーだけを持てる。

| キー | 型 | 必須 | 説明 |
|------|----|------|------|
| `format_version` | 整数 | 必須 | 第 8 節 |
| `pipeline` | マップ | 必須 | 第 9.1 節 |
| `job` | マップのリスト | 必須(1 つ以上) | 第 9.2 節 |

許されていないキー(上の 3 つ以外)は、`unknownKey` である。`jobs`(複数形)も未知のキーとして拒否される(``キー `jobs` は定義にありません``)。`unknownKey` の理由は、`` キー `<キー名>` は定義にありません `` の形(`<キー名>` は整形したキー名)で、キー名の整形は第 12.2 節。位置はそのキーの位置。値の型は問わない(null でも、アンカーの参照でも同じ)。

### 9.1 `pipeline`

| キー | 型 | 必須 | 既定値 | 検査 |
|------|----|------|--------|------|
| `name` | 文字列 | 必須 | なし | 空白だけ(trim して空)なら `emptyField` |
| `description` | 文字列 | 任意 | なし | 型だけ |
| `run_id_env` | 文字列 | 任意 | なし(実行時の既定は環境変数 `CONDUCTOR_RUN_ID`) | 名前の形(下記) |
| `remove_on_complete` | 真偽値 | 任意 | `false` | 型だけ |

- 許されたキー以外は `unknownKey`(例: `owner`、`remove_on_complet`)。
- `name` が無い: `typeMismatch`、行は `pipeline` のマップの位置、理由 ``必須の値 `name` がありません``。文字列でない(null を含む): `typeMismatch`、値の位置、理由 `` `name` は文字列で書きます ``。`description` が文字列でない: `typeMismatch`、値の位置、理由 `` `description` は文字列で書きます ``。`run_id_env` が文字列でない: `typeMismatch`、値の位置、理由 `` `run_id_env` は文字列で書きます ``。`remove_on_complete` が真偽値でない: `typeMismatch`、値の位置、理由 `` `remove_on_complete` は真偽値(`true` または `false`)で書きます ``。
- `name` が空白だけ: `emptyField`、`name` の値の位置、理由 `` `name` が空です ``(名前の照合はしない)。
- `run_id_env` の名前の形の誤り: `invalidEnvName`、値の位置、理由 `` `run_id_env` は、英字または `_` で始まり、英数字と `_` だけの名前で書きます ``。
- `run_id_env` の名前の形: 1 文字以上で、先頭が ASCII の英字(`A-Za-z`)または `_`、2 文字目以降が ASCII の英数字(`A-Za-z0-9`)または `_`。正規表現で書くなら `[A-Za-z_][A-Za-z0-9_]*` を、**`re.fullmatch` で**照合する(**`re.match` + `$` は使わない**。確認: `$` は末尾の改行の直前にも一致し、`"A\n"` が通ってしまう。`\w` や `str.isalnum`・`str.isidentifier` も使わない。非 ASCII を受理するため)。受理: `A`、`_`、`_a1`、`GITHUB_RUN_ID`。拒否(`invalidEnvName`): `""`、`1A`、`A-B`、`A B`、`A=B`、`é`、`A.B`、NUL を含む文字列、`A` + 改行。文字列でない値(整数など)は `typeMismatch`。誤りの文に、値は含めない。
- `remove_on_complete` は真偽値だけ(`true` / `false`、YAML では `True`、`TRUE` なども)。文字列 `"true"`、`yes`(文字列)、整数 `1`、リスト `[true]` は `typeMismatch`。判定は、ノードの種別が `BoolNode` であること(整数の `1` は `bool` ではない)。型が違うときの値は、`false` として扱って続行する(誤りは報告済み)。
- `pipeline` の形:
  - 無い: `typeMismatch`、行は **1 行目**(位置 (1, 1))、理由 ``必須の値 `pipeline` がありません``。
  - リスト: `typeMismatch`、リストの位置、理由 `` `pipeline` は 1 つだけで、マップで書きます(1 ファイルに 1 パイプライン) ``。
  - その他(整数、文字列、null など): `typeMismatch`、値の位置、理由 `` `pipeline` はマップで書きます ``。
  - 上の誤りのとき、`pipeline` の中身の検査は行わない。
- 名前の照合: `expected_pipeline_name` が与えられ、定義の `name` と**完全に同じでない**(大文字小文字・空白も区別。`str` の `!=`)と、`pipelineNameMismatch`、行は `name` の値の位置、理由 ``指定されたパイプライン名が、定義の `name` と一致しません``。理由に両方の名前は含めない。`name` が空白だけのときは、`emptyField` だけを返し、照合はしない。`name` が文字列でない・無いときも、照合はしない。

### 9.2 `job`

`job` は、マップのリストでなければならない。

- 無い: `noJobs`、行は 1 行目(位置 (1, 1))、理由 ``ジョブ(`job`)が 1 つもありません``。
- 空のリスト(`job: []`): `noJobs`、行は `job` の値の位置。
- リストでない(マップ、整数、null など): `typeMismatch`、値の位置、理由 `` `job` はマップのリストで書きます ``。
- リストの要素がマップでない: `typeMismatch`、その要素の位置、理由 `` `job` の要素はマップで書きます ``(その要素の検査は行わない)。

各ジョブ(マップ)のキー:

| キー | 型 | 必須 | 既定値 | 説明 |
|------|----|------|--------|------|
| `id` | 文字列 | 必須 | なし | ジョブID。第 11.1 節の検査 |
| `command` | 文字列、または文字列のリスト | 必須 | なし | 第 9.3 節 |
| `warning_exit_codes` | 整数のリスト | 任意 | 空(`[]`) | 警告にする終了コード |
| `success_exit_codes` | 整数のリスト | 任意 | 省略(意味は `[0]`) | 成功にする終了コード |
| `transitions` | マップのリスト | 任意 | 空 | 第 9.4 節 |
| `retry` | マップ | 任意 | なし | 第 9.5 節 |

許されたキー以外は `unknownKey`(例: `warn_exit_codes`)。

- `id` が無い: `typeMismatch`、行はジョブのマップの位置、理由 ``必須の値 `id` がありません``。文字列でない: `typeMismatch`、値の位置、理由 `` `id` は文字列で書きます ``。
- 終了コードのリスト(`warning_exit_codes` と `success_exit_codes`):
  - リストでない(null を含む): `typeMismatch`、値の位置、理由 `` `<キー名>` は整数のリストで書きます ``(`<キー名>` は実際のキー名)。
  - 要素が整数でない、または 32 ビット符号つき整数の範囲(-2,147,483,648〜2,147,483,647)に収まらない: 要素ごとに `typeMismatch`、その要素の位置、理由 `` `<キー名>` の要素は、整数(32 ビットの範囲)で書きます ``。1 つでも誤りがあれば、そのキー全体を「無効」として扱い、後続の重なりの検査では使わない。範囲の判定は、`IntNode` の値(Python の `int`)で行う(`-2147483648 <= v <= 2147483647`)。
  - 負の値(例: `-1`)は、その範囲なので**受理**する。重複した値も受理し、除かない(書いた順のまま保持する)。空のリストも受理する(`success_exit_codes: []` は、成功にする終了コードが無い、の意味になる)。
  - 整数は、YAML の `0x1F`、`0o17`、`+3`、`007` でもよい(値で判定する)。JSON は 10 進の整数だけ。
- `success_exit_codes` を省略すると、成功の終了コードは `[0]`。書いたら、**書いた値だけ**が成功(`0` を書かなければ 0 でも成功にならない)。
- 要素が浮動小数(`1.0`、`1e0`)や、範囲外の整数(`99999999999999999999`、種別 `hugeInt`)、真偽値(`true`)のときも、要素の型の誤り(`typeMismatch`)になる。

### 9.3 `command`

| 書き方 | 受理の条件 | 保持される値 |
|--------|-----------|---------------|
| 文字列 | trim して空でない | 1 本の文字列(そのまま。trim した値ではない) |
| 文字列のリスト | 空でないリストで、全要素が文字列で、**先頭の要素が trim して空でない**。2 番目以降の要素は空文字列でもよい | 要素の並び(そのまま) |

どちらの書き方かは、取り込み後も区別して保持する(実行側の解釈が異なる。[05. 実行フロー](05-execution-flow.md)・[07. プロセスとシグナル](07-process-and-signals.md))。

誤り:

| 条件 | `kind` | 行 | 理由 |
|------|--------|----|------|
| キーが無い | `typeMismatch` | ジョブのマップの位置 | ``必須の値 `command` がありません`` |
| 文字列が空または空白だけ | `emptyField` | 値の位置 | `` `command` が空です `` |
| リストが空 | `emptyField` | 値の位置 | `` `command` の配列が空です `` |
| リストに文字列でない要素がある | `typeMismatch`(要素ごと) | その要素の位置 | `` `command` の配列の要素は、文字列で書きます `` |
| リストの先頭の要素が空または空白だけ(全要素が文字列のとき) | `emptyField` | 先頭の要素の位置 | `` `command` の配列の先頭の要素が空です `` |
| 文字列でもリストでもない(整数・真偽値・マップ・null) | `typeMismatch` | 値の位置 | `` `command` は文字列、または文字列の配列で書きます `` |

- リストに型の誤りの要素があるときは、先頭要素の空の検査はしない。
- 受理の例(YAML): `command: echo x`、`command: ["my prog", "a b", "$HOME", ""]`、`command: [echo, ""]`。拒否の例: `command: 5`、`command: true`、`command: {a: 1}`、`command: ["a", 5]`、`command: [[a]]`(`typeMismatch`)、`command: ""`、`command: "   "`、`command: []`、`command: [""]`、`command: ["  ", x]`(`emptyField`)、`command:`(値なしは null。`typeMismatch`)。
- 文字列の `command` の中の引用符・`$` などは、この段階では解釈しない(実行時の解釈は実行側の仕様)。YAML の引用符なしの複数行のスカラーは、折りたたまれた 1 つの文字列(改行が空白 1 個になる)になるが、書き方による値の違いは、そのまま保持する。
- 理由の文言(`の配列` という語)は、リストを指す(日本語の原文として固定する。`リスト` に言い換えない)。
- 誤りの文に、入力の値は含めない。

### 9.4 `transitions`

`transitions` は、マップのリスト(YAML のブロックの `- on: success` の繰り返し、またはフロー形式 `[{on: success, next: b}]`、JSON の配列)。

| キー | 型 | 必須 | 説明 |
|------|----|------|------|
| `on` | 文字列 | 必須 | `success` または `warning` |
| `next` | 文字列 | 必須 | 遷移先のジョブID、または `@end` |

- 許されたキー以外(`when` など)は `unknownKey`。
- `transitions` がリストでない(null を含む): `typeMismatch`、値の位置、理由 `` `transitions` はマップのリストで書きます ``(遷移は空として扱う)。要素がマップでない: `typeMismatch`、その要素の位置、理由 `` `transitions` の要素はマップで書きます ``。
- `on` が無い: `typeMismatch`、遷移のマップの位置、理由 ``必須の値 `on` がありません``。文字列でない: `typeMismatch`、値の位置、`` `on` は文字列で書きます ``。
- `on` の値: `success`、`warning` を受理。`error` は `errorTransition`、値の位置、理由 ``エラー結果(`error`)には遷移先を書けません``。それ以外の文字列(`later`、大文字の `Success` など)は `typeMismatch`、値の位置、理由 `` `on` は `success` または `warning` で書きます ``。YAML のキー `on` は、YAML 1.1 の真偽値ではなく、文字列のキー(`on`)として読まれる(第 4.2 節)。
- `next` が無い: `typeMismatch`、遷移のマップの位置、理由 ``必須の値 `next` がありません``。文字列でない: `typeMismatch`、値の位置、`` `next` は文字列で書きます ``。
- 同じ `on`(`success` どうし、`warning` どうし)の遷移が 2 つ以上: 2 つ目以降の遷移に `duplicateTransition`、行は**その遷移(マップ)の位置**、理由 ``同じ結果(`on`)の遷移が 2 つ以上あります``。`success` と `warning` を 1 つずつは受理。`on` が不正(`error` や未知の値、型の誤り)の遷移は、重複判定に入れない。
- 遷移先の存在・順序の検査は、第 11 節。

### 9.5 `retry`

ジョブが決めた終了コードで終わったときに、待って実行し直す設定。書き方は、ブロックのマップでもフローのマップでも、JSON のオブジェクトでもよい。

許されたキーは次の 5 つだけ。それ以外は `unknownKey`(例: `retries`)。

| キー | 型 | 必須 | 範囲・書式 | 取り込み後 |
|------|----|------|-----------|-------------|
| `exit_codes` | 整数のリスト | 必須 | 空でない。各要素は 1 以上 255 以下の整数 | 昇順に並べ、重複をまとめる(`[75, 3, 75, 3, 12]` → `[3, 12, 75]`) |
| `max` | 整数 | 必須 | 1 以上 100 以下 | `int` |
| `interval` | 文字列 | 必須 | `<整数><s\|m\|h>`、1 秒以上 24 時間以下 | 秒(`int`。1〜86,400) |
| `multiplier` | 整数 | 任意 | 2 以上 10 以下 | `int`、または無し |
| `max_interval` | 文字列 | 任意 | `interval` と同じ書式、`interval` 以上 | 秒(`int`)、または無し |

- 127 などの値も受理する(`[127, 1]` → `[1, 127]`)。並べ替えは、数値の昇順(`sorted(set(codes))`。要素は `int` なので、数値で並ぶ)。
- `multiplier` と `max_interval` は、**両方を書くか、両方とも書かない**か。片方だけなら `retryBackoffIncomplete`。両方なしなら、待ち時間は毎回 `interval`。
- 取り込み後の値は、Python の `int` で、最大でも 86,400。**待ち時間の計算(倍率の累乗、上限、64 ビット符号なし整数の飽和)は、[05. 実行フロー](05-execution-flow.md)の規定に従う**(`int` は任意精度で桁あふれしないので、64 ビット符号なし整数の上限 `2**64 - 1` を `min(値, 2**64 - 1)` で飽和させる)。

#### 間隔の文字列の書式

- 文字列の最後の 1 文字が単位(`s`=秒、`m`=分=60 秒、`h`=時間=3600 秒。小文字だけ)。その前が、**ASCII の数字(0〜9)だけ**の 1 文字以上の列(符号・空白・小数点・`_`・全角数字・16 進(`0x`)は不可)。正規表現で書くなら `[0-9]+[smh]` を **`re.fullmatch`** で照合する(**`\d` を使わない**。全角数字に一致するため。`$` の注意は第 9.1 節と同じ。確認: `re.fullmatch(r"[0-9]+[smh]", "１s")` は一致しない)。
- 数値は 1 以上。秒に換算した値が 1 以上 86,400(24 時間)以下。桁あふれ(64 ビット符号なし整数に収まらない、または換算の乗算があふれる)は拒否。先頭の 0 は何個並べてもよい(`0000000000000000000000000001s` は値 1 で受理)。値が 86,400 秒を超えるものは、桁数にかかわらず拒否する。**判定は `int` で行う**(数字の列を `int()` にして、単位の倍率を掛けて、1 以上 86,400 以下かを調べる)。巨大な桁数の字句で時間を使わず、`int()` の桁数の制限(4,300 桁。第 4.2 節)に当たらないために、先頭の 0 を除いた数字の桁数が 5 を超えるものは、`int()` を呼ばずに範囲外とする(6 桁以上の数は 100,000 以上で、単位が `s` でも 86,400 を超えるので、結果は同じ)。5 桁以下だけ `int()` で調べればよい。
- 受理: `1s`、`30s`、`5m`、`2h`、`24h`、`1440m`、`86400s`、`01s`(値 1)。拒否: `""`、`s`、`10`、`1.5s`、`-1s`、`+1s`、` 1s`、`1s `、`1 s`、`1d`、`1S`、`１s`、`1ms`、`0x10s`、`1_0s`、`0s`、`0h`、`86401s`、`25h`、`99999999999999999999999s`、`18446744073709551615h`。文字列でない値(整数・真偽値・null)も拒否。
- YAML では、`interval: 30s` のように引用符なしで書いた `30s` は文字列、`interval: 30` は整数なので拒否。`interval: 0x10s` は文字列だが、書式に合わないので拒否(`retryDurationInvalid`)。

#### 誤りと検査

| 条件 | `kind` | 行 | 理由 |
|------|--------|----|------|
| `retry` がマップでない(整数、文字列、リスト、null) | `retryNotTable` | `retry` の値の位置(リストのときは、リストの位置) | `` `retry` はマップで書きます `` |
| 必須のキー(`exit_codes`、`max`、`interval`)が無い | `retryMissingKey`(欠けたキーごとに 1 件) | `retry` のマップの位置 | ``必須の値 `<キー名>` がありません`` |
| `exit_codes` がリストでない | `retryExitCodeInvalid` | 値の位置 | `` `exit_codes` は整数の一覧で書きます `` |
| `exit_codes` が空のリスト | `retryExitCodesEmpty` | 値の位置 | `` `exit_codes` が空です `` |
| `exit_codes` の要素が整数でない、32 ビットの範囲外、1〜255 の範囲外(0、256、-1、1.5、`"75"`、`true` など) | `retryExitCodeInvalid`(要素ごと) | その要素の位置 | `` `exit_codes` の要素は、1 以上 255 以下の整数で書きます `` |
| `max` が整数でない、または 1〜100 の範囲外(0、101、-1、1.5、`"3"`、`true`) | `retryMaxInvalid` | 値の位置 | `` `max` は、1 以上 100 以下の整数で書きます `` |
| `interval` / `max_interval` が書式・範囲に合わない | `retryDurationInvalid` | 値の位置 | `` `<キー名>` は、整数と単位(`s`、`m`、`h`)で、1 秒以上 24 時間以下に書きます(例: `30s`) ``(`<キー名>` は `interval` か `max_interval`) |
| `multiplier` が整数でない、または 2〜10 の範囲外(1、11、0、-2、`2.0`、`"2"`、`true`) | `retryMultiplierInvalid` | 値の位置 | `` `multiplier` は、2 以上 10 以下の整数で書きます `` |
| `multiplier` と `max_interval` の片方だけがある | `retryBackoffIncomplete` | `retry` のマップの位置 | `` `multiplier` と `max_interval` は、両方を書くか、両方とも書きません `` |
| `exit_codes` に、そのジョブの成功または警告の終了コードと同じ値がある | `retryExitCodesOverlap` | `exit_codes` の**キー**の位置 | `` `exit_codes` に、成功または警告の終了コードと同じ値があります `` |
| `max_interval` が `interval` より小さい(秒で比べる。等しければ受理) | `retryMaxIntervalTooSmall` | `max_interval` の値の位置 | `` `max_interval` は、`interval` 以上で書きます `` |

- 整数の判定は、`IntNode`(`int` の値)で行う。範囲外の整数(`hugeInt`)と真偽値は、範囲外の誤りと同じ扱い。
- 空のマップ(`retry: {}`)は、`retryMissingKey` が 3 件(`exit_codes`、`max`、`interval` の順)返る(行はすべて同じ。マップの位置は、フロー形式では `{` の位置)。
- `exit_codes` の複数の要素が不正なら、不正な要素ごとに 1 件(例: `[0, 75, 256]` は 2 件)。
- **重なりの検査**(`retryExitCodesOverlap`)は、定義の他の値と照合する。`exit_codes` が有効(エラーなし)のときだけ行う。
  - 成功の終了コード: `success_exit_codes` を**書かなければ `[0]`**。書いて有効なら、その値。書いたが誤り(無効)のときは、成功との重なりを調べない(警告との重なりは調べる)。
  - 警告の終了コード: `warning_exit_codes` が有効なら、その値(無効なら調べない)。
  - どちらかと 1 つでも共通する値があれば、1 件(重なりの値の数にかかわらず 1 件)。
  - 例: `success_exit_codes: [0, 5]` と `exit_codes: [5, 75]` は誤り。`success_exit_codes: [3]` と `exit_codes: [3]` も誤り。`success_exit_codes: [0, 5]`、`warning_exit_codes: [4]`、`exit_codes: [75]` は受理。
- `retry` の有無は、ほかのキーの読み取りの結果に影響しない。
- 誤りの文に、入力の値は含めない。
- `retry` のマップの位置は、ブロック形式では**最初のキーの位置**(`retry:` の次の行)であり、`retry` のキーの行ではない(第 13.2 節)。

## 10. 検査の順序とエラーの集約・並び

Walk の中の処理順(誤りは、見つかった順に集める):

1. 根のキー検査(`unknownKey`)。
2. `pipeline`: キー検査 → `name` → `description` → `run_id_env`(型の誤り、続けて名前の形の誤り) → `remove_on_complete` → `name` の空の検査 → 名前の照合。
3. `job`: 無い/空/型の誤りの処理。リストなら、各ジョブを順に、次の順で検査する: キー検査 → `id` → `command` → `warning_exit_codes` → `success_exit_codes` → `transitions`(各遷移について、キー検査 → `on` → `next` → 重複) → `retry`(キー検査 → `exit_codes` → `max` → `interval` → `multiplier` → `max_interval` → 倍率と上限の片方だけの検査)。
4. 全ジョブにまたがる検査(第 11 節): ジョブIDの検査 → 各ジョブについて、遷移先 → 終了コード(`zeroAsWarning`、`overlappingExitCodes`) → `retry` の重なり・上限と間隔の大小。
5. 誤りが 1 件もなく、`pipeline` とすべてのジョブが組み立てられるときだけ、定義を返す。

返す誤りの順序: すべての誤りを、**位置(行、同じ行なら列)の昇順**に並べて返す。同じ位置のものは、上の検査の順(集めた順)を保つ(**安定な並べ替え**。Python の `list.sort` と `sorted` は、安定であることが言語の規定で保証されている)。位置の取り方は第 13 節。

- 型の誤りなどで検査できなくなった値は、その値に依存する後続の検査だけを省略する(他の検査は続ける)。
- 位置が (1, 1) の誤りは、行 1 として扱われる(`pipeline` が無い、`job` が無い)。

複数の誤りの例:

```yaml
format_version: 1
unknown_top: true          # 2 行目: unknownKey

pipeline:
  name: p

job:
  - id: a
    command: x
    success_exit_codes: [zero]   # 10 行目: typeMismatch

  - id: b
    command: y
    colour: red              # 14 行目: unknownKey
    transitions:
      - on: success
        next: nowhere        # 17 行目: unknownTarget
```

返る誤り: `unknownKey`(2)、`typeMismatch`(10)、`unknownKey`(14)、`unknownTarget`(17)。確認(試作): 上のとおり。

## 11. ジョブ間の検査

### 11.1 ジョブID

`id` が文字列であるジョブごとに、記述順に検査する。

- trim して空、または先頭が `@` → `invalidJobId`、`id` の値の位置、理由 ``ジョブID(`id`)は、空でなく、`@` で始まらない文字列で書きます``。この ID は、遷移先の索引に入らない(後続のジョブから、遷移先として参照できない)。
- 既出の ID と完全に同じ(大文字小文字・前後の空白も区別。`" a "` と `"a"` は別) → `duplicateJobId`、2 つ目以降の `id` の値の位置、理由 ``同じジョブID(`id`)が、すでに定義されています``。(既出の ID は `set[str]` で調べる。`__proto__` や `constructor` という ID も、通常の文字列として扱う。)
- 長さの上限、使える文字(空白・記号)の制限は、これ以外にない(定義の検査では。実行時の状態ファイル名などへの影響は、[06. ステートファイル](06-state-file.md)による)。

### 11.2 遷移先

`on` と `next` がともに有効な遷移について、`next` を検査する(`on` が不正な遷移は、検査しない)。

- `next == "@end"`: 受理(以降のジョブをスキップして終える)。
- ID の索引に無い(存在しない、または無効な ID): `unknownTarget`、`next` の値の位置、理由 ``遷移先(`next`)のジョブが、定義にありません``。
- 記述順で、自分自身または前のジョブ(位置 ≦ 自分の位置): `backwardOrSelfTarget`、`next` の値の位置、理由 ``遷移先(`next`)は、記述順で後ろのジョブまたは `@end` で書きます``。
- 後ろのジョブの ID は受理する。

### 11.3 終了コード

各ジョブについて(`warning_exit_codes` と `success_exit_codes` が有効なとき):

- `warning_exit_codes` に 0 を含む → `zeroAsWarning`、`warning_exit_codes` の**キー**の位置、理由 ``0 は警告の終了コード(`warning_exit_codes`)にできません``。(`success_exit_codes` の誤りの有無に関わらず検査する。)
- 両方を書き、有効で、共通する値がある → `overlappingExitCodes`、`warning_exit_codes` の**キー**の位置、理由 `` `warning_exit_codes` と `success_exit_codes` に、同じ値があります ``。ただし、共通の値が 0 だけで、すでに `zeroAsWarning` を報告した場合は、重ねて報告しない(例: `warning_exit_codes: [0]` と `success_exit_codes: [0]` は `zeroAsWarning` の 1 件だけ)。
- `success_exit_codes` を書かないとき、成功は `[0]` だが、`warning_exit_codes` との重なりは(書かれていない側は)調べない。警告に 0 を入れた場合は、`zeroAsWarning` で拒否される。

### 11.4 `retry` との関係

第 9.5 節(重なり、上限と間隔の大小)。

## 12. エラーの種類と表示

### 12.1 エラーの構造

型の骨格(例。種類 `kind` は `Literal`。上の第 6.1 節と同じファイルで `mypy --strict` を通した):

```python
    "overlappingExitCodes", "zeroAsWarning", "pipelineNameMismatch",
    "duplicateJobId", "invalidJobId", "noJobs", "emptyField",
    "duplicateTransition", "invalidEnvName", "retryNotTable",
    "retryMissingKey", "retryExitCodesEmpty", "retryExitCodeInvalid",
    "retryExitCodesOverlap", "retryMaxInvalid", "retryDurationInvalid",
    "retryBackoffIncomplete", "retryMultiplierInvalid",
    "retryMaxIntervalTooSmall",

ERROR_KINDS: Final[tuple[str, ...]] = get_args(ErrorKind)


@dataclass(frozen=True, slots=True)
class DefinitionError:
    kind: ErrorKind
    file: str  # 表示用のファイル名(第 2.1 節)
    line: int | None  # 1 始まり。None は「行なし」
    column: int | None  # 1 始まり。None は「列なし」。順序づけにだけ使い、表示には出さない
    reason: str  # 固定の文から組み立てた理由(日本語)。入力の値は含めない


@dataclass(frozen=True, slots=True)
class LoadOk:
    definition: Definition
    ok: Literal[True] = True


@dataclass(frozen=True, slots=True)
class LoadFailed:
    errors: tuple[DefinitionError, ...]  # 1 件以上
    ok: Literal[False] = False


LoadResult: TypeAlias = LoadOk | LoadFailed
```

| フィールド | 内容 |
|------------|------|
| `file` | 表示用のファイル名 |
| `line` | 行番号(1 始まり)。位置が決まらないときは無し |
| `column` | 列番号(1 始まり)。同じ行の中での順序づけのために保持する。**表示には出さない** |
| `kind` | 種類(第 12.3 節) |
| `reason` | 固定の文から組み立てた理由。入力の値は含めない。入力由来はキー名だけ(`unknownKey`) |

ライブラリ(読み込み処理の呼び出し側)に返す表示の書式:

```
<file>:<line>: <種類の文>: <reason>      行があるとき
<file>: <種類の文>: <reason>             行が無いとき
```

例: ``conductor.yaml:7: 定義にないキーです: キー `x` は定義にありません``。ここで `<file>` は、制御文字・書式文字・サロゲート(第 12.2 節と同じ対象)をエスケープし、エスケープ後の文字数で 256 文字までに切る(超えるときは、256 文字までで切って末尾に `…` を付ける)。

`conductor` コマンドの標準エラーへの表示は、`conductor: error: <file>[:<line>]: <種類の文(言語による)>: <reason>` の 1 行(誤りごとに 1 行、位置の順)で、`reason` は日本語のまま(言語によらない)。種類の文は、メッセージの言語([08](08-output-and-i18n.md))が日本語のとき日本語(第 12.3 節の「日本語」)、それ以外は英語(「英語」)。`<file>` と `reason` は、改行・制御文字・書式文字・サロゲートをエスケープして表示する(`\n`、`\r`、`\t`、その他は `\u{16進小文字}`)。**ここでは文字数で切らない**。例:

```
conductor: error: bad.yaml:7: unknown key: キー `typo` は定義にありません
conductor: error: conductor.yaml: definition file does not exist: 指定の場所にファイルがありません
```

定義の誤りがあるときの終了コード(64)と、その標準出力・標準エラーの扱いは、[10. エラーと終了コード](10-errors-and-exit-codes.md)に従う。

### 12.2 キー名の表示

`unknownKey` の理由に入るキー名は、`` ` `` で囲み、次の整形をする。

- 改行を `\n`、復帰を `\r`、タブを `\t` に、その他の制御文字(U+0000〜U+001F、U+007F〜U+009F)と書式文字(U+200B〜U+200F、U+2028、U+2029、U+202A〜U+202E、U+2060〜U+2064、U+2066〜U+2069、U+FEFF)を `\u{16進小文字}` にエスケープする(例: U+0001 は `\u{1}`)。**対にならないサロゲート(U+D800〜U+DFFF)も、同じ形でエスケープする**(例: U+DC80 は `\u{dc80}`)。Python では、OS から得た文字列(コマンドラインの引数、環境変数、ファイル名)に、不正なバイトが U+DC80〜U+DCFF の単独のサロゲートとして入りうる(`surrogateescape`。[08. 出力と多言語対応](08-output-and-i18n.md))。表示の前にエスケープしないと、標準エラーへの書き出しで `UnicodeEncodeError` になる。定義の中のキー名には、単独のサロゲートは含まれない(第 1 節)ので、この規定が働くのは、`<file>` だけである。
- エスケープ後の文字数(コードポイントの数)が **64 文字**を超えるときは、64 文字までで切って末尾に `…` を付ける(エスケープの途中では切らない。たとえば、残りが 2 文字でエスケープが 6 文字なら、そのエスケープは入れず、そこで切る)。ちょうど 64 文字は切らない。
- この整形は、`file`(256 文字)の整形と同じ手順で、上限だけが違う。
- 文字列は、コードポイントごとに走査する(`for ch in s`。`str` の走査は、コードポイント単位である)。

## 13. 位置(行番号と列番号)の出し方

### 13.1 位置の単位

- 位置は、行と列の組(`Pos`)。**行は 1 始まりで、LF の数で数える**(CRLF でも、CR は直前の行に属し、LF のあとが次の行)。**列は 1 始まりで、その行の先頭からの文字(コードポイント)の数 + 1**。YAML も JSON も、同じ単位である(入力の `str` の添字から、実装が求める)。**列は、同じ行の中の誤りの並びを決めるためだけに使い、行が違えば比べない**。同じ行の中で、前にあるものほど小さい列を返す限り、単位はどちらでもよい。
- **行と列は、ライブラリの `mark.line`・`mark.column` を使わず、`mark.index` から求める**。理由: ライブラリは、U+0085、U+2028、U+2029、CR だけの改行も改行として数える(確認)。第 4.1 節の事前の確認で、これらを拒否した後でも、拒否の位置の求め方と、受理する入力の位置を、LF の数に統一するためである(受理する入力には、これらの文字が無いので、`mark.line` と一致するが、**規定は `index` から求める**)。求め方: LF の添字の表(`[0] + [i + 1 for i, c in enumerate(text) if c == "\n"]`)を作り、`bisect.bisect_right(表, index)` が行、`index - 表[行 - 1] + 1` が列。
- 先頭の BOM は、位置には数えない(1 行目の 1 列目は、BOM の次の文字)。実装は、BOM を取り除いた文字列を、ライブラリと自前の読み取りに渡す。
- 位置が決まらない誤りは、行なし(取り込み、`versionMissing`、一部の `syntax`(範囲外のエスケープ))。
- 位置が (1, 1)(入力の先頭)の誤りは、`pipeline` が無い、`job` が無い。

### 13.2 ノードの位置

YAML のノードの位置は、構文要素の `start_mark.index`(入力の文字列の中のコードポイントの添字)を、第 13.1 節の求め方で行・列にしたもの。ただし、アンカーを前置したノードは、次の補正をする。

- **アンカー・タグを前置したノード**(構文要素の `anchor` または `tag` が `None` でない、エイリアスでないもの)の `start_mark` は、アンカー・タグの先頭を指す(確認)。**内容の位置**に直すために、`start_mark.index` から、次の手順で進める: 繰り返し、(1) 空白(半角スペース、タブ、CR、LF)を飛ばす、(2) `#` ならその行の LF まで飛ばす(コメント)、(3) `&` または `!` ならその次の空白まで飛ばす(アンカー・タグの 1 つ)、(4) それ以外の文字なら止まる。止まった添字が、内容の位置である。確認: `a: &s` + 改行 + `  x` で `x` の位置(2 行目 3 列目)、`a: &s "q"` で `"` の位置、`a: &m` + 改行 + `  b: 1` で `b` の位置(2 行目 3 列目。マップは、次の「ブロックのマップ」の規定)。

| ノード | 位置 |
|--------|------|
| スカラー | 値の先頭の文字(引用符つきなら、開く引用符。ブロックスカラーなら、`\|` または `>` の位置)。アンカーやタグが前置されていても、**内容の位置**(上の補正。アンカーやタグの位置ではない) |
| ブロックのマップ | **最初のキーの位置**(最初のキーのノードの位置。そのキー自身が引用符つきなら、開く引用符。アンカーつきのキーも内容の位置)。明示のキー `? a` のときは、`?` の位置ではなくキー `a` の位置(確認: ライブラリのマップの `start_mark` は `?` の位置を返すので、補正が要る。`? a` + 改行 + `: 1` で 1 行目 3 列目)。マップがアンカーやタグを前置していても、同じ(最初のキーの位置)。実装は、マップの開始の要素の次の要素を 1 つ先読みして、その位置を得る(先読みの要素が、スカラー、エイリアス、コレクションの開始のいずれでも、そのノードの位置) |
| フローのマップ | `{` の位置(アンカーやタグが前置されていても、上の補正で `{` の位置) |
| ブロックのリスト | **最初の `-` の位置**(アンカーが前置されていても、上の補正で `-` の位置。インデントなしのリストも `-` の位置) |
| フローのリスト | `[` の位置 |
| JSON のオブジェクト・配列 | `{` / `[` の位置 |
| マップのキー(`key_pos`) | キーのスカラーの先頭(エイリアスのキーは、`*name` の位置) |
| 値が省略された対の値(`key:` の後ろに何もない、`{a, b: 1}` の `a`、`? a`、`a: &x` のようにアンカーだけ) | その対の**キーの位置**(確認: ライブラリは、`a:` の値の位置を、コロンの直後(同じ行)に、`? a` の値の位置を、次の行の先頭に返す。実装は、これらを使わず、キーの位置にする) |
| リストの要素が省略された `- ` の後ろの null | ライブラリが返す位置(ダッシュの直後。同じ行) |
| `---` だけの文書(最上位が null)の根 | `---` の直後の位置(`DocumentStartEvent` の `end_mark.index`)。行は `---` の行(確認: `---` + 改行 で 1 行目) |
| 展開されたノード(エイリアスから) | **エイリアスのトークン `*name` の位置**(複製した子のすべても同じ位置。確認: `c: *x` で `*` の位置) |
| マージで取り込まれたエントリ | そのマージキー `<<` の位置(キー、値、値の中のすべて) |

- 「値の位置」とは、そのキーの値のノードの位置。「キーの位置」とは、`key_pos`。「マップの位置」とは、上の表のマップのノードの位置(必須キーの欠落、`retryMissingKey`、`retryBackoffIncomplete` で使う)。
- 複数の文書の 2 つ目の文書の位置(第 4.6 節の行)は、その文書の根のノードの位置(上の表)である。空の文書(`---` の後ろが空)は、ライブラリが返す位置(次の行の先頭など。確認: `a: 1\n---\n` で 3 行目)。

### 13.3 誤りの位置の取り方(まとめ)

- 型の誤りや範囲の誤りは、**誤った値のノードの位置**。
- 未知のキーは、**キーの位置**。
- 必須のキーの欠落は、**それを含むマップの位置**。
- `pipeline` や `job` 自体が無いときは、(1, 1)。
- 終了コードの重なり(`overlappingExitCodes`、`zeroAsWarning`、`retryExitCodesOverlap`)は、対象の**キー**の位置(値ではない)。
- リストの誤りは、要素ごとに、その要素の位置。
- 取り込みの誤り、`unsupportedFormat`、`versionMissing` は、行なし。
- 段階 3 の誤りは、そのノードの位置(キーの誤り(重複、非文字列)はキーの位置、マージキーの誤りは `<<` の位置、深さの誤りは 33 段目のコレクションの位置、上限(要素数、大きさ)の誤りは、超えたノードの位置。エイリアスの展開の中で超えたときは、エイリアスの位置)。

### 13.4 文法の誤りの行

- **JSON**: 第 5.2 節のとおり、必須。
- **YAML**: 文法の誤りは、ライブラリが検出した位置の行(例外の `problem_mark.index` から求めた行)。検出位置は、ライブラリの作りで変わる(原因の行より後ろになることも、前になることもある)。**必須なのは、種類(`syntax`)と理由(`YAML の文法に誤りがあります`)であり、行は、ライブラリが返すものでよい**。PyYAML 6.0.3 での確認結果(この表の行が、実装時の版で変わったときは、その版の結果に合わせて、この表を更新する):

| 入力(`\n` は改行) | ライブラリの誤り | 行 |
|------|------|----|
| `format_version: 1\npipeline: [1, 2\n` | `ParserError`(閉じていないフロー) | 3(入力の末尾の空の行) |
| `a: [1, 2\n` | `ParserError` | 2 |
| `a: [1, 2\nb: 3\n` | `ParserError` | 2(`b` の行) |
| `a: [1, 2`(末尾の改行なし) | `ParserError` | 1 |
| `a: "x\n` | `ScannerError`(閉じていない引用符) | 2 |
| `a: 1\nb: "\q"\n` | `ScannerError`(未知のエスケープ) | 2 |
| `x: 1\na: b: c\n` | `ScannerError`(`mapping values are not allowed here`) | 2 |
| `a: 1\nb:\n\t- x\n` | `ScannerError`(タブ) | 3 |
| `a:\n  b: 1\n c: 2\n` | `ParserError`(インデント) | 3 |
| `a: @x\n` | `ScannerError` | 1 |
| `a: 1\r\nb: [1,\r\n c: 2\r\n`(CRLF) | `ParserError` | 4(CRLF でも、LF の数で数えた行) |
| `a: [1,\n  2\n` | `ParserError` | 3 |
| `a: 1\nb: 2\nc: \x07\n`(制御文字) | `ReaderError` | 3(`position` から) |
| `a: "\U00110000"` | `ValueError` | 行なし |

## 14. 取り込み後のデータモデルと検査の関数

### 14.1 データモデル

検証に成功すると、次のデータを返す(型の骨格。`frozen=True` で、変更できない値として返す)。

```python
@dataclass(frozen=True, slots=True)
class LineCommand:
    line: str
    form: Literal["line"] = "line"


@dataclass(frozen=True, slots=True)
class ArgvCommand:
    argv: tuple[str, ...]  # 1 要素以上。先頭は空白だけでない
    form: Literal["argv"] = "argv"


Command: TypeAlias = LineCommand | ArgvCommand


@dataclass(frozen=True, slots=True)
class ToJob:
    on: Literal["success", "warning"]
    job_id: str
    next: Literal["job"] = "job"


@dataclass(frozen=True, slots=True)
class ToEnd:
    on: Literal["success", "warning"]
    next: Literal["end"] = "end"


Transition: TypeAlias = ToJob | ToEnd


@dataclass(frozen=True, slots=True)
class Backoff:
    multiplier: int  # 2〜10
    max_interval_secs: int  # interval_secs 以上、86400 以下


@dataclass(frozen=True, slots=True)
class RetryPolicy:
    exit_codes: tuple[int, ...]  # 昇順・重複なし・各 1〜255・空でない
    max: int  # 1〜100
    interval_secs: int  # 1〜86400。待ち時間は 64 ビット符号なしの飽和演算で使う([05. 実行フロー](05-execution-flow.md))
    backoff: Backoff | None  # None なら固定間隔。multiplier と max_interval は必ず同時に有る/無い


@dataclass(frozen=True, slots=True)
class Job:
    id: str  # 空白だけでなく、@ で始まらず、定義内で一意
    command: Command  # 文字列で書いたか、リストで書いたか
    warning_exit_codes: tuple[int, ...]  # 省略時は空。0 を含まない。書いた順のまま。各値は 32 ビット符号つき整数の範囲
    success_exit_codes: tuple[int, ...] | None  # 省略時 None(意味は (0,))。書いた順のまま
    transitions: tuple[Transition, ...]  # 書いた順。on ごとに高々 1 つ
    retry: RetryPolicy | None  # 書かなければ None


@dataclass(frozen=True, slots=True)
class Definition:
    name: str  # 空白だけでない(trim していない元の値)
    description: str | None  # 無ければ None
    run_id_env: str | None  # 名前の形は検査済み。None なら実行時に CONDUCTOR_RUN_ID
    remove_on_complete: bool  # 省略時 False
    format_version: Literal[1]
    jobs: tuple[Job, ...]  # 記述順を保つ。1 つ以上
```

- 成功として扱う終了コード = `success_exit_codes` があればそれ、なければ `(0,)`。
- ジョブIDから記述順の位置(0 始まり)を引く操作がある(遷移先の検査と、実行時の遷移の解決に使う)。`dict[str, int]` で持つ。
- 取り込み後の整数(終了コード、`max`、`multiplier`、秒数)は、すべて Python の `int` で、`bool` ではない(`IntNode` から取り出すので、`True` が紛れ込まない)。

## 15. `run_id_env` のゆるい読み取り

`watch` と `reset` は、`--run-id` が無いとき、定義全体を検証せず、`pipeline.run_id_env` だけを取り出す。

- 書式の決定(第 2.1 節)から段階 3(第 6 節の上限を含む)までは、定義の読み込みと同じに行う。段階 4・5 は行わない。
- 拡張子が対応していない、ファイルを読めない、大きさの上限を超える、YAML・JSON として読めない(上限を含む)、最上位がマップでない、`pipeline` がマップでない、キーが無い、文字列でない、名前の形(第 9.1 節)に合わない、のどれでも「無し」(`None`。実行時は `CONDUCTOR_RUN_ID`)。
- ほかの誤り(`format_version` の誤り、未知のキーなど)は無視する。壊れた入力でも異常終了しない(例外を投げず、`None` を返す)。
- ファイルの大きさの上限(第 3 節)は、この読み取りにも適用する(超えれば「無し」)。
- 例(YAML): `pipeline:\n  name: p\n  run_id_env: X_ID\n` → `X_ID`。`run_id_env: 5`、`"1A"`、`""` → 無し。`pipeline: 3` → 無し。空の入力 → 無し。

## 17. Python 固有の落とし穴(確認した事実の一覧)

この文書の規定のうち、Python の標準の関数をそのまま使うと誤るものを、まとめる(確認は CPython 3.14.10。3.10.7、3.15.2 でも同じ。差のあるものは備考)。

| 落とし穴 | 確認した事実 | この文書の規定 |
|----------|--------------|----------------|
| `bool` は `int` | `isinstance(True, int)`、`True == 1`、`{1: "a", True: "b"}` は 1 要素 | 種別で判定する(第 1 節) |
| `re` の `$` | `re.match(r"^[A-Za-z_][A-Za-z0-9_]*$", "A\n")` は一致する | `re.fullmatch` を使う(第 4.2、9.1、9.5 節) |
| `\d` | `str` に対する `\d` は全角数字 `"１"` に一致する | `[0-9]` を使う(第 4.2、9.5 節) |
| `int()`、`float()` が受け付ける形 | `int("１２")` は 12、`int("1_0")` は 10、`int(" 7 ")` は 7、`float("1_0")` は 10.0、`float("infinity")` は `inf` | 形を正規表現で確かめてから渡す(第 4.2 節) |
| 整数の桁数の制限 | 10 進の整数と文字列の変換は、4,300 桁まで(既定)。超えると `ValueError` | 桁数で先に範囲外にする(第 4.2、5.1、9.5 節) |
| `str.strip()`、`isspace()` | U+001C〜U+001F を空白として扱う(White_Space ではない) | 列挙した集合で判定する(第 1 節) |
| `os.path.splitext` | `".yaml"` の拡張子は空 | 自前で決める(第 2.1 節) |
| `str.lower()` | `"\u212a".lower()` は `"k"` | `isascii()` のときだけ使う(第 2.1 節) |
| テキストモード、`utf-8-sig` | CR だけの改行が LF になる、BOM が消える | バイトで読み、`"utf-8"` で厳格に復号する(第 3 節) |
| `json` モジュール | 重複は後勝ち、`NaN` を受理、位置は文法の誤りだけ、単独のサロゲートを受理、深い入れ子は `RecursionError`(3.10.7) | 使わず、自前で読む(第 5 節) |
| `float` の等価 | `nan != nan`、`0.0 == -0.0` | 木の等価はビット表現で比べる([09. 変換器](09-converter.md)) |
| 再帰の深さ | `sys.getrecursionlimit()` は 1,000 | 明示のスタックで走査する(第 6.1、6.4 節) |
| `str.encode("utf-8")` | 単独のサロゲートで `UnicodeEncodeError` | 木に単独のサロゲートを入れない(第 5、7.4 節 #12)。表示するときはエスケープする(第 12.2 節) |
| PyYAML の `compose` | アンカーの再定義を拒否する | 構文要素(`yaml.parse`)を使う(第 4.3 節) |
| PyYAML の C の拡張 | 環境で有無が違い、挙動も違う | 純粋な実装(`yaml.BaseLoader`)だけを使う(第 7.2 節) |
| PyYAML の行 | U+0085、U+2028、U+2029、CR だけの改行も改行として数える | `mark.index` から求める(第 13.1 節) |
| `dict` の順序 | 挿入順を保つ | 木のマップは `tuple` で持つ。検索用の `dict` は挿入順に作る(第 6.1 節) |
