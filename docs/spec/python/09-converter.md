# 09. 変換器(YAML と JSON の相互変換)

この文書は、`conductor convert <ファイル> --to <yaml|json>` の中身である変換器の振る舞いを定める。この文書だけで、Python でゼロから、同じ受理・拒否・出力・エラーを返す変換器を実装できることを目標とする。

- 変換器は、定義ファイルの**検証をしない**。変換した結果が `conductor` の定義([03. 定義ファイルの書式と検証](03-definition-format.md))として正しいかは見ない(任意の YAML / JSON のマップを変換する)。
- 副作用はない: ファイルへの書き込み、環境変数、プロセス、ネットワークに触れない(読むのは入力ファイル 1 つだけ)。変換結果は、文字列として返す(標準出力への書き出しは、[04. CLI](04-cli.md) の側の仕事)。
- 入力の値を、エラーの文に含めない(キー名だけを、エスケープと切り詰めをして、場所として示すことがある)。
- 確認できなかった点は「未確認」と書く。この文書の作成時に実際に動かして確かめた点は「確認」と書く(環境は [03 第 7.6 節](03-definition-format.md): CPython 3.10.7、3.14.10、3.15.2、PyYAML 6.0.3、macOS arm64)。
- 「必須」の挙動は、利用者から見える結果(受理/拒否、変換結果の文字列、エラーの種類・文言・行・場所)で、同じにしなければならない。「任意」「実装に任せてよい」と書いた点は、変換結果を読み戻した木が変わらない範囲で、実装が選んでよい。
- コマンドの引数・終了コードの全体は [04. CLI](04-cli.md) と [10. エラーと終了コード](10-errors-and-exit-codes.md)、メッセージの言語の選び方と標準出力の文字コードは [08. 出力と多言語対応](08-output-and-i18n.md) に従う。
- YAML と JSON の**読み取り**(文法、スカラーの型、アンカー、マージキー、重複キー、上限、木の型)は、[03](03-definition-format.md)の第 4〜7 節と**同じ**で、実装も共有する(`src/conductor/definition/` の木の読み取りを、`src/conductor/convert/` が呼ぶ)。この文書は、読み取りの上の差分(取り込み、最上位、拒否する数)と、書き出しを定める。
- Python の `int` は任意精度で、整数をそのまま正確に扱える。`float` は倍精度(IEEE 754 binary64)である。変換の本体では、標準ライブラリの `json`(`json.dumps`、`json.loads`)と、YAML ライブラリの書き出し(`yaml.dump`、`yaml.safe_dump`)を**使わない**(出力の文字列を、この規定に一致させるため。第 6.1、7、8 節)。

## 1. 入口と入出力

型と関数の骨格(例。本体は省略している。[03 第 6.1 節](03-definition-format.md)に書いた方法で、`mypy --strict` を通した。`Format` は [03 第 14.2 節](03-definition-format.md)と同じ):

```python
from __future__ import annotations

from dataclasses import dataclass
from typing import Literal, TypeAlias

Format: TypeAlias = Literal["yaml", "json"]  # 変換後の形式


@dataclass(frozen=True, slots=True)
class ConvertOk:
    text: str
    ok: Literal[True] = True


@dataclass(frozen=True, slots=True)
class ConvertFailed:
    error: ConvertError
    ok: Literal[False] = False


ConvertResult: TypeAlias = ConvertOk | ConvertFailed


def convert_file(path: str, to: Format) -> ConvertResult:
    """パスのファイルを読み、to の形式に変換した文字列を返す。"""


def convert_text(text: str, to: Format, file_label: str) -> ConvertResult:
    """ファイルに触れない。file_label はエラーの表示に使う名前。"""
```

| 入口 | 引数 | 戻り値 |
|------|------|--------|
| `convert_file` | 入力ファイルのパス、変換後の形式 | 成功: 変換結果の文字列、失敗: 変換の誤り(第 10 節) |
| `convert_text` | 文字列(復号済み)、変換後の形式、表示用のファイル名 | 同上(ファイルに触れない) |

- 変換後の形式は `yaml` または `json`。
- **入力の形式は、変換後の形式の反対**とみなす(`--to yaml` なら入力は JSON、`--to json` なら入力は YAML)。**拡張子は見ない**。`.yaml` の名前のファイルでも、`--to yaml` なら JSON として読む(YAML を JSON として読めば、JSON の文法の誤りになる)。
- 変換結果は、全部作ってから 1 つの文字列として返す。失敗のときは、出力は無い。
- 誤りは、例外ではなく戻り値で返す。例外は、実装の不具合にだけ使う。
- `conductor convert` は、成功したら結果を標準出力に 1 回で書く。**変換結果の改行は LF だけであり、書き出しで CRLF に変わってはならない**(確認: macOS ではテキストモードの標準出力が改行を変換しない。Windows のテキストモードの標準出力は、`\n` を `\r\n` に変える。したがって、標準出力へは、`sys.stdout.buffer` に UTF-8 のバイト列で書く、または改行の変換を切る。実機での確認は Windows では未確認。[08](08-output-and-i18n.md)に従う)。失敗したら標準出力は空で、標準エラーに原因を出し、終了コード 67 で終わる([04](04-cli.md)・[10](10-errors-and-exit-codes.md))。

## 2. 処理の流れと失敗の順序

```
Intake → 読み取り(Parse) → 展開と写し取り(Resolve) → 最上位の確認(RootCheck) → 書き出し(Write)
```

失敗は、次の順で最初に見つかったものを 1 件だけ返す(以降は実行しない)。

| 順 | 段階 | 失敗 |
|----|------|------|
| 1〜2 | Intake: 開く(存在しない → `fileMissing`、権限など → `unreadable`) | 第 3 節 |
| 3 | Intake: 通常のファイルでない → `unreadable`、大きさが 1 MiB を超える → `tooLarge` | 第 3 節 |
| 4 | Intake: 上限 + 1 バイトまでの読み取りと UTF-8 の確認 → `unreadable` | 第 3 節 |
| 5 | Parse: 文法の誤り → `syntax`。JSON は、先頭から読んで最初に見つかった文法の誤り・重複キー。YAML は、ライブラリで全文書を読み終えてからの文法の誤り | 第 4 節 |
| 6 | Resolve(入力に現れる順で、最初に見つかったもの): 複数の文書(YAML)・タグ・非文字列キー・重複キー・再帰するアンカー・マージキーの誤り(いずれも `syntax`)、要素数・文字の大きさの上限(`tooLarge`)、入れ子の深さの上限(`syntax`) | 第 4 節 |
| 7 | RootCheck: 最上位がマップでない → `rootNotMap` | 第 4.3 節 |
| 8 | Resolve で記録した、表せない値のうち、入力に現れる順で最初のもの → `unrepresentable` | 第 5 節 |

- 順 6 の失敗は、順 8 より優先する(先に表せない数があっても、上限超過が返る)。
- 順 7 は順 6 より後。最上位がマップでない入力に順 6 の失敗が含まれるときは、順 6 の失敗が先に返る(例: `- &a [*a]\n` は、`rootNotMap` ではなく、再帰の `syntax`。確認)。実装は、順 6 の走査を終えてから最上位を確認する。
- 順 3 は順 4 より先: 1 MiB を超え、かつ UTF-8 でない入力は `tooLarge`。順 3 は順 5 より先: 1 MiB を超える入力は、中身が壊れていても `tooLarge`。
- 順 5(文法)は、順 6(複数の文書など)より先。たとえば `a: 1\n---\nb: [1\n` は、2 つ目の文書の文法の誤りを `syntax` として返す(確認: 4 行目)。

## 3. 取り込み(Intake)

| 順 | 条件 | `kind` | 理由(日本語の原文) |
|----|------|--------|----------------------|
| 1 | ファイルを開こうとして「存在しない」 | `fileMissing` | `指定の場所にファイルがありません` |
| 2 | ファイルを開けない。権限がない | `unreadable` | `読み取りの権限がありません` |
| 2' | 同、メタデータで通常のファイルでないと分かるとき(ディレクトリを開く操作自体は成功する OS など) | `unreadable` | `通常のファイルではありません` |
| 2'' | 同、その他の失敗 | `unreadable` | `読み取りに失敗しました` |
| 3 | 開いたファイルの情報(種別・大きさ)が取れない | `unreadable` | 権限なら `読み取りの権限がありません`、他は `読み取りに失敗しました` |
| 3' | 通常のファイルでない(ディレクトリなど) | `unreadable` | `通常のファイルではありません` |
| 4 | 大きさが 1 MiB(1,048,576 バイト)を超える | `tooLarge` | `入力が上限(1 MiB)を超えています` |
| 5 | 読み取り結果が上限を超える(順 4 のあとに大きくなった場合) | `tooLarge` | 同上 |
| 6 | 読み取りの途中の失敗 | `unreadable` | 権限なら `読み取りの権限がありません`、他は `読み取りに失敗しました` |
| 7 | UTF-8 として読めない | `unreadable` | `UTF-8 として読めません` |

実装(Python)の対応:

- 順 1〜2'': `os.open(path, os.O_RDONLY | O_NONBLOCK | O_CLOEXEC | O_BINARY)`(`O_NONBLOCK`、`O_CLOEXEC`、`O_BINARY` は、`getattr(os, "名前", 0)` で、無い OS では 0 にする)。失敗したとき、`FileNotFoundError` なら順 1、`PermissionError` なら順 2、`IsADirectoryError`(ディレクトリを開こうとした)なら順 2'、それ以外(`NotADirectoryError`、`OSError`。パスに NUL を含むときの `ValueError` を含む)は順 2''。
  - **`O_NONBLOCK` が必須**である(確認: macOS で、名前つきパイプ(FIFO)を `open(path, "rb")` で開くと、書き込む側が現れるまで**ブロックして戻らない**。`os.open` に `O_NONBLOCK` を付けると、すぐに開け、`fstat` が「通常のファイルでない」を返す。通常のファイルでは、`O_NONBLOCK` は読み取りに影響しない)。
  - **`O_BINARY` が必須**である(Windows の `os.open` は、既定でテキストモードで、CRLF を LF に変え、Ctrl-Z を終端とする。バイトのまま読むために付ける。Windows では未確認)。
  - 確認: ディレクトリは、`open(path, "rb")` なら `IsADirectoryError`(errno 21)、`os.open(path, os.O_RDONLY)` なら成功する(`fstat` が「ディレクトリ」を返す。順 3')。どちらでも、利用者から見える結果(理由 `通常のファイルではありません`)は同じ。
- 順 3・3'・4: 開いた記述子の `os.fstat(fd)`(開いたものの情報)。失敗は順 3(`PermissionError` なら権限、他は失敗)。`stat.S_ISREG(st.st_mode)` が偽なら順 3'。`st.st_size` が 1,048,576 を超えれば順 4。
- 順 5・6: `os.read(fd, n)` で、**上限 + 1 バイトまで**を読む(`os.read` が空のバイト列を返すか、合計が上限 + 1 バイトに達するまで繰り返す。1 回の `os.read` が、要求より少なく返すことがあるので、繰り返す)。**ファイル全体を一度に読む `Path.read_bytes()` は使わない**。記述子は、`try`/`finally` で `os.close` する。
- 順 7: `data.decode("utf-8")`([03 第 3 節](03-definition-format.md)と同じ。**`"utf-8-sig"` は使わない**。厳格な復号で、`UnicodeDecodeError` なら順 7)。

- 先にファイルを開き、**開いたもの**の情報で通常のファイルかと大きさを調べる。開いてから調べるので、調べたあとにファイルが差し替わっても、読み取りの結果と食い違わない。
- **ちょうど 1 MiB は受理**し、1 バイトでも超えれば `tooLarge`。
- 権限のない(モード 000 の)ファイルは、大きさにかかわらず `unreadable`(開く操作が先に失敗するので、1 MiB を超えるモード 000 のファイルも `unreadable`)。ただし、権限の確認を迂回する利用者(root など)では、この結果にならない(その場合は、通常どおり読める)。確認(macOS): モード 000 のファイルは、`os.open` が `PermissionError`(errno 13)。
- 行番号は付かない。
- 空のファイル(0 バイト)は、空の入力として次へ進む(YAML は `rootNotMap`(`文書が空です`)、JSON は `syntax`)。
- OS による権限・種別の判定の細部(Windows での `OSError` の `errno`・`winerror` など)は、実装に任せてよい(Windows での値は未確認)。必須なのは、上の表の条件の順序と、各理由の文言である。
- 定義ファイルの取り込み([03 第 3 節](03-definition-format.md))とは、上限超過と UTF-8 の理由の文言が違う(ここは `入力が上限(1 MiB)を超えています`、`UTF-8 として読めません`)。また、定義ファイルと違い、**拡張子の確認はしない**。

## 4. 読み取り

### 4.1 受理する文法

- `--to yaml`(入力は JSON)のとき: JSON は、[03 第 5 節](03-definition-format.md)の形式(RFC 8259 の厳格な形式。コメント・末尾カンマ・重複キー・対にならないサロゲートの拒否を含む)で、[03 第 5.3 節](03-definition-format.md)の自前の字句・構文解析で読む。標準ライブラリの `json` は使わない。
- `--to json`(入力は YAML)のとき: YAML は、[03 第 4 節](03-definition-format.md)の部分集合を、[03 第 7 節](03-definition-format.md)のライブラリの設定と補完で読む。要点: YAML 1.2 のコアスキーマ、ブロックとフローのマップ・リスト、引用符なしと引用符つきとブロックのスカラー、コメント(捨てる)、アンカーとエイリアス(展開する)、マージキー `<<`(展開する)。**拒否**: タグ(標準のタグも)、複数の文書、非文字列のキー、重複したキー、タブのインデント。さらに、[03 第 4.1 節](03-definition-format.md)の「狭い」点も同じ(U+0085・U+2028・U+2029・CR だけの改行・制御文字・タブを区切りに使う書き方・ASCII 英数字と `-`、`_` 以外を含むアンカー名は、`syntax`)。
- 読み取りの誤りの種類・理由・行は、[03 第 12.3 節](03-definition-format.md)の `syntax`/`tooLarge` の理由の表と同じ(`YAML の文法に誤りがあります`、`JSON の文法に誤りがあります`、`キーが重複しています`、`キーは文字列で書きます`、`タグは使えません`、`複数の文書は書けません(1 ファイルに書ける文書は 1 つです)`、`アンカーが自分自身を含んでいます`、`マージキーの値がマップではありません`、`入れ子が深すぎます(上限は 32 段)`、`要素数が上限(100000)を超えています`、`文字の大きさが上限(16 MiB)を超えています`)。行の出し方も、[03 第 13 節](03-definition-format.md)と同じ。
- 入力の先頭の BOM(U+FEFF)は受理される(無視する)。LF・CRLF の両方を受理する。
- YAML の対にならないサロゲートのエスケープ(`"\ud800"`)は、`syntax`(`YAML の文法に誤りがあります`。[03 第 7.4 節](03-definition-format.md) #12)。

### 4.2 上限(03 と同じ)

| 上限 | 値 | 超過したときの失敗 |
|------|----|--------------------|
| 入力の大きさ | 1 MiB | `tooLarge`(Intake) |
| 要素数 | 100,000 | `tooLarge` |
| 文字の大きさ | 16 MiB | `tooLarge` |
| 入れ子の深さ | **根のマップを数えず 32 段まで** | `syntax`(33 段目) |

数え方は [03 第 6.3 節](03-definition-format.md)の規定のとおり(要素数にはキーも数える、エイリアスは参照のたびに参照先を数える、文字の大きさは値のバイト数など)。ここでは、JSON の入力にも同じ上限があり、同じ境界になる(例: `{"a":[0,0,...]}` で、0 を n 個並べるとき、n = 99,997 まで受理、99,998 で失敗。確認: YAML、JSON とも)。

数千〜数十万段の入れ子の入力、アンカーの入れ子による爆発的な展開、マージキーによる増幅は、いずれも、プロセスを落とさず、30 秒以内に、上の上限の失敗(または `syntax`)で終わること(必須)。確認(試作。[03 第 7.5 節](03-definition-format.md)の表): `[` を 1 MiB 並べた YAML は約 1.1 秒、アンカーの入れ子(40 段。要素数の上限)は約 0.2 秒、マージキーを重ねた増幅(8 段の参照を 3 重)は 0.01 秒未満、JSON の `[` を 1 MiB 並べた入力は約 1.7 秒。読み取りの途中の入れ子の上限(1,000 段。[03 第 6.4 節](03-definition-format.md))も、同じ。

### 4.3 最上位の確認(RootCheck)

| 入力 | 結果 |
|------|------|
| 最上位がマップ(YAML の `{a: 1}`、JSON の `{}` を含む) | 次へ |
| YAML で、文書が 0 個(空の入力、コメントと空行だけ) | `rootNotMap`、理由 ``文書が空です``、行なし |
| 最上位が、マップでない(YAML のリスト・スカラー・null(`---` だけの文書)、JSON の配列・数・文字列・`null`) | `rootNotMap`、理由 ``最上位がマップではありません``、行は最上位のノードの位置の行 |

- 定義ファイルと違い、**空の入力や null の文書を、空のマップとして扱わない**(変換器は、中身のない入力をマップにしない)。
- JSON で、空の入力(0 バイト、空白だけ)は、`rootNotMap` ではなく `syntax`(JSON は値が 1 つ必要)。
- 空のマップ(`{}`)は受理され、変換できる(第 8 節)。
- `---` だけの文書(最上位が null)の行は、`---` の行(1 行目。[03 第 13.2 節](03-definition-format.md)の、`---` だけの文書の根の位置。確認)。
- 実装の注意: 定義の読み込みでは、文書が 0 個、または最上位が null のとき、空のマップにして続ける([03 第 6.7 節](03-definition-format.md))。変換器は、同じ読み取りの関数(`read_tree`)を使い、その手前の結果(`TreeOk.root` が `None`(文書が 0 個)、`NullNode`(最上位が null))を見分けられる形で受け取る。

### 4.4 内部表現

読み取りと展開の結果は、[03 第 6.1 節](03-definition-format.md)の木にする。

| 種類(`kind`) | 内容 |
|--------------|------|
| `null` | 値なし |
| `bool` | `bool` |
| `int` | `int`(64 ビット符号つき整数の範囲) |
| `hugeInt` | 範囲外の整数(値は持たない。第 5 節で拒否) |
| `float` | `float`(IEEE 754 binary64)と、`overflow` の印 |
| `string` | `str`(対にならないサロゲートを含まない) |
| `seq` | 木の `tuple` |
| `map` | `MapEntry`(文字列のキー, 木)の `tuple`。**キーは重複しない。記述順を保つ** |

- 変換器は、`hugeInt` と、`overflow` の印のある浮動小数を、第 5 節のとおり記録して失敗させる。
- **内部表現の等価**(往復の確認に使う): 型が違えば不等(`"1"` と 1、1 と 1.0、`true` と `"true"`、null と `"null"`。**`True` と `1` を等しいと見なさない**: ノードの種別が違えば不等とし、Python の `==` に任せない)。整数は、`int` の値が等しいこと。浮動小数は、ビット表現が同じなら等しい(`struct.pack("<d", a) == struct.pack("<d", b)`。NaN どうしは等しい(`math.isnan` が両方で真)。**`0.0` と `-0.0` は異なる**。Python の `==` は、`0.0 == -0.0` が真で、`nan == nan` が偽なので、使わない)。マップは、**キーの順序を無視**して比べる。リストは順序を含めて比べる。

## 5. 表せない値(`unrepresentable`)

展開の途中で見つけた「相手の形式で表せない値」のうち、**入力に現れる順で最初の 1 つ**だけを記録し、走査の終了後に返す(上限超過・マージキーの誤りなど、第 2 節の順 6 の失敗は、これより優先する)。展開の走査は、捨てられるマージのエントリも訪れるので、そこにある表せない値も、記録の対象である。

| 値 | 理由(日本語の原文) | 対象の入力 | 例 |
|----|----------------------|------------|-----|
| 範囲外の整数(64 ビット符号つき整数に収まらない。種別 `hugeInt`) | `数値が表せる範囲を超えています` | JSON、YAML | `{"a": 9223372036854775808}`、`a: 0xFFFFFFFFFFFFFFFFFF` |
| 範囲を超える浮動小数(`overflow` の印) | `数値が表せる範囲を超えています` | JSON、YAML | `{"a": 1e400}`、`a: 1e999`、`a: -1e999` |
| NaN、無限大(YAML の `.nan`、`.inf`、`-.inf`、`+.inf` など。`overflow` の印がない、値が NaN・±`inf` の浮動小数) | `NaN と無限大は JSON で表せません` | YAML(`--to json` のときだけ) | `a: .nan`、`a: [1, .inf]` |
| 長すぎるキー(1,024 文字を超える。文字数で数える) | `キーが長すぎます(上限 1024 文字)` | JSON(`--to yaml` のときだけ。YAML の単純キーの上限のため) | 1,025 文字のキー |

- 失敗の表示: `kind` は `unrepresentable`、行なし。**場所(`key_path`)**がつく。
- **場所の書式**: キーを `.` でつなぐ。リストの要素は `[添字]`(0 始まり。直前のキーに続けて、`.` なしで書く)。リストが最上位に来ることはない(最上位はマップ)。キー名は、制御文字・書式文字をエスケープし(`\n`、`\r`、`\t`、その他は `\u{16進小文字}`。対象の文字と切り詰めは [03 第 12.2 節](03-definition-format.md)と同じ)、64 文字(エスケープ後の文字数。コードポイントで数える)を超えると、64 文字で切って `…` を付ける。例: `job[1].note`、`a.b`、`a[2]`。マージで取り込まれる値の中の表せない値の場所は、`<<` のキーを経由した経路(`a.<<.x`)とする(この仕様の決定)。エイリアスの中の表せない値の場所は、エイリアスを書いた場所の経路とする。
  - 実装の指針: 経路は、走査の明示のスタックから、**最初の 1 件を記録するときだけ**文字列にする(すべてのノードで作らない)。
- **長すぎるキーの検査**: 内部表現のキー(エスケープを解いた後の文字列)の文字数(`len(key)`。Python の `len` は、コードポイントの数である)で判定する。1,024 文字ちょうどは受理。
- YAML の NaN・無限大は、`--to json` のときだけ拒否する。`--to yaml` の入力は JSON なので、NaN・無限大は文法として存在しない。
- 範囲外の数は、変換後の形式が YAML でも JSON でも拒否する(内部表現が 64 ビットのため)。
- 入力に現れる順の例: `a: 1\njob:\n  - id: x\n  - id: y\n    note: .nan\n  - z: .inf\nlater: .nan\n`(`--to json`)は、最初の `job[1].note` を返す(確認)。

読み取り(Resolve)の関数は、変換器のために、記録の機能を持つ(例):

```python
@dataclass(frozen=True, slots=True)
class Unrepresentable:
    reason: str
    key_path: str
```

[03 第 14.2 節](03-definition-format.md)の `read_tree(text, fmt, file_label, convert_to=...)` が、変換器のとき(`convert_to` が `"yaml"` か `"json"`)に、最初の `Unrepresentable` を `TreeOk.first_unrepresentable` に入れて返す。定義の読み込みでは `convert_to=None` で、記録しない。

## 6. 書き出し(共通)

- 書き出しの前に、最上位は(必ず)マップになっている(第 4.3 節)。
- **各マップのキーは、入力の記述順のまま出力する**(キーをソートしない)。マージキーで取り込まれたエントリは、`<<` のエントリのあった位置に並ぶ([03 第 4.5 節](03-definition-format.md))。リストの順序も保たれる。コメントは捨てられる。
- 変換結果の最後は改行(LF)で終わる。改行は LF だけ。
- 木の深さは、読み取りの上限により 33 以下(根を含む)だが、**書き出しも、関数の再帰を使わない明示のスタックで書くことが望ましい**(Python の再帰の上限は、既定で 1,000。深さ 33 の再帰は上限に遠いが、実装が `RecursionError` に依存しないために)。再帰で書いてもよい(深さ 33 では、上限に達しない)。
- 出力は、断片の `list[str]` に溜めて、最後に `"".join(...)` で 1 つの文字列にする(任意。性能のため。`+=` の繰り返しは避ける)。

### 6.1 浮動小数の書き方(YAML と JSON で共通)

内部表現の浮動小数を、**必ず浮動小数と読み戻される形**で書く。

- NaN、+∞、-∞: YAML は `.nan`、`.inf`、`-.inf`。JSON は書けない(第 5 節で拒否済み)。
- それ以外は、往復で同じ値になる**最短の桁数**の 10 進で書く。Python の `repr(float)`(`str(float)` も同じ)は、最短の桁数で、往復できる文字列を返す(Python の規定。確認: `float(repr(x)) == x`)。次の規則で組み立てる。
  - `-0.0` は `-0.0`(`repr(-0.0)` が `"-0.0"`。確認)。
  - 絶対値が 1e16 以上、または 1e-4 未満(0 を除く)のときは**指数形**: `repr(x)` の結果の、指数部の符号 `+` を取り除き、指数部の先頭の 0 を取り除く(**`repr` は `1e+16`、`1e-05`、`1.5e-07` と書く**。`1e+16` → `1e16`、`1e-05` → `1e-5`、`1.5e-07` → `1.5e-7`、`1.7976931348623157e+308` → `1.7976931348623157e308`)。仮数は、2 桁以上なら `d.ddd`、1 桁なら `d`(`repr` がそのように書く)。例: `1e16`、`1e21`、`1e-5`、`1.5e-7`、`1.2345678901234568e17`、`5e-324`、`1.7976931348623157e308`。
  - それ以外は、10 進の小数表記で、整数値でも必ず小数部を付ける(`repr` がそのように書く: `1.0`、`100.0`)。確認: 絶対値が 1e-4 以上 1e16 未満の範囲では、`repr(x)` は指数形にならない(Python が指数形に切り替えるのは、1e16 以上と 1e-4 未満で、この仕様の閾値と一致する)。`1e15` は `1000000000000000.0`、`0.0001` は `0.0001`、`0.1` は `0.1`。
  - 実装は、`repr(x)` に `e` が含まれるかで分け、含まれるときだけ、指数部を整える(`mantissa, exponent = repr(x).split("e")`。指数部は、符号 `-` を残し、`+` と先頭の 0 を落とす)。それ以外は `repr(x)` をそのまま使う。
- 確認: 最短の桁(`repr` から得た桁)に、この節の置き方の規則(指数形の閾値、`.0` の付与、指数部の整形)を、別の実装で当てはめた結果と、`repr` を整えた結果が、ランダムな 20 万個の浮動小数(ビット列から作ったもの。0、`-0.0`、`5e-324`、最大値、`1e15`、`1e16`、`1e21`、`1e-5`、`1e-4` などの境界を含む)で一致した(CPython 3.14.10)。
- 指数形(`1e16`)は、JSON でも YAML でも、読み戻すと浮動小数になる(JSON は指数部を持つ数、YAML は [03 第 4.2 節](03-definition-format.md)の順 7)。
- 確認した例: `1.0` → `1.0`、`100.0` → `100.0`、`1e15` → `1000000000000000.0`、`1e16` → `1e16`、`1e21` → `1e21`、`1e-5` → `1e-5`、`0.0001` → `0.0001`、`0.00009999` → `9.999e-5`、`0.1` → `0.1`、`-0.0` → `-0.0`、`9999999999999998.0` → `9999999999999998.0`、`0.30000000000000004` → `0.30000000000000004`、`12345678901234567.0`(入力。値は 12345678901234568)→ `1.2345678901234568e16`。
- `json.dumps` は、浮動小数を `1e+16`、`1.5e-07` と書き、NaN を `NaN` と書く(確認)ので、**使えない**。

### 6.2 整数・真偽値・null

- 整数: 10 進(64 ビット符号つき整数。`-9223372036854775808` を含む)。**`str(int)` で書く**(`format` や `f"{x:d}"` でもよい)。桁は 19 桁以下なので、整数と文字列の変換の桁数の制限(4,300 桁。[03 第 4.2 節](03-definition-format.md))に当たらない。
- 真偽値: `true` / `false`(`str(True)` は `True` で、使えない。ノードの種別から `"true"`、`"false"` を選ぶ)。
- null: `null`。

### 6.3 整数の精度と Python の `int`(決定)

Python の `int` は任意精度で、64 ビット符号つき整数の範囲(±9.22 × 10^18)の整数を、そのまま正確に保てる。浮動小数への変換で桁が落ちることはない。次を**必須**とする。

| 場面 | 規定 |
|------|------|
| 入力の整数の字句(YAML の 10 進・`0x`・`0o`、JSON の整数) | 数字の列から `int(数字, 基数)` で値を得る([03 第 4.2・5.1 節](03-definition-format.md))。範囲を超えるものは、`int()` を呼ばずに(桁数で)`hugeInt` にする(桁数の制限に当たらないため) |
| 木 | 整数は `IntNode`(`int`)。浮動小数は `FloatNode`(`float`)。**型が違えば別の値**(JSON の `1` と `1.0`、YAML の `1` と `1.0` は、変換でも区別する)。真偽値は `BoolNode`(`int` ではない) |
| 出力 | 整数は `str(int)`。浮動小数は第 6.1 節 |
| 浮動小数の書き方の整数値 | 値が整数でも、書き方に小数部か指数部があれば浮動小数。2^53 を超える値は、`float` の最も近い値になり、桁が変わりうる(`9007199254740993.0` → 値 9007199254740992.0 → 出力 `9007199254740992.0`。`12345678901234567.0` → `1.2345678901234568e16`)。これは浮動小数の性質であり、エラーにしない |
| 比較・検査 | 範囲の比較は `int` どうしで行う(`-(2**63) <= v <= 2**63 - 1`)。`float` に変換してから比べない |

- 例: JSON `{"a": 9007199254740993}`(2^53 + 1)→ YAML `a: 9007199254740993`(値が保たれる。`float` を経由すると 9007199254740992.0 になって誤る)。YAML `a: 9223372036854775807` → JSON `"a": 9223372036854775807`。YAML `a: -9223372036854775808` → JSON でも同じ。`{"a": 9223372036854775808}` と `a: 9223372036854775808` は、`unrepresentable`(範囲外の整数)。

### 6.4 文字列と対にならないサロゲート(決定)

- Python の `str` は、対にならないサロゲート(U+D800〜U+DFFF)を持てる(確認: `chr(0xD800)` は作れる。`"\ud800".encode("utf-8")` は `UnicodeEncodeError`)。**変換器の木の文字列は、対にならないサロゲートを含まない**。入力が UTF-8 のバイト列から厳格に復号されること([03 第 3 節](03-definition-format.md))、JSON の `\ud800` と YAML の `"\ud800"` のエスケープが拒否されること([03 第 5、7.4 節](03-definition-format.md))、前半と後半のエスケープが続けて書かれた JSON の `\ud83d\ude00` が 1 つの文字(U+1F600)に結合されること、によって保たれる。したがって、書き出しの文字列は、常に UTF-8 に符号化できる。
- 書き出しは、`str` を**コードポイントごと**に走査する(`for ch in s`。UTF-16 のコード単位ではない。絵文字などの BMP 外の文字は、1 要素として得られる)。
- 変換結果の文字列を標準出力へ書く符号化(UTF-8)と、`errors` の扱いは [08](08-output-and-i18n.md) に従う。変換結果には単独のサロゲートが無いので、`errors="strict"` でも失敗しない。変換の誤りの表示の `<file>` には、OS から `surrogateescape` で得た文字列(U+DC80〜U+DCFF)が入りうるので、第 10 節のとおり、表示の前にエスケープする。

## 7. JSON の書き出し(`--to json`)

**すべて必須**(出力の文字列が一致する)。

**レイアウト**(インデントは半角スペース 2 個。タブは使わない。行末に空白を残さない):

- 空のマップ: `{}`。空のリスト: `[]`。
- 空でないマップ: `{` + 改行、各エントリを `<インデント + 2>"<キー>": <値>` で、エントリの間を `,` + 改行で区切り、最後のエントリの後に改行、`<インデント>}`。キーと値の間は `": `(コロンの後に半角スペース 1 個)。
- 空でないリスト: `[` + 改行、各要素を `<インデント + 2><値>` で、`,` + 改行で区切り、最後の後に改行、`<インデント>]`。**要素は 1 行に 1 つ**(短い配列も 1 行にまとめない)。
- 最上位の値の後ろに LF を 1 個付ける。

**文字列(値もキーも同じ)**: `"` で囲み、次のとおりエスケープする。

| 文字 | 出力 |
|------|------|
| `"` | `\"` |
| `\` | `\\` |
| U+000A | `\n` |
| U+000D | `\r` |
| U+0009 | `\t` |
| U+0008 | `\b` |
| U+000C | `\f` |
| そのほかの U+0000〜U+001F、U+007F〜U+009F、U+2028、U+2029、U+FEFF、U+FFFE、U+FFFF | `\u` + 16 進の**小文字** 4 桁(例: `\u001b`、`\u007f`、`\u2028`) |
| それ以外(`/`、`<`、`>`、`&`、非 ASCII、絵文字を含む) | そのまま書く(エスケープしない) |

- **`json.dumps` は使えない**(確認: `ensure_ascii=False` でも、U+007F、U+2028、U+FEFF をエスケープせずにそのまま出す。`ensure_ascii=True` は非 ASCII をすべて `\u` にする。どちらも、この規定と違う)。自前で書く(必須)。数・真偽値・null は、第 6 節のとおり。

JSON の出力例(YAML の入力 `a: 1.5e-7\nb: [1, [2, []], {}]\nc: "x\ty"\n`。確認):

```json
{
  "a": 1.5e-7,
  "b": [
    1,
    [
      2,
      []
    ],
    {}
  ],
  "c": "x\ty"
}
```

## 8. YAML の書き出し(`--to yaml`)

自前の書き出し(ブロック形式の YAML)。ライブラリの書き出し(`yaml.dump`、`yaml.safe_dump`、`yaml.emit`)は**使わない**(出力の文字列を、この規定に一致させるため)。**すべて必須**(出力の文字列が一致する)。

**レイアウト**

- 最上位のマップが空: `{}` + 改行。空でなければ、各エントリを書く。
- マップのエントリ: `<キー>: <値>`。値がスカラー、空のリスト(`[]`)、空のマップ(`{}`)なら同じ行に書く。値がコレクションなら、`<キー>:` のあと改行し、子を**2 スペース深く**書く。
- リストの要素: `- <値>`。要素がスカラー・`[]`・`{}` なら同じ行。要素がマップなら、最初のエントリを `- ` と同じ行に書き、残りのエントリを、`- ` の内容の位置(ダッシュの桁 + 2)に揃える。要素がリストなら、`- - 1`(最初の要素を同じ行)の形で、残りの要素も、内容の位置に揃える。
- リストは、親のキーより 2 スペース深く書く(`job:` の次の行に `  - id: a`)。
- インデントは 2 スペース。タブは使わない。行末に空白を残さない。

**スカラー**

- 整数・真偽値・null・浮動小数: 第 6 節のとおり。
- 文字列(値もキーも同じ規則): 次の条件を**すべて**満たすときだけ、引用符なし(plain)で書く。1 つでも外れたら、二重引用符で囲む。
  1. 空でない。
  2. 先頭が、ASCII の英字(`A-Za-z`)、`_`、`/` のどれか(数字・`-`・`.` などで始まるものは、数値や記号に読まれうるので引用符)。
  3. 末尾が空白でない。
  4. すべての文字が、ASCII の英数字、`_`、`-`、`.`、`/`、半角スペース のどれか。
  5. 半角スペースが 2 つ連続しない。
  6. YAML 1.1 の語(`y`、`Y`、`yes`、`Yes`、`YES`、`n`、`N`、`no`、`No`、`NO`、`on`、`On`、`ON`、`off`、`Off`、`OFF`)でない。
  7. [03 第 4.2 節](03-definition-format.md)の規則で解決して文字列になる(`true`、`false`、`null`、`Null`、`NULL`、`True` などは引用符)。この判定は、読み取りと**同じ関数**(引用符なしのスカラーの型の判定)を呼んで行う。
  - 条件 1〜5 は、正規表現 `[A-Za-z_/][A-Za-z0-9_./ -]*` に **`re.fullmatch`** で一致し、末尾が半角スペースでなく、`"  "`(半角スペース 2 つ)を含まない、と言い換えられる(**`re.match` + `$` を使わない**: `$` は末尾の改行の直前にも一致し、`"a\n"` が通ってしまう。[03 第 4.2 節](03-definition-format.md))。
  - plain になる例: `hello`、`echo hello world`、`/bin/run.sh`、`a-b_c.d`、`prog build --release`、`inf`、`_x`、`a b`。引用符になる例: `yes`、`no`、`on`(キー `on` は `"on": warning`)、`off`、`y`(キー `y` は `"y": []`)、`n`(キー `n` は `"n": null`)、`true`、`null`、`~`、`1`、`-1`、`1.5`、`0x1F`、`` (空)、` lead`、`trail `、`<<`、`a: b`、`a #b`、`.nan`、`1e3`、`Yes`、`Y`、`@end`、`-a`、`x  y`、`a `、非 ASCII を含む文字列(`"夜間バッチ"`、`"é key"`)。
- 二重引用符の中のエスケープ: `"` → `\"`、`\` → `\\`、改行 → `\n`、復帰 → `\r`、タブ → `\t`。そのほかの制御文字(U+0000〜U+001F、U+007F〜U+009F)と U+2028、U+2029、U+FEFF、U+FFFE、U+FFFF は `\uXXXX`(16 進の**大文字** 4 桁。例: `\u001B`、`\u007F`)。その他の文字(非 ASCII、絵文字を含む)は、そのまま書く。例: `"a\u2028b \u007F é 😀"`。(JSON の書き出しは小文字の 16 進。第 7 節。)
- キー `<<` は、必ず引用符で囲む(マージキーとして読み戻されないように。上の plain の規則で、`<` で始まるので引用符になる)。
- 非 ASCII を含む文字列は、常に二重引用符で囲む(値もキーも)。
- **長いキー**: 1,024 文字を超えるキーは書き出せない(第 5 節で `unrepresentable` として拒否済み。YAML のライブラリが、ブロックのマップの 1,025 文字の単純キーを拒否するため。[03 第 4.1 節](03-definition-format.md))。

例(JSON の入力を `--to yaml` で変換した出力。確認):

```yaml
format_version: 1
pipeline:
  name: nightly
job:
  - id: extract
    command: extract --all --since yesterday
    warning_exit_codes:
      - 3
      - 4
  - warning_exit_codes:
      - 3
      - 4
    id: transform
    command: "transform \"in dir\" $HOME"
    success_exit_codes:
      - 0
```

入れ子のリストとマップの例(入力 JSON `{"a": [[1,2],[3,[4]]], "b": [{"x":1,"y":[{"z":2}]}]}`。確認):

```yaml
a:
  - - 1
    - 2
  - - 3
    - - 4
b:
  - x: 1
    "y":
      - z: 2
```

空のマップ、空のリスト、null、浮動小数を含む入力 JSON `{"x": {}, "y": [], "n": null, "f": 1.0, "e": 1e21}` は次になる(確認。キー `y` と `n` は YAML 1.1 の語なので、引用符つき)。

```yaml
x: {}
"y": []
"n": null
f: 1.0
e: 1e21
```

空の入力に近い最小の入力 `{}` は、`{}` + 改行になる。

## 9. 往復の保証

- 保証するのは、**木の等価**である(第 4.4 節。マップのキーの順序は無視、リストの順序は有意)。入力を読んだ内部表現と、変換結果を(変換後の形式として)読み戻した内部表現が、等しい。さらに、変換結果を元の形式へ戻した結果の木も、元の木と等しい。
- 保証されないもの: コメント、アンカー・エイリアス・マージキー(展開される。出力に `<<`・`*`・`&` は残らない)、引用符・文字列の書き方(plain と引用符の別、ブロックスカラーの形)、数値の書式(`0x1F` → `31`、`007` → `7`、`1e3` → `1000.0`、JSON の `-0` → `0`)、`1_000` のような YAML の文字列の、他の形式での再解釈(YAML の `1_000` は文字列なので、`"1_000"` になる)。
- 往復で保たれることが確認されている値: 文字列(`yes`、`no`、`on`、`off`、`1`、`1.5`、`null`、`~`、`true`、`false`、`<<`、空文字列、前後に空白がある文字列、`a: b`、改行・タブ・引用符・バックスラッシュ・制御文字・日本語・絵文字を含む文字列、長い文字列)、整数(64 ビット符号つき整数の最小値・最大値、0、2^53 + 1 などの 2^53 を超える整数)、浮動小数(`1.0`、`-0.0`、`1.5e-7`、`1e21`、`0.1`、`5e-324`、最大値。NaN、±∞ は YAML 内だけ)、真偽値、null、空のリスト・空のマップ、入れ子のリスト、リストの中のマップ、型が混在するリスト、`on` キー。
- 確認(試作): ランダムに作った 1 万個の木(深さ 4 まで。文字列は、`yes`・`~`・`<<`・`a: b`・`#`・`:`・`,`・`[`・`{`・`&`・`*`・`!`・`|`・`>`・`'`・`"`・`%`・`@`・`` ` ``・`\`・タブ・改行・CR・U+0085・U+2028・U+FEFF・U+FFFE・U+007F・制御文字・`é`・日本語・絵文字・全角空白などの文字と、キーワードの語からランダムに組み立てたもの。浮動小数は、ビット列からランダムに作ったものと境界の値。整数は、範囲の両端、2^53 + 1、ランダム)を、JSON と YAML に書き出し、読み戻した木が、元の木と等しかった(不一致 0 件。読み取りは、PyYAML 6.0.3 と自前の JSON の読み取り。CPython 3.10.7、3.14.10、3.15.2 で実行)。
- ただし、**NaN と無限大を含む YAML は、JSON に変換できない**(第 5 節)。また、**範囲外の数**は、どちらにも変換できない。

## 10. エラーの構造と表示

型の骨格(例。種類 `kind` は `Literal`。`mypy --strict` を通した):

```python
ConvertErrorKind = Literal[
    "fileMissing",
    "unreadable",
    "tooLarge",
    "syntax",
    "unrepresentable",
    "rootNotMap",
]


@dataclass(frozen=True, slots=True)
class ConvertError:
    kind: ConvertErrorKind
    file: str  # 入力ファイルの表示用の名前
    line: int | None  # 1 始まり。None は行なし
    key_path: str | None  # 表せない値の場所。None は場所なし(空文字列にしない)
    reason: str  # 固定の文(日本語)。入力の値・ライブラリのエラー文は含まない
```

| フィールド | 内容 |
|------------|------|
| `file` | 入力ファイルの表示用の名前 |
| `line` | 行番号(1 始まり)。位置が分かるときだけ |
| `key_path` | 表せない値の場所(キーの経路)。値そのものは含まない |
| `kind` | 種類 |
| `reason` | 固定の文(入力の値・ライブラリのエラー文は含まない) |

種類(6 種):

| 識別子 | 日本語 | 英語(英語のメッセージのとき) |
|--------|--------|----------------------------|
| `fileMissing` | 入力ファイルが存在しません | input file does not exist |
| `unreadable` | 入力ファイルを読めません | cannot read input file |
| `tooLarge` | 入力が大きすぎます | input is too large |
| `syntax` | 文法の誤りです | syntax error |
| `unrepresentable` | 相手の形式で表せない値があります | value cannot be represented in the target format |
| `rootNotMap` | 最上位がキーと値の集まり(マップ)ではありません | top level is not a map |

ライブラリ(呼び出し側)の表示:

```
<file>:<line>: <種類の文>: <reason>(場所: <key_path>)    行も場所もあるとき
<file>: <種類の文>: <reason>                              どちらも無いとき
```

行だけ・場所だけのときは、それぞれ `<file>:<line>: <種類の文>: <reason>`、`<file>: <種類の文>: <reason>(場所: <key_path>)` となる。`(場所: …)` は、`key_path` があるときだけ、末尾に付く(直前に区切りの空白はない)。`<file>` は、制御文字・書式文字・サロゲート(U+D800〜U+DFFF)をエスケープし、エスケープ後の文字数で 256 文字までに切る(超えるときは末尾に `…`。エスケープの規則は [03 第 12.2 節](03-definition-format.md))。

`conductor convert` の失敗の表示(標準エラーの 1 行、終了コード 67):

```
conductor: error: <file>[:<line>]: <種類の文(言語による)>: <reason> (<at|場所>: <key_path>)
```

`<reason>` は日本語のまま。`(at: …)` は英語のメッセージ、`(場所: …)` は日本語のメッセージ(言語の選び方は [08](08-output-and-i18n.md))。`(…)` の前に半角スペース 1 個。`key_path` がないときは `(…)` を付けない。`<file>`・`<reason>`・`<key_path>` は、制御文字・書式文字・サロゲートをエスケープして出す(ここでは文字数で切らない。`key_path` の中のキー名は、第 5 節の規則で 64 文字に切られている)。**サロゲートのエスケープが要る理由**: コマンドラインの引数のファイル名に、UTF-8 として不正なバイトがあると、`str` では U+DC80〜U+DCFF の単独のサロゲートとして入り(`surrogateescape`)、そのまま標準エラーに UTF-8 で書くと `UnicodeEncodeError` になる(確認: `"\udc80".encode("utf-8")` は失敗する)。実行例:

```
conductor: error: n.yaml: value cannot be represented in the target format: NaN と無限大は JSON で表せません (at: a)
conductor: error: x.json:3: syntax error: JSON の文法に誤りがあります
conductor: error: x.yaml: top level is not a map: 文書が空です
conductor: error: m.yaml: syntax error: 複数の文書は書けません(1 ファイルに書ける文書は 1 つです)
```

### 理由の一覧(日本語の原文。英語版はない)

| 理由 | 使われる種類 |
|------|--------------|
| `指定の場所にファイルがありません` | `fileMissing` |
| `読み取りの権限がありません` / `読み取りに失敗しました` / `通常のファイルではありません` / `UTF-8 として読めません` | `unreadable` |
| `入力が上限(1 MiB)を超えています` / `要素数が上限(100000)を超えています` / `文字の大きさが上限(16 MiB)を超えています` | `tooLarge` |
| `YAML の文法に誤りがあります` / `JSON の文法に誤りがあります` / `キーが重複しています` / `キーは文字列で書きます` / `タグは使えません` / `複数の文書は書けません(1 ファイルに書ける文書は 1 つです)` / `アンカーが自分自身を含んでいます` / `マージキーの値がマップではありません` / `入れ子が深すぎます(上限は 32 段)` | `syntax` |
| `数値が表せる範囲を超えています` / `NaN と無限大は JSON で表せません` / `キーが長すぎます(上限 1024 文字)` | `unrepresentable` |
| `最上位がマップではありません` / `文書が空です` | `rootNotMap` |

### 11.1 YAML(アンカー、エイリアス、マージキー、`on` キー、`on: error` を含む)→ JSON(`--to json`)

```yaml
        next: "@end"
```

出力(アンカーとマージは展開され、`<<` はそのマップの位置に取り込み元のキー `warning_exit_codes` が入り、`id`・`command` は自分のキーが優先する。キーの順は入力の記述順):

```json
{
  "format_version": 1,
  "pipeline": {
    "name": "nightly"
```


## 12. 未確認事項

- YAML の受理する文法の細部(引用符なしのスカラー中の特殊な文字、他の版のライブラリの挙動)と、ライブラリの採否: [03 第 7・18 節](03-definition-format.md)と同じ。YAML ライブラリの採否は、そこに書いた受け入れ試験で決める。
- YAML の文法の誤りの行番号の厳密な規則(ライブラリの検出位置による。[03 第 13.4 節](03-definition-format.md)の表は、確認した例に限る)。
- Windows での、標準出力の改行(CRLF への変換)と、`os.open` の `O_BINARY`、`OSError` の分類([03 第 3 節](03-definition-format.md)と同じ)。Linux での確認。
- Python 3.11、3.12、3.13 での確認(3.10.7、3.14.10、3.15.2 で、第 6.1 節の浮動小数の書き方と、往復の確認が一致した)。
- 非 ASCII のキー・値の YAML 出力は、常に二重引用符で囲む(この仕様で決めた)。plain で書ける範囲を広げる変更は、この仕様の変更になる。
- JSON の出力で、U+007F〜U+009F などを `\u` でエスケープする(この仕様で決めた。他の実装が、これらをそのまま書いても、木は同じだが、出力の文字列は一致しない)。
- マージで取り込まれる値の中の表せない値の場所(`a.<<.x`)は、この仕様の決定であり、他の規定による裏づけはない。
- `--to yaml` で、1,024 文字を超えるキーを拒否する規定は、YAML ライブラリの単純キーの上限による(確認: PyYAML 6.0.3 は、1,025 文字の単純キーを拒否する)。フロー形式の中の長いキーは、ライブラリが受理する(確認)が、この変換器はブロック形式だけを書くので、使わない。
- 変換の入力の大きさの上限(1 MiB)の近くの入力の、実行時間とメモリ(`list` に溜める断片の大きさを含む)の測定は、実装時に行う。
