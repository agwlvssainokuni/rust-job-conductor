# 意図の記述(Intent Statement): 動きを変えない整理のリファクタリング

## Problem Statement

- 機能を順に足してきた跡で、同じ処理が複数か所にある。run ID の決定とステートの照合が cli の 3 か所に、ジョブの状態の文字列の対応が 3 か所に、コマンドの分割が 3 回ある。[desc]
- 分類や遷移を文字列で表示に渡し、表示の側で文字列を比べている。[desc]
- core の `definition/walk.rs` は機能を積み足した形のまま大きく、既定の値や上限の数が複数か所に書かれている。[desc]
- テストは、graph のテストが intent の名前で分かれ、converter のテスト名が英語で、テストの偽物に重なりがある。v0.8.0 で止まった 5 つの仕様書には、そのことが書かれていない。[desc] [Q1]
- 解決したいのは、利用者から見える動きを変えずに、これらを 1 か所にまとめ、読みやすくすることである。[desc]

## Target Customer

- このコマンドラインツールのコードとテストを保守し、機能を足す開発者。仕様書を読む実装者。[desc]

## Success Metrics

- 段 1(cli の整理): run ID の決定とステートの照合が cli の 1 か所にまとまる。コマンドの分割は定義の検査の 1 回だけになり、通らない枝がなくなる。定義と `.env` の検査の関数が `ctx.rs` にある。run と pipeline の入口の重複がない。[desc]
- 段 2(型の整理): 分類と遷移を文字列でなく型で表示に渡す。ジョブの状態とスキップの理由の文字列の対応が core の型の 1 か所にある。`check_consistency` が core にある。ステートの上限つきの読み取りが 1 か所にある。[desc]
- 段 3(core の整理): `walk.rs` が、リトライと環境変数のファイルに分かれる。既定の成功コード、終了コードの読み取り、入れ子の上限、表示の上限、空の次の動きの重複がない。終了コードで終わった実行結果を作る関数が 1 つある。[desc]
- 段 4(テストと文書): graph のテストが形ごとのファイルに分かれ、同じ例を重ねて確かめていない。converter のテスト名が日本語。テストの偽物の共通の補助がある。README の終了コード 68 の行が、実装と合う。5 つの仕様書(go、python、typescript、csharp、powershell)の `00-README.md` の冒頭に、v0.8.0 時点の凍結版で、最新は rust と language-agnostic であると書かれる。[desc] [Q1]
- 利用者から見える動き(出力、終了コード、ステート、`--dry-run` の出力)は変わらない。段 1〜3 は、既存のテストを 1 行も変えずにすべて通る。段 4 は、確かめている入力と期待を落とさずにテストを組み直し、重複してまとめたものの一覧を記録する。[desc] [Q3]
  - 段 1〜3 で、内部の名前や型を直接見ている既存のテストを変えざるを得ないと分かったときは、機能の設計の段階でその一覧と理由を示し、承認を取ってから進める(利用者から見える動きを確かめる部分は変えない)。[Q3]
  - 確かめる手段: 段の前と後でテストの件数を記録する。「1 か所にまとまる」「重複がない」は、設計の段階で、まとめる前の場所(ファイルと行)を一覧にし、実装の後に、その場所に重複が残っていないことを確かめる。段 4 の「同じ例を重ねて確かめている」は、入力(定義と状態)と期待(出力の全文)が同じテストを指す。[Q3]
- 合格の条件: `cargo fmt --all -- --check` と `cargo clippy --workspace --all-targets --locked -- -D warnings` が通る [memory:M4]。行カバレッジ 80% 以上 [memory:M2]。MSRV 1.100 でのテストが通る [memory:M3]。新しい依存を足さない [memory:M5]。

## Initiative Trigger

- 同じ処理が複数か所にあると、機能を足すたびに揃えて直す必要があり、ずれる恐れがある。引数の表(`args.rs`)は、この intent とは別にする。[desc]

## Initial Scope Signal

- Workflow-selected scope: `refactor`(workflow-selected)[scope]
- 範囲: 段 1〜4 の整理。引数の読み取りの表(`args.rs`)は範囲の外(別の intent)。5 つの仕様書は、凍結の明記だけで、中身は変えない。[desc] [Q1]
- 進め方: 設計とコードの計画は 1 回で承認し、実装は段の順に、小さなコミットで進める。各段の終わりにテストが通ることを確かめ、結果は最後にまとめて見せる。[Q2] [memory:M1]
