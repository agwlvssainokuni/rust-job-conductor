# 機能の設計の質問(Functional Design Questions): graph の text 表示の改善 その 4

## 先に分かったこと

範囲(意図の把握 Q2: A): 交差する飛び越しに、同じ行き先(合流)が混ざる形。`git log --graph` の出力を正解データにした(ジョブ 3〜7 個で 4,348 例。うち約 3 分の 1 は、離れた 2 本の線が同じ行き先を持ち、git が、あとで寄せる形)。

**git のソースは読まず、出力の観察だけから規則を立てた**(前回までと同じ。BR5.1)。その規則は、次のすべてと、1 文字も違わず一致した。

| 照合の相手 | 例の数 | 結果 |
|-----------|--------|------|
| 交差と同じ行き先が混ざる形(ジョブ 3〜7 個) | 4,348 | すべて一致 |
| 既存の正解データ: 通常の飛び越し(行き先がすべて違う。交差なし) | 537 | すべて一致 |
| 既存の正解データ: 同じ行き先(交差なし) | 1,517 | すべて一致 |
| 前回の正解データ: 交差(行き先がすべて違う。ジョブ 3〜8 個) | 4,757 | すべて一致 |
| ジョブ 8〜11 個のランダムな、交差と同じ行き先が混ざる形(git の実際の出力) | 1,517 | すべて一致 |

分かったこと: 線の寄せ方は、「ある線が、同じ行き先の別の線へ寄る」(`| |/` のような行)の 1 つの仕組みで、既存の合流(`|/`)、前回の交差(`|/|`)、今回の離れた同じ行き先を、すべて説明できる。つまり、**通常の飛び越しだけのグラフ(各ジョブの飛び越しは高々 1 本)は、行き先がかぶっても、交差しても、すべて 1 つの仕組みで描ける**。

見本 M2(`a` が `e`、`b` が `d`、`c` が `e`。`a` と `c` の線が、離れて同じ行き先 `e` を持ち、`b` の線と交差する):

```text

|\

|\ \
* \ \   c
|\ \ \
| |/ /
|/| /
| |/

|/
* e
o @end
```

見本 M4(`a` が `d`、`b` が `f`、`c` が `e`):

```text

|\

|\ \
* \ \   c
|\ \ \
| |_|/
|/| |

```

## Q1. [開発者] 実装の方針

背景: 今のコード(`layout.rs`)は、「新しい線」「同じ行き先への合流」「交差」を、別々の処理で持っています。今回の規則は、これらを 1 つの仕組み(線の寄せ)にまとめられます。

- A. 通常の飛び越しだけのグラフ(次のジョブへの辺を持ち、各ジョブの飛び越しは高々 1 本。「両方の飛び越し」と分岐がない)の配置を、新しい 1 つの仕組みに置き換える。出力は、既存の 3 つの正解データ(537、1,517、4,757 例)と、1 文字も変わらない。「両方の飛び越し」と分岐を含むグラフは、今の処理のまま(後回し)
- B. 今の処理は、そのまま残し、足りない形(離れた同じ行き先)だけを、足す
- X. Other (please specify)

[Answer]: A
