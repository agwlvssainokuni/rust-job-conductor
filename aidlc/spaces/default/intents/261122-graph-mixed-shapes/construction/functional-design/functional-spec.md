# 機能の仕様(Functional Spec): graph の text 表示の改善 その 4

対象: `conductor graph` の text(`--format text`)の、「通常の飛び越しだけのグラフ」(各ジョブの飛び越しは高々 1 本)のレーンの配置。質問と答え: `functional-design-questions.md`(Q1: A、Q2: A、Q3: A)。実行できる参照実装(Python): `layout-reference.py`(同じ記録の中。正解データとの一致を、自分で確かめられる)。

## 1. 変更の要点

| 形 | 今(v0.9.2) | この変更のあと |
|----|-------------|----------------|
| 通常の飛び越しだけのグラフで、行き先が同じ線が、離れて 2 本以上あり、かつ交差する | 辺の一覧 | レーンの図(`git log --graph` と同じ見た目)(BR1.1〜BR1.5) |
| 上記以外の通常の飛び越しだけのグラフ(交差なし、行き先がすべて違う、同じ行き先で交差しない) | レーンの図 | 1 文字も変わらない(BR3.1) |
| 「両方の飛び越し」、分岐を含むグラフ(交差の有無によらず) | 前回までのとおり(図、または辺の一覧) | 変わらない(BR2.1、BR3.1) |

## 2. 判定(WF1)

1. **グラフ全体**で、次をすべて満たすなら、「通常の飛び越しだけのグラフ」(BR1.1): すべてのジョブが次のジョブへの辺を持つ。各ジョブの飛び越しは高々 1 本。「両方の飛び越し」と分岐がない。この条件を満たすなら、行き先が同じ線があっても、線が交差しても、レーンの図にする(前回までの「行き先がすべて違う」の条件は外す)。
2. 満たさないグラフは、今の処理のまま(前回までの出力を変えない。BR2.1)。

## 3. 線の行の作り方(WF2)

開いている線 `lanes`(内側が先頭。同じ行き先の重複を許す)と、ノードを記述順に見て、行を作る。正確な定義は、`layout-reference.py` の `layout(n, skip)`(BR1.2〜BR1.5)。要点:

1. **ノードの手前**(各ノード `i` の前、最初のノードの前は何もない)。
   - 到着する線(行き先 = `i`)があるとき: (1) 到着する線をまたがない、同じ行き先の重複の組を、先に寄せる。(2) 到着する線の最初の 1 本(位置 `k`)を、主線へ寄せる(`MOVE(k+1, 0)`)。同じ行き先 `i` の別の線は、静かに取り除く。(3) 残りの重複の組を寄せる。
   - 到着する線がなくても、重複の組があれば、寄せる。
   - 重複の組の順序: 内側から(前の線 `a`、後ろの線 `b` の組で、`a` の小さい順、同じなら `b` の小さい順)(BR1.4)。後ろの線 `b` を、前の線 `a` へ寄せる(`MOVE(b+1, a+1)`)。
2. **ノードの行**。ラベルの位置は、`2 × (1 + 開いている線の数 + (新しい線を作るなら 1))`。既存の線の記号は BR1.5。
3. **飛び越しを持つジョブ**: 先頭の線と行き先が同じなら、合流の行 `|\|`(外側の線ごとに ` |`)を置き、新しい線を作らない。そうでなければ、分岐の行(`|\` に ` \` を既存の線の数だけ)を置き、新しい線を先頭に入れる。

`MOVE(c, d)`(BR1.3): 列 `c` の線を、列 `d`(0 は主線)へ寄せる。`c − d = 1` は 1 行(従来の合流の行)、`c − d ≥ 2` は 2 行(行 1 と行 2。3 本以上またぐと、行 1 に横線 `_`)。

## 5. 辺の一覧に残る形

「両方の飛び越し」、分岐を含むグラフ(BR2.1)。注記(英語)は変えない。

## 5a. コードの変更点(core の `graph/layout.rs`)

注意: この仕様は、線の並びを「内側が先頭」で書く。`layout.rs` の `open` は、最後の要素が最も内側である(逆順)。実装では、添字を読み替える。

1. `is_crossing_class`(前回の判定)から、「飛び越しの行き先が、終点も含めて、どの 2 本でも違う」の条件を外す。名前は、「通常の飛び越しだけのグラフ」の判定にふさわしいものに直してよい(`is_ordinary_skip_graph` など)。
2. `lane_layout`: 通常の飛び越しだけのグラフの配置を、`layout-reference.py` の仕組み(重複を許す `lanes`、`MOVE`、寄せる順序、ノードの行の記号)に置き換える。前回までの、合流(`join_lane_row`)と交差(`crossing_rows`)の処理は、この仕組みの特別な場合なので、この範囲のグラフでは、使わなくなる。**「両方の飛び越し」と分岐を含むグラフの配置(`open_all_off_main` などの処理)は、今のまま残す**(BR2.1)。
3. 前回までの出力が、1 文字も変わらないこと(既存の 4 つの正解データ: 537、1,517、871、4,757 例)。変わる形があれば、そのコードの置き換えを見直す。
4. `graph_text.rs`、`mod.rs`: 変更なし(`Underscore` は前回足した)。`-v` の詳細の行の置き場所は、寄せの行を含めて、変わらない。

## 6. テストの方針(Minimal の test-after、行カバレッジ 80%)

- そのまま通る既存のテスト: 既存の 4 つの正解データ(537、1,517、871、4,757 例)の照合、通常の図、分岐、「両方の飛び越し」、前回の交差の例(C1〜C3)。
- **書き換えが要る**既存のテスト(コード生成の計画で、実際に失敗するものを確かめて一覧にする): 「交差と同じ行き先が混ざる形は辺の一覧」とするもの。前回、`graph_lane_polish.rs`(`a>e, b>f, c>e` の 7 ジョブ)、`graph_drawable.rs`、`graph_crossing_lanes.rs`(混ざった形の辺の一覧の例)、`graph_report.rs` の E1(交差して同じ行き先もある形)、`binary_graph.rs`(同じ形)、README の説明と `docs_graph.rs`、仕様書の 05、08、11。新しい期待は、図になる(辺の一覧に残るのは、「両方の飛び越し」と分岐を含むグラフ)。
- 新規: `layout-oracle-mixed.md`(487 例)を `crates/core/tests/fixtures/graph_layout_oracle_mixed.md` として入れ、全例が一致すること(BR4.1)。ジョブ 7 個の 3,861 例は、手元で 1 回だけ照合して、結果を報告する(ファイルには入れない)。M2〜M4、`-v`、`--state`、辺の一覧に残る形(「両方の飛び越し」、分岐を含むグラフ)、実バイナリ、README の例と実出力の一致、性能(幅の広い、同じ行き先が重なる形で、1,000 ジョブでも 1 秒以内)。

## 6b. 検証の範囲と、検証していないこと

- 正解データ: 交差と同じ行き先が混ざる形、ジョブ 4〜7 個の 4,348 例を、git の実際の出力と照合し、全例一致。前回の交差(ジョブ 3〜8 個の 4,757 例)、既存の 537、1,517 例も、同じ参照実装で全例一致。ジョブ 8〜11 個のランダムな、交差と同じ行き先が混ざる 1,517 例も、全例一致(最初の 1 例の不一致を直したあと、新しい乱数の 1,517 例で、不一致 0)。
- 検証していないこと: 線が非常に多い形(1,000 ジョブなど)は、規則の一般化によるもので、git の出力では確かめていない。性能のテストで、動くことだけを確かめる。
