## 公開の前(下書きのうち)

| 場面 | 手順 |
|---|---|
| `release.yml` のどれかのジョブが落ちた | 原因を `main` で直して CI を通す → `git push origin :refs/tags/v0.10.2` と `git tag -d v0.10.2` でタグを消す → 直したコミットの上にタグを付け直して push |
| 下書きを確かめて問題が見つかった | 下書きのリリースを消す(`gh release delete v0.10.2`)→ 上と同じくタグを消し、直してから付け直す |

- 公開前は利用者に届いていないため、影響は無い。
- `checks` の性能のテストが上限を超えたときは、上限を下げずに、v0.10.1 の `build-and-test-summary.md` の「原因不明の失敗の記録の手順」で記録する。
