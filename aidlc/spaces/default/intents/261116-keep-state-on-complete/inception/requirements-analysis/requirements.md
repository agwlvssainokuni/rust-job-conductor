# 要件: 完了後もステートを残す(0.7.0)

## 意図の分析

`conductor` は今、パイプラインが最後まで終わると、ステートファイル(`<定義>.state`、run ID つきは `<定義>.<run-id>.state`)を消します。run ID で実行を分けると、完了した run のファイルは消え、失敗した run のファイルだけが残ります。利用者の目的は次の 3 つです。

- 完了した run のステートも、完了のまま残し、あとから `watch` で結果を見られるようにする(`no state` では、「まだ始まっていない」と「完了して消えた」を区別できない)。
- 完了時の挙動を、run ID の有無によらず揃える。
- 従来どおり消したい利用者のために、削除はオプションで有効にできるようにする。

事前の相談で、次の決定がされています。

- 適用範囲は、run ID の有無によらない(run ID なしの `.state` も、完了後は残る)。
- 完了済みのステートがあるときに、同じ run ID(または run ID なし)で再実行したら、今までどおり先頭からやり直す。リーダーの挙動は変えない。
- 溜まるファイルの掃除機能は足さない。`reset` と `reset --all` は今のまま。
- 破壊的変更として、互換の仕組みは設けない。版は 0.7.0 にする。
- 削除のオプションは `--remove-on-complete`、定義ファイルの項目は `[pipeline].remove_on_complete`。環境変数は設けない。`--keep-on-complete` は足さない。

## 機能要件

### FR1 完了後のステートを残す(標準の動作)

- **FR1.1** `pipeline` と `run` は、パイプラインの完了(最後のジョブの完了、`@end`、スキップでの完了)のとき、ステートファイルを削除せず、`completed = true` を書いて残す。run ID の有無によらない。完了の判定は、3 つの経路(スキップ、通常の遷移、中断後の再開位置)のどれでも、削除の分岐を 1 か所にそろえる。
- **FR1.2** 残るステートの形式は変えない(`format_version = 1`。キーの追加・削除をしない)。書き込みは、今までどおり、一時ファイルへ書いてから名前を替える方法で、完了時のステートも同じ手順で書く。
- **FR1.3** 完了のステートが残っているとき、同じ定義・同じ run ID で `pipeline` を実行すると、先頭から始まる(`read_state` が完了のステートを空として返す挙動のまま。変更しない)。`run <job>` の判定も変えない(完了のステートは空と見なされるので、先頭以外のジョブを単独で呼ぶと、順序の誤りとして 66)。
- **FR1.4** 完了のステートの書き込みに失敗したとき、今までの完了時の初期化の失敗と同じく、65 で終わる。

### FR2 完了時に削除するオプション

- **FR2.1** `pipeline` と `run` は、`--remove-on-complete` を受け付ける。指定すると、完了のとき、従来どおり、ステートファイルを削除する(完了のステートを書かず、消す)。
- **FR2.2** 定義ファイルの `[pipeline]` に、真偽値の `remove_on_complete`(省略時は `false`)を書ける。`true` なら、オプションなしでも、完了のときに削除する。
- **FR2.3** 優先順位: `--remove-on-complete` を指定したら、定義ファイルの値によらず削除する。指定しなければ、定義ファイルの値に従う。オプションは「有効にする」だけで、定義ファイルの `true` をコマンドラインで `false` に戻す手段は設けない。
- **FR2.4** `remove_on_complete` が真偽値でないとき、定義ファイルの誤りとして 64 で終わる。`validate` も、同じ検査をする。
- **FR2.5** `--remove-on-complete` を、`watch`・`reset`・`validate`・`convert` に付けたら、使い方の誤りとして 68 で終わる。
- **FR2.6** 環境変数による指定は設けない。

### FR3 `watch` の表示

- **FR3.1** `watch` は、完了のステートを、空と区別して読む。完了のステートを読んだら、今までの表(パイプライン名、run ID があればその行、ジョブ・状態・補足の 3 列)を出し、表の下に、完了を示す 1 行を足す。1 行は言語に従う(英語は `completed`、日本語は `完了`)。状態の列の文字は、今までどおり英語固定。終了コードは 0。
- **FR3.2** `no state`(`WatchEmpty`)は、ステートファイルがない、または長さが 0 のときだけ出す。
- **FR3.3** run ID を指定した `watch` でも、同じ表示にする。run ID の行は、今までと同じ位置。
- **FR3.4** 完了のステートが壊れている、または版が違うときは、今までどおり 65(`read_state` の検査は変えない)。

### FR4 `reset` と `reset --all`

- **FR4.1** 挙動は変えない。`reset` は、完了のステートも含め、読まずに削除する。`reset --all` は、run ID つきの完了のステートも、規則に合えば削除する。

### FR5 文書、デモ、テスト

- **FR5.1** README を、新しい挙動に合わせる。クイックスタートの 5(「ステートは消えています」)、`pipeline` の説明、「ステートファイルの場所」(最後のジョブの完了、`@end`、スキップでの完了で消える、という記述)、run ID の小節(完了した run は消える、という記述と、ステートは自動では消えない、という記述の整合)、`watch` の説明、`--remove-on-complete` と `remove_on_complete` の説明、引数の表と終了コードの表の記述、定義ファイルの書き方、版の注記(0.7.0 以降)。
- **FR5.2** デモ(`demo/run-demo.sh`、`demo/windows/run-demo.cmd`、`demo/README.md`)の、場面 4・8・9 を、新しい挙動に合わせる(完了後に `watch` で完了を示す行が出る、ステートが残る、片づけの手順)。
- **FR5.3** 完了後の挙動を前提にした既存テストを直し、新しい挙動のテストを足す。直す対象は、`flow_pipeline.rs`(完了後の初期化の失敗が 65 になるテストを含む)、`flow_run_id.rs`、`flow_aux.rs`(`watch_は完了のまま残ったステートを空として扱う`)、`binary_basic.rs`、`binary_run_id.rs`、`unix_demo.rs`、`windows_demo.rs`。

### FR6 版

- **FR6.1** 4 つのクレートの版と `Cargo.lock` を 0.7.0 にする。タグを付けることと、リリースは、この intent の範囲外(利用者が行う)。

## 非機能要件

- **NFR1 互換**: 破壊的変更。旧版の挙動(完了したら消える)に戻す設定は、`--remove-on-complete` だけ。ステートの形式は変えないので、旧版が書いたステートと、0.7.0 が書いたステートは、互いに読める。
- **NFR2 保証の維持**: at-least-once、一時ファイルと名前の入れ替えによる書き込み、ロックなし、既存の終了コードの割り当て(0・ジョブの値・1・64・65・66・67・68・70・127・128+番号)は、変えない。
- **NFR3 品質の下限**: `cargo fmt --check`、`cargo clippy -D warnings`、`cargo test --workspace`、Rust 1.85 のビルドが成功する。行カバレッジは 80% 以上。Linux・macOS・Windows の CI が成功する。
- **NFR4 規約**: ソースにライセンスのヘッダー、`conductor-cli` に `forbid(unsafe_code)`、let チェーンは使わない(1.85)。利用者向けの文章は日本語。CI の `docs-check` の 7 語句を、README に残す。
- **NFR5 テストの方針**: express の Minimal。要件ごとに 1 つ以上の単体テストと、バイナリを実行する統合テストを、既存のものを直して足す。

## 制約

- Rust 1.85 を保つ(let チェーン不可)。
- 変更するクレートは、`core`(定義の項目)、`runtime`(完了ステートの読み取りの入口)、`cli`(引数・完了処理・`watch`)。`converter` は、`[pipeline]` のキーを知らない汎用の変換なので、変更しない見込み。

## 前提

- 完了のステートは、`completed = true` で、`read_state` が空として返すので、ステートの形式を変えずに、FR1.3 を満たせる(コード調査で確認)。
- 残ったステートに対する、定義との食い違いの検査は、`read_state` が空を返す完了のステートには、働かない。定義を変えたあとの再実行は、従来どおり先頭から始まる。
- `convert` は、`--remove-on-complete` を受け付けない(FR2.5)。

## 範囲外

- 古いステートの掃除機能(期限による削除、完了済みだけを消す `reset` の絞り込み)。
- 完了済みの run を、何もせず 0 で終わらせる仕様。
- `--keep-on-complete` と、環境変数での指定。
- ステートの排他ロック。
- タグ付けとリリース。
