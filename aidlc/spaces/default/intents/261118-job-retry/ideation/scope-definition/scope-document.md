# Scope Document — 正常終了しなかったジョブの自動リトライ

根拠: `intent-capture/intent-statement.md`(意図の整理)と、`scope-definition-questions.md` の回答(Q1〜Q5)。

## 目的

一時的な失敗でジョブが止まるたびに、手で再実行する手間をなくす。ジョブが所定の終了コードで終わったとき、最大 N 回、設定した間隔を空けて自動でリトライする。(`intent-statement.md` の Problem Statement、Q1〜Q5)

## 範囲(In)

| 項目 | 優先度 | 根拠 |
|---|---|---|
| リトライする終了コードの指定 | Must | Q1: A |
| 最大の回数 N | Must | Q1: B |
| 固定の間隔(秒数) | Must | Q1: C |
| 設定の単位はジョブごと(ジョブの定義の中に書く) | Must | Q2: A |
| リトライの途中の様子の表示(何回目か、次まで何秒か) | Must | Q3: A |
| 回ごとに間隔を伸ばす方式(指数バックオフ)。固定の間隔に加えて、最初の版に入れる | Should(最初の版に入れる) | Q4: B |
| リトライを設定しない定義ファイルは、これまでと同じ動作のままである | Must(制約) | `intent-statement.md` の Success Metrics |

## 範囲外(Out)

| 項目 | 根拠 |
|---|---|
| 終了コード以外(コマンドの出力の内容など)でリトライを決めること | `intent-statement.md` の Initial Scope Signal(意図の整理 Q6: B) |
| リトライの回数や結果を、外部に通知すること | `intent-statement.md` の Initial Scope Signal(意図の整理 Q6: C) |

## 最初の版では選ばれていないもの(未決。除外とは扱わない)

- 全ジョブ共通の既定のリトライ設定、パイプライン全体だけの設定(Q2 で、ジョブごとだけが選ばれた)
- リトライの途中の表示の様子の細かい形(Q3 は「必須」とだけ決めた)

## 進め方と期限

期限はない。必須の項目を先に作って出す。(Q5: A)

## 価値の流れ

1. 運用者が、ジョブの定義に、リトライする終了コード、最大回数 N、間隔を書く。(Q1、Q2)
2. ジョブが、書いた終了コードで終わる。
3. `conductor` が、設定した間隔を空けて、最大 N 回まで、同じジョブを自動で実行し直す。その様子(何回目か、次まで何秒か)が表示される。(Q3、Q4)
4. 一時的な失敗が直れば、ジョブが成功して、先に進む。手で再実行する手間がなくなる。(`intent-statement.md` の Problem Statement)
