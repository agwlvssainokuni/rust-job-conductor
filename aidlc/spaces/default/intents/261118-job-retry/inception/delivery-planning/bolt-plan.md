# Bolt Plan — 正常終了しなかったジョブの自動リトライ

Bolt は、作業の一部を 1 回通して作り、動くものとして終える単位である。ここでは、作業単位(Unit)1 つを Bolt 1 つにする(Bolt は 3 つ)。(`delivery-planning-questions.md` Q1: A)

根拠: `unit-of-work.md`、`unit-of-work-dependency.md`、`unit-of-work-story-map.md`、`requirements.md`。コンポーネントの一覧(`components.md`)は、Domain Design を省いたため、ない。

## Bolt の順番

| Bolt | Unit | ウォーキングスケルトン | 順番の根拠 |
|---|---|---|---|
| B1 | U1 u1-retry-config | いいえ | u2 が u1 の設定の型を読むため、最初 |
| B2 | U2 u2-retry-execution | いいえ | u3 が u2 の表示の種類を使うため、2 番目 |
| B3 | U3 u3-retry-display-docs | いいえ | 最後。文言の確定と README |

ウォーキングスケルトン(薄い端から端までの動くものを最初に作ること)は、チームの方針で行わない。(`team.md`)順番は、依存の一列で決まる。(`unit-of-work-dependency.md`)

## B1 — リトライの設定と検証(u1-retry-config)

- 対象の要件: FR1.1〜FR1.9、FR7.1、FR7.2
- 完了の条件(Definition of Done):
  - リトライの項目(終了コードの一覧、最大回数、間隔、倍率、上限)を、ジョブの定義に書け、読み取れる。
  - 省略、範囲外、一覧と成功・警告の重なり、倍率と上限の片方だけ、間隔の書式の誤りが、すべて定義の誤り(64)になり、`validate` でも検出される。
  - `convert` が、リトライの項目を失わずに往復変換する。
  - リトライの項目がない既存の定義とテストが、変更なしで通る。
  - `cargo fmt --check`、`cargo clippy -D warnings`、`cargo test` が通り、行カバレッジ 80% 以上を保つ。
- 確かめたい仮説(confidence hypothesis): リトライの設定を、既存の定義の規則(成功・警告の終了コード、誤りの種類、日英の文言)と矛盾なく足せる。
- 見せるもの(expected demo): リトライの項目を書いた定義を `conductor validate` で通し、誤りの定義で 64 になるところを見せる。

## B2 — リトライの実行と、途中の知らせ(u2-retry-execution)

- 対象の要件: FR1.2 の動き、FR1.6 の動き、FR2.1、FR2.2、FR3.1〜FR3.6、FR4.1、FR4.2、FR5.1、FR5.2、FR6.1、NFR3、NFR7
- 完了の条件:
  - 設定した終了コードで終わったジョブが、間隔を空けて最大 N 回、`run` と `pipeline` の両方で実行し直される。固定の間隔と、倍率と上限の方式が、期待どおりの待機になる。
  - 使い切ったときは、通常のエラーと同じ扱い(最後の終了コード、再開位置はそのジョブ)になる。
  - 待機中のシグナルで、すぐに待機をやめ、128 + 番号で終わり、再開位置がそのジョブになる。実行中のシグナルは、これまでと同じ。
  - 回数は、ステートファイルに記録しない(形式は変わらない)。
  - リトライの前の知らせ(何回目か、最大回数、次までの待ち時間)が表示される(最初の文言は英語と日本語)。
  - 待機を差し込める形で、実際に待たないテストができる。
  - 既存のテストが変更なしで通り、`nfr_source` の検査も通る。
- 確かめたい仮説: 待機中のシグナルの扱いと、時間の差し込み口を、既存の中断の動きと矛盾なく足せる。(いちばん心配なこと。Q2: A)
- 見せるもの: 2 回続けて対象の終了コードで終わり、3 回目に成功するジョブを `run` で動かし、実行の回数と、リトライの前の知らせを見せる。待機中にシグナルを送って、すぐに止まるところも見せる。

## B3 — 表示の文言の確定と文書(u3-retry-display-docs)

- 対象の要件: FR6.2、FR8.1
- 完了の条件:
  - リトライの前の知らせの、英語と日本語の文言が確定し、表示のレベル(`-v` なしで出すか)が確認されている。
  - README に、項目の書き方、動き、at-least-once との関係(リトライするジョブは、同じ処理が複数回走っても困らないことが必要)が書かれている。
  - CI の `docs-check`(README の必須の語の検査)が通る。
- 確かめたい仮説: README の説明どおりに、利用者が設定して動かせる。
- 見せるもの: README の例の定義を、そのまま動かして見せる。

## Bolt をまたぐ共通の条件

後方互換(NFR1)、既存の検査(NFR2)、カバレッジ(NFR4)、3 つの OS(NFR5)、新しい外部クレートを増やさないこと(NFR6)を、すべての Bolt で守る。
