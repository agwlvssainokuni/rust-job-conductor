## 公開の前(下書きのうち)

| 場面 | 手順 |
|---|---|
| `release.yml` のどれかのジョブが落ちた | 1. 原因を `main` で直して CI を通す。<br>2. `git push origin :refs/tags/v0.10.3` と `git tag -d v0.10.3` でタグを消す。<br>3. 直したコミットの上にタグを付け直して push する。 |
| 下書きを確かめて問題が見つかった | 1. 下書きのリリースを消す(`gh release delete v0.10.3`)。<br>2. 上と同じくタグを消し、直してから付け直す。 |

- 公開前は利用者に届いていないので、影響は無い。
- `checks` の時間に敏感なテスト(性能のテスト、`runner_log` など)が落ちたときは、上限を下げない。走らせ直し、記録を残す。

## 公開の後

| 場面 | 手順 |
|---|---|
| 利用者が困る不具合が見つかった | v0.10.2 のリリースは残っているので、利用者はそのバイナリに戻せる。直したものを v0.10.4 として、同じ流れで出す。 |
| 公開を取り下げる | リリースを下書きに戻すか、消す。タグは残し、v0.10.4 で置き換える。 |
