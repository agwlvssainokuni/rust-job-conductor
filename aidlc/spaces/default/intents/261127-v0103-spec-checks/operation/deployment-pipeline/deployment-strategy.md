# 配り方: v0.10.3

出典: `deployment-pipeline-questions.md`(Q1〜Q5、まとめの確かめ済み)、`cd-config.md`、team.md の Deployment・Way of Working、project.md の Mandated。

## やり方

- **一度に全部(下書きを経る)**:
  - 単一バイナリの CLI で、利用者が自分で取ってくる。そのため、段階的な切り替えは当てはまらない。
  - 「下書きのリリース」が、人が確かめる段になる(Q3)。
- 環境は 1 つ(利用者の手元)(Q1)。

## 手順

1. `main` が最新で、CI がすべて通っていることを確かめる。46092396041 で確認済み。記録のコミットの後の CI も確かめる。
2. `main` の上にタグ `v0.10.3` を付けて push する。人が行うか、人の頼みで AI が行う。
3. `release.yml` の 4 つのジョブが通るのを見る。
4. 下書きのリリースで、成果物、`SHA256SUMS`、自動の注記を確かめる。そのうえで、v0.10.3 の注記を足す(Q5)。
   - `conductor` の動きは v0.10.2 と同じ。コードの変更は版だけ。
   - 仕様書の小さな粗を直した。
     - language-agnostic の受け入れの条件の、テスト名の書き方をそろえた。
     - AC-430 の前提を、実際のテストに合わせた。
     - 性能の表の「目安」に、参照実装は強制として検査することを書き添えた。
   - 仕様書の数(誤りの種類、定義とステートのキー、`watch` の列、`--interval`、`--format`、デモの場面)が実装と一致することを確かめるテストを足した。
5. 公開は、人が確かめてから行う。

## smoke test

- `build` のジョブで、展開したバイナリの `--version` を 3 対象で確かめる(Intel macOS を除く)。
- 公開の後、利用者の手元では `conductor --version` が `conductor 0.10.3` を出す。

## 中止の条件

- `verify-tag`、`checks`、`build` のどれかが落ちたら、下書きは作られない。直してから、タグを消して付け直す(`rollback-runbook.md`)。
