# Requirements Analysis — 質問

依頼: (1) 定義ファイルの誤りを、実行せずに検査できる `validate` サブコマンドを追加する。(2) `PipelineDefinition` の Rust のフィールド名 `jobs` を `job` に改名する(converter のテストのサンプルデータのキーも)。(3) README のタイトルを `# rust-job-conductor — Rust製のジョブ実行制御ツール` にする(依頼で文言まで決まっているため、質問はしません)。

調査(codekb)で分かった、`validate` の細部で決める必要のある点を 3 つ確認します。`validate` は、`run`/`pipeline` が実行の前に行う処理(定義の読み込みと検証、全ジョブの `command` の検査)だけを行い、何も実行せず、ステートファイルも読み書きしません。

## Q1. [検査の範囲] `command` のプログラムが実在するかの確認

`command` の検査は、いまの `run`/`pipeline` では、書き方の検査(引用符が閉じているか、先頭が空でないか)までで、PATH にプログラムがあるかは調べません(起動の可否は、実行する環境によって変わるため)。

- A. 調べない。`validate` も、定義だけで決まる誤り(書き方、型、遷移の整合、終了コードの重なり、`command` の書き方)を検査する(推奨)
- B. A に加えて、プログラムが見つからなければ、警告として表示する(終了コードは変えない)
- C. Not yet defined(まだ定まっていない)
- X. Other (please specify)

[Answer]: A

## Q2. [引数] パイプライン名

`pipeline <名前>` は、定義の `[pipeline].name` と、渡した名前が一致するか照合します。

- A. `conductor validate [--config <パス>] [<パイプライン名>]`。名前は任意。渡したら照合し、省略したら照合しない(推奨)
- B. 名前は必須にして、`pipeline` と同じ照合をする
- C. 名前は受け付けない(定義の中身だけを検査する)
- X. Other (please specify)

[Answer]: A

## Q3. [表示] 成功したときの出力

いまの `conductor` は、成功したときは、何も出力しません(エラーのときだけ、標準エラーに表示)。`-v` は `run`/`pipeline` だけが受け付けます。

- A. 何も出力せず、終了コード 0 だけ。`-v` は受け付けない(使い方の誤り)(推奨ではないが、最も素直)
- B. 既定は何も出力しない。`-v` を付けたときだけ、標準エラーに 1 行(例: `定義は正しいです(ジョブ 4 個)`)を表示する(推奨)
- C. 常に、標準出力に 1 行を表示する
- X. Other (please specify)

[Answer]: B
