# 機能の設計の質問(Functional Design Questions): graph の配置のリファクタリング

## 先に分かったこと(試作の結果)

前回の「線の並びと寄せ」の仕組み(参照実装 `layout-reference.py`)に、「両方の飛び越し」と分岐を、次の形で組み込んだ試作を作った。

- 「両方の飛び越し」は、主線につながらない線を 1 本開く。分岐は、主線につながらない線を 2 本同時に開く(近い行き先が内側)。
- 主線につながらない線の分岐の行と合流の行は、列 0 の `|` を描かない(前回までの規則と同じ。線を開いたジョブがすべて主線につながらないときだけ)。
- 寄せ(交差、同じ行き先)は、通常の飛び越しと同じ仕組みで描く。

照合の結果:

| 照合の相手 | 例の数 | 結果 |
|-----------|--------|------|
| git の出力: 537、1,517、4,757(交差)、4,348(交差と同じ行き先)例 | 11,159 | すべて一致 |
| 規則から導いた分岐の正解データ | 871 | すべて一致 |
| 今の実バイナリが図にする、「両方の飛び越し」か分岐を含むランダムなグラフ(ジョブ 3〜8 個) | 679 | すべて一致 |
| 今の実バイナリが辺の一覧にする、同じ種類のランダムなグラフ | 2,379 | すべて図になった(新しい図) |

つまり、**今、図になる形は 1 文字も変わらず、今、辺の一覧の形が図になる**。新しい図は、git では作れないので、見た目を確かめていただく。

## Q1. [プロダクト] 新しい図の見た目

背景: 主線の列 0 の `|` を描かない規則は、前回までと同じ「その線を開いたジョブが、すべて主線につながらない(両方の飛び越し、分岐)とき」です。そのため、交差の行(N1 の `  |/`、` /|`)でも、列 0 は空になります。N1 の `c` と `d` の間には、実際には `c` から `d` への辺がありますが、前回承認いただいた分岐の図(B1: `c` から `d` への辺があっても、`d` の前の合流の行の列 0 は空)と同じ考えです。

- A. この見た目で進める(前回までの規則のまま。今、図になる形は 1 文字も変わらない)
- B. 列 0 は、「上のジョブが実行されうる、かつ次のジョブへの辺を持つ」ときに `|` を描く規則に変える(N1 なら `| |/`、`|/|`)。ただし、前回承認いただいた分岐の図(B1 など、871 例の一部)の見た目も変わる
- X. Other (please specify)

[Answer]: B

## Q2. [開発者] 新しい図の正解データ

- A. ジョブ 6 個以下で、「両方の飛び越し」か分岐を含み、今は辺の一覧になる形を、全部、規則から生成して、テスト用のファイルにする(「git では確かめられず、規則から導いた」と先頭に明記)。代表的な図(上の N1〜N5)は、この設計で承認する
- B. 代表的な図(10 個ほど)だけを、手で書いてテストにする
- X. Other (please specify)
