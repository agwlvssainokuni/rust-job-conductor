# 機能の仕様(Functional Spec): graph の配置のリファクタリング

対象: `conductor graph` の text(`--format text`)のレーンの配置(core の `graph/layout.rs`)。質問と答え: `functional-design-questions.md`(Q1: B、Q2: A)。**実行できる参照実装(規範): `layout-reference.py`**(同じ記録。文と食い違うときは、参照実装が正)。

## 1. 変更の要点

| 形 | 今(v0.9.3) | この変更のあと |
|----|-------------|----------------|
| 通常の飛び越しだけのグラフ | レーンの図(新しい経路) | 1 文字も変わらない(git の出力 11,159 例) |
| 「両方の飛び越し」か分岐を含み、今は図になる形 | レーンの図(古い経路) | レーンの図(同じ 1 つの仕組み)。**主線の列 0 の規則の変更(Q1: B)で、一部の行が変わる** |
| 「両方の飛び越し」か分岐が、交差・同じ行き先と組み合わさる形 | 辺の一覧 | レーンの図 |
| 上記以外で、次のジョブへの辺も飛び越しもないジョブがある形、3 本以上の辺を持つジョブがある形 | 辺の一覧 | 辺の一覧(変わらない) |

配置の経路は 1 つになり、古い経路(`lane_layout` と、その特例 `open_all_off_main`、「分岐が開いた」印、`join_lane_row` の off-main の扱いなど)は、なくなる。

## 2. 判定(WF1)

レーンの図にするのは、すべてのジョブが、次のどれかのとき(グラフ全体の条件)。
- 飛び越しなし(次のジョブへの辺だけ)
- 通常の飛び越し(次のジョブへの辺と、飛び越しの辺 1 本)
- 「両方の飛び越し」(辺は 1 本で、成功と警告の両方。行き先は次のジョブでない)
- 分岐(次のジョブへの辺がなく、次でない、異なる 2 つの行き先への辺 2 本)

ほかのジョブ(辺が 3 本以上、など)が 1 つでもあれば、辺の一覧(従来どおり)。交差と同じ行き先は、どの組み合わせでも、図にする。

## 3. 線の行の作り方(WF2)

前回の「線の並びと寄せ」の仕組み(graph-mixed-shapes の `layout-reference.py`)を、そのまま土台にし、次を足す。正確な定義は、`layout-reference.py`。

1. **線を開く**: 通常の飛び越しは、線を 1 本、先頭(列 1)に入れる(先頭の線と行き先が同じなら、合流の行 `|\|`)。「両方の飛び越し」も、線を 1 本(先頭の線と行き先が同じなら、合流の行)。分岐は、線を 2 本、同時に入れる(近い行き先が内側)。分岐の行は、`\` を (既存の線の数 + 新しい線の数) 個。分岐の線の行き先が、既存の線と同じでも、2 本を入れ、次のノードの手前の「寄せ」で 1 本にする。
2. **寄せ**: 前回と同じ(到着の線を主線へ、同じ行き先の重複の線を寄せる。`MOVE(c, d)`、寄せる順序、ノードの行の記号)。
3. **主線の列 0 の記号(Q1: B)**: ノード `j` と次のノード `j + 1` のあいだの、すべての行(分岐の行、合流の行 `|\|`、寄せの行)の列 0 は、**ジョブ `j` が実行されうる(先頭のジョブから、辺をたどって着ける)、かつ、次のジョブへの辺を持つ**ときだけ `|`、それ以外は空白。前回までの「線を開いたジョブが、すべて主線につながらないときだけ空白」の規則は、使わない。
   - 通常の飛び越しだけのグラフでは、すべてのジョブが実行されうるので、列 0 は、常に `|`(前回までの出力と、1 文字も変わらない)。

## 5. 影響(この変更で、出力が変わるもの)

- git の出力の正解データ(537、1,517、940、487 例)と、通常の飛び越しだけのグラフ: **変わらない**。
- 分岐の正解データ(871 例): **全例で 1〜5 行が変わる**(637 例が 1 行、87 例が 2 行、125 例が 3 行、4 例が 4 行、18 例が 5 行)。作り直した版を `layout-oracle-branch-v2.md` にした。
- 今、図になる「両方の飛び越し」か分岐を含むグラフ: 試作の照合では、ランダムな 679 例のうち 359 例の出力が変わり、320 例は変わらない。
- 今、辺の一覧になる、「両方の飛び越し」か分岐を含むグラフ: 図になる(ランダムな 2,379 例で、すべて図になった)。

## 5a. コードの変更点(core の `graph/layout.rs`)

1. 判定: §2 のグラフ全体の条件で、レーンの図にするかを決める(前回の `is_ordinary_skip_graph` を広げる)。
2. 配置: `ordinary_layout`(内側が先頭の線の並び)を、唯一の配置にする。「両方の飛び越し」と分岐の線を開く処理と、主線の列 0 の規則(§3 の 3)を足す。実行されうるジョブは、先頭のジョブから、辺をたどって求める(ジョブの数に比例)。
3. 古い経路(`lane_layout`、`open_all_off_main`、「分岐が開いた」印、`debug_assert`、古い経路だけが使う補助)を削除する。`SkipPlan` の `ordinary` の欄は、要らなくなる。`is_lane_drawable` の名前は変えない。
4. cli の `graph_text.rs`、`mod.rs`: 変更なし。

## 6. テストの方針(Minimal の test-after、行カバレッジ 80%)

- そのまま通る既存のテスト: git の出力の正解データ(537、1,517、940、487 例)の照合、通常の飛び越しだけのグラフのテスト。
- **書き換え**: 分岐の正解データを `layout-oracle-branch-v2.md` に差し替える(`crates/core/tests/fixtures/graph_layout_oracle_branch.md`)。「両方の飛び越し」と分岐の図の期待(`graph_lane_polish.rs`、`graph_branch_lanes.rs`、`graph_report.rs`、`binary_graph.rs`、`docs_graph.rs`、README の例)のうち、§3 の 3 で変わるものを、新しい期待にする。「両方の飛び越し」や分岐と交差・同じ行き先の組み合わせを「辺の一覧」とするテスト(`graph_drawable.rs`、`graph_crossing_lanes.rs`、`graph_mixed_shapes.rs` など)を、図の期待にする。辺の一覧に残る形のテストは、3 本以上の辺を持つジョブなどの形に差し替える。
- 新規: `layout-oracle-offmain.md`(ジョブ 3〜5 個で、「両方の飛び越し」か分岐を含む、すべての形。2,748 例。約 39 万バイト)を、`crates/core/tests/fixtures/graph_layout_oracle_offmain.md` として入れ、全例が一致すること。N1〜N5 と B1、D1 の全文、`-v`、`--state`、実バイナリ、性能(1,000 ジョブで 1 秒以内)。
- 注: 質問 Q2 の A は「ジョブ 6 個以下」だったが、6 個では約 5 万 6 千例(数百万バイト)になるため、ジョブ 5 個以下にした(設計の承認の場で、確かめていただく)。

## 6b. 設計の確認の指摘の反映(承認のときに、ユーザーが選んだ)

1. **`-v` の詳細の行の列 0(Major)**: 詳細の行も、BR1.4 と同じ規則に従う。ノード `j` の下に置く詳細の行の列 0 は、ジョブ `j` が実行されうる、かつ次のジョブへの辺を持つときだけ `|`、それ以外は空白(ユーザーの選択「詳細の行も規則 B に合わせる」)。cli の `graph_text.rs` の `render_lanes` は、列 0 を、配置の結果から受け取る(core の `LaneRow` か、`LaneLayout` に、ノードごとの列 0 の記号を持たせる。どちらかは、実装で決める)。N1、N2、N5 の `-v` のテストで固める。
2. **参照実装の使われない状態**: 古い経路の名残の `off`(主線につながらない印)を、参照実装から削除した。削除の後も、`layout-oracle-offmain.md`(2,748)、`layout-oracle-branch-v2.md`(871)、交差と同じ行き先(4,348)、交差(4,757)の全例が一致する。
3. **判定の正確な形(WF1)**: ジョブごとに、辺の数と種類で決める。(a) 飛び越しなし: 辺は次のジョブへの 1 本。(b) 通常の飛び越し: 次のジョブへの辺と、それ以外への辺 1 本(種類は 1 つずつ)。(c) 両方の飛び越し: 辺は 1 本(成功と警告の両方)で、行き先は次のジョブでない。(d) 分岐: 辺は 2 本で、どちらも次のジョブでなく、行き先が異なる。これ以外(例: 次のジョブへの辺がなく、成功だけの辺が 1 本、辺が 3 本以上)が 1 つでもあれば、辺の一覧。`SkipPlan` は、ジョブごとの「次のジョブへの辺の有無」と「種類」と「行き先(0〜2 個)」を持つ。古い `off_main` は、種類(両方の飛び越し、分岐)と、実行されうるジョブの集合で置き換える。
4. **テストと文書の一覧の補足**: `crates/core/tests/graph_layout_oracle.rs` の読み取りに、`a>>d`(両方の飛び越し)の書き方を足す。`graph_perf.rs` に、「両方の飛び越し」と分岐を含む 1,000 ジョブの性能のテストを足す。削除する名前(`lane_layout`、`open_all_off_main`、`is_ordinary_skip_graph`、`ordinary` など)は、`graph_types.rs`、`nfr_source.rs`、`crates/cli/src/graph.rs`、`graph_common` にも出てくるので、合わせて直す。
5. **ジョブ 6〜7 個の確認**: 乱数の種を固定した、ジョブ 6〜7 個の、「両方の飛び越し」か分岐を含む形を、数百例(約 5 万バイト)、規則から生成して、テスト用のファイルに足す(深い入れ子の確認)。
