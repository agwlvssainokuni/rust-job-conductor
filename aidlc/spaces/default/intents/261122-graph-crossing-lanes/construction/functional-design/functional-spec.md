# 機能の仕様(Functional Spec): graph の text 表示の改善 その 3

対象: `conductor graph` の text(`--format text`)の、「交差する飛び越し」のレーンの配置。質問と答え: `functional-design-questions.md`(Q1: A(git のソースを読まず、出力の観察だけから規則を立てる)、Q2: A、Q3: A)。

## 1. 変更の要点

| 形 | 今 | この変更のあと |
|----|-----|----------------|
| 通常の飛び越し(各ジョブ高々 1 本、行き先が違う)で、線が交差する | 辺の一覧 | レーンの図(`git log --graph` と同じ見た目)(BR1.1〜BR1.5) |
| 交差に、両方の飛び越し・分岐・同じ行き先を含む | 辺の一覧 | 辺の一覧(変わらない。BR2.1) |
| 上記以外 | 従来どおり | 1 文字も変わらない(BR3.1) |

## 2. 判定(WF1)

1. **グラフ全体**で、次をすべて満たすなら、交差の有無によらず、レーンの図にする(BR1.1): すべてのジョブが次のジョブへの辺を持つ。各ジョブの飛び越しは高々 1 本。「両方の飛び越し」と分岐がない。飛び越しの行き先が、終点も含めて、どの 2 本でも違う。
2. 線が交差し、かつ上の条件を満たさない(グラフのどこかに、「両方の飛び越し」、分岐、同じ行き先がある)なら、辺の一覧(BR2.1)。交差のないグラフは、前回までと同じ(変わらない)。
3. 混ざった例(交差する 2 本と、離れた別のジョブの「両方の飛び越し」、分岐、同じ行き先)を、辺の一覧のテストに足す。

## 3. 線の行の作り方(WF2)

節(ジョブ、最後に終点)を記述順に見て、行を作る(BR1.2〜BR1.5)。開いている線を `lanes`(内側が先頭)、その数を `m` とする。

1. そのノードが、線の行き先なら、その線の位置を `k`(0 が内側)とする。
   - `k = 0`: 従来の合流の行(`|/` と ` /` を `m − 1` 個)を 1 行(BR1.3)。
   - `k ≥ 1`: **交差の行を 2 行**(BR1.4)。行 A: 列 0 `|`、続けて `j = 0 … k−1` について `|` と、(最後の `j = k−1` は `/`、それ以外は `_`)。続けて、到着した線より外側(`m−1−k` 本)について ` /`。行 B: `|/` に続けて、残りの線(`m − 1` 本)について `|` を空白 1 つおき。
   - その線を、`lanes` から取り除く。
2. ノードの行。既存の線の記号は、BR1.5 の優先順: (a) そのノードが新しい線を作り、直前が分岐の行なら `\`。(b) そのノードが**新しい線を作らず**、そのノードの前の合流の行が `k = 0` で、次のノードも線の行き先(位置 `q`)なら、`q` 以降を `/`、内側を `|`。(c) それ以外は `|`(交差の行(`k ≥ 1`)の直後も `|`)。
3. 飛び越しを持つジョブなら、分岐の行(`|\` に ` \` を既存の線の数だけ)を置き、新しい線を `lanes` の先頭に入れる。

## 4. 図の例(`git log --graph` の実際の出力と一致を確かめた。全 940 例は `layout-oracle-cross.md`)

C1: `a` が `d`、`b` が `e`(5 ジョブ)。行 A は `| |/`、行 B は `|/|`

```text
*   a
|\
* \   b
|\ \
* | | c
| |/
|/|
* | d
|/
* e
o @end
```

C2: `a` が `d`、`b` が `e`、`c` が `f`(7 ジョブ)。3 本の線が続けて交差すると、行 A に横線 `_`

```text
*   a
|\
* \   b
|\ \
* \ \   c
|\ \ \
| |_|/
|/| |
* | | d
| |/
|/|
* | e
|/
* f
* g
o @end
```

C3: `a` が `f`、`b` が終点、`c` が `e`(6 ジョブ)。合流の行(`|/ / /`)のあとの `e` の行の `/` は、次のノード `f` が到着する線の位置 `q = 1` 以降

```text
*   a
|\
* \   b
|\ \
* \ \   c
|\ \ \
* | | | d
|/ / /
* | / e
| |/
|/|
* | f
|/
o @end
```

`-v` の詳細の行は、前回までの規則のまま(ノードの行と、続く分岐の行のあとに、列の数だけ `| `)。交差の行(行 A、行 B)は、ノードの行の前にあり、詳細の行の置き場所は変わらない。

## 5. 辺の一覧に残る形

交差に、「両方の飛び越し」、分岐、同じ行き先を含む形(BR2.1)。注記(英語)は変えない(「…cross or form a shape the lane diagram cannot draw…」は、これらの形を含む言い方)。

## 5a. コードの変更点(core の `graph/layout.rs` と cli)

注意: この仕様は、線の並びを「内側が先頭」で書く。`layout.rs` の `open` は、最後の要素が最も内側である(逆順)。実装では、`k`(内側から数えた位置)を、`open.len() − 1 − (添字)` に読み替える。

1. `skip_targets`(判定): BR1.1 の範囲の条件(グラフ全体)を満たすなら、交差を許す(積み上げの `t > top` の交差の判定と、`open.contains(&i)` の交差の判定を、この範囲では使わない)。条件を満たさないグラフでは、従来どおり、交差を辺の一覧(`None`)にする(BR2.1)。同じ行き先(合流)と「両方の飛び越し」と分岐の判定は、変えない。
2. `lane_layout`(配置): 線の取り除きを、「最後の 1 つ」から、「位置 `k` の 1 つ」に広げる。線ごとの付随データ(`open_all_off_main`、「分岐が開いた」印)も、同じ添字で取り除く。`k ≥ 1` のとき、交差の行(行 A、行 B)を、ノードの行の前に置く。`is_target` と `joins` の判定は、`k` の線を対象にする。`k ≥ 1` の到着のあと、`after_fork` を偽にする。終点への到着は、交差の範囲では常に `k = 0`(終点の行は変わらない)。ノードの行の記号を、BR1.5 の優先順で決める。
   - 一般化(`q` 以降を `/`)は、既存の出力を変えない。既存の図で、開いている線の行き先は、内側から外側へ厳密に増えるので、`k = 0` の到着のあと、次のノードが線の行き先なら、必ず `q = 0`(従来どおり、すべて `/`)(レビューの確認)。
3. `core/graph/mod.rs`: `LaneGlyph::Underscore` を足す。cli の `graph_text.rs` の `glyph_char` を、`Underscore` → `_` にする。ほかは変えない。`-v` の詳細の行の置き場所は、`Fork` の記号に頼る(変えない)。
4. 既存の、分岐と「両方の飛び越し」の図で、`q` 以降を `/` にする一般化が、出力を変えないこと(既存の 871 例で確かめる)。変わるなら、その形の出力を、ユーザーに見せて確認する。

## 6. テストの方針(Minimal の test-after、行カバレッジ 80%)

- そのまま通る既存のテスト: 正解データ 537 例、1,517 例、871 例の照合、通常の図、同じ行き先、両方の飛び越し、分岐、辺の一覧の例。
- **書き換えが要る**既存のテスト(設計のレビューで確認した場所。コード生成の計画で、実際に失敗するものを、確かめて一覧にする):
  - `crates/core/tests/graph_drawable.rs`: 107 行目あたりの、交差を「図にできない」とする表明だけ(ほかは変えない)。
  - `crates/core/tests/graph_lane_polish.rs`: 164 行目あたりのテストだけ(71、144、188 行目あたりは、変えない)。
  - `crates/core/tests/graph_branch_lanes.rs`: 124 行目あたりの最初の表明だけ。
  - `crates/cli/tests/graph_report.rs`: 辺の一覧の例 E1(交差)、`-v` の辺の一覧のテスト(347 行目あたり)。
  - `crates/cli/tests/binary_graph.rs`: 交差の形の、辺の一覧を期待するテスト。
  - `crates/core/tests/graph_perf.rs`: 「交差する形は辺の一覧に切り替わり」。交差の最悪の形(幅の広い交差。`j(i)` → `j(i+2)` に加えて)も足し、1,000 ジョブで 1 秒以内を確かめる。
  - `crates/cli/tests/docs_graph.rs`: README の辺の一覧の記述。README に、新しい例を足すときは、`graph_example` の添字がずれないよう、最後に足す。
- 新規: `layout-oracle-cross.md`(940 例)を `crates/core/tests/fixtures/graph_layout_oracle_cross.md` として入れ、全例が一致すること(BR4.1)。ジョブ 8 個の 3,817 例は、手元で 1 回照合して、結果を報告する(ファイルには入れない)。C1〜C3、`-v`、`--state`、辺の一覧に残る形(交差と、両方の飛び越し・分岐・同じ行き先の組み合わせ)、実バイナリ、README の例と実出力の一致。
- 交差の性能: 交差する形が、1,000 ジョブでも 1 秒以内(既存の `graph_perf.rs` の目標)。

## 6b. 検証の範囲と、検証していないこと

- 正解データ: ジョブ 3〜8 個の交差 4,757 例(開いている線は、最大 4 本)を、git の実際の出力と照合した。ジョブ 9〜11 個のランダムな交差 342 例(線が 5 本以上開く形を含む)も、git の実際の出力と照合して、不一致 0(設計のレビューのあと)。
- 検証していないこと: 線が非常に多い形(1,000 ジョブなど)は、規則の一般化によるもので、git の出力では確かめていない。性能のテスト(1 秒以内)で、動くことだけを確かめる。
