# 機能の設計の質問(Functional Design Questions): graph の text 表示の改善 その 3

## 先に分かったこと(`git log --graph` で、交差する形を作った結果)

範囲(意図の把握 Q2: A): 各ジョブの飛び越しは高々 1 本、行き先は、どの 2 本でも違う、線が交差する形(ジョブ 3〜8 個)。git の実際の出力で、全部作れた。

| ジョブの数 | 交差する形の数 |
|-----------|----------------|
| 3〜6 個 | 190 |
| 7 個 | 750 |
| 8 個 | 3,817 |
| 合計 | 4,757(約 76 万バイト) |

見本 1(5 ジョブ、`a` が `d`、`b` が `e`): 交差の行(`| |/` と `|/|`)で、線が入れ替わる。

```text
*   a
|\
* \   b
|\ \
* | | c
| |/
|/|
* | d
|/
* e
o @end
```

見本 2(7 ジョブ、`a` が `d`、`b` が `e`、`c` が `f`): 3 本の線が連続して交差すると、git は横線 `_` を使う。

```text
*   a
|\
* \   b
|\ \
* \ \   c
|\ \ \
| |_|/
|/| |
* | | d
| |/
|/|
* | e
|/
* f
* g
o @end
```

4,757 例のうち、1,748 例(約 37%)は、`_` を含む。これまでの図(入れ子、並び、同じ行き先)には、`_` は 1 つもなかった。

## Q1. [開発者] 実装の方針

背景: 交差の図は、線の入れ替えの行(`| |/`、`|/|`、`| |_|/` など)を、git が、列の状態から決めています。規則を観察して足す方法では、`_` を含む形(37%)の追従が難しく、取りこぼしが出やすいです。

- A. git の列の状態機械(`graph.c` の考え方)を、自前で移植する。交差する形は、これで描く(`_` を含む形も図になる)。全例と一字一句一致することを正解データで確かめる。既存の図(入れ子、同じ行き先、両方の飛び越し、分岐)は、今のまま変えない
- B. 規則を観察して足す。`_` を含む形は、辺の一覧のまま(図にするのは、`_` を含まない約 63%)
- X. Other (please specify)

[Answer]: X. 「git のライセンスは? 他プロダクトのソースを見るのは避けたい」と質問があった。回答: git 本体は GPL v2、このプロジェクトは Apache-2.0 なので、`graph.c` の移植は避ける(A は取り下げ)。やり直しの質問で、ユーザーは「git のソースは読まず、出力の観察だけから規則を立てる(`_` を含む形も目標)。実装済みのパターンの出力形式を変えた方が良さそうなら、それも許容しうる。難しいようなら断念する」を選んだ。結果、観察だけから立てた規則が、4,757 例すべてと一致した(断念は不要)。
