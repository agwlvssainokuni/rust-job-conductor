# 配り方: v0.10.4

出典: `deployment-pipeline-questions.md`(Q1〜Q5、まとめの確かめ済み)、`cd-config.md`、team.md の Deployment・Way of Working、project.md の Mandated。

## やり方

- **一度に全部配る(下書きを経る)**
  - 単一バイナリの CLI で、利用者が自分で取りに来る。そのため、段階的な切り替えは当てはまらない。
  - 下書きのリリースが、人の確かめの段になる(Q3)。
- 環境は 1 つ(利用者の手元)(Q1)。

## 手順

1. `main` が最新で、CI がすべて通っていることを確かめる。
2. `main` の上にタグ `v0.10.4` を付けて push する。人が行うか、人の頼みで AI が行う。
3. `release.yml` の 4 つのジョブが通るのを見る。
4. 下書きのリリースで、成果物、`SHA256SUMS`、自動の注記を確かめる。そのうえで、v0.10.4 の注記を書き足す(Q5)。
   - `conductor` の動きは v0.10.3 と同じであること。
   - 大きなソースのファイル 3 つを、責務ごとに分けたこと。ファイルは、引数の解釈、定義の検査、表示の 3 つ。
5. 公開は、人が確かめてから行う。

## smoke test

- `build` のジョブが、展開したバイナリの `--version` を 3 つの対象で確かめる(Intel macOS を除く)。

## 中止の条件

- `verify-tag`、`checks`、`build` のどれかが落ちたら、下書きは作られない。原因を直してから、タグを消して付け直す(`rollback-runbook.md`)。
- `checks` の `coverage` で、時間に敏感なテスト(`runner_log` など)が落ちたときは、走らせ直す。上限は下げない。
