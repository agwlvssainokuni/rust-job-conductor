# Requirements Analysis — 質問

依頼: ジョブの `command` に、文字列に加えて、文字列の配列も書けるようにする。文字列は従来どおり、配列は 1 要素が 1 引数で、分割も展開もしない。空の配列と空の要素は定義の誤り。

調査(codekb)で分かった、決める必要のある点を 2 つ確認します。

## Q1. [検証] 配列の「空の要素」の扱い

依頼では「空の要素は定義の誤り」とありました。ただ、実行するコマンドの引数には、空の文字列を渡したい場合があります(例: `["sh", "-c", "echo \"$1\"", "x", ""]` の最後の `""`)。

- A. **先頭の要素(実行するプログラム)だけ**、空・空白だけを定義の誤りにする。2 番目以降は、空の文字列も、有効な引数として渡す(推奨)
- B. **すべての要素**で、空・空白だけの文字列を定義の誤りにする(依頼の文面どおり。空の引数は渡せない)
- C. Not yet defined(まだ定まっていない)
- X. Other (please specify)

[Answer]: A

## Q2. [書式の版] `format_version` の扱い

配列の `command` は、これまでの `conductor`(v0.1.x)が読むと、「文字列でない」という定義の誤りになります。

- A. `format_version = 1` のまま。配列は、追加の書き方として扱う(推奨。古い `conductor` は、配列を使った定義を、定義の誤りとして拒否する)
- B. 配列を使うときは `format_version = 2` を要求する(古い版は「未対応の版」として拒否する。文字列だけの定義は、1 のまま動く)
- C. Not yet defined(まだ定まっていない)
- X. Other (please specify)

[Answer]: A
