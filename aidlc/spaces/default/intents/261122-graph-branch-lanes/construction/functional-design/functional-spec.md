# 機能の仕様(Functional Spec): graph の text 表示の改善 その 2

対象: `conductor graph` の text(`--format text`)の、「分岐」(1 つのジョブの成功と警告が、異なる、どちらも次でない行き先へ進む形)のレーンの配置。質問と答え: `functional-design-questions.md`(Q1: A、Q2: A、Q3: A)。

## 1. 変更の要点

| 形 | 今 | この変更のあと |
|----|-----|----------------|
| 分岐(例: `a` の成功が `c`、警告が `d`)で、線が入れ子か並び、同じ行き先を含まない | 辺の一覧 | レーンの図。2 本の線を同時に出し、主線の `\|` を省く(BR1.1〜BR1.5) |
| 分岐の線が交差、または同じ行き先を含む | 辺の一覧 | 辺の一覧(変わらない。BR2.1) |
| 上記以外 | 従来どおり | 1 文字も変わらない(BR3.1) |

## 2. 分岐の判定(WF1)

1. ジョブから出る辺のうち、次のジョブへの辺がなく、辺がちょうど 2 本で、行き先が異なるジョブは「分岐」。近い順に t1 < t2(終点の位置はジョブの数)。
2. 分岐のジョブは、飛び越しの積み上げ(上が最も内側)に、外側 t2、内側 t1 の順に載せる。積み上げが空なら、常に載せられる(終点への分岐を含む)。空でなければ、`t2 < top` のときだけ載せられる(これで `t1 < t2 < top` となり、すでに開いている線と、行き先が同じにも、交差にもならない)。`t2 >= top` なら、辺の一覧(BR2.1)。
3. 通常のジョブの合流(同じ行き先。`t == top`)は、前回までと同じ。ただし、積み上げの上の線が**分岐が開いた線**のとき(後のジョブが、分岐の線に同じ行き先で合流する形。例: `a` が `c` と `e` へ分岐し、`d` が `e` へ飛ぶ)は、辺の一覧にする(BR2.2)。分岐の線には、「分岐が開いた」印を付ける。
4. 「両方の飛び越し」と通常のジョブの判定は、前回までと同じ。

## 3. 線の行の作り方(WF2)

前回までの規則(合流の行 `/`、ノードの行、分岐の行 `\`)に、分岐を足す(BR1.2〜BR1.5)。

- ノードの行: 幅は 2 × (1 + 開いている線の数 + 2)。既存の線の記号は、直前が分岐の行(新しい線を作るジョブのあと)なら `\`、それ以外は `|`。
- 分岐の行: 列 0 は空。列 1 から `\` を (既存の線の数 + 2) 個、空白 1 つおきに並べる。
- 行き先のノードの前の合流の行: 前回までと同じ(線を 1 本閉じ、残りを左へ寄せる)。列 0 は、その線を開いたジョブがすべて主線につながらない(分岐、「両方の飛び越し」)なら空、1 つでも通常の飛び越しがあれば `|`。

## 4. 図の例(規則から導いた。git の出力ではない。全 871 例は `layout-oracle-branch.md`)

B1: `a` の成功が `c`、警告が `d`(5 ジョブ)

```text
*     a
 \ \
* | | b
 / /
* | c
 /
* d
* e
o @end
```

B2: `a` の成功が `c`、警告が終点(4 ジョブ)

```text
*     a
 \ \
* | | b
 / /
* | c
* | d
 /
o @end
```

B3: 外側に通常の飛び越し(`a>g`、`b` の成功が `d`、警告が `e`。7 ジョブ)

```text
*   a
|\
* \     b
 \ \ \
* | | | c
 / / /
* | | d
 / /
* | e
* | f
|/
* g
o @end
```

B4: 線が離れる(`a` の成功が `d`、警告が `f`。6 ジョブ)

```text
*     a
 \ \
* | | b
* | | c
 / /
* | d
* | e
 /
* f
o @end
```

`-v` の詳細の行は、前回までの規則(ノードの行と、続く分岐の行のあとに、列の数だけ `| ` を描く)のまま。分岐の行(空白と `\`)は `Fork` の記号を含むので、置き場所は変わらない。列の数は、ノードの行の幅 ÷ 2。

## 5. 辺の一覧に残る形

交差(`a` の成功が `d`、`b` の成功が `e`)、分岐の線が、ほかの線と同じ行き先を持つ形、分岐の行き先が最も内側の線より遠い形(交差)、3 本以上の辺を持つ形などは、従来どおり辺の一覧。先頭の注記の英語(「…cross or form a shape the lane diagram cannot draw…」)は、変えない(すでに、これらの形を含む言い方)。

## 5a. コードの変更点(core の `graph/layout.rs` と cli)

1. `skip_targets`: 戻り値を、ジョブごとの飛び越しの行き先 1 つ(`Option<usize>`)から、行き先の昇順の並び(0〜2 個)に広げる(分岐だけ 2 個)。現在の「1 ジョブに飛び越しの辺が 2 本あると `None`」(`skip[from].replace(to).is_some()`)を、次のジョブへの辺を持たず、辺がちょうど 2 本で、どちらも次でなく、行き先が異なるジョブ(分岐)だけ許すように変える。`!has_next` の判定は、「両方の飛び越し」に加えて、分岐も免除する。分岐の 2 本の辺は、それぞれ種類が 1 つ(`edge.kinds` の長さ 1)なので、「両方の飛び越し」(種類が 2 つ)とは重ならない。それ以外で、次のジョブへの辺を持たないジョブは、従来どおり辺の一覧。`SkipKind` は、`entities.md` の説明用の名前で、コードの型ではない(合流は、従来どおり `lane_layout` の中で、積み上げの上と比べて見分ける)。
2. `skip_targets`: 積み上げの判定は、分岐では、積み上げが空なら載せ、空でなければ `t2 < top` のときだけ、外側 t2、内側 t1 の順に載せる(それ以外は辺の一覧。BR2.1)。通常のジョブの合流(`t == top`)は、積み上げの上が「分岐が開いた線」のとき、辺の一覧にする(BR2.2)。それ以外の通常のジョブの合流は、そのまま。積み上げの各線に「分岐が開いた」印を持たせ、`lane_layout` と `skip_targets` の両方で使う。
3. `lane_layout`: 分岐のジョブに、ノードの行(幅 +2 本分)と、分岐の行(列 0 を空にし、`\` を (既存 + 2) 個)を置き、2 本の線を積む。積み上げの各線に、「すべて主線につながらないか」の印を持たせる(前回の `open_all_both` の考え方)。合流の行の列 0 は、この印で決める。
4. `after_fork`: 新しい線を作るジョブ(通常の新しい線、分岐)のあとだけ真(前回と同じ)。
5. cli の `graph_text.rs`: 変更なし。`-v` の詳細の行の置き場所は、分岐の行が `Fork` を含むことに頼る(前回と同じ依存)。
6. テストの書き換えと追加(次の §6)、README、仕様書(BR4.2)。

## 6. テストの方針(Minimal の test-after、行カバレッジ 80%)

- そのまま通る既存のテスト: 正解データ 537 例と 1,517 例の照合、通常の図、同じ行き先、両方の飛び越し、交差の例(`graph_report`、`binary_graph`、`graph_perf`)。
- **書き換えが要る**既存のテスト(確実に失敗するもの。レビューで確認済み):
  - `crates/core/tests/graph_drawable.rs` の `対応しない形_異なる行き先が_2つ`(118 行目あたり): 「`a` の成功が `c`、警告が `e`」は、**図にできる**(分岐)に変わる。名前も直す。
  - `crates/core/tests/graph_lane_polish.rs` の `辺の一覧に残る形_異なる行き先が_2つ`: 交差の形、または「分岐の線への合流」の形に差し替える。
  - `crates/cli/tests/docs_graph.rs` の `readme_の辺の一覧に切り替わる形は_交差と異なる行き先の_2_つだけを述べる`: README が「異なる行き先」を含むことを要求しているので、新しい README の記述(交差と、分岐の線への合流など)に合わせる。
  - `binary_graph.rs` と `graph_report.rs` は、交差の形だけを使っているので、影響しない。
- 新規: `layout-oracle-branch.md` を `crates/core/tests/fixtures/graph_layout_oracle_branch.md` として入れ、全 871 例が一致すること(BR4.1)。B1〜B4、`-v`、`--state`、辺の一覧に残る形(交差、同じ行き先を含む分岐)の例。実バイナリで、分岐の定義の図を確かめる。README の例と実出力の一致。
