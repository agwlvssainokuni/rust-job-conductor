# Team Practices(ドラフト)

> 全項目は `memory/org.md` の既定値を出発点にした**ドラフトの既定値**であり、確立済みのチーム事実ではない。インタビューで確認・修正する。

## Way of Working

- **Integration branch**: main
- ドラフト既定: トランクベース開発。作業ごとの短命ブランチを `main` に squash マージし、`main` の履歴を線形に保つ。[ドラフト既定・要確認]
- 複数環境を持たないため、リリースはタグで区切り、長命のリリースブランチは作らない。[ドラフト既定・要確認]
- 開発者は Rust に不慣れなため、小さな単位でのレビュー(変更を小さく保つ)を推奨する。[ドラフト既定・要確認]

## Walking Skeleton

- ドラフト既定: 最初に薄いエンドツーエンドの縦切り(定義ファイルを読み、1 ジョブを実行し、ステートファイルに記録して、終了コードを返す)を作り、各部が繋がることを確認してから残りの機能を足す。[ドラフト既定・要確認]
- 根拠: Rust 未経験の開発者が、ビルド・テスト・3 OS 対応の土台を早期に検証できる。[ドラフト既定・要確認]

## Testing Posture

- **Methodology**: test-after
- **Methodology evidence**: `memory/org.md` の未確定時の既定値が test-after であるため、それを暫定採用した。Rust 未経験という事情を踏まえ、TDD などへの変更はインタビューで判断する。[ドラフト既定・要確認]
- **Ordering**: 各テスト可能な層を実装してから、その層のテストを書いて実行する。
- ドラフト既定: `cargo test` による単体テストと、バイナリを実行する統合テストを含める。[ドラフト既定・要確認]
- ドラフト既定: 行カバレッジ 80% を下限とし、マージ前に CI で実行する。[ドラフト既定・要確認]
- ドラフト既定: Linux・macOS・Windows の 3 OS で CI テストを実行する(制約 C3)。[ドラフト既定・要確認]

## Deployment

- ドラフト既定: 単一バイナリ CLI であり、ステージング環境への自動デプロイは該当しない。マージ時に CI でビルドと検査を行い、タグ付けでリリース成果物(3 OS 向けバイナリ)を作成する。[ドラフト既定・要確認]
- ドラフト既定: 配布先と公開の承認(手動承認の要否)はインタビューで確認する。[ドラフト既定・要確認]

## Code Style

- ドラフト既定: フォーマッタは `rustfmt`(`cargo fmt`)、リンタは `clippy`(`cargo clippy`)を使い、CI で失敗時にマージをブロックする。[ドラフト既定・要確認]
- ドラフト既定: 命名は Rust 標準(関数・変数は snake_case、型は PascalCase、定数は SCREAMING_SNAKE_CASE)。プロジェクト独自の命名規則は設けない。[ドラフト既定・要確認]
- ドラフト既定: 設定ファイル(`rustfmt.toml`、`clippy.toml` 等)はリポジトリのルートに置く。[ドラフト既定・要確認]
