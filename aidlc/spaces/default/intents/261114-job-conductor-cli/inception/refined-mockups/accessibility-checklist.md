# Accessibility Checklist(CLI の見やすさと使いやすさ)

上流: wireframes と user-flow(Rough Mockups)、stories、requirements、team-practices。画面を持たない CLI のため、WCAG の画面向けの項目は該当しない。代わりに、ここでは要件にある表示の判別性(NFR6)と、コマンドラインの利用者にとっての使いやすさを、確認項目としてまとめる。

## 確認項目

| 項目 | 基準 | 対応するストーリー | 出典 |
|------|------|--------------------|------|
| 色だけに頼らない | 状態は、色がなくても文字で判別できる | US5.1 | requirements の NFR6 |
| 色の自動無効 | 端末以外への出力では、色の制御文字を出力に含めない | US5.1 | requirements の NFR6 |
| キーボードだけで操作できる | すべての機能が、コマンドとオプションで操作できる(マウスや画面の操作を必要としない) | US2.1〜US7.1 | 画面を持たない CLI であること(intent-statement) |
| 読み上げと検索のしやすさ | 出力は、1行に1つの情報とし、一覧は列を空白で区切ったテキストにする。装飾だけに意味を持たせない | US5.1 | [assumption] |
| 誤りの手がかり | エラーには、ファイル名・行・原因を含め、直す手がかりが分かる | US1.2、US4.1 | requirements の FR1.4、FR4.5 |
| 言語 | 表示の言語は、環境のロケールに従う | 全般 | [Q5] |
| 同じ語を使う | 状態を表す語は、すべてのコマンドで同じものを使う | US5.1、US2.4 | design-system-mapping |

## 該当しない項目

- 画面の見出し、ランドマーク、画像の代替テキスト、画面の拡大・縮小、レスポンシブな表示: 画面を持たないため、該当しない。 intent-statement の Initial Scope Signal
- 画面向けの WCAG のレベルは、設定しない。 [assumption]

## Assumptions & Open Questions

- 出力の「1行に1つの情報」といった取り決めは、画面を持たない CLI の一般的な使いやすさの観点から置いた既定であり、あなたが修正できる。 [assumption]
