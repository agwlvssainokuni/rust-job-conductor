# Reliability Requirements(u3-cli)

上流: requirements(FR2、FR3、FR4、NFR1〜NFR4)、functional-spec、rules(BR2.x〜BR5.x)、u1-core・u2-runtime の保証(at-least-once、原子的な書き込み)。`conductor` は、1回で終わるコマンドで、常駐せず、可用性(SLA)、フェイルオーバー、複製、バックアップ、サーキットブレーカーの対象ではない。ここでは、**1回の実行が、どう失敗し、何が保証されるか**を、要件として定める。inception に、信頼性の NFR は無い。ここでは、要件(FR2.9、FR3.2、FR4.1、FR6.1 など)と、決めてある契約に由来する要件を、最も近い NFR(NFR2: 単一バイナリ、NFR3: 3つの OS で同じ)の枝番として置く。**出典は、各行の出典欄で示す**。

## 要件

| ID | 要件 | 判定の基準 | 出典 |
|----|------|------------|------|
| NFR2.2 | 実行の結果は、決定的である。同じ定義・同じステート・同じジョブの結果に、同じ終了コードと、同じステートの更新を返す。終了コードの意味は、E1 の表(0、ジョブの終了コード(0〜255)、1、64〜68、70、127、128 + 番号)で固定し、どの OS でも同じ(BR5.2) | 終了コードの表の全項目を、テストで確かめる(実際のジョブと補助の実行ファイル)。3つの OS で、同じ定義に、同じ終了コード | NFR2、NFR3、BR5.1、BR5.2、AC2.5.5 |
| NFR2.3 | ジョブは、自動で再試行しない。エラーで止まったら、ステートにエラーの位置を残し、利用者の操作(再実行、`reset`)を待つ | エラーで止まったあと、何も操作しなければ、何も起きない(ジョブが、追加で起動されない)。再実行で、エラーのジョブから再開する(AC4.3.x) | FR3.2、AC3.2.2、AC4.3.4 |
| NFR2.4 | **保証の範囲(at-least-once)**: ジョブの終了と、その結果のステートへの書き込みのあいだに、`conductor` が落ちる(または強制終了される)と、そのジョブは、次の呼び出しで、再実行されうる。ステートの内容が壊れることは、ない(原子的な書き込み)。この保証の範囲を、利用者向けの文書に書く | README などの利用者向けの文書に、「ジョブの終了と記録のあいだに落ちると、ジョブが再実行されうる(冪等でないジョブは注意)」と明記する(Code Generation のステージで、文書の項目を作る)。ステートが、書き込みの途中で壊れた内容にならないことは、u2-runtime のテスト | FR4.1、u2-runtime の BR2.9、NFR4.4 |
| NFR2.5 | 中断(シグナル)の扱いは、決まった順序で行う: ジョブに転送し、終了を待ち、結果をエラーとして記録し(起動前・ジョブのあいだの中断は、再開位置だけ)、128 + 番号で終わる。2回目以降のシグナルは、追加の動作をしない(強制終了しない) | 中断のテスト(UNIX 系: ジョブの実行中、起動前、ジョブのあいだの3つ)で、期待する終了コードと、ステート(再開位置)。中断のあと、ステートが読み戻せ、次の実行が、再開位置から始まる | FR2.9、AC2.5.6 |
| NFR2.6 | 失敗の経路で、利用者が、必ず原因を知れる: `conductor` 自身のエラー(終了コード 64〜68、70)は、標準エラーに、固定の文と場所で、常に表示する(`-v` なしでも)。ジョブ自身のエラー(ジョブの終了コード)は、ジョブ本体の出力に任せる。ステートの書き込みや初期化の失敗は、ジョブがすでに実行されていることを含めて、表示する | `conductor` 自身のエラーの全種類(64〜68、70)で、標準エラーに、原因が出る(テスト)。`-v` なしでも出る | FR2.6、AC2.4.2 |
| NFR2.7 | 回復の手段は、`conductor reset`(ステートの初期化)と、再実行だけで、いつでも使える。ステートが壊れていても、定義が食い違っていても、`reset` は動く(検査を迂回する)。回復の目標時間(RTO)・目標時点(RPO)は、定めない(利用者の操作) | ステートを壊した状態、定義と食い違う状態、完了のまま残った状態で、`reset` が成功し、次の実行が、先頭から始まる | FR6.1、AC4.4.2、AC6.1.x |
| NFR2.8 | 書式の互換性: 定義ファイルとステートファイルは、書式の版(`format_version`)を持つ。この版の `conductor` は、版 1 だけを読む。将来の版を、勝手に解釈せず、エラーにする(定義: 64、ステート: 65) | 版の違う入力で、期待する終了コードと、reset を促す表示(ステート) | contract E2・E3 |

## この Unit に該当しない信頼性の項目

- 可用性の目標(SLA/SLO)、フェイルオーバー、複製、データの耐久性(バックアップ)、サーキットブレーカー、リトライの方針(バックオフ)、ヘルスチェック、縮退運転: `conductor` は、1回で終わるコマンドで、これらを持たない。再試行は、しないことを要件にする(NFR2.3)。

## Assumptions & Open Questions

- 利用者向けの文書(README)の作成は、このステージの対象ではなく、Code Generation(または Deployment のステージ)で行う。ここでは、書くべき内容(NFR2.4)を、要件にした。 [assumption]
