# Performance Requirements(u3-cli)

上流: requirements(NFR1)、functional-spec(W1〜W6)、rules(BR6.6)、u1-core・u2-runtime の NFR の配分(それぞれ p95 20ms 以内、仮)。`conductor` は、1回で終わるコマンドであり、スループットや同時の接続はない。性能の要件は、**起動から終了までの、`conductor` 自身のオーバーヘッド**に限る。各行は、inception の NFR の ID に枝番を付けた ID を持つ。

## 要件

| ID | 要件 | 判定の基準 | 出典 |
|----|------|------------|------|
| NFR1.1 | `conductor run <job-id>` と `conductor pipeline <name>` の、**起動から、ジョブの起動(またはスキップの判定)まで**を、100ms 以内にする。内訳の目標(仮): u1-core(定義の読み込みと検証)20ms 以内、u2-runtime(全ジョブの command の検査、ステートの読み込み、照合、初期ステートの書き込み)20ms 以内、この Unit 自身(引数の解釈、シグナルの準備、判断)10ms 以内、プロセスの起動と実行ファイルの読み込みの余裕を含めた残り | ジョブ10個程度の定義で、同じ環境で 20 回測定した p95 が 100ms 以内。Linux・macOS・Windows のそれぞれで満たす(AC2.5.3)。測定は、何もしない補助のジョブ(すぐに終わる)で、`conductor` の起動から、ジョブの起動までの時間を、ジョブ側で記録した時刻との差で求める | NFR1、AC2.5.3 |
| NFR1.2 | ジョブが終わってから、`conductor` が終了するまで(分類、記録、ステートの書き込み(`Durable`)、完了時の初期化、終了)を、100ms 以内にする。ジョブ自身の実行時間は、含めない。なお、**起動前(NFR1.1)と、ジョブのあと(NFR1.2)を合わせた `conductor` 自身のオーバーヘッドも、AC2.5.3 の「p95 が 100ms 以内」として、合計で測る**(合計が 100ms を超える場合は、NFR1.1 と NFR1.2 の配分を、実測で見直す) | 同じ測定で、ジョブの終了から、`conductor` の終了までの時間の p95 が 100ms 以内。合計(起動前 + ジョブのあと)の p95 も、100ms 以内を目標とする。**合否: 100ms の基準を超えたら、CI を失敗にする(Code Generation の実測のあとに、仮の配分を確定してから)。確定までは、警告として記録する** | NFR1、AC2.5.3 |
| NFR1.3 | ジョブの実行中の、`conductor` の CPU の使用は、無視できる程度にする(待ちは、短い間隔の確認のくり返しで、間隔は 10ms まで広がる)。ジョブの出力を、加工・バッファリングせず、そのまま通す | ジョブを 5 秒動かしたときの、`conductor` 自身の CPU 時間が、100ms 以内(測定のテスト)。ジョブの出力が、順序と内容を保って、そのまま届く | NFR1、u2-runtime の NFR1.1 |
| NFR1.4 | 表示のための準備(ロケールの判定、文言の用意)は、最初の表示が必要になるまで行わない。convert のライブラリの初期化は、convert コマンドのときだけ行う | `run` の成功(`-v` なし)の経路で、ロケールの判定と、文言の用意が、行われないこと(コードの確認と、呼び出しの回数を数える単体テスト) | NFR1、BR6.1、BR6.6 |

## この Unit に該当しない性能の項目

- スループット、同時の接続数、キャッシュ、データベース、ネットワークの遅延: `conductor` は、1回で終わるコマンドで、これらを持たない。

## Assumptions & Open Questions

- 100ms の内訳(20ms、20ms、10ms)は、仮の配分である。Code Generation で、3つの OS で実測して、見直す。特に、macOS での `fsync` の遅さ(結果の書き込み)が、NFR1.2 に効く。 [assumption]
- 測定の方法(ジョブ側で時刻を記録する補助の実行ファイル)は、Code Generation で、u2-runtime の補助の実行ファイルを拡張して、作る。 [assumption]
