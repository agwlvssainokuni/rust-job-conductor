# Performance Requirements(u3-cli)

上流: requirements(NFR1)、functional-spec(W1〜W6)、rules(BR6.6)、u1-core・u2-runtime の NFR の配分(それぞれ p95 20ms 以内、仮)。`conductor` は、1回で終わるコマンドであり、スループットや同時の接続はない。性能の要件は、**起動から終了までの、`conductor` 自身のオーバーヘッド**に限る。各行は、inception の NFR の ID に枝番を付けた ID を持つ。

## 要件

| ID | 要件 | 判定の基準 | 出典 |
|----|------|------------|------|
| NFR1.1 | **`conductor` 自身のオーバーヘッド(AC2.5.3)**: `conductor run <job-id>` と `conductor pipeline <name>` で、「`conductor` の実行時間の合計から、ジョブ自身の実行時間を引いたもの」を、p95 で **100ms 以内**にする(**AC2.5.3 の対象は、`conductor run <job-id>`(ジョブ1つの個別実行)**。`conductor pipeline` は、ジョブごとに、起動、`Durable` の書き込み、最大 10ms の待ちが加わるため、合計の 100ms を、ジョブの数に対して約束しない。`pipeline` は、**ジョブ1つあたり**の、「ジョブのあとの処理 + 次のジョブの起動前の処理」を、p95 で 50ms 以内(警告として記録。基準は、実測で見直す)とする)。内訳の配分(仮): ジョブの起動まで(起動前)50ms = u1-core 20ms + u2-runtime 20ms + この Unit 10ms、ジョブの終了から `conductor` の終了まで(ジョブのあと)50ms(待ちのくり返しによる終了の観測の遅れ(最大 10ms)、分類、記録、`Durable` の書き込み、完了時の初期化、終了。u2-runtime の実測では、macOS の debug ビルドで、`Durable` の書き込みの p95 が約 9.7ms) | ジョブ10個程度の定義で、同じ環境で 20 回測定した p95 が 100ms 以内。Linux・macOS・Windows のそれぞれで満たす。**測定の方法**: ジョブは、起動したらすぐに終わる補助の実行ファイル(u2-runtime のものを拡張し、起動時刻と、終了の直前の時刻を、単調な時計で記録する)。オーバーヘッド = `conductor` の起動から終了までの時間 − (補助の実行ファイルの、起動から終了の直前まで)。**合否: 100ms の基準を超えたら失敗にする。ただし、仮の配分の確定(Code Generation の実測)までは、警告として記録する** | NFR1、AC2.5.3 |
| NFR1.2 | 起動前の 50ms と、ジョブのあとの 50ms の内訳(NFR1.1)を、それぞれ測って記録する(合否は、NFR1.1 の合計だけで決める。内訳は、どこが遅いかを見つけるための記録) | 測定のテストが、起動前の時間と、ジョブのあとの時間を、別々に出力する。**時計は、単調な時計(プロセスをまたぐ比較は、補助の実行ファイルが、ジョブの起動時刻を、`conductor` の外から見える形(標準出力)で出し、測定のテストが、`conductor` を起動する直前の時刻と、終了の直後の時刻を、同じプロセスの時計で測って、差を取る)** | NFR1、AC2.5.3 |
| NFR1.3 | ジョブの実行中の、`conductor` の CPU の使用は、無視できる程度にする(待ちは、短い間隔の確認のくり返しで、間隔は 10ms まで広がる)。ジョブの出力を、加工・バッファリングせず、そのまま通す | ジョブを 5 秒動かしたときの、`conductor` 自身の CPU 時間が、100ms 以内(測定のテスト)。ジョブの出力が、順序と内容を保って、そのまま届く | NFR1、u2-runtime の NFR1.1 |

## この Unit に該当しない性能の項目

- スループット、同時の接続数、キャッシュ、データベース、ネットワークの遅延: `conductor` は、1回で終わるコマンドで、これらを持たない。

## Assumptions & Open Questions

- 100ms の内訳(20ms、20ms、10ms)は、仮の配分である。Code Generation で、3つの OS で実測して、見直す。特に、macOS での `fsync` の遅さ(結果の書き込み)が、NFR1.2 に効く。 [assumption]
- 測定の方法(ジョブ側で時刻を記録する補助の実行ファイル)は、Code Generation で、u2-runtime の補助の実行ファイルを拡張して、作る。 [assumption]
