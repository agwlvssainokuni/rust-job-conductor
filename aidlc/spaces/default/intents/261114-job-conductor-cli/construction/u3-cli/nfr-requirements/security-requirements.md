# Security Requirements(u3-cli)

上流: functional-spec(W1〜W6)、rules(BR1.1〜BR7.3)、requirements(NFR4)、contract-summary(E1)、質問への回答(Q1〜Q3)。u3-cli は、`conductor` の実行ファイルであり、認証・認可・暗号化・ネットワークはない。入力は、(1) コマンドラインの引数、(2) 環境変数(`LANG` など)、(3) 定義ファイル・ステートファイル・convert の入力(いずれも、他の Unit が読み、検査する)、(4) シグナルである。出力は、標準出力・標準エラー、終了コード、ジョブの起動(u2-runtime)である。各行は、inception の NFR の ID に枝番を付けた ID を持つ。

## 要件

| ID | 要件 | 判定の基準 | 出典 |
|----|------|------------|------|
| NFR4.1 | コマンドとオプションは、BR1.1〜BR1.3、BR1.6 の文法だけを受け付ける。知らないコマンド、必須の引数がない、余分な引数、許されない場所のオプションは、ジョブを一切実行せず、使い方の誤り(終了コード 68)にする。引数は、シェルを介して、解釈・展開しない | 規則の表(コマンドごとの、正しい引数と誤った引数)のテストで、期待どおりの終了コードと、ジョブが実行されないこと。`--` で始まる未知のオプションと、`-v` を `watch`・`reset`・`convert` に付けたとき、68 | NFR4、BR1.1〜BR1.3 |

| NFR4.3 | シグナルのハンドラの中では、印を立てることだけを行う(確保、ロック、書き込み、表示をしない)。シグナルの受け取りの準備は、定義の検査より前に行う。この Unit(クレート)は、`unsafe` を使わない | クレートに `#![forbid(unsafe_code)]` を置く。ソースの検索で、`unsafe` がない。シグナルを受け取るテスト(UNIX 系)で、ハンドラが、印だけを立て、終了の処理は、メインの流れで行われること | NFR4、BR4.1、Q2: A |

## この Unit に該当しない NFR

- 認証・認可・暗号化・秘密情報の取り扱い: `conductor` は、秘密情報を扱わず、ネットワークにも触れない。ジョブの環境変数は、そのまま引き継ぐだけで、読み取って表示も保存もしない。

## Assumptions & Open Questions

- 終了コード 70(内部の誤り)は、E1 に足す新しい値である(契約の更新は、この Unit の Code Generation の `code-summary.md` に記録する)。 [assumption]
- 実行ファイルの署名(コードサイニング)は、この版では、行わない。チェックサムの公開だけとする。署名を求める要望が出たら、見直す。 [assumption]
- 依存のライセンスと脆弱性の確認(`cargo-deny`、`cargo-audit`)は、CI Pipeline のステージで決める(u1-core の依存の方針と同じ)。 [assumption]
