# Security Requirements(u2-runtime)

上流: functional-spec(W1〜W6)、rules(BR1.1〜BR2.10)、requirements(NFR4)、contract-summary(C3、E3)、質問への回答(Q1〜Q3)。u2-runtime は library であり、認証・認可・暗号化・ネットワークはない。入力は、(1) 定義ファイルの `command`(利用者が書く文字列)、(2) ステートファイル(以前の実行が書いたもの。壊れうる)、(3) OS が返すプロセスの結果である。出力は、外部のプロセスの起動と、ステートファイルの書き込みである。各行は、inception の NFR の ID に枝番を付けた ID を持つ。

## 要件

| ID | 要件 | 判定の基準 | 出典 |
|----|------|------------|------|
| NFR4.1 | ジョブは、シェルを介さず、引数を1つずつそのまま渡して起動する。引数のメタ文字(`;` `&&` `\|` `$` `*` `>` など)は、解釈されない | 引数をそのまま出力する補助の実行ファイルに、メタ文字を含む引数を渡し、出力が、渡した文字列と完全に一致する(3つの OS)。`sh`、`cmd` を、この Unit のソースが呼ばない(ソースの文字列の検索) | NFR4、AC2.1.1、BR1.2 |
| NFR4.2 | command の文字列の分け方は、BR1.1 の規則だけで決まり、閉じていない引用符と空の command は、ジョブの起動前に検知できる(`check_command`)。分け方の結果は、3つの OS で同じ | 規則の表(引用符、バックスラッシュ、空の引数、タブ・改行、連結)のテストが、3つの OS で同じ結果。閉じていない引用符は `unclosedQuote`、空は `empty` | NFR4、BR1.1、AC2.1.1 |
| NFR4.3 | ステートの読み込みは、上限(1 MiB)で読み取りを打ち切り、版を先に確認し、未知のキー・型の誤り・内容の矛盾(BR2.3 の一覧)を、`corrupt` で拒否する。壊れた、または読めないステートで、ジョブを実行させない。**長さ 0 のファイルは、空のステートとして扱い(`corrupt` にしない)、完了(`completed` が true)のまま残ったステートも、空として扱う**(下の「既存の成果物との差分」) | 1 MiB ちょうどは受理、1 MiB + 1 バイトは `tooLarge`(終わりのない入力でも、上限 + 1 バイトで止まる)。BR2.3 の各項目(未知のキー、型の誤り、必須のキーの欠落、status の不正、不正な UTF-8、id の重複、並びの不一致、resume_job_id が job_order にない、completed と resume_job_id の両立、skip_reason の矛盾、版の違い)が、それぞれ期待する kind(`corrupt` / `versionMismatch` / `unreadable`)で拒否される。将来の版(未知のキーを含む)が `versionMismatch` になる。長さ 0 のファイルと、completed のステートが、空として返る | NFR4、FR4.4、FR4.5、BR2.3 |
| NFR4.4 | ステートの書き込みは、原子的である。中断・失敗しても、ステートファイルは、直前の完全な内容のままで、壊れた内容を残さない。この Unit が作った一時ファイルは、失敗したとき消し、残った一時ファイルは読まない。**結果の書き込み(ジョブのあと)は、ファイルの内容を同期(`sync_all`)してから置き換える。起動前の初期ステートの書き込みだけは、同期を省いてよい**(NFR1.1。電源断で、長さ 0 のファイルが残りうるが、NFR4.3 により、空として扱われ、再作成できる) | 書き込みの各段階で失敗を起こしたとき、ステートファイルの内容が変わらず、`writeFailed` が返る。失敗の起こし方は、**権限に頼らない**: 置き換え先を、ディレクトリにしておく(置き換えが失敗する)、一時ファイルの名前を、ディレクトリで塞ぐ(作成が失敗する)。権限(読み取り専用のディレクトリ)による失敗のテストは、UNIX 系で、root でないときだけ行う。一時ファイルが残っていても、読み込みの結果が変わらない。結果の書き込みが、同期を行うこと(同期の指定が、結果の書き込みで有効)を、関数の単体テストで確かめる | NFR4、FR4.1、AC4.1.2、BR2.4 |
| NFR4.5 | ステートファイルには、ジョブID、終了コード、定義ファイルのパス、パイプライン名、ステートの管理の項目(版、順序、再開位置、完了の印)を書く。ジョブの command、引数、環境変数、標準出力・標準エラーの内容は、書かない。エラーの表示は、固定の文とパス(ステートファイルのパス)だけで組み立て、入力の値と、ライブラリのエラー文を含めない。**ステートは、どのジョブをスキップ・再開するかを決めるため、書き換えられると、実行の流れが変わる。この影響は、同じユーザー(または、書き込める人)の範囲に限られ、既定の権限(Q3: A)でも、他のユーザーが書き換えられない環境が通常であることを前提とする**(他のユーザーが書き込めるディレクトリに置く場合は、利用者が権限を管理する) | ステートファイルの内容に、command や環境変数の値が現れないこと(テスト)。全 kind の StateError と CommandError の表示に、入力の値が現れない(パスは、現れてよい) | NFR4、BR2.2 |
| NFR4.6 | ジョブの環境変数、作業ディレクトリは、変更せず、そのまま引き継ぐ。この Unit は、環境変数を、読み取って表示も保存もしない | 補助の実行ファイルが、conductor から引き継いだ環境変数と作業ディレクトリを、そのまま出力する(3つの OS) | NFR4、AC2.1.2、BR1.3 |
| NFR4.7 | 外部の入力と OS の結果に対する処理で、パニックしない。失敗は、戻り値のエラー(JobExecution の startFailure、StateError、CommandError)で返す。範囲外の値(終了コード、シグナル番号)で、桁あふれしない | 壊れた TOML、空のファイル、巨大な値、不正な UTF-8 のステート、存在しない・実行できないコマンド、で、パニックしない。`128 + signalNumber` は、桁あふれしない(飽和) | NFR4 |
| NFR4.8 | `unsafe` のコードは、UNIX 系のシグナル送信の1か所(`libc` の `kill` の呼び出し)だけに限る。ほかの場所では、`unsafe` を使わない。**その1か所は、次の条件を守る: (1) 宛先は、ジョブの子プロセスの pid(`Child::id()`)だけ(プロセスグループ全体ではない)。(2) pid は、`i32` に収まり、0 より大きいときだけ送る(0 や負にならない。変換に失敗したら、送らない)。(3) 送るのは、その子プロセスを、まだ回収(wait)していないあいだだけ(回収のあとに送ると、pid の再利用で、無関係のプロセスに届きうるため)。回収は、送信の判断の後に行う。(4) 送る回数は、1回** | クレートに `#![deny(unsafe_code)]` を置き、`unsafe` を許す場所を、1つのモジュール(UNIX 系のシグナル送信)だけに限る。ソースの検索で、ほかの場所に `unsafe` がない。送信の関数の単体テスト: pid が 0・負・`i32` を超える値のとき、送らずに拒否される。統合テスト: 補助の実行ファイル(SIGTERM を受けたら、その事実を出力して終わる)に、合図を立てると、1回だけ SIGTERM が届く。ジョブが先に終了していた場合に、`kill` が呼ばれない、または、回収前の呼び出しとして安全であること(コードの確認) | NFR4、Q1: A |
| NFR4.9 | Windows で、`.bat` と `.cmd` の起動は、標準のライブラリが、引数を安全に渡せると判断したときだけ行い、安全に渡せない引数は、起動失敗(startFailure)にする(コマンドの注入の防止)。この判断は、標準のライブラリが、そのための修正を含む版(1.77.2 以降)であることに頼り、最小のバージョン(1.85)は、それを満たす | Windows の CI のテストで、`.cmd` に、危険な引数(引用符を壊す文字列)を渡すと、`startFailure` になる。**CI で確かめるまでは、未確認とする。期待と異なる場合(起動してしまう、または、別の失敗になる)は、基準を見直す(危険な引数を、この Unit が先に拒否する)**。最小のバージョンの確認は、1.77.2 以降であることを、設計の記録として確かめる(テストではない) | NFR4、BR1.2 |


## 既存の成果物との差分(この文書を優先する)

functional-design の成果物は、レビュー済みのため、ここでは書き換えない。Code Generation で、次のとおり実装し、差分を `code-summary.md` に記録する。反映までは、この文書が優先する。

| 対象 | 変更の内容 |
|------|------------|
| rules の BR2.3 | 長さ 0 のファイルは、空のステートとして扱う(`corrupt` にしない)。「completed が true のステートは、空として返す」は、そのまま |
| rules の BR2.4、functional-spec の W3 | `write_state` に、耐久性の指定(`durable`)を足す。`durable = true`(既定。結果の書き込み)は、ファイルの内容を同期してから置き換える。`durable = false`(起動前の初期ステートの書き込み)は、同期を省く(NFR1.1)。契約 C3 の `write_state` の入力にも足す(u3-cli の設計で更新) |
| rules の BR1.7 | 宛先は、ジョブの子プロセスの pid だけで、回収の前だけに送る(NFR4.8 の条件)。プロセスグループ全体には送らない(BR1.7 の「子孫は追跡しない」と整合) |

## この Unit に該当しない NFR

- 認証・認可・暗号化・秘密情報の取り扱い: この Unit は、秘密情報を扱わず、ネットワークにも触れない。ステートファイルの権限は、既定のまま(Q3: A)で、秘密を含まない(NFR4.5)。

## Assumptions & Open Questions

- ステートファイルの権限は、作成時の既定(umask に従う)とした(Q3: A)。他のユーザーが読めうるが、書かれるのは、ジョブID・終了コード・パスだけである。 [assumption]
- 補助の実行ファイル(引数や環境変数を出力する、テスト専用のもの)の作り方(クレートの例の実行ファイルなど)は、Code Generation で決める。 [assumption]
- NFR4.9 の、標準のライブラリの挙動(1.77.2 以降の修正)は、最小のバージョン(1.85)で、Windows の CI で確かめる。手元に Windows がないため、CI で確かめるまで、未確認とする。 [assumption]
