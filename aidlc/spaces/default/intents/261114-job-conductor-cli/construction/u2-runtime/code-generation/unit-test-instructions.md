# Unit Test Instructions(u2-runtime)

## 実行の環境

- 言語とツール: Rust(edition 2024)、`cargo`。外部のサービスやネットワークは要らない(依存は、最初の取得だけ公開のレジストリから)。
- テストの枠組み: 標準の `cargo test`(単体は `#[cfg(test)]`、統合は `crates/u2-runtime/tests/`)。開発用の依存は `tempfile` のみ。実際のプロセスの起動は、テスト専用の補助の実行ファイル(`conductor-test-helper`。この Unit のクレートの `bin`)で行い、`cargo test` が自動でビルドする。
- 設定ファイル: ワークスペースの根の `Cargo.toml`(`crates/*` を含む)と、`crates/u2-runtime/Cargo.toml`(Step 1 で作る)。この Unit は、`conductor-core`(u1-core)に依存する。

## この Unit のテストの実行(この Unit に限る)

```bash
cargo test -p conductor-runtime --locked
```

- 最初のテストを書く前に、この命令が、テスト 0 件で成功することを確かめる(Step 1)。
- 特定のテストだけを動かすときは、フィルタを足す(例: `cargo test -p conductor-runtime --locked split::`、`cargo test -p conductor-runtime --locked --test state_reader`)。
- 全体の命令(`cargo test` を、`-p` なしで)は、この Unit では使わない。

## 整形と静的検査(Unit の確認)

```bash
cargo fmt --all -- --check
cargo clippy -p conductor-runtime --all-targets --locked -- -D warnings
```

## 時間の上限

- プロセスを起動するテストは、各 30 秒の時間の上限(別のスレッド + `recv_timeout`)を持つ。超えたら、テストが持つ子プロセスを強制終了して回収してから、失敗にする。この上限が検知するのは、ハングだけである。

## カバレッジ

- 目標: 行カバレッジ **80% 以上**(チームの下限。しきい値は下げない)。
- 全体の下限は、Build and Test が、組み立てたプロジェクトの全テストで判定する。この Unit だけのテストで 80% を下回ったときは、**この Unit のテストの失敗としては扱わず**、結果に記録する。測定は、`cargo llvm-cov -p conductor-runtime --locked`(導入されていれば)を、**ほかの命令とは別の命令として**実行する。補助の実行ファイルのソースは、測定から除外する(`--ignore-filename-regex`)。
- `cfg(windows)` のコードは、Linux の測定に入らない。その部分は、Windows の CI のテストの成功で確かめる。
- この Unit の範囲(`crates/u2-runtime/src/` のうち、補助の実行ファイルを除く)で、行カバレッジ 80% 以上を、Build and Test が確かめる。

## モックとスタブ

- 純粋な処理(分け方、照合、記録、送信の判断)は、モックを使わず、引数の値を直接作って渡す。
- プロセスの起動は、補助の実行ファイルを使う(モックにしない)。ファイルを使うテストは、`tempfile` の一時ディレクトリに作り、テストの終わりに自動で消える。書き込みの失敗は、権限に頼らず、置き換え先をディレクトリにして起こす。
- 時間の測定(NFR1.1)は、標準のライブラリの時計を使う。基準を超えても失敗にしない。

## テストデータ

- ステートファイルの例は、テストの中の文字列で直接書く。大きなステート(1 MiB 前後)は、テストの中で生成する(ファイルをコミットしない)。
- 実際の機密や、利用者の環境のパスは、テストデータに含めない。
