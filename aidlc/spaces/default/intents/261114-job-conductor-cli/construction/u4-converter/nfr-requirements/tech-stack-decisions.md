## 判断の記録(候補と、退けた案)

### T1 YAML のライブラリ [Q1: A]

- **Context:** 設計の規則(読み戻すと同じ木、YAML 1.2、アンカー・エイリアス・マージキー、重複するキーの検知、行の位置)を満たすライブラリが必要だが、満たすものがあるかを、いま確かめていない。
- **Decision:** 名前を固定せず、条件(上の行)を、Code Generation の最初に確かめて選ぶ。候補は、次のとおり(未確認。確かめるまで、条件を満たすとは言わない): (1) イベント(ノードの出現)の列を提供する YAML 1.2 のライブラリ(例: `saphyr` の系列)、(2) `serde` ベースの YAML のライブラリ(例: `serde_yaml` から派生して保守されているもの)。
- **Consequences:** 良い点は、条件に合うものを選べる。悪い点は、確かめるまで、設計の規則が実現できるかが、確定しない(リスク。上の止める手順で扱う)。
- **Alternatives Rejected:** (B) 候補を1つ決めて進める案: 確かめる前に、条件に合わない可能性があり、あとで設計を直す手戻りになるため退けた(Q1: A)。(C) YAML のパーサを自作する案: 誤りやすく、依存を減らす利点より、実装と検証の手間が大きいため退けた。

### T2 TOML のライブラリ [Q3: A]

- **Context:** TOML の読み取りと書き出しが必要。u1-core が、`toml` のライブラリを使っている。
- **Decision:** u1-core と同じ `toml` のライブラリを使い、バージョンを揃える。日時の値の判別、整数の範囲、文字列の引用符の出力を、Code Generation で確かめる。
- **Consequences:** 良い点は、依存が増えず、ビルドが単純。悪い点は、書き出しの形式(キーの順序、引用符)が、ライブラリの既定に従うこと(BR1.3 で許容済み)。
- **Alternatives Rejected:** (B) 書き出しにだけ別のライブラリ(`toml_edit` など)を使う案: コメントや書式の保持に強いが、この Unit は、コメントと順序を保持しないため、利点がなく、依存が増えるため退けた。

## 依存するライブラリの方針

- この Unit が使う外部のライブラリは、YAML のライブラリ(Code Generation で選ぶ)、`toml`、`thiserror` を基本とする。いずれも、Rust だけで書かれていること(NFR2.1)。
- ライブラリの具体のバージョンは、Code Generation で、その時点の安定版を選び、`Cargo.lock` で固定する。
- ライブラリを増やすときは、起動オーバーヘッド(NFR1)と、単一バイナリ(NFR2)への影響を確認する。

## この Unit に該当しない NFR

- NFR6(状態の表示の判別性、色の無効化)は、表示を受け持つ u3-cli の Reporter に該当し、この Unit にはない。
