# Intent Statement

## Problem Statement

- 既存のジョブ実行環境は、ジョブを一列に順次実行することしかできず、終了判定も限定的なため、「警告終了時は別の処理へ分岐する」「特定のジョブをスキップする」といった制御ができない。 [Q1]
- 加えて、ジョブ間で実行状態を引き継げない(ステート管理がない)ことも主要な課題である。 [Q1]

## Target Customer

- 既存の直列ジョブスケジューラ上でバッチジョブを運用する、組織内の運用担当者・開発者。 [Q2]
- ローカルでパイプラインをデバッグ・テストする開発者。 [Q2]

## Success Metrics

- 「個別実行」と「一連の実行」の2モードで、警告時の分岐・スキップが定義どおりに動作する(機能面の達成)。 [Q3]
- 起動オーバーヘッドなど数値目標は、この段階では設定していない。 [Q3]

## Initiative Trigger

- 既存実行環境の制約を、環境自体は変えずに上位レイヤーで補いたい。 [Q4]

## Initial Scope Signal

- ワークフローで選択されたスコープ(workflow-selected): `mvp`。 [scope]
- 初版の対象外(ユーザー確認済みのプロダクト境界)は次の3点。 [Q7]
  - 通知機能(Slack 通知など)そのものの組み込み。通知はジョブ側のスクリプトで行う。 [Q7]
  - 複数ホストにまたがる分散実行・ステート共有。 [Q7]
  - Web UI / GUI。 [Q7]

## Assumptions & Open Questions

None.
