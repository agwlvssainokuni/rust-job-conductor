## Intent analysis

README は、機能を足すたびに書き足してきたため、run ID の説明が散らばり、表のセルが長く、版の注記が揺れ、最初に動かす例がない。内容(事実)は変えずに、利用者が上から順に読める構成にする。あわせて、調査で見つかった誤りと書き漏れを直す。`demo/README.md` も、スクリプトの実際の動作と突き合わせて見直す。

## Functional requirements

- **FR1 構成**
  - **FR1.1 節の順番** [Q2: A] 見出しの階層は、今のまま(`##` と `###`)にして、次の順に並べる: 概要 → 目次 → インストール → クイックスタート → 使い方 → 定義ファイルの書き方 → ステートファイルの場所(run ID を含む) → 終了コードの表 → 保証の範囲(at-least-once) → シグナルの扱い → convert の使い方 → ロケールと言語 → ライセンス。
    - 受け入れ基準: 見出しの順が、この順である。
  - **FR1.2 目次** 概要のあとに、`##` の節へのリンクの一覧を置く(必要なら `###` の主要なものを含める)。
    - 受け入れ基準: 目次の各リンクが、実在する見出しに対応する(GitHub の見出しのアンカーの規則で)。
  - **FR1.3 クイックスタート** インストールのあとに、最小の定義(ジョブ 3 つ程度。1 つは失敗させられる)を作り、`validate`、`pipeline`、失敗、`watch`、再開までを、順に動かす手順を置く。コマンドと、期待する終了コードと出力を示す。UNIX 系の `sh` で動く書き方にし、Windows では `command` を `cmd` のものに読み替える旨を 1 行書く。
    - 受け入れ基準: 書いたとおりに、実際の `conductor`(リリースビルド)で実行すると、書いた終了コードと出力になる。
- **FR2 run ID の説明を 1 か所に** 与え方、優先順位、`--run-id ""`、値の規則、ファイル名、中身の `run_id`、`watch`・`reset` の動き、`reset --all` の対象、大文字小文字の注意、同時起動の注意を、「ステートファイルの場所」の中の、1 つの小節にだけ書く。ほかの場所(使い方の構文、コマンド表、オプション表、定義ファイルの例とキー表、終了コードの表、例)は、そこで必要な最小の事実(オプションの形、`run_id_env` のキーの意味を 1 文、終了コードの意味)と、その小節への参照だけにする。
  - 受け入れ基準: 値の規則(`A-Za-z0-9._-`、64 文字、先頭の `.`)、優先順位、`--run-id ""` の固定、`reset --all` の対象の記述が、README の中で 1 か所だけにある。ほかの箇所は、参照か、1 文以内。
- **FR3 表の短縮** コマンド表とオプション表の各セルは、1 文(目安 100 文字以内)にし、詳細は、対応する節(使い方の下の小節、または run ID の小節)に移す。
  - 受け入れ基準: 2 つの表の、どのセルも 1 文で、長い説明は節にある。移した説明が、README の中に残っている。
- **FR4 誤りと書き漏れの修正(質問なしで直す 6 項目)**
  - **FR4.1** インストールの展開の手順: アーカイブには、最上位に `conductor-<版>-<対象>/` のディレクトリがあり、その中に `conductor`(Windows は `conductor.exe`)と `LICENSE` がある。展開してから、そのディレクトリの中の実行ファイルを、`PATH` に置く手順に直す(zip も同じ構造)。
  - **FR4.2** シグナルの節: 「既定の動作で終わる」コマンドに、`watch`・`reset`・`convert` のほか、`validate` も含める。
  - **FR4.3** `reset --all`: run ID なしの `<名>.state` は、中身を読まず、通常のファイルなら消す(シンボリックリンクは消さない)。消すのに失敗したときは 65。run ID つきのファイルだけが、中身の `run_id` の照合を受ける。
  - **FR4.4** OS の表: Intel macOS 版は、クロスビルドで、動作の確認をしていない、と書く。
  - **FR4.5** `--all` の「(68)」など、終了コードの書き方を、ほかの箇所と揃える(例: 「使い方の誤り(68)」)。
  - **FR4.6** `demo/README.md`: 場面の表に、場面 0(定義の表示)を足す。
    - 受け入れ基準: 各項目が、実際のコード・リリースの構造・スクリプトと一致している(整理後の README を、調査の照合表と突き合わせる)。
- **FR5 ソースからのビルド** [Q1: A] 「インストール」の中の小節として、次を書く: 必要なもの(Rust 1.85 以降、`git`)、`git clone` とディレクトリの移動、`cargo build --release --locked --bin conductor`、できる実行ファイルの場所(`target/release/conductor`、Windows は `.exe`)、テスト(`cargo test --workspace --locked`)、`PATH` への置き方(`install`、または `cargo install --path crates/cli --locked`)。fmt・clippy・カバレッジなどの開発者向けの確認は、書かない。
  - 受け入れ基準: 書いたコマンドが、実際にこのリポジトリで動く(ビルドとテストを実行して確かめる。`cargo install --path crates/cli --locked` は、実行の確認を、`--root` を一時ディレクトリにして行う)。
- **FR6 版の注記** [Q3: A] 機能の追加された版を、同じ書き方(`(vX.Y.Z 以降)`)で、見出しまたは節の先頭に付ける: 配列の `command`(v0.2.0 以降)、`validate`(v0.4.0 以降)、run ID と `reset --all`(v0.5.0 以降)。古い版との互換の注意(配列の `command` は v0.1.x では読めない、など)は、その節の中に残す。
  - 受け入れ基準: 4 つの機能に、同じ形の版の注記がある。版の数字が、各リリースの内容と合っている。
- **FR7 `demo/README.md` の見直し** スクリプトの実際の動作と、既定値に合わせる(`DEMO_SLEEP` の既定: UNIX 版 0.5 秒、Windows 版 1 秒、`DEMO_PAUSE`、`DEMO_LANG`、`DEMO_RUN_ID`、`DEMO_<ジョブ名>_EXIT`、`CONDUCTOR`)。場面 0〜9 の表(UNIX 版と Windows 版で同じ場面)と、環境変数の説明を、整理して、UNIX 版と Windows 版の使い方を並べる構成は保つ。ルートの README のクイックスタートと、用語(run ID、ステート)が、揃っている。
  - 受け入れ基準: `demo/README.md` の、場面の内容、環境変数の名前と既定値、コマンド例が、`demo/run-demo.sh`・`demo/windows/run-demo.cmd`・各スクリプトと一致する(突き合わせて確認する)。
- **FR8 意味を変えない** 整理で、規則・終了コード・表示・保証の記述(事実)を、削らず、変えない(FR4 の修正を除く)。
  - 受け入れ基準: 調査の照合表の各行の根拠となる記述が、整理後の README にも残っている(語句を検索して確かめる)。

## Non-functional requirements

- **NFR1 docs-check** CI の `docs-check` の 7 語句(`SHA-256`、`Gatekeeper`、`終了コードの表`、`ステートファイルの場所`、`at-least-once`、`シグナル`、`convert`)が、README に残る。見出しの語(`SHA-256`、`終了コードの表`、`ステートファイルの場所`、`at-least-once`)は、変えない。
  - 受け入れ基準: CI の検索と同じ `grep` が、すべて見つかる。
- **NFR2 変更の範囲** 変更は `README.md` と `demo/README.md` だけ。`conductor` 本体、デモのスクリプトとテスト、`.github/`、`Cargo.toml`・`Cargo.lock`、版は、変えない。リリースはしない。
- **NFR3 リンク** README 内のリンク(目次、節への参照、`demo/README.md` へのリンク、`LICENSE` へのリンク)が、切れていない。
- **NFR4 品質** `cargo fmt --check`、`cargo clippy -D warnings`、`cargo test`、Rust 1.85 でのビルドと、3 OS の CI が成功のまま(コードは変えないので、変わらない)。

## Constraints

- 日本語で書く(英語版は作らない)。既存の文体(です・ます調、見出しの名前の付け方)に合わせる。
- 見出しの名前を変えるときは、`docs-check` の語を含む見出しは変えない。
- クイックスタートで示す出力は、実際に実行して得たものだけを使う。

## Assumptions

- クイックスタートの `command` は、UNIX 系の `sh -c` で書く。Windows では `cmd /c` に読み替える旨を書く。[assumption]
- 目次は、`##` の節を中心にし、リンクの数を増やしすぎない。[assumption]
- 「保証の範囲(at-least-once)」「シグナルの扱い」などの節の本文は、FR4 の修正を除き、文言を直さない(順番が変わるだけ)。[assumption]

- `conductor` 本体、デモのスクリプトとテスト、`.github/`、版の変更。リリース。
- 見出しの階層の変更(大区分の追加)。
