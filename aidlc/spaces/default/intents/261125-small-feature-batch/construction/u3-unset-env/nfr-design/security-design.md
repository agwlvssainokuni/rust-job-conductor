# セキュリティの設計: u3-unset-env

出典: セキュリティの要件(`security-requirements.md` の NFR6.1〜NFR6.3、NFR5.1、NFR4.1)、技術の選択(`tech-stack-decisions.md`)、機能の仕様(`functional-spec.md` の 2、4)、契約(`contract-summary.md` の C1)。

## 1. 消す名前と重なりの比べ方(NFR6.1)

要件のレビューの指摘(Windows で、重なりの検査は完全一致なのに消し方は大文字小文字を区別しない食い違い)に応えて、比べ方を次に決める。

- 実際に消すのは std の `Command::env_remove`。UNIX 系は完全一致、Windows は大文字小文字を区別しない(機能の設計の Q1)。
- 重なりの検査(`env` と `.env`)は、**どの OS でも ASCII の大文字小文字を区別せずに**比べる。こうすると、Windows で `unset_env = ["path"]` と `env` の `PATH` を併記した定義は、どの OS でも 64 になり、「消したつもりが残る」が起きない。UNIX 系で大文字小文字だけが違う名前を消して足す使い方は、誤りになる(まれで、OS によって意味が変わる書き方なので止める)。
- 重複のまとめ(機能の設計の BR1.3)は完全一致のまま(まとめなくても `env_remove` を 2 回呼ぶだけで結果は同じ)。
- 確かめ方: 重なりの検査の単体テストで、`FOO`/`foo` の組が誤りになること。Windows の CI の実バイナリのテストで、`unset_env = ["PATH"]` で親の `Path` が消えること。

## 2. 表示とステート(NFR6.2、NFR6.3)

- 新しい 2 つの誤りの理由の文は固定の文で、値も名前も入れない(機能の設計の BR2.1、BR2.2)。`unset_env` の名前の規則の誤りは、`env` と同じ種類を使い、理由の文は「`unset_env` の名前は、…で書きます」のように `unset_env` の文に分ける(機能の設計のレビューの指摘)。
- `--dry-run` は消す名前だけを出し、親の環境を読まない。
- ステートには、足す変数も消す名前も書かない(今の `nfr_content.rs` の検査の範囲。要件のレビューの指摘)。
- 確かめ方: `nfr_security.rs` の `cases` に新しい 2 つの種類と型の誤りを足す。`--dry-run` の出力に親の値が出ないことを実バイナリのテストで確かめる。
