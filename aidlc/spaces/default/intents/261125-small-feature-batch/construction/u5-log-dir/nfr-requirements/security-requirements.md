# セキュリティの要件: u5-log-dir

出典: 要件(`requirements.md` の FR5.3、NFR4、NFR5、NFR6)、機能の仕様(`functional-spec.md` の 2、6)、ビジネスルール(`rules.md` の BR3.2、BR3.4、BR4.2、BR5.1〜BR5.3)、契約(`contract-summary.md` の C6)、技術スタック(`technology-stack.md`)、project.md の Forbidden。

ジョブの出力には秘密が混じりうる。ログのファイルは、それを手元に残すものである。

## 要件

| ID | 要件 | 合否の基準 | 出典 |
|---|---|---|---|
| NFR6.1 | ログのファイルは、UNIX 系では作る時点で 0600(作った後に権限を変えるのではなく、作るときに指定する) | UNIX 系のテストで、作ったファイルの権限が 0600 であること | NFR6、BR3.4 |
| NFR6.2 | ファイルにはジョブの出力だけを書き、conductor は環境変数・コマンド・見出しを書き足さない | 決まった出力をするジョブで、ファイルの中身がその出力と一致すること(実バイナリ) | NFR6、BR4.2 |
| NFR6.3 | ジョブ ID からファイル名を作るとき、`log_dir` の外にファイルを作らない(`/`、`\`、`..`、先頭の `.`、Windows の予約名と末尾の `.`・空白を安全にする) | `../x`、`a/b`、`CON`、`a.` などの ID で、作られるファイルが `log_dir` の直下にあり、名前が安全であること | NFR6、BR3.2 |
| NFR6.4 | ログの失敗の表示は固定の文と表示用に escape したパスだけで、ファイルの中身やジョブの出力を含めない | 失敗の各場合の標準エラーをテストで確かめる | NFR6、BR5.1〜BR5.3 |
| NFR6.5 | 既存のファイルを上書きも追記もしない(「無いときだけ作る」で開く) | 同じ名前のファイルを置いた状態で、元のファイルの中身が変わらないこと | FR5.3、BR3.1、BR3.3 |
| NFR5.1 | 権限の指定など OS ごとの違いは runtime の `platform` に置き、`cfg` をその外に書かない。`unsafe` を足さない | `nfr_source.rs`(runtime、cli) | NFR5 |
| NFR4.1 | 新しい依存を加えない(時刻の計算、パイプの読み取りは std だけ) | `Cargo.lock` が変わらない | NFR4 |
