# 観測の要件: u5-log-dir

出典: 要件(`requirements.md` の FR5.2、FR5.4、NFR6)、機能の仕様(`functional-spec.md` の 2、3、6)、ビジネスルール(`rules.md` の BR4.1、BR5.1〜BR5.3)、契約(`contract-summary.md` の C6)、技術スタック(`technology-stack.md`)。

ログのファイル自体が、このユニットの観測の手段である。

## 要件

| ID | 要件 | 合否の基準 | 出典 |
|---|---|---|---|
| NFR1.8 | 端末への出力は、`log_dir` の有無で同じ内容になる(子の標準出力は conductor の標準出力へ、標準エラーは標準エラーへ)。各流れの中の順は保つ | 同じジョブを `log_dir` あり・なしで動かし、標準出力と標準エラーをそれぞれ比べる | FR5.2、BR4.1 |
| NFR1.9 | 子の出力は、読んだ分をすぐ端末に書き出す(溜めずに flush する)。conductor 自身の表示(`-v` の行など)とは別の経路だが、試行の前後の conductor の表示とは前後が入れ替わらない | 試行の前後の `-v` の行と、ジョブの出力の順を確かめるテスト | FR5.2 |
| NFR6.6 | ログの警告(書き込みの失敗、待ち切れ)と 127 の理由は、標準エラーの 1 行で、英日の文言を持つ(今の表示の仕組みに従う) | 表示のテスト | BR5.1〜BR5.3 |
