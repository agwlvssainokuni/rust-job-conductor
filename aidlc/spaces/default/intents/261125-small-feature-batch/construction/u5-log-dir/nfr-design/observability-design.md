# 観測の設計: u5-log-dir

出典: 観測の要件(`observability-requirements.md` の NFR1.8、NFR1.9、NFR6.6)、技術の選択(`tech-stack-decisions.md`)、機能の仕様(`functional-spec.md` の 2、6)、契約(`contract-summary.md` の C6)。

## 設計

- **端末への出力を揃える(NFR1.8)**: 子の標準出力を読むスレッドは conductor の標準出力へ、標準エラーを読むスレッドは標準エラーへ書く。各流れの中は読んだ順。
- **溜めない(NFR1.9)**: 読んだ分を書いたらすぐ flush する。conductor 自身の表示は今の `Sink` を通るが、試行の前の表示は起動の前に、試行の後の表示は読み取りの待ち(最大 2 秒)の後に出すので、ジョブの出力と前後が入れ替わらない。子の出力は `Sink` を通らない(機能の設計のレビューの指摘。表示の層の文言を通さないジョブそのままの出力なので、今の引き継ぎと同じ扱い)。
- **ログの文言(NFR6.6)**: 127 の理由、書き込みの失敗、待ち切れの 3 つの文を、今の表示の仕組み(`DisplayEvent` と `messages.rs` の英日)に足す。
- **2 つの流れの間の順**: 契約 C6 の「子が書いた順」は、2 つのパイプを別々に読む以上、流れの間では厳密には保てない(機能の設計のレビューの指摘)。各流れの中の順は保ち、流れの間は読んだ順とする。README に書く。

## 確かめ方

- 同じジョブを `log_dir` あり・なしで動かし、標準出力と標準エラーをそれぞれ比べる実バイナリのテスト。
- `-v` の試行の前後の行とジョブの出力の順を確かめる実バイナリのテスト。
- 3 つの文の英日の表示のテスト(`src/tests/report_messages.rs`)。
