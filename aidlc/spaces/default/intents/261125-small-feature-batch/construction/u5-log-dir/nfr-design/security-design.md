# セキュリティの設計: u5-log-dir

出典: セキュリティの要件(`security-requirements.md` の NFR6.1〜NFR6.5、NFR5.1、NFR4.1)、技術の選択(`tech-stack-decisions.md`)、機能の仕様(`functional-spec.md` の 2、6)、契約(`contract-summary.md` の C6)。

## 1. 安全な名前(NFR6.3)

要件のレビューの指摘(機能の設計の名前の規則と要件の食い違い)に応えて、名前の規則をここで確定する。機能の設計の置き換えに、次の 2 つを足す。

1. 置き換える文字: `/` `\` `:` `*` `?` `"` `<` `>` `|`、制御文字(U+0000〜U+001F、U+007F〜U+009F)→ `_`。先頭の `.` → `_`。
2. 末尾の `.` と空白(Windows が名前から落とすもの)→ `_`。
3. 置き換えた後の名前が、大文字小文字を問わず Windows の予約名(`CON`、`PRN`、`AUX`、`NUL`、`COM1`〜`COM9`、`LPT1`〜`LPT9`)と一致するなら、先頭に `_` を足す(すべての OS で同じ名前にする)。
4. 空になることは無い(ジョブ ID は空でない)。

- 名前は 1 つの関数 `safe_log_stem` にまとめ、OS によらず同じ結果にする。ディレクトリの区切りが残らないため、ファイルは必ず `log_dir` の直下にできる。
- 確かめ方: 入力と出力の対の表(`a`→`a`、`a/b`→`a_b`、`../x`→`_._x`、`.env`→`_env`、`a.`→`a_`、`a `→`a_`、`CON`→`_CON`、`com1`→`_com1`、`日本語`→`日本語`、`a\tb`→`a_b`)の単体テスト。

## 2. 権限と作り方(NFR6.1、NFR6.5)

- 開き方は `OpenOptions` の `write` と `create_new`。既存のファイルを開かない。
- UNIX 系は、開く前に `platform::unix` の関数で `mode(0o600)` を付ける。Windows の `platform` の同じ名前の関数は何もしない。`cfg` は `platform` の中だけ。
- 確かめ方: UNIX 系のテスト(`platform` の中か、`cfg` を使えるテストの中)で権限 0600。同じ名前のファイルを置いたテストで元の中身が変わらない。

## 3. 書き足さない・表示に中身を出さない(NFR6.2、NFR6.4)

- 読み取りのスレッドは、読んだバイト列をそのまま端末とファイルへ書く。conductor の文はファイルに書かない。
- 失敗の表示は固定の文と `escape_full` を通したパスだけ。ジョブの出力やファイルの中身を含めない。

## 4. 依存とコードの規則(NFR5.1、NFR4.1)

- 新しい依存は無い。`unsafe` は足さない。`cfg` は runtime の `platform` の中だけ。`nfr_source.rs` と CI の `build-check` が確かめる。
