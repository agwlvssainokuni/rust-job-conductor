# セキュリティの要件: u1-pipeline-retry

出典: 要件(`requirements.md` の NFR4、NFR5、NFR6)、機能の仕様(`functional-spec.md` の 6)、ビジネスルール(`rules.md` の BR3.2、BR4.1)、契約(`contract-summary.md` の C3)、技術スタック(`technology-stack.md`)、project.md の Forbidden。

このユニットは定義ファイルの検証だけを変える。認証・認可・通信は無い(単体の CLI)。守るものは、誤りの表示とステートに秘密や入力の値を漏らさないこと、依存と `unsafe` を増やさないことである。

## 要件

| ID | 要件 | 合否の基準 | 出典 |
|---|---|---|---|
| NFR6.1 | `[pipeline.retry]` と `retry` に関する誤りの理由の文は、固定の文だけで作る。終了コードの値、ジョブの ID、`retry` に書いた値を入れない | 新しく足す誤り(既定の型、既定との重なり、`retry` の型)の表示に、入力の値もジョブの ID も現れないことをテストで確かめる。入力に由来してよいのはキー名だけ(今の規則) | NFR6、BR3.2 |
| NFR6.2 | 既定の当てはめは、ステートにも出力にも何も書き足さない | ステートの中身のテスト(`nfr_content.rs`)が今のまま通る。既定を当てはめたジョブのステートが、`[job.retry]` を書いたジョブのステートと同じ形 | NFR6 |
| NFR5.1 | 変更は core の定義の検証(`definition/walk`)と型の文書の中に閉じ、`unsafe` と `cfg(unix)`/`cfg(windows)` を書かない | core の `#![forbid(unsafe_code)]` が保たれ、`nfr_source.rs` が通る | NFR5 |
| NFR4.1 | 新しい外部ライブラリ(依存)を加えない | `Cargo.toml` と `Cargo.lock` の依存が変わらない。CI の `build-check` が通る | NFR4 |

## 脅威の検討

| 脅威 | 対策 |
|---|---|
| 誤りの表示から、定義に書いた値やジョブの ID が CI のログなどに漏れる | NFR6.1。誤りの位置は行の番号だけで示す(BR3.2) |
| 細工した定義で、検証の手間を大きくする | 既定との重なりの検査はジョブごとに 1 回、終了コードの並びは最大 255 個で、手間は今の `[job.retry]` の検査と同じ程度(`performance-requirements.md` の NFR1.3)。定義の大きさの上限は今のまま |
| リトライの既定で、意図せず多くのジョブが繰り返し動く | 範囲は `[job.retry]` と同じ(`max` は 1〜100、間隔は 1 秒〜24 時間)。打ち消しは `retry = false`(BR2.1)。README で、既定がすべてのジョブに当たることと、再実行されても困らない作りにすることを示す(BR4.2) |
