# 性能の要件: u1-pipeline-retry

出典: 要件(`requirements.md` の NFR1)、機能の仕様(`functional-spec.md` の 2)、ビジネスルール(`rules.md` の BR2.2、BR3.1)、契約(`contract-summary.md` の C3)、技術スタック(`technology-stack.md` の CI の `startup-bench`)。

このユニットは定義の検証に、既定の読み取りと、ジョブごとの重なりの検査を足すだけである。待ち時間やリトライの間隔の計算は変えない。

## 要件

| ID | 要件 | 合否の基準 | 出典 |
|---|---|---|---|
| NFR1.3 | 既定の検査の手間は、ジョブの数に比例し、ジョブごとに 1 回(既定の `exit_codes` と成功・警告の終了コードの比較)とする。既定の複製は組み立てのときに 1 度だけ作る | 検証はジョブを 1 回ずつ見る形で書く(設計の流れの 4)。起動の測定(`startup-bench`、`nfr_perf.rs`)で、今の結果より目に見えて遅くならない(測定は警告のみで、失敗にしない今の扱いのまま) | NFR1、BR3.1、BR2.2 |

## 範囲の外

- リトライの待ち時間の正確さ、待機の仕組み: 変えない(リトライの判断と流れは今のまま。BR2.4)。
