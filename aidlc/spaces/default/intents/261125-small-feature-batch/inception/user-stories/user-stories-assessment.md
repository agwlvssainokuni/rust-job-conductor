# ユーザーストーリーの要否の判断

- **判断**: Skip(省く)
- **理由**: 開発者ご自身と身近な運用の担当者が使う、コマンドラインツール(`conductor`)の小さな機能追加である(intent-statement.md の Target Customer)。ステージの条件「開発者向けのツールの場合は省略」に当てはまる。前の機能追加(v0.9.0)でも同じ理由で省いた。
- **考えた点**:
  - 種類: 既存の CLI への 7 つの小さな機能追加。画面は無い。
  - 利用者: 2 種類だが、どちらも同じ定義ファイルとコマンドを使い、目的も同じ(定義の書き方と、実行の確かめやすさ)。
  - 複雑さ: 業務の規則は少なく、チームをまたぐ調整も無い。
- **代わりの網羅**: 要件(`requirements.md`)が FR1〜FR8 と NFR1〜NFR7 を細目に分け、各項目に合否の基準を付けている。設計とテストは要件の ID から直接たどれる。
