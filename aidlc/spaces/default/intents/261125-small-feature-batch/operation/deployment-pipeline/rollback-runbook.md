## 公開の前(下書きのうち)

| 場面 | 手順 |
|---|---|
| `release.yml` のどれかのジョブが落ちた | 原因を `main` で直して CI を通す → `git push origin :refs/tags/v0.10.0` と `git tag -d v0.10.0` でタグを消す → 直したコミットの上にタグを付け直して push |
| 下書きを確かめて問題が見つかった | 下書きのリリースを消す(`gh release delete v0.10.0`)→ 上と同じくタグを消し、直してから付け直す |

- 公開前は利用者に届いていないため、利用者への影響は無い。

## 公開の後

| 場面 | 手順 |
|---|---|
| 利用者が困る不具合 | 前の版 v0.9.9 のリリースは残るため、利用者はそのバイナリに戻せる。直したものを v0.10.1(3 桁目を上げる。team.md)として同じ流れで出す |

## ステートの互換の注意(v0.10.0 から戻すとき)

- v0.10.0 が書いたステート(`[[job.attempt]]` を含む)は、v0.9.9 では知らないキーとして読めない(65)。戻すときは `conductor reset`(または `reset --all`)でステートを消してから使う。逆に、v0.9.9 のステートで動いたジョブがあるものは、v0.10.0 で 65 になり、`reset` の案内が出る(README に記載)。
- 定義ファイルは、v0.10.0 の新しいキー(`[pipeline.retry]`、表の `env_file`、`unset_env`、`log_dir`)を使っていなければ、v0.9.9 でもそのまま読める。
