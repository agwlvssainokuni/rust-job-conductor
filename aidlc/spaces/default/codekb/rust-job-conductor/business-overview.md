# ビジネス概要

## 目的

`conductor` は、既存のジョブスケジューラ(cron など)から呼び出される、ジョブの流れの制御ツールである。定義ファイル(`conductor.toml`)に、ジョブと、結果(成功・警告・エラー)ごとの次の動きを書いておくと、ジョブを記述順に実行し、遷移の規則に従ってスキップや終了を行い、実行の状態(ステート)をファイルに覚える。エラーで止まったあとは、エラーのジョブから再開できる。

- 単一の実行ファイル(`conductor`)。外部のランタイムは要らない。Linux・macOS・Windows で同じ定義に同じ結果を返す。
- ネットワークに接続せず、利用状況の収集もしない。
- 表示は、環境のロケールに従って英語と日本語を切り替える。
- 現在の版は 0.8.0(4 クレートとも同じ版)。

## 利用者とユースケース

| 利用者 | ユースケース |
|--------|--------------|
| スケジューラの運用者 | cron 等から `conductor pipeline <名前>` または `conductor run <ジョブID>` を呼び、夜間バッチなどのジョブ列を制御する |
| ジョブの作者 | 定義ファイルに、ジョブ、警告の終了コード、遷移(`@end` を含む)、リトライを書く |
| 障害対応の担当者 | エラーで止まったジョブから再実行する。`watch` で状態を見る。`reset` でステートを消す |
| 定義の整備者 | `validate` で定義を実行せずに検査する。`convert` で YAML と TOML を相互に変換する |

## 主要な機能(0.8.0 時点)

1. 定義の読み込みと検証(30 種のエラー、行番号つき。複数の誤りをまとめて報告する)。
2. ジョブの直接起動(シェルを介さない。`command` は文字列または文字列の配列)。
3. 結果の分類(success / warning / error と、起動失敗 127、シグナル 128+n)と、遷移・`@end`・スキップ。
4. ステートファイル(TOML)による再開。run ID でステートを分ける(`--run-id`、定義の `run_id_env`)。完了時の削除(`--remove-on-complete`、`remove_on_complete`)。
5. リトライ(`[job.retry]`。固定または指数の待機、上限つき。0.8.0 で追加)。
6. シグナルの転送と中断の記録(UNIX は SIGHUP・SIGINT・SIGQUIT・SIGTERM、Windows は Ctrl+C)。
7. 補助のコマンド: `watch`(状態の一覧)、`reset`(`--all` を含む)、`validate`、`convert`。
8. 終了コードの規約: 成功・警告・スキップは 0。ジョブのエラーはジョブの終了コード。`conductor` 自身のエラーは 64(定義)、65(ステート)、66(拒否)、67(変換)、68(使い方)、70(内部)。

## 保証と非目標

- at-least-once: ジョブの終了とステートの書き込みのあいだに落ちると、そのジョブは再実行されうる。排他制御はしない。自動の再試行は `[job.retry]` の設定がある場合だけ。
- 入力に対してパニックしない。エラー表示に入力の値(誤った値、ライブラリのエラー文)を含めない。ステートファイルに command・環境変数・出力を書かない。

## この intent(env-graph-dryrun-init、v0.9.0)との関係

現在の実装に無く、この intent が足す予定の機能(要求の確定は後続のステージ):

- 環境変数の注入と `.env` ファイル(ジョブの起動に環境変数を渡す)。
- `conductor graph`(定義の流れの図示)。
- `--dry-run`(ジョブを起動せずに流れを確かめる)。
- `conductor init`(定義の雛形の生成)。

これらは、定義の読み込み・検証(core)、ジョブの起動(runtime)、コマンドと表示(cli)、変換(converter)に及ぶ。

## 業務上の主な取引(トランザクション)

| 取引 | 入口 | 結果 |
|------|------|------|
| ジョブ列の一括実行 | `conductor pipeline <名前>` | 全ジョブを記述順に処理し、完了のステートを残す(または削除する) |
| 1 ジョブの個別実行 | `conductor run <ジョブID>` | 起動前の判断に従い、実行・スキップ・拒否 |
| 再開 | 同じコマンドの再実行 | エラーのジョブ(`resume_job_id`)から再開 |
| 状態の確認 | `conductor watch` | ステートの表 |
| 定義の検査 | `conductor validate` | 誤りの一覧(64)または成功 |
| 形式の変換 | `conductor convert <file> --to <yaml|toml>` | 変換した文字列を標準出力へ |
