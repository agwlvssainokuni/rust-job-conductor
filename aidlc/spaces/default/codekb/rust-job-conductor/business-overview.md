# Business Overview

## 目的

`conductor` は、定義ファイル(TOML)に書いたジョブを、記述順に実行する、単一バイナリの CLI である。遷移の規則(`success`/`warning` ごとに、次のジョブか `@end`)でスキップや終了を行い、実行の状態(ステート)を定義ファイルの隣のファイルに覚える。エラーで止まったら、同じコマンドで、止まった位置から再開できる。自動の再試行はしない(`README.md`)。

## 主な機能(コマンドは 6 つ。詳細は `api-documentation.md`)

- `run <job-id>`: ジョブを 1 つ実行する。
- `pipeline <name>`: 全ジョブを、記述順に、1 つずつ実行する。エラーで止まる。
- `watch`: ステートを、ジョブ・状態・補足の表で、1 回表示する。
- `reset`: ステートを消す(`--run-id`、`--all`)。
- `validate`: 定義と、全ジョブの `command` を検査する。
- `convert`: 定義を TOML と YAML のあいだで変換する。

## 利用者と価値

- 利用者: バッチやパイプラインを、シェルのスクリプトより安全に、止まった所から再開したい運用者・開発者。
- 価値: 再開(済んだジョブは再実行しない)、run ID による並行した実行単位の分離(v0.5.0 以降)、終了コードの規則(0〜255、64〜70 は conductor 自身の誤り)、英語・日本語の表示。

## この intent に関わる業務の現状

- 実行が最後まで進む(最後のジョブの成功・警告、`@end`、スキップでの完了)と、ステートファイルは**自動で消える**(run ID の有無によらない)。次の実行は先頭から始まる(`README.md` の「ステートファイルの場所」)。
- そのため、`watch` は、完了後に `no state (nothing has run yet)` を表示し、「完了した」と「まだ動いていない」を区別できない。
- 古い run のステートの後始末は、`reset --all`(利用者が行う)。run ID つきのステートは、完了で消えるので、残るのは止まった run だけである。

## 前提と制約

- Rust に不慣れな開発者が保守する。変更は小さく、小さな単位でレビューする(`team.md`)。
- 3 OS(Linux・macOS・Windows)で動く。同時実行の排他制御はしない(後に書いた方が勝つ)。
