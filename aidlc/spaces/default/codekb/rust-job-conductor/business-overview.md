# Business Overview

## 目的

`conductor` は、既存のジョブスケジューラ(cron など)から呼び出される、ジョブの流れの制御ツールである。定義ファイル(`conductor.toml`)に、ジョブと、結果(成功・警告・エラー)ごとの次の動きを書いておくと、`conductor` がジョブを記述順に実行し、遷移の規則に従ってスキップや終了を行い、実行の状態(ステート)をファイルに覚えておく。エラーで止まったあとは、エラーのジョブから再開できる。

- 配布形態は単一の実行ファイル `conductor`(外部ランタイム不要)。Linux・macOS・Windows で、同じ定義に同じ結果を返す。
- ネットワークに接続せず、利用状況の収集もしない。
- 表示は環境のロケールで英語と日本語を切り替える。
- リポジトリの版は 0.7.0(Cargo のワークスペース)、ライセンスは Apache-2.0。

## 利用者と使われ方

| 利用者 | 使い方 |
|--------|--------|
| 運用担当者・開発者 | `conductor.toml` を書き、cron などのスケジューラから `conductor run <job-id>`(ジョブ単位)または `conductor pipeline <name>`(一括)を呼ぶ |
| スケジューラ | `conductor` の終了コード(0 = 成功・警告・スキップ、ジョブ自身のコード、64〜70 = conductor 自身のエラー)で、次の動きを判断する |
| 運用担当者 | `conductor watch` でステートを一覧し、`conductor reset` で初期化し、`conductor validate` で定義を検査し、`conductor convert` で YAML と TOML を変換する |

## 主要な機能

1. **ジョブの実行**: 定義の `command`(文字列または文字列の配列)を、シェルを介さずに直接起動し、終了を待つ。時間の上限はない。
2. **結果の分類**: 終了コードを成功(既定は `[0]`)・警告(`warning_exit_codes`)・エラー(それ以外)に分ける。
3. **遷移**: 成功・警告のあとの行き先を、記述順で後ろのジョブまたは `@end` で指定できる。エラーには遷移を書けない。間のジョブはスキップになる。
4. **ステートと再開**: 結果のたびにステートファイル(`<定義ファイル名>.state`、run ID があれば `<定義ファイル名>.<run-id>.state`)を原子的に書き、エラーで止まった次の呼び出しで、エラーのジョブから続ける。at-least-once(ジョブの終了と記録のあいだに落ちると再実行されうる)。
5. **run ID**: 同じ定義の複数の実行を、run ID でステートを分けて並べられる(環境変数 `CONDUCTOR_RUN_ID` か定義の `run_id_env` か `--run-id`)。
6. **シグナル**: UNIX 系は SIGHUP・SIGINT・SIGQUIT・SIGTERM を実行中のジョブへ 1 回だけ転送し、ジョブのあいだでは次を起動せず再開位置を記録して 128 + 番号で終わる。Windows は Ctrl+C のみ。
7. **補助コマンド**: `watch`(ステートの表)、`reset`(`--all` を含む)、`validate`、`convert`(YAML と TOML の相互変換)。

## 現在の intent との関係(job-retry)

この intent は「ジョブが、設定された終了コードで終わったとき、最大 N 回、設定した間隔で自動的に再実行する」機能を足す。間隔は固定、増える間隔(指数バックオフ)の選択肢もあり、ジョブごとに `conductor.toml` で設定し、進捗(何回目の再試行か、次まで何秒か)を表示する。設定しなければ現行の動きのまま(後方互換)。

現行のコードは「自動の再試行はしない」ことを仕様として明記している(`crates/core/src/flow/next_step.rs` の `classify_and_decide` の doc コメント、`crates/runtime/src/lib.rs` の「公開しないもの」、`crates/cli/src/pipeline.rs` の冒頭)。エラーのジョブは停止し、`resume_job_id` を自分にして、利用者(またはスケジューラ)による再呼び出しで再開する。再試行は、この「エラーで即停止」の前に挟む新しい層になる。

## ビジネス上の制約・前提(コードから読み取れるもの)

- 冪等でないジョブが 2 回動きうることを、README が明示的に利用者へ求めている(at-least-once)。再試行は、この前提を同じプロセスの中でも起こすことになる。
- 時間の上限(タイムアウト)がなく、ジョブが終わらなければ待ち続ける。
- 排他制御(ファイルのロック)はない。同じ定義の同時の実行は、後に書いた方が勝つ。
- 定義の書式は `format_version = 1` のみ。定義・ステートとも、未知のキーは拒否する(厳格)。
- 開発体制の前提(`aidlc/active-memory/team.md`): 開発者は Rust に不慣れで、変更を小さく保つ。テストは test-after、行カバレッジ 80%、CI で 3 OS を検査する。
